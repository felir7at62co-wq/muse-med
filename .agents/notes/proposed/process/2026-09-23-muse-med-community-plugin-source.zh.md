# Agent Note: 在 muse-med 分支保留社区插件源码

Status: proposed

[English](2026-09-23-muse-med-community-plugin-source.md) | 中文

## 问题

操作者的 Web 配置加载了五个社区插件，其安装包并不都包含原始源码。直接复制安装目录会带入生成的 JavaScript，甚至可能带入用户配置；只在分支中保留 npm 依赖，则不能满足检查和保留插件源码的要求。桌面安装包也不能因为仓库中有源码，就宣称插件已经加载。

## 提案

在 [`third_party/plugins`](../../../../third_party/plugins/README.zh.md) 保存只含源码的快照，用 `sources.json` 固定上游提交，并保留各自许可证。保留 Codex 的第三方声明；排除安装包、生成文件、另有权利限制的图标、令牌、配置和用户媒体。对照固定的上游提交核对保留文件，并记录文本换行规范化。在安装包依照[内置运行时决策](../../implemented/architecture/2026-09-08-desktop-bundled-runtime-and-external-plugins.zh.md)管理共享包、编译并加载各个兼容插件之前，这五个目录不加入 pnpm 工作区。

## 构建实现

[源码构建脚本](../../../../third_party/plugins/build.mjs)使用已构建的当前仓库和独立冻结的工具链锁文件，在隔离的临时目录中编译五份快照。它保留许可证、在各压缩包中记录源码固定版本，且不复制在线用户配置。仅产物元数据向 peer 候选添加当前精确 Host 版本；不修改上游清单或根工作区依赖范围。这是经审核的本地兼容性补充，不代表任意未来 Host 版本都能工作。临时 Codex 运行时还将检查和准备同时固定为已批准的 provider 版本，保留 CLI 0.153.4，并将其清单与启动文件映射到解包目录。仅修改 peer 元数据不能覆盖上游执行时的允许列表；若不修改安装目标，仍可能降级。

免密检查覆盖全部已构建 Host 入口的导入、针对当前 API 的 Codex 模型准备和 RPC 校验，以及 FFmpeg 工具行为和逐字节一致的重复构建。这些检查不能取代真实产品 Loader 与 Client 的验收标准。准备阶段另行拒绝缺失的原生 CLI 包、解析到复制产物之外的依赖，以及内置 Node 执行 CLI 后返回的错误版本：npm 允许可选下载失败，因此仅安装成功不能证明产物合格。Lark 的无凭据路径会发起开户，运行时还会开启本地控制服务，因此需要明确启用。Market 在无端口桌面产品中作为源码依赖携带，不挂载其 HTTP 界面。

保留文件在 CRLF 转 LF 后与固定的公开源码包一致；已有快照并非都与上游文本逐字节相同。源码和工具链的仓库所有权取代了对已安装用户配置的复制，但不宣称整个安装包或跨平台产物逐字节一致。为保持上游原文，翻译发现仅排除五个固定的源码目录；父级文档和新目录仍纳入自有双语文档范围。

构建器使用 pnpm 原生的有界下载截止时间处理大型平台包，而不另建下载器或引入二进制复制回退。Pnpm 11.7.0 使用 Undici 和 `AbortSignal.timeout`；数值错误 23 是 Node 的 `TimeoutError`，不是 libcurl 写入错误。实测官方 Codex tarball 响应为 141,495,386 字节，87 秒后仅收到 13,524,363 字节，超过 pnpm 默认的 60 秒完整响应截止时间。仅冻结的生产安装使用延长的截止时间；元数据解析保留原生截止时间和重试，避免停滞的元数据请求阻塞三十分钟。参数使用已声明的 `--fetch-timeout`，而不是 `--config.fetch-timeout`：pnpm 的无类型配置透传将数值保留为字符串，导致 `AbortSignal.timeout` 在请求开始前失败。隔离空缓存的远程安装确认，已声明的选项以数字传入 Node 并完成下载；仅本地 tarball 测试无法覆盖此故障。显式的构建专用超时保留锁文件完整性校验和遇缺失即拒绝的产物检查；它不证明未完成的下载合格。

## 考虑过的替代方案

**直接复制 Web 安装目录。** 已发布的包可能缺少源码，而且配置可能含有凭据或状态；这种做法也不能固定可重复获取的源码版本。

**只保留 npm 依赖。** 精确版本可以安装插件，但分支没有用户要求的源码。

**使用 Git 子模块。** 不递归初始化的仓库副本仍缺少源码，还要求组员的机器再次通过 Git 获取文件。

## 验收标准

仓库包含五份完整的原始 `src/` 目录、固定的上游修订与许可证文本。全新 Windows 安装包能构建或携带审核过的插件，只加载明确配置的能力，并通过真实的 Host/Client 组合烟测，且组员不必安装 Git、Node 或 Python。发布前须核对已安装 Codex 包与上游清单的差异，以及传递依赖和资源文件各自的许可证。

## 风险

只有源码快照并不会产生可用的插件，也不会授予飞书、ChatGPT 或视频编码器的访问权。若不遵守桌面插件的所有权和批准规则，运行时加载可能导致共享 peer 实例不兼容或泄露凭据。ffmpeg 的版本固定在上游提交，而非发布标签；二进制等价与全新构建仍需单独核验。
