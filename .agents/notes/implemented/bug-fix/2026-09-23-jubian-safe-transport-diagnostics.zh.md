# Agent Note: 安全的剧变传输诊断

Status: implemented

[English](2026-09-23-jubian-safe-transport-diagnostics.md) | 中文

## 问题

`JubianClient` 丢弃了传输失败类别与非成功 HTTP 状态数字。通用消息无法区分 DNS、连接、TLS、超时或 HTTP 失败。暴露原始错误文本会让凭据、URL 与提供方内容泄漏到工具结果中。

## 决策

客户端保留 `JubianError` 错误码及其现有的可选详情 API。失败的 HTTP 响应只提供数字状态。传输失败通过精确匹配错误或其直接 cause 上的 code/name，选择包内撰写的文本；未知或更深的失败保持通用消息。合并后的中止 signal 区分调用方取消与客户端截止时间。同一分类也覆盖响应体读取。请求仍只尝试一次。

## 考虑过的替代方案

**转发原始消息或 cause。** 否决，因为传输错误可能包含密钥与远端文本；仅对已知令牌脱敏无法保证输出集合安全。

**重试或新增公开错误码。** 否决，因为诊断无法确定写入是否已到达提供方，且既有调用方已经依赖稳定类别。

## 影响

[客户端测试](../../../../packages/jubian/jubian/tests/client.spec.ts)固定精确诊断文本、HTTP 错误码兼容性、直接与包装后的传输错误、任意嵌套密钥脱敏、取消、截止时间处理及单次尝试行为。未知错误码与更深的 cause 刻意提供较少详情。本次限定客户端范围的修改不包含会话录制或实时失败复现。报告中的四次快速失败及随后相同 GET 的成功，无法确定历史网络原因；本修改既不诊断、也不声称修复该事件。
