# Agent Note: 拒绝覆盖已有剪映草稿

Status: implemented

[English](2026-09-23-preserve-existing-jianying-drafts.md) | 中文

## 问题

本地草稿生成器在调用 pyJianYingDraft 新建草稿前，会删除调用方草稿根目录中同名的目录。该根目录可能就是剪辑软件实际使用的项目目录；重复的候选名称会抹掉人工编辑内容。调用方提供的名称前缀也未经路径分隔符检查就进入输出路径。

## 决策

[`jianying_draft.py`](../../../../packages/drama/skills/skills/tweet-drama-draft-build/scripts/jianying_draft.py) 在调用外部写入器之前拒绝同名草稿，保留原目录；它在读取素材前拒绝 `name_prefix` 中的路径分隔符、Windows 保留字符与控制字符。另一个候选须由调用方指定不同的前缀。新草稿生成前依旧核对项目视频禁用清单；这一独立规则由[视频禁用决策](../feature/2026-09-21-drama-video-bans.zh.md)负责。

## 考虑过的替代方案

**删除并重建同名草稿。** 重跑看似成功，却不可恢复地抹掉用户编辑；外部写入器稍后失败时甚至可能一个草稿也不剩。

**碰到重名后自动追加序号。** 仅有不同的目录名，无法把候选 MP4 与新草稿版本关联。在统一的渲染与草稿操作同时拥有两份输出之前，调用方须明确指定不同的候选名称。

## 后果

已有草稿会触发明确错误而不是被覆盖；不同名称可以并存。该检查并不证明草稿落在已安装剪映的真实目录，不会生成与版本绑定的 MP4，也不能让外部库的创建动作在其他进程面前变成原子操作。离线回归使用临时项目和模拟写入器；真实剪映中能否打开草稿仍须在已安装软件的机器上另外验收。
