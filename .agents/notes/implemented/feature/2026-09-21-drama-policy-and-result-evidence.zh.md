# Agent Note: Drama production policy and result evidence

Status: implemented

[English](2026-09-21-drama-policy-and-result-evidence.md) | 中文

## Problem

创作估算无法判定台词是否听得清、表演是否成立。把估算当成硬失败检查，会促使制作者为了满足算式而截断原文。反过来，提供方任务成功、看似合理的文件名或缓存编码，也无法说明最终画面来自已审核结果。制作需要保留创作选择，同时不削弱身份、授权或交付检查。

## Decision

镜头编译器将单镜一至四秒、每秒九个有效字、36 字上限、旁白与风格限制作为建议报告，而不是硬失败。结构合法、正式资产身份和任务包容量仍受强制检查。`preview` 与 `compile` 必须显式传入 `max_submit_seconds`，取目标分镜在已确认模型能力内的实际总时长，而不是自动取模型上限。预算包含自然收束；打包保留完整镜头、ID、说话人、原文与顺序，不为凑时长截断内容。

运营自有的 `short-drama-local` 预设采用实时分镜意图，并在既有授权范围内自主完成收费前自检。缺少授权、费用超额、超出范围的破坏性操作仍需另行决定。这是本地部署策略，不代表所有随附预设都已改变。免费创建分镜强制 `isGenerate=0`；收费提交保留独立的冻结请求与对账流程。[模型意图决策](2026-09-21-jubian-model-intent-and-scoped-settings.zh.md) 负责精确目录匹配与限定范围的配置写入。

交付证据通过镜头与任务包映射及视频内容哈希，将已选备料源与 `pipeline_state.json` 中通过的审核关联起来，并引用审核帧作为证据。文件名、阶段标记或无关的成功结果都不能授予交付资格。待去字幕素材可用于明确标注的草稿，绝不因等待时间过长就成为最终交付的降级替代。技术测量明确报告尚未检查的审核项目；提供方完成不能替代抽帧检查、试听或核对实际渲染输入。

复用镜头编码要求源哈希与编码参数一致，且只有编码成功后才发布缓存身份。可选 BGM 计划记录声明的段落；重复另一集的来源顺序只产生建议，不拒绝制作。计划本身不能证明对应音频。成功的 `drama_bgm compose` 报告把源哈希、偏移、实测增益与输出哈希关联到确定性合成，但不能证明音乐听感合适。

`jubian_watch` 为已受理操作的 `task_id` 与 `stage`（`generate`、`upscale` 或 `erase_subtitle`）登记当前进程内的后台任务。完成判定要求精确的操作身份及对应阶段成功的当前结果，而不是只有父任务成功标记。监听只读：不提交、不重试、不改制作状态，也不批准媒体。取消仅停止观察，不取消提供方任务；超时表示完成情况未核实。通知与默认连续三次唤醒预算由现有后台任务机制负责，因此监听不另建续跑循环，也不绕过批准要求。

## Alternatives considered

**保留硬失败的创作启发规则。** 这些是可测量的估算，不是普遍要求。保留原文发声并检查实际表演，比强迫所有叙事套用同一节奏公式更有价值。

**相信文件名、阶段标签或等待时间。** 它们无法识别已审核字节，也无法确认去字幕成功。显式素材映射与审核证据增加记录成本，但能防止旧结果或未审核结果成为最终输入。

**另建轮询与重试循环。** 现有后台任务已经负责取消、结果投递与唤醒限制。让监听器承担收费恢复会混淆观察与授权，并带来重复购买风险。

## Consequences

创作警告需要判断；结构检查通过不等于艺术效果获批。哈希计算消耗本地 I/O，审核证据必须随素材变化而更新，进程内监听需要在重启后重新登记。可选计划仍是声明；合成报告增加组装证据，不代表试听通过。

[镜头工具记录](2026-09-19-drama-shot-gate-tool.zh.md) 因独立工具归属理由而保留为活跃记录，但其创作策略与固定预算被部分取代。[渲染工具记录](2026-09-19-drama-episode-render-tool.zh.md) 因交付样式与尾帧验证理由而保持活跃。两者都不改写为相反决策，也不归档。

验证区分确定性检查与生产验收：编译器及 guard 回归、免费写入约束、缓存失效、审核证据匹配和监听生命周期需要针对性覆盖。集成、收费提供方行为与最终视听质量需要独立证据；本文不声称所有项目均已测试或部署。
