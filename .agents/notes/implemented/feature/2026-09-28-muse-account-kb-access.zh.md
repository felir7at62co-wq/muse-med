# Agent Note: MUSE 账号访问与授权知识库阅读

Status: implemented

[English](2026-09-28-muse-account-kb-access.md) | 中文

## Problem

Muse Desktop 需要访问编辑可引用并阅读的剧本及 Wiki 来源。若将登录做成模型工具，密码会进入工具调用参数和持久 Session 记录。若在配置中保存固定知识库令牌，它会比用户账号会话存活更久，也可能被复制到模型结果中。

## Decision

私有 `dsh-muse-account` Host 包负责桌面设置页、经过身份验证的 `museAccount` Remote 方法、绑定网关源地址的本地会话，以及内置的只读 MCP 子进程。设置页直接向 Host 提交密码。登录请求包含明确的 `registerIfMissing` 布尔值；页面展示该选项，只有用户主动勾选才启用。只有登录被拒绝且该值为 true 时，Host 才尝试注册。模型工具只提供状态、检索、全文分页阅读和开头分页阅读；不接收密码，也不执行登录、注册或退出。

Host 把网关 cookie 保存到产品主目录。每次知识库调用都用当前 cookie 向同源 `/api/kb/access` 接口换取短时 bearer，再将其传给远程只读 MCP 接口。bearer 不持久化，也不返回。本地桥接只接受已配置的源地址和固定 MCP 路径，拒绝重定向与非文本响应，并限制可返回的文本大小。服务端决定账号可阅读哪些来源和 Wiki ID；`read_opening` 只接受获授权且标为 `标定: viral-script` 的 `SRC-...` 检索结果。检索摘要不满足编辑预设的[阅读开头要求](2026-09-28-muse-editor-sourced-opening.zh.md)；编辑会沿获授权的 ID 阅读相关页面。

密码处理与 cookie 保护是两项不同的属性。设置页和 Remote 路由使密码不进入模型调用及 Session 数据。以同一系统用户身份运行的进程，仍可能通过文件工具读取 cookie 文件；完整隔离需要系统凭据库、独立进程身份或更严格的沙箱文件读取权限。

## Alternatives considered

**将原账号 MCP 登录工具暴露给模型。** 这样可以在对话中登录，但工具参数会记入 Session 数据。设置页路由使凭据不进入该记录。

**配置持久知识库 bearer。** 这样每次调用不必换取令牌，但退出、修改密码或停用账号后，已复制的令牌不会及时失效。网关从有效账号会话发放新的短时令牌。

**将客户端页面视为完整的密钥隔离。** 页面控制模型调用，但与智能体工具共享一个系统账号。设计明确这一限制，不声称 Remote 身份验证能阻止同一用户读取本地文件。

## Consequences

桌面启动会等待账号 Remote 服务和内置 MCP 的工具发现，因此子进程故障会使该包启动失败，而不会留下看似就绪的账号功能。MCP 客户端用通用文本卡片呈现四个工具；阅读返回 6,000 字页面，本地失败使用固定错误码。MCP 工具参数及返回的来源页面属于模型可见的 Session 数据；密码、cookie 和 bearer 不进入这些工具字段。网关在每次阅读时检查来源授权。聚焦账号、网关、知识库及 MCP 测试覆盖本地路径；真实网关登录和远程知识库往返仍需部署验证。
