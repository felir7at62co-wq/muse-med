# Agent Note: 短剧设置段与它的两个 Web 界面

Status: implemented

[English](2026-09-20-drama-settings-panel.md) | 中文

## Problem

短剧流水线面向运营者的那些选择没有归宿。成片交付到哪个目录、剪映草稿根目录在哪、渲染必须命中的交付规格、以及本地 BGM 库——这些全都只存在于文字里：preset 的提示词描述它们，每个 skill 各自重新发现它们，而 `tweet-drama-key-manager` 为剪辑路径另维护了一份平行的本地配置。跑 Web GUI 的人看不到也改不了其中任何一项。

动态 Cordis 原型已经把交互验证过一遍——一个读持久值的设置页——但进程内的插件定义不会在重启后存活、对其它包不可见，也不可能被某个宿主行依赖。

## Decision

`@deepseek-ai/dsh-drama-settings` 持有持久 `drama` 设置命名空间，以及编辑它的那个 Web GUI 界面。它是一个双面包：Host 半用 `ctx.settings` 注册命名空间，Client 半渲染 **设置 → 短剧** 页。

Host 半是 `src/index.ts`，而且只有那次注册：`ctx.inject(['settings'], settingsCtx => settingsCtx.settings.register('drama', DramaSettingsSchema))`。这一行不发布服务、自身不持状态，也不接收 `Config`——每个默认值都是 schema 自己的默认值，所以每个事实只有一处出处，部署要改就只会改设置文档。没有设置提供方的组合下它什么都不注册，Client 半则把该命名空间报告为不可用，而不是编造一个值。

`src/settings.ts` 由两个编译面共用。它持有命名空间、字段名、默认值，以及 Host 注册、浏览器作用域校验其设置段所用的 schemastery schema。`jianyingDraftDir` 的默认值为空：一位运营者安装的目录不能用来指认另一位运营者的软件。页面要求明确填写草稿根目录，不展示虚构的本机默认路径。

Client 半只绑定一个作用域——`ctx.settingsScope.bind({ namespace: 'drama' })`。`src/client/section.ts` 把页面的表单编译成路径操作：已经等于目标值的字段不动，而目标值等于 schema 默认值的字段会被*清空*，这样用户层永远不会存下一份什么都不表示的默认值副本。`src/client/DramaSettingsSection.tsx` 是纯 props 组件：作用域与写入都从注入面到来，由渲染器绑定 hook。

写入结论从解析后的设置段读出，而不是从传输读出。写入被拒绝时设置作用域不抛异常——它恢复宿主的当前状态后正常返回——所以页面把它渲染的设置段与草稿要求的那一份比对，不一致就报告失败。这让本包不必再持有一份 wire 契约，同时仍然拒绝把被拒绝的写入显示成已保存。

页面通过 `ctx.slots.inject` 注册：本包不拥有设置外壳，注册会等待声明方，并随该声明或随本行的 fiber 一起离开。

页面还回答「一次生产由什么组成」，形式是一份只读清单：短剧会话所组成的六个包——`dsh-guard-drama`、`dsh-tool-drama-assets`、`dsh-tool-shot-script`、独立匹配插件 `dsh-perception-bgm`、`dsh-tool-bgm-compose` 与 `dsh-tool-episode-render`——各带一句它的职责。每行旁边的状态来自宿主那份只读的 `pluginInventory` 投影，它报告 Loader 条目以及每个已挂载 preset 的组成行及其启用状态与 fiber 阶段。该命名空间通过 `ctx.get` 读取，因为它属于组合了插件清单的部署：没有清单时页面照样渲染这份列表，每个包都报「无法查询」，并附上「这些行随 short-drama preset 或宿主 cordis patch 加载」的说明。沉默永远不会被渲染成「已加载」，而清单里没有点名的包显示为「清单里没有」，不是「未加载」。

页面的最后一组 **资产图生成通道** 是第二处这类可选的跨包读取，也是本包唯一存储「由另一个包消费的选择」的地方。账户目录把 `gpt-image-2` 按平台各列一行、各自定价，而 `jubian_video image_generate` 拒绝在它们之间选择，所以必须有人锁定一行。选择器把这几行列出来——平台、该行自己的单价，以及锁定它的 id——数据来自 `@deepseek-ai/dsh-tool-jubian` 持有的只读 `jubianImage` Remote 命名空间，因为那次读取所需的凭证与传输本来就在那里；页面通过 `ctx.get` 取得它，理由与取 `pluginInventory` 相同，并且逐次调用重新解析，因为持有它的插件可能在本页之后才挂载。选中行的 id 和其余字段一样存进 `drama` 设置段，因此它跟着页面那一次原子写入走，而工具行解析它时优先于自己的组合配置。设置段里锁定、目录里已经没有的那一行仍留在选择器里、也仍然存着：这个页面读不到的清单，不是清掉别人做过的选择的许可。

## Alternatives considered

**沿用动态原型自己的机制，发布一个进程内插件。** 原型正是本包要取代的东西：它的定义只活在某个 DSH 进程里，其它包读不到它的值，重启就没了。运营者选的交付目录与 BGM 库必须活过重启，并且能被某个宿主行读到。

**照 `dsh-tool-jubian` 的做法，单开一个 Typert Remote 命名空间。** 那个页面需要自己的命名空间，是因为它只写一个凭证引用，而凭证接缝的通用命名空间把引用名当参数。这里的值属于设置接缝，后者已经持有注册、分层、revision 栅栏、脱敏与浏览器传输。再开一个命名空间会为同一个设置段重复这一切，并给同一批事实留下两个存储。唯一不是普通设置字段的值——账户实时的 `gpt-image-2` 行——由那个本来就持有其凭证的包所提供的命名空间来读，而不是让本包自带一个提供方客户端。

**直接经 `ctx.remote.settings` 写设置段，像 `ui-agent-preset` 写它的名册默认值那样。** 那条路把拒绝作为返回值报出来，这正是它吸引人的地方；但它也要求调用方自己持有 describe 镜像与 revision 栅栏。绑定作用域两者都免费得到，而上面说的落地判定用页面渲染的同一份快照补上了缺失的拒绝信号。

**把这些值放进这一行的 `Config`，而不是设置命名空间。** 组合配置对运营者的逐次制作选择来说是错误的生命周期：改它意味着编辑组合文件并重启，Web GUI 根本没法提供。Config 还会让每个默认值有两处出处，而上面只留 schema 的决定正是要消掉这一点。生图通道的锁定是唯一自带配置字段的值，而且它是刻意做成*兜底*的：配置没法把人该看的单价摆给人看。

**把生图锁定存进 `dsh-tool-jubian` 自己的 `jubian` 命名空间，在短剧页里渲染它。** 那样归属与消费者一致，那个包也能用 `installSection` 把它现有的 `imageStandardId` 配置变成基础层。它落选是因为页面的表单于是每次保存要写两个命名空间，一次拒绝可能只落地半个设置段；也因为字段的 schema 会住在一个包里，而解释它的界面住在另一个包。锁定改为跟着交付规格同处 `drama` 设置段，由工具行在解析时优先于自己的配置。

**存一个许可档位，并在输入框上换挡。** 本包的第一版正是这样：一个 `permissionTier` 字段（`generate` / `video` / `full`）加一枚挂在 `conversation.input.left`、与权限选择器并排的控件。落地前它被删掉了。两个理由决定了这件事：存下的档位是同一个问题的第二份、更过时的答案，而 agent 每次调用时判断得更好——流水线自己的规矩是「具体某次提交摆在桌面上时问人」，不是「几天前设的一个总开关」；而且一个没有执行者读取的档位比没有这个字段更糟，因为页面会暗示一种并不存在的强制力。drama-gate 的硬预检查照旧；改变的是不再有任何设置声称自己决定「计费步骤何时询问」。

## Consequences

流水线面向运营者的值现在有了一个持久的归宿，在 GUI 里可见可改，宿主行无需了解浏览器就能读到它们。其中现在也包括计费资产图通道从哪一行 `gpt-image-2` 购买——这是这里第一个由另一个包在每次计费调用时解析的值。

页面显示的是解析后的设置段而不是自己的回声，这也是被拒绝的写入会把运营者的修改留在原地、供其再试一次的原因。

组件清单回答的是「它由什么组成」，而不是断言「它在运行」。部署没有组合清单、某个包以不同的模块说明符挂载、或 preset 行只带条件启用时，页面报告的是它能确认的东西——无法查询、清单里没有、按条件加载——而不是没人观察到的绿色状态。

计费步骤何时征求确认是 agent 的判断，并且记录在它发生的地方：对话里、紧挨着那次请求。本包里的任何东西都不能被读成一份长期授权。

本包不发布运行时不变量配套入口：它只注册一个设置命名空间与一处槽位贡献，不拥有独立生命周期事件流，而这两者的销毁都由它的注册测试证明。

## Testing

`tests/settings.spec.ts` 在内存提供方上驱动真实的设置服务：客户端读到的默认值、部分设置段、schema 自己的拒绝（小数帧率、零码率下限、不是正整数的行 id）、恢复路径，以及随本行 fiber 一起移除。`tests/apply.client.spec.ts` 启动生产 `SlotRegistry`、真实 `LocaleRuntime`，以及脚本化 `remote.settings` 之上的真实设置域基座，然后断言注册、解析后的作用域、每次写入发出的操作、非法草稿路径、被拒绝写入的结论、迟到声明与销毁；它还用「没有清单」「清单有回答」「清单拒绝」「读取抛异常」四种情形驱动组件探针，并用「没有命名空间」「有回答」「被拒绝」「调用抛异常」四种情形驱动生图通道探针。`tests/components.client.spec.ts` 覆盖从一次清单回答折算出各状态的过程，包括它读取的两种行，以及始终没来的回答。`tests/settings-page.client.spec.tsx` 直接把 props 喂给组件，断言每种状态下人读到的文案，包括通道选项、预选中的行，以及目录里已经没有却仍然存着的锁定行；`tests/section.client.spec.ts` 覆盖草稿编译器，包括尚未解析的命名空间与「不锁定任何行」的选择。`npx vitest run --coverage packages/drama/drama-settings` 报出 66 个测试与逐文件 100% 语句、分支、函数与行覆盖。
