# Agent Note：按每镜自己的音频测字幕时间，不用语音识别

Status: implemented

[English](2026-09-21-drama-subtitle-timing-without-asr.md) | 中文

## Problem

字幕 cue 的时间来自「整集转写 + 把识别文本投影回剧本 + 再纠错」这条链。识别输出从不作为字幕文字——交付规则是字幕用剧本原文——所以转写唯一的作用是取时间，而它产生的每一个错字都要由消费它的那一环再擦掉。

没有任何包拥有这个操作。跑转写的脚本已经从 draft-build 技能里归档出去，`build_spoken_subtitles.py` 只读 `actual_speech_start` 与 `actual_speech_end`，而技能里没有任何东西写这两个字段。于是每次会话都各自重新实现一遍计时：没有工具 schema、没有覆盖率检查，也没有留下任何后续会话能重读的证据。

## Decision

`drama_render` 增加第四个方法 `subtitles`。它归 `@deepseek-ai/dsh-tool-episode-render`，因为这一步属于剪辑，而渲染器已经拥有它需要的全部输入：成片清单、每镜已解析的音轨路径，以及按 ffprobe 实测时长铺好的时间线。

`subtitles` 读这份清单加一份逐镜台词计划，写出 `editing/<集>.srt`。对每一镜，它在该镜**自己的**音轨上跑 `silencedetect=noise=-35dB:d=0.15`（此时还没有任何 BGM 混进来），把静音段反演成这一镜在发声的时刻，再让每条声明台词占住它所在的那一段。cue 时间 = 该镜在时间线上的起点 + 镜内偏移。全程不做语音识别、不联网、不加载任何模型。

独占一段发声的台词是实测的。一段发声要装多条台词时，段内切分按有效字数比例计算，这些 cue 带 `estimated_within_run`，逐镜写进 `warnings`，而 `speech_alignment` 留在 `not_checked` 里，不认证整集。两类缺陷按 `subtitle_line_coverage` failure 阻塞：声明了台词但音频里没有发声，以及有发声却没声明台词。无论哪种情况 SRT 都照常写出，便于核对我们测到了什么。

文字是镜头脚本的；把它切成交付长度的 cue 是台词计划的决定，所以工具只配时间，绝不改字。

## Alternatives considered

**新建 `tool-subtitle-timeline` 包。** 否决。合成器包确实立下了「确定性工具挨着模型工具」的模式，但这一环复用了渲染器的清单解析、镜头解析、时间线布局与 FFmpeg 进程边界；单独成包要为拥有一个方法而复制这四样。

**保留整集转写。** 否决。它在解一个这条流水线并不存在的全局问题：镜头边界本来就已知且已实测，整集对齐等于用搜索重新推出时间线直接写明的东西，而它唯一独有输出——文字——到手就被丢弃。

**带词级时间戳的识别。** 否决。为静音轮廓已经给出的时间，付出同样的识别成本与幻觉面，且相对逐镜落位没有任何增益。

**用 CTC 强制对齐做词级切分。** 推迟。一段发声内部的词边界能消掉估算，但它需要本包不携带的普通话声学模型，英文音素模型不能替代。在选型之前，按字数比例的切分如实上报，而不是藏起来。

**Silero VAD，或引入 Python 运行时。** 否决。姊妹合成器包已经用 FFmpeg `silencedetect` 做起音检测，所以这一环不新增运行时依赖、不需要解释器、不需要下载。

## Consequences

cue 时间不再依赖 Python 环境、下载的模型或模型许可。`faster_whisper` 只作为可选的抽查保留，用来确认某句确实按原文读了出来；它不再参与排 cue，交付的时间证据也不再依赖纠正它的输出。

渲染器现在生产 `prepare` 消费、`render` 烧录的那个产物。三个方法仍各自独立，所以写出的 SRT 在计时与烧录之间仍可手工修改。

估算保持可见：全部 cue 都来自检出说话的整集会报出 `speech_alignment` 并把它从 `not_checked` 里移除；存在按比例切分的整集则把它留在 `not_checked`，并在 `warnings` 里逐镜点名。过去对此保持沉默的素材，现在会明说。

漏读与未声明台词按镜报出，而不是等读转写稿时才发现。这一环仍然看不见的是「说了但读错词」——那属于内容审核问题，而 `speech_alignment` 只覆盖它实测过的时间。

[整集渲染器决定](2026-09-19-drama-episode-render-tool.zh.md)仍然有效，本note是对它的扩展而非取代：它为那个决定引入的工具增加了一个方法。[BGM 合成决定](2026-09-21-drama-bgm-compose-tool.zh.md)与本note互补——两者都让一个确定性的 FFmpeg 操作独立于模型驱动的姊妹能力。
