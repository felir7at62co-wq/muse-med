# Agent Note: Reversible bans for exact video versions

Status: implemented

[English](2026-09-21-drama-video-bans.md) | 中文

## Problem

视频即使满足技术导出规格，也可能包含已知内容缺陷，例如角色对调。只在对话中记录缺陷，仍会让同一文件进入后续备料、缓存渲染或草稿。运营需要立即排除这个版本，而不必先提供审核图片或删除文件。

## Decision

`drama_video` 归现有整集渲染工具包所有，提供 `ban`、`unban`、`list` 与 `inspect`。禁用要求提供可读的本地视频与非空标签；原因可选，不要求审核证据。工具自行计算文件字节的哈希，并将最新的可逆决定记录在项目的版本 1 `video-bans.json` 中。共享文件锁与原子写入保护更新；损坏或不支持的记录会报错，不按空禁用清单处理。

SHA-256 标识被排除的版本，而不是文件名、镜头号或远端任务。同一项目内字节完全相同的副本共享禁用状态。重新生成且哈希不同的内容不会自动被禁用。解除禁用保留已记录的标签与原因，但不授予审核通过资格：[审核证据决策](2026-09-21-drama-policy-and-result-evidence.zh.md) 仍独立适用。

原生备料与渲染检查实际选用的媒体，包括缓存复用。本地生产用 Python 渲染、草稿与状态路径通过共享只读辅助模块读取相同格式。验证报告输出文件直接命中禁用的情况及当前选用输入被禁用的风险，不删除输出；当前输入无法说明历史导出实际使用了哪些源文件。

## Alternatives considered

**先要求审核证据，再允许禁用。** 这会拖延用户明确作出的排除决定。制作流程要求证据时，批准仍需证据，但拒绝使用某个版本不需要。

**删除文件，或按路径、任务禁用。** 删除造成不必要的破坏，路径禁用漏掉副本，按任务禁用可能排除已经修正的结果。精确字节支持可逆的版本级范围。

**追踪所有派生文件或拦截每次 FFmpeg 调用。** 无法仅凭哈希可靠归属任意转码结果。新建全局拦截或回执系统超出了本次项目级决定的范围。

## Consequences

禁用防止已集成的生产路径再次使用该版本，不替代内容审核，也不改变远端提供方状态。通用 FFmpeg 命令、其他项目与无法识别的变换派生文件不在强制范围内。哈希计算增加本地 I/O；哈希不同只表示未命中这条禁用记录，不代表视频可接受。

必要回归覆盖同字节副本、不同字节的重新生成、解除禁用不等于批准、损坏记录、并发更新、缓存输入及非破坏性验证。源码修改不会在已经运行的 Host 中激活新的静态工具；部署与实际项目标记是独立操作。
