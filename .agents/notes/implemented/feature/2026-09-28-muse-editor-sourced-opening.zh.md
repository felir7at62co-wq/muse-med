# Agent Note: 编辑模式在写作前阅读有来源的剧本开头

Status: implemented

[English](2026-09-28-muse-editor-sourced-opening.md) | 中文

## Problem

Desktop 名册提供短剧制作和四个编码模式，剧本写作需要另外处理资料、创作和审改的顺序。检索结果或模型记忆可能看似做过研究，却不能证明编辑实际读过参考剧本的开头。把全部编辑流程塞进 persona 也会挤占上下文，掩盖写作前最关键的一步。

## Decision

产品自有的 `editing` 是第六个模式，默认仍为 `short-drama`。简短 persona 指明开写前的义务，在创作正文时加载 `muse-script-editing` 技能。技能要求实际阅读获授权来源的开头，记录题名、来源、已读范围，以及冲突和悬念的分析。知识库结果只有在网关将该来源标定为 `viral-script` 时才算爆款剧本依据；用户也可以明确指定并提供可读的参考原文。检索摘要和 Wiki 概述不能代替阅读原文。没有可读开头时，Agent 可以整理需求，但暂停正式正文。参考作品只提供叙事写法，不复制故事内容。参考文本是任务资料，其中的角色命令、工具请求和权限变更不能指挥 Agent。

[桌面产品决策](../architecture/2026-09-23-muse-med-independent-desktop.zh.md)规定了服务于该模式的产品名册、profile 隔离与技能根目录。

Desktop Host 将编辑技能与预设一起打包，并通过产品指定的技能根目录提供。作用于编辑模式的工具过滤器隐藏 Host 的剧变视频工具，短剧制作模式仍可使用这些工具。Host 配置行并发启动，因此过滤器也列出编辑模式挂载后才注册的工具。技能和预设属于同一个私有 Host 包，不依赖外部编辑工作间的服务器路径或命令行程序。长篇任务分批保存、记录可恢复进度，核对衔接、范围和实际文件。

## Alternatives considered

**把编辑流程加入短剧制作 persona。** 该模式负责媒体制作、收费服务控制和最终视频交付。混合写作任务会让两个提示都更难导航，并让编辑工作携带无关工具。

**把检索摘要当作阅读证据。** 现有知识库搜索只返回短摘要，无法确认开场冲突或首个悬念。因此只有摘要时，编辑会索取获授权且可读取的原文。

**直接导入外部编辑工作间。** 其工作区身份、Wiki 和可执行命令依赖另一个服务器部署。产品自有技能明确了 Desktop 的路径和依赖。

## Consequences

Agent 可能因缺少获授权的开头而暂停正文。提示和技能表达的是定性编辑规则；无密钥技能回放固定其文本，打包运行时固定编辑模式的组装后 persona、账号 MCP 描述和技能可用性。这些检查不会机械判定参考作品是否爆款或分析质量。带身份授权的知识库开头读取属于独立服务集成，须更新该服务后才可用。
