# Agent Note: 授权共享资料阅读之外的账号私有剧本入库

Status: implemented

[English](2026-09-29-muse-account-private-script-vault.md) | 中文

## Problem

视频转写会给编辑提供已校订、可阅读的剧本，后续写作仍需使用。现有知识库提供管理员授权阅读的共享来源；若把用户转写稿写进共享 vault，可能造成跨账号发现，也会把编辑素材与管理员认可的参考资料混在一起。只有本地项目文件，也无法让该账号在其他设备上查阅剧本。

## Decision

网关把已校订的 Markdown 剧本分段存入 `MUSE_KB_USER_ROOT/<稳定账号 ID>` 下独立的私有 vault。已登录账号的短时 bearer 授权 `ingest_script`；输入是有大小限制的正文、标题和安全的项目相对来源标识，不接收视频二进制或密码。每个不可变分段分别返回 saved、duplicate 或 failed，并在可用时给出 `private/SRC-...` ID。部分成功不能代表整批成功；编辑通过检索和阅读核对成功的 ID，保留本地项目稿件并报告失败。模型传入的 `reviewed: true` 是输入声明，不能作为服务端已验证人工校订或素材权属的证据。

私有剧本只在所属账号上下文中按关键词检索和阅读。共享剧本来源与 Wiki 文档对 Agent 仍是只读，必须由管理员明确授予账号、来源 ID、Wiki ID 和允许阅读的范围；网关在返回文档前核对授权内容的哈希。检索只合并当前账号的私有文档与其获授权共享结果。`read` 和 `read_opening` 接受属于该账号的私有 ID，以及符合条件的获授权共享 ID。其他账号和旧式 machine bearer 都无法使用私有 ID。私有根目录必须预先存在、仅属主可访问，并位于共享 vault 之外；共享授权文件也要与 vault 分离，不能允许非属主写入。路径或权限不安全时启动失败。

[账号访问决策](2026-09-28-muse-account-kb-access.zh.md)继续规定界面登录、cookie 换取 bearer，以及模型工具不接收凭据。该决策早期描述的只读 MCP 适用于共享参考资料；本决策增加账号私有写入，但不允许写共享 vault。[编辑流程决策](2026-09-29-muse-editor-outline-led-drafting.zh.md)规定何时形成已校订剧本，以及开写前如何使用。

## Alternatives considered

**把用户剧本写入共享 vault，再给每份文档加权限标记。** 标记必须在每次检索、分页阅读、开头阅读和管理员操作中始终正确。按账号分离根目录让存储和查询范围清晰，同时保留共享资料的管理员授权机制。

**只把已校订剧本留在本地项目。** 这样不占用服务器存储，却无法让已登录账号日后把剧本当作知识页找回。云端写入失败时，本地稿件仍是后备来源。

**自动入库原始媒体或每次反馈形成的修订。** 媒体字节和未经校订的文字不符合可阅读剧本知识页的用途；自动写入反馈版本也可能保存未经确认的稿件。编辑明确提交已校订分段，并核对写入结果。

## Consequences

私有资料采用关键词召回；现有共享向量索引不包含私有剧本。网关的存储隔离和授权检查保护账号范围，素材是否适合使用及稿件是否校订正确仍须由人和 Agent 判断。仅发布源码不会启用该能力：部署时需要配置私有根目录与共享授权，再用两个真实账号检查写入、检索、阅读和跨账号拒绝。服务及 Host 的聚焦测试覆盖源码实现，但不能代替部署检查。
