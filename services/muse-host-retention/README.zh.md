# Muse 主机保留期

[English](README.md) | 中文

本服务独立于公司媒体保留期，对应用版本和归档日志进行盘点。私有策略明确版本分类、必需构建文件、日志根目录及显式保留项。账号数据库、员工项目、提供方凭据及媒体卷不作为清理目标读取或删除。

## 引用与保护

采集器仅从进程命令、工作目录、可执行文件、内存映射文件、环境变量值、打开的描述符、已安装 systemd 文件、生效的单元属性、环境文件、Nginx 配置、Docker 挂载及容器命令中提取保留期根目录下的路径。不持久保存原始进程参数和配置正文。版本符号链接及回执形成版本之间的依赖。保留版本的引用会传递保护其依赖；历史回执中的自身引用不会让该版本永久成为活跃版本。

规划器保护被直接引用的版本、显式保留项、未知分类、构建不完整版本，以及每个分类至少两个额外回滚候选。没有被引用当前版本的分类保留三个构建完整的版本。保留的回滚候选也保护其依赖。必需文件检查表示构建完整，不代表已经成功执行线上回滚或数据库降级兼容。盘点期间不会将服务切换到旧版本。

只有匹配生效 Nginx 配置的编号日志归档及已归档 journal 文件可成为日志候选，活跃文件名不在选择范围内。打开的文件、符号链接、近期写入，以及没有归档状态和旧末条时间戳的 journal 文件继续受保护。默认版本和日志至少保留 14 天。根目录缺失、引用不可读、命令失败及清单截断都会使盘点失败，不能解释为空引用集合。

## 预演与恢复

观察器在 `state_dir` 保存私有 SQLite 审计记录及最新完整清单。预演模式不修改版本目录或日志归档。开启清理要求相同代码与策略至少连续运行 24 小时、观测间隔不超过 `maximum_gap_seconds`、没有错误或目标变更、近期观测正常，且运行代码与测试合格记录匹配。代码或策略变更要求重新预演；仅修改模式不改变策略摘要。批准记录绑定固定的观测序列。启用后再次执行开启命令不会授予另一份批准。

启用后，每次变更前重新检查引用及文件身份。候选对象原子移动到同一文件系统中仅所有者可访问的隔离区，再等待 24 小时，重新检查后才删除。任一待处理对象新增引用，都会恢复整批待处理对象，保留隔离版本之间的依赖。回滚储备减少也会恢复相应版本。恢复不会覆盖原路径的新对象。移动结果不确定、删除中断、内容变化及盘点失败都会停止执行，等待运维核验。切回预演模式会暂停隔离及删除，保留待处理对象。

每次最多隔离十个对象、合计 1 GiB，并独立限制最多删除十个已隔离对象、合计 1 GiB。恢复不受删除额度限制。活跃部署单元会暂停版本筛选及最终删除。部署写入方在修改版本引用前，必须获取同一把 `state_dir/cleanup.lock` 独占锁；仅靠定期盘点无法保证未协调 root 写入的安全。现有 Nginx 轮转继续负责生成归档。本服务仅管理过期且已关闭的归档，不截断活跃日志，也不全局更改 journal 保留期。

## 验证

运行 `python3 -m unittest discover -s services/muse-host-retention -p 'test_*.py'` 和 `python3 -m compileall -q services/muse-host-retention`。使用 `python3 services/muse-host-retention/build.py --output .artifacts/host-retention.tar.gz` 构建。可复现构建包含文件摘要，并编译每个 Python 模块。测试使用临时根目录、受控时钟，以及真实子进程、文件、符号链接和隔离恢复。生产盘点需要 root 读取进程描述符和系统配置；报告包含路径和保护原因，不含秘密。

## 服务器操作

将验证过的构建包安装到 `/opt/muse/host-retention/releases` 下以摘要命名的不可变目录，再以 root 运行其中的 `deploy.py install`。安装器逐文件验证，在服务器运行隔离测试，以预演模式写入 `/etc/muse/host-retention/policy.json`，并记录首个成功观测。策略或审计历史已存在会阻止安装；恢复前先核查未完成部署。安装器仅创建 `muse-host-retention-observe` 和 `muse-host-retention-review` 单元，不重启账号服务或容器，不修改媒体保留期或重置其预演。

周期定时器使用策略间隔。持久化单次复核定时器在首个成功观测加预演时长及最大间隔宽限后运行。复核将成功或失败写入 `/var/lib/muse-host-retention/review.json`；失败会保持清理关闭。部署、测试合格记录、批准、最新清单及当前状态均为同目录下的私有记录。审计数据库保留批准时的观测及待处理恢复记录。本服务不清理自己的审计历史。暂停清理时，原子地将策略模式改为 `dry-run`；不要删除数据库或隔离目录。其他策略字段或代码变更要求重新验证，并在批准前重新连续预演。
