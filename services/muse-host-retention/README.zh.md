# Muse 主机保留期

[English](README.md) | 中文

本服务独立于公司媒体保留期，对应用版本和归档日志进行盘点。私有策略明确版本分类、必需构建文件、日志根目录及显式保留项。账号数据库、员工项目、提供方凭据及媒体卷不作为清理目标读取或删除。

## 引用与保护

采集器仅从进程命令、工作目录、可执行文件、打开的描述符、已安装 systemd 文件、生效的单元属性、环境文件、Nginx 配置、Docker 挂载及容器命令中提取保留期根目录下的路径。不持久保存原始进程参数和配置正文。版本符号链接及回执形成版本之间的依赖。保留版本的引用会传递保护其依赖；历史回执中的自身引用不会让该版本永久成为活跃版本。

规划器保护被直接引用的版本、显式保留项、未知分类、构建不完整版本，以及每个分类至少两个额外回滚候选。没有被引用当前版本的分类保留三个构建完整的版本。保留的回滚候选也保护其依赖。必需文件检查表示构建完整，不代表已经成功执行线上回滚或数据库降级兼容。盘点期间不会将服务切换到旧版本。

只有匹配生效 Nginx 配置的编号日志归档及已归档 journal 文件可成为日志候选，活跃文件名不在选择范围内。打开的文件、符号链接、近期写入，以及没有归档状态和旧末条时间戳的 journal 文件继续受保护。默认版本和日志至少保留 14 天。根目录缺失、引用不可读、命令失败及清单截断都会使盘点失败，不能解释为空引用集合。

## 验证

运行 `python3 -m unittest discover -s services/muse-host-retention -p 'test_*.py'` 和 `python3 -m compileall -q services/muse-host-retention`。测试使用临时根目录、受控快照和真实符号链接。生产盘点需要 root 读取进程描述符和系统配置；报告包含路径和保护原因，不含秘密。
