# 持续发现与扩库

爬虫使用 Crawlee 的本地持久队列，数据站没有导入 Muse、调用模型或创建 Muse 实例。公司 fork 为 [felir7at62co-wq/crawlee](https://github.com/felir7at62co-wq/crawlee)，建立时主分支为 `eb7b0342b01c3b6e060008be38a383ea05c87c06`；运行依赖固定为上游发布的 `@crawlee/basic@3.18.2`，完整性由 pnpm 锁文件记录，许可为 Apache-2.0。

榜单刷新保留完整批次要求；扩库逐页处理公开目录、分类与账号窗口。每页先校验、按平台 ID 入库，再确认队列任务和加入新发现链接。进程在两步之间停止时会重新读取该页，作品 ID 去重避免重复作品。不同平台共用现有任务锁和停止信号，失败不清除旧数据。

队列位于项目独立数据目录的 `crawl-queues` 下，按平台分别命名；不使用 Crawlee 全局默认目录或 Apify 云账号。每轮限制处理页数、每分钟请求数和重试次数；预算用完保留剩余任务，下轮继续。成功 URL 保持去重，周期回访和失败重试使用新的周期键，作品仍按原平台 ID 归并。适配器把核验失败或访问拒绝标为 `retryable: false` 时，该任务本轮只请求一次即记为失败页；网络错误仍使用重试次数。失败页不触发短间隔续采，每个回访周期或管理员手动继续时重试一轮，避免同一页面在一个周期内被反复请求；尚有待办时的定时分批续采不包含失败页。周期入口和有数量上限的最新作品详情优先处理；历史分页继续排队，避免新发现作品被历史补采长期挡住。

扩库进度独立保存在数据库设置中，记录成功页、累计与本轮新增、待处理、待重试、最近发布与下次执行时间。失败页逐条保存在 `discovery_failures` 表，每个平台最多保留 5,000 条，超出时删除最早失败的记录并写日志，队列不会因失败页过多而停住；每轮最多重新排入 200 个待重试页。早先保存在设置记录中的失败页在启动时迁入该表。没有通过验证的适配器显示“待接入入口”，不能启动或宣称正在扩库。管理员在采集管理查看进度并手动继续；修改采集周期同步改变入口回访周期，不清空队列。

页内作品、观察和新增计数在同一个数据库事务提交；进度保存失败时整页回滚，不提前确认队列。目录观察不覆盖已有榜单记录的指标及其原观测时间，自己的新目录观察另行保留；显式空榜单参数可以读取目录观察。当前已接入红果三类根目录和真实题材分页、番茄书库的分类筛选与逐部明文核对，以及七猫原创小说分类分页；三个平台分别续采，不接入抖音。

应用通过数据库写锁和单平台锁保证单写者，使用 Crawlee 公开的 `RequestQueueV1`。它与原队列共用持久格式，保留已处理键和待办；避免 V2 批次结束时的预取解锁把最新详情移回历史队尾。最新任务的重试仍保留优先级，历史任务保持普通续采。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `MUSE_DATA_DISCOVERY_PAGE_BUDGET` | 12 | 每个平台单轮最多处理任务数 |
| `MUSE_DATA_DISCOVERY_REQUESTS_PER_MINUTE` | 30 | 调度任务速率上限；适配器内部请求另有间隔 |
| `MUSE_DATA_DISCOVERY_MAX_RETRIES` | 2 | 单个队列任务的额外尝试次数 |
| `MUSE_DATA_DISCOVERY_RESUME_DELAY_MS` | 60000 | 尚有待办时，下一轮分批补采的间隔 |
| `MUSE_DATA_FANQIE_LATEST_CATEGORIES_PER_CYCLE` | 8 | 每周期滚动复访的番茄最新分类数，允许 1–100 |
| `MUSE_DATA_QIMAO_LATEST_CATEGORIES_PER_CYCLE` | 8 | 每周期滚动复访的七猫最新分类数，允许 1–100 |

分类目录位置不是官方榜单名次；目录作品使用空榜单和空名次存入平台作品库。未知指标保持空值，覆盖范围记录实际读取的公开窗口，不把窗口上限当作平台作品总量。

## 作品指标自动刷新

分类页和书库列表不提供热度、收藏或在读人数，目录作品入库时这些指标为空。`MetricRefresher` 按平台定时选出当前记录来自目录、指标缺失或测得时间早于刷新周期的真实作品，逐部读取作品详情页并作为新的目录观察入库；榜单作品的指标由榜单刷新，不在此列。从未取得指标的作品先读，最新发现的优先；其余按测得时间从旧到新。每轮在该平台的采集任务锁内执行，与榜单刷新和扩库互不重叠；平台正忙时等下一分钟再试。

| 平台 | 详情来源 | 写入的指标 |
| --- | --- | --- |
| 红果 | `/detail?series_id=` 页面的 `detail_page` 路由数据 | 热度（`hot_score_data.score`）、收藏、点赞 |
| 番茄 | `/api/book/info?bookId=` 的 `readCount`，与榜单 `read_count` 同值 | 在读人数 |
| 七猫 | `/shuku/<id>/` 页面状态的 `hot_value`、`pursue_count`，单位取页面同时显示的“万/亿” | 累计人气值、次阅读；页面没有源热度，保持空值 |

页面未显示的指标保持空值；作品已不存在时记为“缺失”，读取失败记为“失败”，两者都等重试间隔后再读。每次尝试记录在 `metric_refresh_attempts`，状态记录在数据设置 `metric_refresh_v1:<platform>`。之后目录再次列出该作品而不带指标时，作品记录保留已测得的指标并以 `metricsObservedAt` 标明测量时间，目录观察本身仍记录为空值。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `MUSE_DATA_METRIC_REFRESH_BATCH` | 20 | 每个平台每轮最多读取的作品数，允许 1–500 |
| `MUSE_DATA_METRIC_REFRESH_INTERVAL_MINUTES` | 10 | 同一平台两轮之间的间隔，允许 1–1440 |
| `MUSE_DATA_METRIC_REFRESH_MAX_AGE_HOURS` | 72 | 指标测得超过该时长即重新读取，允许 1–720 |
| `MUSE_DATA_METRIC_REFRESH_RETRY_HOURS` | 6 | 读取失败或作品缺失后的重试间隔，允许 1–168 |
| `MUSE_DATA_METRIC_REFRESH_REQUEST_INTERVAL_MS` | 1500 | 同一轮内两部作品之间的请求间隔 |

按默认值，每个平台每天最多读取约 2,880 部作品。红果详情页约 0.6 MB，番茄接口约 10 KB，七猫书页约 75 KB；作品库较大时可调低每轮数量或拉长间隔。自动采集关闭（`MUSE_DATA_AUTO_COLLECT=0`）时不定时刷新，管理员仍可手动运行。
