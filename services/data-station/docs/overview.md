# Muse 数据 Web

独立的作品数据站。页面沿用 Muse 网站的顶栏、配色、字体和深色模式，「作品数据 / 我的书架 / 采集管理」是页面内的标签页；颜色变量与 Muse 网关的 `site-shell.css` 同名，Muse 换配色时需同步 `src/client/styles.css` 开头的取值。主页面为大搜索框、分平台榜单与细分题材标签。书架保存用户已取得的剧本和原小说，并关联作品的最新平台数据。采集管理只向管理员开放。

## 本地运行

需要 Node.js 24 与 pnpm。

```sh
pnpm install
pnpm test
pnpm build
pnpm test:browser
pnpm start
```

默认访问 `http://127.0.0.1:4317`，只监听本机环回地址。独立 PostgreSQL 引擎 PGlite 的数据保存在 `.data/preview`，不连接机器现有数据库、公司 Web、Muse 客户端或 `.muse` 会话目录。

## 数据范围

| 平台 | 默认公开采集范围 | 主要指标 |
| --- | --- | --- |
| 红果 | 综合、真人、AI、漫剧热播榜，加新剧、收藏、必看共七榜全部公开分页；分类目录持续分批发现与补采 | 当前热度、收藏、点赞、分享、评分、评分人数及独立榜单主指标，详情页补采评论数；不是全平台剧库 |
| 七猫 | 男女频道大热、新书、完结的日/月榜，以及收藏、更新榜，共 16 榜、每榜最多 100 名；公开原创书库的男女分类持续分页扩库 | 来源热度、字数；收藏/更新名次不当热度，书库位置不当榜单名次，缺失指标保持未知 |
| 番茄 | 男女分类阅读榜、新书榜前 100 名；当前 74 个榜单窗口；官方书库的分类、筛选分页持续发现并逐部核对明文资料 | 官方名次、榜单在读、字数、明文作者和分类、状态；目录不提供排名和在读值 |

正常页面只展示红果、番茄、七猫的真实采集数据。进入平台后默认选中一个具体榜单，在显眼的榜单选择器中切换；平台、榜单与细分题材可以组合筛选，不混排多个榜单的名次。红果榜单上方另有“全部 / 真人剧 / 漫剧 / AI剧”剧种标签：选中剧种后，热播榜换成该剧种的官方热播榜；新剧、收藏、必看三个综合榜只显示该剧种作品，剧种取自红果给每部剧的平台标签，名次沿用综合榜原名次并在页面注明。榜单页提供日榜、周榜、月榜和“统计日期”：日榜展示所选北京时间日期最后一次采集的完整名单，排名变化对比前一天最后一次采集，未采集的日期显示“当天未采集”而不补数据；周榜、月榜由本站按日榜计算（标注“非平台官方”），按上榜天数、平均名次、最高名次排序，并显示覆盖天数。“对比前一天”列出上升、下降、新上榜和掉榜作品。整期名单一次读取，翻页、本榜搜索和题材筛选在浏览器内完成，切换已读或已预读的榜单不再等待服务器。掉榜作品保留历史但不占用新榜名次。不同榜单的同一作品保留各自的历史。未知值不写成零，排名和指标不跨平台混算。采集失败保留最后一次成功数据，并记录来源、时间和覆盖范围。

大搜索框默认查当前平台的全部已采作品，不受当前具体榜单限制。搜索时显示“平台内搜索结果”，不混排官方名次或涨跌，题材和导出跟随相同搜索范围；清空关键词后恢复原来选择的具体榜单。搜索结果可包含掉榜作品，其详情读取最后已知观测与原历史，不强制要求仍在当前榜。

榜单选择中的“全部收录”展示当前平台的全部累积作品，包含目录补采与榜单历史，按最近观测排序并隐藏官方名次和涨跌。此范围支持题材、搜索、导出与复访恢复；进入具体榜单时仍只显示该榜当前成功批次。

服务在返回页面时一并嵌入已确认的账号和红果默认榜单最新一天的数据，首次打开不等接口即可显示榜单；页面加载后仍重新确认账号，确认的账号与嵌入的不同时以确认结果为准。服务端按榜单、周期和日期缓存计算结果，该榜单有新采集或所列作品变化时重新计算。页面、脚本和接口数据使用 gzip 压缩，带内容哈希的脚本和样式由浏览器长期缓存。再次打开页面时，直接展示该账号上次保存的平台、榜单、题材和作品页面，同时在后台读取本站最新结果；连接失败保留可读内容并显示页面保存时间。作品行的“数据更新”仍是原始采集时间，点击“刷新数据”会重新请求本站结果，不会启动平台采集。展示副本最多保存 24 小时、每个账号最多 2 MB，按网站地址、账号和角色分别存储；书架、管理配置、剧本文件及文件信息不存入副本，连接核对前剧本入口显示“剧本待核对”。无缓存、存储受限或副本损坏时正常从服务器加载。账号切换不读取其他账号的副本，权限失效清除当前副本；采集进度轮询只更新状态，成功发布新批次才刷新作品数据。

官方榜单仍列出作品而对应官网精确返回“查无此书”时，可保留其字符串 ID、官方名次与指标，`title` 为 `null`，同时记录 `metadataStatus: unavailable` 和具体说明。页面显示“作品资料暂不可用”及原始 ID，不猜测书名或下架原因；API 仍返回空标题，CSV 的书名列为空，资料状态与说明另列。访问验证、错 ID 或无法确认的字体编码不按此规则降级。

题材按时代、设定、剧情、关系、身份、风格分组。平台原标签优先，标题与简介的明确词语作为补充线索，每个分类都保留依据。没有明确证据时保持待分类，文本线索不等于人工确认。

封面通过按作品 ID 访问的同源图片接口加载，不接受任意图片 URL。服务只请求允许的公开图片 CDN，检查解析地址、HTTPS、大小和文件类型，并使用有上限的缓存。

## 自动更新与管理

默认每 6 小时更新。管理员可在采集管理中修改为 1–168 小时，设置和各平台的下次执行时间保存在数据库，重启后继续生效。手动与定时任务共用同一平台锁，避免重复采集；某个平台失败不阻断其他平台。每次榜单采集都在服务日志写一行结果：发布成功记录作品数和覆盖范围，失败记录原因。失败后不等满整个周期，按 `MUSE_DATA_COLLECTION_RETRY_MINUTES`（默认 30，允许 1–1440）重试，连续失败时间隔逐次翻倍，最长等于更新周期；成功后恢复正常周期。

抖音采集已退出本数据站：页面不展示入口，运行进程不注册其采集任务，管理及启动接口返回 410。原有作品、历史与来源配置保留，不自动删除；旧页面保存的平台选择会恢复到红果。保留的解析代码与数据类型仅用于历史兼容，不代表仍在采集。

番茄首次全量会核对数千本明文资料，采集管理显示窗口和资料进度。资料缓存原始获取时间起默认有效 24 小时，每轮榜单和在读指标重新读取；失败或取消会保存已核验资料供下轮继续，完整批次才发布。可通过 `MUSE_DATA_FANQIE_DETAIL_CACHE_HOURS`、`MUSE_DATA_FANQIE_REQUEST_INTERVAL_MS`、`MUSE_DATA_FANQIE_DETAIL_BUDGET` 分别配置缓存小时数、串行请求间隔及本轮新详情预算，详情见 [番茄采集说明](../src/server/collectors/fanqie/README.md)。

服务运行时执行定时任务；电脑休眠或服务停止时无法采集，恢复后会检查到期任务。独立云端运行方式见[部署说明](../deploy/README.md)，无需启动 Muse。

## 持续扩库

持续发现使用已 fork 的 Crawlee 持久队列，独立于完整榜单刷新，分批补采并保存待办；详情与配置见[持续扩库说明](crawlee.md)。各平台适配器按验证状态分别启用，未接入的入口显示明确状态。该数据站不依赖 Muse 或模型整理。

分类页和书库列表不带热度、收藏或在读人数，只在目录中发现、尚未上榜的作品由“作品指标自动刷新”定时读取作品详情页：红果取热度、收藏和点赞，番茄取在读人数，七猫取累计人气值和次阅读（七猫源热度只在榜单提供）。先补从未取得指标的作品，再轮流更新最旧的；作品库每行显示指标的实际测量时间。目录再次列出作品时不清除已测得的指标。采集管理显示各平台进度并可立即刷新，配置与规则见[持续扩库说明](crawlee.md#作品指标自动刷新)。

## 储备看板与每日爆款转写

数据站按五个条件自动选出红果剧：收藏超过 10 万、抖音同名话题播放超过 5000 万、题材下沉（用户 2026-10-19 规则）、已完结、没有对应的番茄 IP（疑似 IP 照常入选并标注）。缺少完结状态或收藏的候选由选片程序读取官方详情页补齐。入选作品进入转写任务表，由 Muse 云端的转写工人凭服务令牌领取、上报进度、登记 TOS 原片并上传剧本；成员在「储备看板」查看每部剧的进度、储备总数、今日新增、平均出稿时间和失败数，下载剧本与原片，或点「立即转写」排到队首。规则、阈值、状态流转和服务接口契约见 [每日爆款转写说明](hit-transcription.md)。

## 抖音搜索

「抖音搜索」页按关键词实时搜索抖音公开作品和账号，不是榜单，也不入库。搜索经同机私有 DTK 服务完成，由它用一个专用抖音小号登录；数据站只持有只读密钥，不接触小号的 Cookie。作品结果显示作者、发布时间、点赞、评论、收藏，以及所属合集与集数；抖音不公开播放量，显示为「—」。可以打开合集，按作者顺序查看全部集数。结果的合集名、《》书名、开头剧名或话题与本站红果作品同名时标出「红果有」，点开即进入该红果作品详情，整部剧优先从红果获取。每个成员每分钟最多搜索 20 次，同时最多 4 个搜索在进行。

设置 `MUSE_DATA_DTK_ORIGIN`（仅允许 `http://127.0.0.1:<端口>`）和 `MUSE_DATA_DTK_KEY_FILE`（绝对路径，内容为仅有 `douyin:read` 权限的 DTK API 密钥）后启用；两者都不设置时页面提示尚未开通，接口返回 503。小号登录过期时搜索提示联系管理员；更换小号的步骤见 Muse 仓库 `services/muse-media/deploy/README.md`。

## 抖音下载到 TOS

在「作品数据」选「抖音搜索」后，作品和合集旁有「下载」「下载整部」。成员只点下载：数据站在后台经 DTK 现取无水印地址、下载、算 SHA-256，存进 TOS 的 `download-video-date/douyin/<日期>/<合集或作品ID>/video/<集数>-<作品ID>.mp4`（禁止覆盖，HeadObject 核对大小和 SHA-256），准备好后按钮变成直接指向 TOS 文件的「下载」。全组共用：别人下过的作品直接给现成文件，不再重复下载。整部合集按集数排队（最多 300 集），每人每天最多新增 50 条（管理员不限）。下方「下载记录」列出全组的下载与状态。接口见 [接口说明](api.md#抖音下载到-tos)。

连接中断、临时取源失败、限流和服务端错误会自动重试。默认每轮尝试 3 次，间隔 5 秒；一轮仍失败时冷却 5 分钟，后续冷却翻倍，最多 1 小时，再继续原任务。冷却中的集数让出通道，其他集和成员仍可下载；页面显示尝试次数、冷却轮次和下次重试时间，关闭页面或服务重启不会清空时间。重试沿用记录、请求人和 TOS 路径，不增加每日额度，已完成的集不重下。上传回应丢失时先检查原对象的大小和 SHA-256，匹配则直接完成。登录或验证要求、文件超限、对象冲突和校验失败停止自动重试；原因不明的旧失败记录保留，手动重新下载后使用新机制。可配置 `MUSE_DATA_DOUYIN_DOWNLOAD_MAX_ATTEMPTS`、`MUSE_DATA_DOUYIN_DOWNLOAD_RETRY_DELAY_MS`、`MUSE_DATA_DOUYIN_DOWNLOAD_COOLDOWN_MINUTES`、`MUSE_DATA_DOUYIN_DOWNLOAD_MAX_COOLDOWN_MINUTES`。

设置 `MUSE_DATA_TOS_ENV_FILE`（绝对路径，0600 或 0640，内含 `VOLCENGINE_ACCESS_KEY_ID`、`VOLCENGINE_SECRET_ACCESS_KEY` 两行）并已配置 DTK 后启用；文件不存在或无法读取时数据站照常启动，页面与接口提示「TOS 未配置」。按用户 2026-11-15 的决定，抖音视频与红果视频一样存为公开读对象（`MUSE_DATA_DOUYIN_OBJECT_ACCESS=public`，默认），「下载」直接打开 `https://muse.tos-cn-beijing.volces.com/<key>`，不签名、不需要只读密钥。保留的 `private` 模式把对象 ACL 设为私有，由数据站按次签发 `MUSE_DATA_DOUYIN_LINK_SECONDS`（默认 3600）秒内有效的链接；`muse` 桶目前可被匿名读取，若由桶策略放开，对象 ACL 私有并不能挡住知道路径的人。程序只写 `download-video-date/douyin/` 下，禁止覆盖，不调用删除。其余可调项：`MUSE_DATA_TOS_BUCKET`、`MUSE_DATA_TOS_REGION`、`MUSE_DATA_TOS_ENDPOINT`、`MUSE_DATA_DOUYIN_DAILY_LIMIT`、`MUSE_DATA_DOUYIN_MAX_MIX_EPISODES`、`MUSE_DATA_DOUYIN_MAX_VIDEO_BYTES`、`MUSE_DATA_DOUYIN_DOWNLOAD_INTERVAL_MS`（每个下载通道下完一条后的停顿）、`MUSE_DATA_DOUYIN_DOWNLOAD_CONCURRENCY`（同时下载的条数，1–16，默认 3）。

抖音搜索只有一个登录小号，所以成员在「抖音搜索」页和 Muse 里的搜索、选片的抖音话题检查共用一份额度：任意一小时最多 `MUSE_DATA_DOUYIN_SEARCH_PER_HOUR`（默认 6）次，任意 24 小时最多 `MUSE_DATA_DOUYIN_SEARCH_PER_DAY`（默认 100）次；DTK 报告抖音要求验证（`UPSTREAM_RISK_CONTROL`）后，全站搜索暂停 `MUSE_DATA_DOUYIN_SEARCH_PAUSE_MINUTES`（默认 360）分钟。超额或暂停时请求不发往 DTK，页面和话题检查显示原因；已知话题编号的复查和视频下载不算搜索。计数和暂停只保存在内存中，重启数据站后重新计算。同时下载时，下一条优先给正在下载条数最少的成员，同一成员的请求和合集仍按提交和集数顺序下载，一部大合集不会堵住其他人。

## 剧本接口与书架

真实文件上传、绑定、下载和个人书架。数据站本身不做转写、模型调用或 MCP 服务，不会从简介生成伪剧本；剧本由管理员或转写工人上传。没有文件的作品显示“暂无剧本”。未来的 Muse 或 MCP 适配器可以调用同一 HTTP API，详见 [接口说明](api.md)。

管理员可上传现有 TXT、Markdown、DOCX、PDF，单文件最多 20 MiB。同一作品的相同内容重传去重，不同版本分别保存。下载校验长度及 SHA-256，客户端确认取得文件后加入本人书架；书架动态关联最新作品指标。移出书架不删除共享文件或其他人的记录。

CSV 的长作品 ID 带单引号文本前缀，避免 Excel 舍入；数据库及 API 保留原始 ID。

## 原小说下载

番茄、七猫作品行在“剧本”旁提供“原小说”。原文按用户点击准备，不随全库采集自动抓正文。两平台分别核对正常公开可读的完整目录与章节，没有真实文件时不生成简介占位文件。

运行 `node scripts/setup-novel-runtime.mjs` 创建数据站自己的 Python 环境，再设置 `MUSE_DATA_NOVEL_ENABLED=1` 启用番茄原文。默认 Python 位于项目 `.data/novel-runtime/bin/python3`；可通过 `MUSE_DATA_NOVEL_PYTHON` 指定绝对路径。Python 缺少默认系统证书时，用 `MUSE_DATA_NOVEL_CA_FILE` 明确指定受信 CA 文件，仍保持 TLS 校验；Mac 可使用 `/etc/ssl/cert.pem`。此功能复制并保留独立取文代码的 MIT 许可，不导入或启动 Muse。

同一开关同时注册七猫的独立 Node.js 取文适配器。七猫目录保留完整 `_0` ID，按官方 `index` 核对连续顺序；网页同时有推荐正文时，只接受与目标章节结构化数据、标题及目录身份都相符的正文。默认串行请求间隔 1000 毫秒，由 `MUSE_DATA_QIMAO_NOVEL_REQUEST_INTERVAL_MS` 配置；官网存在特定非法折叠响应头时，受限兼容读取保持 TLS、来源、响应类型、字节和完整结束检查，`MUSE_DATA_QIMAO_NOVEL_ALLOW_LEGACY_HEADERS=0` 可以关闭。

准备时核对官方目录、作品和章节身份、付费与锁定状态，逐章验证并保存续传缓存，全部当前目录通过后才发布 TXT。连载标注当前已发布章节快照，来源明确已完结才标完整目录。重新核对失败保留旧成功版本；“更新原小说”可检查后续已发布章节。文件下载前由服务和浏览器分别校验长度及 SHA-256；浏览器保存核对通过的文件后，加入本人书架的“原小说”分组，可再次下载或移出，移出不删除共享文件。原小说不写入剧本书架。

正文下载与榜单刷新使用独立任务队列，默认单工、最多 50 个活动任务；默认单书最多 20,000 章、20 MiB，私有缓存与发布文件总计最多 1 GiB。上限可通过 `MUSE_DATA_NOVEL_MAX_QUEUED`、`MUSE_DATA_NOVEL_MAX_CHAPTERS`、`MUSE_DATA_NOVEL_MAX_FILE_BYTES`、`MUSE_DATA_NOVEL_MAX_STORAGE_BYTES` 调低，达到上限停止新文件写入并保留旧版本。细节见 [原文存储与任务说明](../src/server/novels/README.md)。

### 全本模式（可选）

默认关闭。设置 `MUSE_DATA_NOVEL_FULL_MODE=1` 后，番茄与七猫按官方移动端阅读接口（App API）取得当前已发布目录的全部正文：番茄网页目录中标记为锁定、只能在小程序/App 内阅读的章节，在官方阅读接口中仍是公开可读的；七猫使用官方 Android App 的正文缓存包并逐章解密。适配器仍逐章核对章节 ID、顺序、标题、字数与非空明文，整本通过后才发布 TXT；来源真实付费、会员限制、已下架或接口不可用的作品继续失败并保留旧版本，不发布截断或占位正文。

该模式绕过平台网页端访问限制，可能违反平台服务条款并涉及版权风险，只应在已取得授权或内部评估的范围内启用；开关与风险由数据站负责人决定，默认保持关闭。

全本模式使用 `MUSE_DATA_NOVEL_MAX_ARCHIVE_BYTES`（默认 64 MiB）限制七猫整本缓存包大小。番茄 worker 的瞬时失败重试与匿名会话轮换（约每 40 章或每 15 秒换一次注册）始终启用，与全本开关无关；这是官方阅读接口对匿名会话的限制所需，不改变严格模式的授权拒绝规则。

## 隔离与权限

默认入口使用明确标注的本地预览管理员身份，只监听环回地址。`MUSE_DATA_MODE=server` 使用单独的私有账号文件与受信反向代理身份，缺失配置即拒绝启动；个人书架按稳定用户 ID 隔离，角色由服务端确定。`/data/` 构建使用独立资产和 API 前缀，权限不足会重新核对身份，保持正常账号可用。配置见[独立身份说明](server-identity.md)。

服务器入口使用独立账号，没有接入现有公司登录，也不替换现有 Web 或 Muse 客户端。初始账号供独立测试；逐人开户使用不同用户名与稳定 ID，共用测试账号会共用书架。PGlite 保持单写者，升级先停止数据站自己的写入并备份，不能让两个实例同时打开同一数据目录；异常遗留锁必须核对，不按年龄自动删除。

测试使用独立内存或项目 `.data/` 下随机数据库，浏览器自动采集默认关闭，不访问真实平台。数据、剧本、封面缓存、日志、截图和构建产物都不提交 Git。
