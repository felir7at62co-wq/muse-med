# 数据站首版设计

## 独立运行

前端为 React，API 为 Hono，开发数据库为 PGlite PostgreSQL。PGlite 在当前项目的数据目录持久化，无需连接系统数据库。前端构建产物由同一个仅监听环回地址的进程提供，浏览器与 API 同源。

当前应用不导入 Muse 客户端运行时，不读取 Muse 用户目录、不连接现有账号服务、不调用模型或读取旧服务配置。独立 server 模式在受信反向代理后使用单独账号；本地预览身份只能在环回访问模式使用。独立身份与部署说明分别位于 [server-identity.md](server-identity.md) 和 [deploy/README.md](../deploy/README.md)。

## 数据记录

作品的身份由平台与原平台 ID 决定，ID 始终为字符串。记录保留来源地址、采集时间、平台更新时间、榜单、原始指标名称和数据来源类型。示例数据与真实采集数据分离；未知指标不写成零。作品摘要与历次观测分开保存，重复执行同一批次不增加重复历史。观测表按榜单、来源类型和时间建索引，发布时查找上一批次、打开榜单时查找最新或指定批次、列出榜单的批次时间、按北京时间日期取每天最后一次采集（日榜及本站计算的周榜、月榜）都直接定位，不随历史增长而全表扫描。

## 可见页面

统一作品页以大搜索框、分平台榜单和细分题材为主；平台指标分别展示，不提供全部平台混合排名。详情展示来源、当前指标、分类依据和已积累历史。个人书架关联已取得的真实剧本与最新作品数据；管理员独立配置更新周期。接口与权限说明集中在 api.md。

作品页的浏览器展示副本通过共享的作品字段校验，排除剧本和个人记录，按已确认的同源地址、用户 ID 和角色分区；身份确认前不恢复任何副本。副本的保存时间与来源采集时间分别展示，24 小时仅限制副本可用期，每次进入仍请求服务器最新结果。身份变化使旧请求世代失效，旧响应不能清除新身份或重建已清理副本；401 及未确认身份的 403 清理当前身份，正常权限 403 重新核对角色。服务器保留一份已解析和分类的作品快照，只有作品事务成功提交后失效，失败事务保留原快照。采集进度轮询与作品刷新分离，只有成功发布时间变化才触发作品刷新。

## 采集与错误

红果、番茄、七猫使用独立采集适配器，具体公开范围见项目 README。采集器请求固定平台域名，设置超时和访问间隔，限制页数，不接受任意 URL。解析或请求失败不发布空批次，不清空先前成功记录。运行状态与作品观测独立保存，同一时间只启动一次同平台任务。抖音不注册任务、不展示入口，存量记录与旧解析模块保留。

Crawlee 持久队列承担持续发现和历史补采，逐页发布已核验作品，与榜单刷新共用平台锁；预算用完和停止后保留未处理任务。扩库状态、配置与恢复规则见 [crawlee.md](crawlee.md)。调度和规则整理均为程序执行，不接入 Muse 或模型。

## 后续生产接入

独立服务先通过受控 `/data/` 入口测试，不替换现有服务或接管其账号。扩大公司接入时，再接现有身份系统、评估独立 PostgreSQL 和多实例任务协调；当前 PGlite 单写者不能使用同库蓝绿部署。数据站与未来 Muse 查询工具可以消费同一 API，实际账号切换、迁移与回滚应另行验收。
