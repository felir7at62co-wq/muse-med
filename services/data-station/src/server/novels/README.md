# 原小说下载

原小说有独立的私有章节缓存、持久下载任务、不可变 TXT 版本和按成员隔离的原小说书架，不写入剧本文件或剧本书架。已接入的来源由 `NovelDownloadManager` 构造时的适配器表决定；没有来源的作品不能发起下载。所有原文接口均要求身份验证，已有应用的同源和请求大小限制继续适用。

`NovelSourceAdapter` 先返回来源当前完整目录，再按明确章节 ID 读取正文；授权、付费、预览、身份及源数据解码属于适配器的核查范围。通用库独立验证作品身份、官方来源 URL、唯一章节 ID、从一开始的连续顺序和来源声明总数。正文须是非空 UTF-8 明文，不含私用区、替换符或二进制控制字符；来源提供章节字数时，去空白后的 Unicode 字符数不得少于其声明。未取得字数时保持未知，不声称完成字数比对。

缓存指纹包含作品身份和单章的 ID、顺序、标题、原始地址、字数及更新时间，不包含整份目录摘要或目录观察时间。新章节追加时可复用旧章；每次复用都验证文件字节数、SHA-256 和明文。任一章节不可用、付费、缺失、短文或解码失败都不发布伪 TXT。只有声明目录的所有章节通过后，才写入最终 TXT 和独立清单并发布数据库版本。连载版本明确标注 `current-published-directory`，表示截至该快照的已发布目录；完结目录标注 `complete-book`。来源目录观察时间和来源地址一并保留，旧版本不被覆盖。

文件仅存于项目 `.data` 内的 `novel-files`，目录和文件使用私有权限，拒绝目录符号链接，读取文件禁止跟随符号链接。发布后下载同时验证 TXT 与清单的 SHA-256，接口只返回公共元数据，不暴露本地路径、账号或章节缓存。文件、章节和总存储限制分别由 `maxFileBytes`、`maxChapters`、`maxStorageBytes` 控制，默认且最大分别为 20 MiB、20,000 章和 1 GiB；达到限制时保留旧版本和已核验缓存，由管理员检查，核心不会自动删除原文。

私有目录仅由本应用写入。库初始化时核对现有普通文件并累计实际字节数，拒绝未知文件名、子目录和符号链接；后续串行创建、删除按文件维护占用，不逐章扫描全部缓存。失败写入或数据库拒绝发布时删除未发布文件，成功删除才退回占用；删除失败保持保守计数，重启后重新核对实际文件大小。缓存、最终 TXT 和清单都计入总限额，崩溃留下的未引用文件也不会漏算。

下载任务由独立的单个 worker 顺序执行，各平台合计并发一，不占用榜单或目录采集锁。同一作品已排队或运行时复用该任务；`maxQueued` 默认且最大为五十个未完成任务。服务重启将 `running` 恢复为 `queued`，重新验证目录及缓存后续传；停止时中止当前来源请求、等待适配器 `release()` 和 worker 结束，未完成任务继续保留。

接口为 `GET /api/works/:id/original`、`POST /api/works/:id/original/jobs`（空 JSON 对象）、`GET /api/original-jobs/:id` 和 `GET /api/originals/:id/download`。下载原小说不会添加剧本书架记录，也不触发其他平台采集。网页核对文件后调用 `POST /api/bookshelf/originals` 写入 `novel_bookshelf`；`GET` 和 `DELETE /api/bookshelf/originals[/:id]` 只读写当前成员的记录。

七猫适配器分别读取固定官方作品页、章节目录及目标章节页。保留完整 `_0` 身份，按 `index` 检查顺序；`chapter_sort` 只保留为来源排序值，不当作连续序号。目标章节结构化正文必须与相同标题、作品及章节身份的页面正文对应，推荐作品的正文容器不参与取文。完结状态只取核对后的作品状态；`is_final` 或滚动 UI 状态不用于推断完结或收费。

作品页的 Nuxt 集合别名只在原文作品入口启用静态构造读取，识别有界空对象、数组及固定自有属性初始化，不执行 JavaScript。普通书库继续使用原有严格模式。所有模式禁止任意调用、成员读取、动态下标、原型属性、循环和无界展开。原文 HTTP 只开放官方作品、目录、具体章节三类地址；元数据采集白名单不接受章节地址。

2026-11-13，构建后的独立服务完成七猫四章连载快照验收：真实目录、四章正文、HTTP TXT 摘要、正常停止重启后同版本读取，以及浏览器实际下载均通过。文件为 27,181 字节，范围为 `current-published-directory`，没有把连载当前目录标成完结全本；取文和测试文件仅位于项目私有数据目录。

## 全本模式

`MUSE_DATA_NOVEL_FULL_MODE=1` 时，来源适配器改用官方移动端阅读接口取得完整已发布目录的正文，仍沿用本模块的目录/章节核验与不可变发布规则：

- 番茄：网页目录只用于作品身份、状态和标题核对，不再因 `needPay`/`isChapterLock`/`isPaidPublication`/`isPaidStory` 拒绝整本；正文仍由独立 Python worker 通过官方正常阅读接口逐章解密，worker 校验 API 目录与每章身份、顺序、字数，并对瞬时失败做有界重试。真实付费/会员书籍仍由 worker 的授权校验拒绝。
- 七猫：使用独立 App API 适配器（`qimao-api.ts`）读取作品详情与目录，再一次性取得官方正文缓存包（zip），逐章 AES-CBC 解密并转纯文本；要求缓存包覆盖目录全部章节、每章非空且字数不少于来源声明，缺章、截文、解密失败或身份不一致都不发布。缓存包暂不可用或作品已下架时按 `unavailable` 失败，保留旧版本，可稍后重试。

两种来源都要求已发布目录完整；连载作品仍标注 `current-published-directory`，不把当前目录当成全书完结。该模式绕过平台网页端限制，存在平台服务条款与版权风险，默认关闭，只在已获授权或内部评估范围内启用。

七猫全本缓存包受 `MUSE_DATA_NOVEL_MAX_ARCHIVE_BYTES`（默认 64 MiB）与解压总量预算限制。番茄 worker 对瞬时网络/接口失败做有界重试，并在匿名会话达到官方读取配额前轮换注册（约每 40 章或每 15 秒），两者在严格模式与全本模式下都启用；严格模式的授权/付费拒绝规则不变。
