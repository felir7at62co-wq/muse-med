# 番茄官方分类榜与明文资料

`collectFanqie()` 从官网 `__INITIAL_STATE__.rank.rankCategoryTypeList` 自动发现男女频道分类，默认采集各分类的阅读榜、新书榜前一百名。2026-11-13 的目录为男频 19 类、女频 18 类，共 74 个窗口；目录会随官网改变，不把这个数量硬编码成固定列表。`channels`、`boards`、`categories`、`perWindowLimit` 可缩小明确范围。每批至多 200 个窗口、20,000 条榜单观察；这不是小说全库，也未接入 App 的其他榜型。

排名来自官网前端使用的 `GET /api/rank/category/list`，固定 `app_id=2503`、`rank_list_type=3`，显式传入频道、分类、榜型、`offset=0`、`limit`，并沿用目录中的 `rankVersion`。所有窗口必须返回同一版本；若官网不再提供该版本，整批失败并保留旧榜。校验官方名次从 1 连续增长、字符串作品 ID 不重复、类别一致，以及条数等于 `min(limit,total_num)`。官方不足一百本时接受真实较短榜，安全的十进制字符串总数也可读取，不补造条目。

榜单响应中的书名、作者和简介可能是私有区字体编码。官网前端另有公开 `GET /api/book/info?bookId=...`，会返回匹配 ID 的明文书名、作者、简介、分类、字数、状态及封面。采集器只使用通过身份校验且名称没有编码残留的详情；不猜字体映射、不读取推荐作品代填。实际存在仍在官方榜单、详情接口却明确返回 `code=-1` 且原文恰为“查无此书”的作品；这类作品保留官方 ID、名次、分类和指标，书名及作者为 `null`、简介为空，记录 `metadataStatus=unavailable` 和原因，不生成标题、不缓存为明文资料，下轮重新核对。覆盖说明分别统计排名与明文资料，不把资料不可用计为已核验明文。其他业务拒绝、字段错误、错书或乱码仍拒绝整批。官方批量书籍接口要求登录，本采集器不使用它，也不发送账号 Cookie、安装身份或签名凭证。

明文资料缓存默认 24 小时，保留每本书真实的 `fetchedAt`，复用不会改写获取日期。榜单名次和在读人数每轮重新获取，字数、状态、签名封面优先用本轮榜单字段。缓存按每 25 本及尝试结束原子写入独立开发数据目录，版本、字符串 ID、字段、日期、大小均经过校验；取消、预算耗尽或网络失败后，下轮可复用已核验资料继续。只有全部选中排名窗口完整、且每部作品得到已核验明文或上述明确的资料不可用结果，才向调用方返回可发布批次，不因一部下架作品丢掉其余真实排名。

默认全局串行节流 250 毫秒、单次请求 15 秒、响应不超过 5 MiB、本轮至多新取 10,000 本详情。网络错误、超时、HTTP 429 与 5xx 最多退避重试两次；普通拒绝、验证码、跳转、版本/字段不符不重试。每十个窗口、每二十五本资料会等待进度回调写入完成，采集管理可看到已完成数、缓存数及新取数，完成后没有迟到进度覆盖成功状态。首次全量需要较长时间，后续每六小时更新通常主要重取榜单和新增/过期资料。

HTTP 200 中的非零业务响应单独报告业务 code、净化并截断的说明以及请求书 ID 或分类，不把它统称为字段变化，也不猜测未知 code 是否可重试。登录和访问验证等业务拒绝不会触发重试。业务成功后的字段校验错误报告字段路径与校验类型；错书、乱码及版本不符仍立即失败。

运行配置通过 `MUSE_DATA_FANQIE_DETAIL_CACHE_HOURS`（1–168，默认 24）、`MUSE_DATA_FANQIE_REQUEST_INTERVAL_MS`（100–60000，默认 250）和 `MUSE_DATA_FANQIE_DETAIL_BUDGET`（1–20000，默认 10000）指定。直接调用还可显式设置 `maxRetries`、`retryDelayMs` 及请求范围。全部文件位于项目忽略的 `.data` 内，不读取 Muse 会话或生产数据库。

SSR 目录只解析平衡 JSON，不执行脚本；仅把字符串之外 JSON 值位置的裸 `undefined` 归一为 `null`。作品在读人数只取榜单 `read_count`，不使用可能为占位零的 `readCount`。缺失或不安全数值为 `null`，发布时间未知不推断。来源保留官网统计时间原文和榜单版本，历史从实际采集开始积累。

`rankVersion` 用于核对官方排名与成员，不能据此承诺在读数字被冻结。真实复核中，同一 URL、同一版本、同一名次的 `read_count` 在数秒内返回过不同数值。在读人数按本次请求观测值保存，之后对照出现差异时记录两次观测时间和来源响应，不改写历史数值，也不将这种差异混为排名错位。

本实现独立依据[官方分类榜](https://fanqienovel.com/rank/1_2_262)及官网前端资源中的接口定义编写，没有复制 GPL 阅读插件源码，也没有使用其 App 安装身份。

## 持续发现与历史扩库

`createFanqieDiscovery()` 使用官网 `/api/author/book/category_list/v0/?gender=-1` 发现真实分类、主题、角色和情节，再读取 `/api/author/library/book_list/v0/`；不依赖固定榜单成员。每周期优先复访全部、男频、女频的最新第一页，并在分类目录中滚动选择最多 `latestCategoriesPerCycle` 个最新窗口（默认 8，可配置 1–100）。最新列表及其详情任务标为优先任务，历史积压不会让新作品长期排在队尾。分类历史第一页、后续页及官方已知的热度/字数排序、连载/完结、字数分区使用跨周期稳定队列键，按采集管理预算继续推进。实际覆盖只计算已读页面，分类和筛选相互重叠，不能把窗口数量相乘当成独立作品总量。

书库每页固定 18 条，从零开始分页，按 `has_more` 决定续采；短页不表示结束。官网公开界面最多显示 99 页，采集器止于 `page_index=98`，此时 API 若仍返回 `has_more=true`，明确记录“达到官网可见窗口上限，尚未取全”。页面 ID 序列与之前页面重复时停止该历史窗口，保留原有成功数据，不标注全库采集完成。目录接口和列表接口必须有成功业务码、合法字符串作品 ID、可核对分页字段及无重复身份；空续采页、非预期字段、登录或验证响应不会返回后继任务。

列表的书名、作者、简介、字数和在读人数可能仍有私有区字体编码，因此列表只产生候选 ID 和独立详情任务，不直接发布作品。一条详情任务最多读取一部匹配 ID 的官方明文资料，复用同一已核验详情缓存，并在每部详情完成后原子落盘。历史详情按作品 ID 和来源章节更新时间去重；周期最新详情带周期键，允许重新核对，缓存仍遵循原始获取时间的有效期。发布的目录作品保持 `board=''`、`rank=null`，在读人数未知为 `null`，不会把列表的占位零、目录位置或更新时间当成排名、真实在读或作品发布日期。只有官网准确返回 `code=-1` 和原文“查无此书”时跳过该候选、不伪造空标题；其他拒绝作为失败保留旧数据。

2026-11-13 对真实官方接口的独立只读验证共 6 个请求均 HTTP 200：最新前两页各 18 个字符串作品 ID、零重合；目录返回 260 个真实分类入口，本周期挑选 8 个最新分类窗口；三部候选均通过现有明文详情校验，标题为《东晋求生记》《公路求生：我靠情报加满装备栏》《魔尊与傻子不好好恋爱，互耍心眼》。验证仅覆盖这两页和三部资料，不代表历史窗口或小说全库已取全。逐页持久队列、数据库事务和调度行为由上层工作流负责，Adapter 不连接 Muse，也不采小说正文。

构建后的独立进程另以空数据库完成两轮真实持久队列验收：第一轮处理 4 个任务、核验 3 部明文作品，正常停止并重启后继续处理 4 个任务，累计 7 部、待办由 19 降至 15。两轮没有重复新增，目录名次和未知指标保持空值；这个小预算验收验证恢复行为，不代表分类窗口全部取完。`MUSE_DATA_FANQIE_LATEST_CATEGORIES_PER_CYCLE` 配置周期复访分类数量。
