# Jingliu backend

English | [中文](README.zh.md)

Jingliu is Muse's production engine. Its FastAPI service runs the generation providers for video, images, voice, speech recognition, upscaling and subtitle erasure. A job queue deduplicates submissions and settles each job's cost against the credit ledger. Its database holds projects, episodes, shots, assets, blocking pictures, subtitles and audio. One-step batch workflows apply a production step to a whole episode.

## How Muse reaches it

Muse calls the studio's `/fwp/v2` API through the signed-in [Jingliu connection](../../packages/drama/jingliu-connection/README.md). The [Jingliu tools](../../packages/drama/tool-jingliu/README.md), including `jingliu_run`, read the workflow catalog from `GET /desktop-agent/tools`, price an operation with `POST /desktop-agent/quote` and run it with `POST /desktop-agent/tool`. Muse's production panels use the same connection.

## Source

This tree is based on the backend of cloud release `20261121-jingliu-mkwait-01`, which is the November 17, 2026 workbench backup plus five deployed changes. Muse writes and locks shot scripts in place of Jingliu's prompt writer. Secrets are redacted from stored errors, job results and logs. `FW_ARK_TRUSTED_ASSETS` leaves portrait-reference registration to the model gateway, and first-frame generation is removed. Blocking pictures are stored and bound to shots. Subtitle erasure waits longer for Volcano MediaKit, and both erasure and upscaling keep polling after a failed status query and no longer send a cancel request, which that API does not support.

Changes in this tree that the cloud does not run yet:

- One-step subtitles: `run_auto_subtitles` can process a single `episode`. When it transcribes shot audio, it corrects each shot's transcript against that shot's script lines without a model (`align_script`, on by default; narration audio is not corrected). Timing and segmentation come from the audio, unspoken lines are not added and ad-libs stay. A short mismatch between matched characters takes the script's characters only when both sides read the same in pypinyin with tones and contain the same negation characters, with Arabic numbers read as Chinese numbers. A mismatch that would add or remove a negation stays as heard even when it reads the same, such as 这不行啊 against the script's 这步行啊. A neutral-tone 的, 地, 得 or 了 matches any reading of the other character with the same initial and final; other neutral-tone characters do not, because 这是你吗 against 这是你妈 is a question against a statement. Characters inside a character name or script speaker name compare without tones and may take any of their readings. 一 and 不 compare with tones like other characters, because pypinyin gives their tone change only for some words: it reads 一个 as yi2 but 一样 as yi1. Any other tone difference, such as 买 against 卖, stays as heard and is listed for review wherever it is in the shot.
- Subtitle review list: `script_check.review` lists the shots a person should check: nothing heard although the script has lines, a similarity to the script below 0.5, at least 4 unspoken script characters, a kept mismatch that reads differently (`differs`), a kept difference a person has to judge (`doubts`), or a correction (`fixes`). `doubts` holds each kept mismatch of equal length whose characters have the same initials and finals and either read the same or differ only in a neutral tone or in the tone of 一 or 不, wherever it is in the shot: a person has to tell a mishearing from a different word. This covers a same-sounding negation change such as 这不行啊 against 这步行啊, 我全不要了 against 我全部要了 and 他们不对啊 against 他们部队啊, a neutral tone such as 这是你吗 against 这是你妈, and a same reading with too few matched characters beside it to be corrected, such as 林辰林辰 against 林晨林晨. `differs` holds each other short mismatch between matched characters, which reads differently, and each other kept mismatch whose characters differ from the script's only in tone, such as 你买不买 against 你卖不卖, where each 买 has only one matched character beside it. `doubts` also holds each other extra, unspoken or kept piece that contains a negation character (不 没 别 未 非 无 莫 勿 甭 否), with an empty string for the missing side: 他是坏人 against the script's 他不是坏人 has a high similarity but says the opposite, either because recognition dropped 不 or because the video model reversed the line. It also holds each other kept mismatch in a shot whose transcript or script has at most 3 characters, such as 林辰 against 林晨: too few matched characters surround the mismatch to tell a mishearing from a different word. Other extra characters, fewer unspoken characters and other kept mismatches only count in the character totals. Shots whose script has no `name: line` lines count in `no_script_shots` and are named once in the job warning. The list starts with the shots that do not match the script, at most 300, and then adds shots that only have corrections until it holds 60 entries. `review_count` gives the full number, `omitted_mismatch_shots` and `omitted_fix_shots` count the shots left out, and the job warning gives the shot numbers of up to 20 shots that do not match.
- Volcano speech recognition for subtitles: when `FW_DRAMA_ASR_CONFIG` is set, the subtitle job uses Volcano flash speech recognition instead of Bailian Paraformer and Whisper. The channel is chosen when the job starts, and a failed call does not fall back to another channel. The value is the path of a JSON file that holds the Volcano voice app's `appId` and `accessToken`. Jingliu reads the variable only from its process environment, so set it with the systemd unit's `Environment=` or `EnvironmentFile=`; the settings loader ignores it in `backend/.env`. Subtitles use only the flash route: when the file's `routes.subtitles` names a standard version, the Volcano subtitle channel stays off. Each shot's audio must fit the file's `maxAudioBytes` and `maxDurationSeconds`. Volcano returns one segment per utterance, and the job splits long ones at punctuation and shares their time by character count. Subtitle calls bypass the per-account daily limits `maxDailyJobs` and `maxDailySeconds`, and the `auto_subtitles` job is not charged (its price is 0) until an ASR price is set.
- Configuration errors and the transcription endpoints: the same variable switches Jingliu's transcription endpoints under `/v2/drama/asr/jobs` from Bailian Paraformer to Volcano, after which reading a Paraformer job still in progress answers 503. When the file is missing, those endpoints stay on Paraformer. When it cannot be read (bad JSON, no `appId`, a value of the wrong type, no permission to read the file or enter its directory), every request to them answers 503, even with Bailian configured, and logs the error. In both cases the Volcano subtitle channel stays off, Jingliu logs the file path and error type once per process, `GET /v2/asr/status` reports the error type in `volc_config_error`, and a subtitle job with no other channel names it in its error.
- Credit enforcement in the balance: `budget.my_balance` (`GET /v2/budget/me`) and the agent tool `get_my_balance` report `enforced`, which is whether `FW_BUDGET_ENFORCED` charges and blocks generation. While it is false, a zero balance does not stop generation.
- 剧变 image models and one charge per image: Nano Banana Pro works on the 剧变 gateway, which has `gemini-3-pro-image` but not `gemini-3-pro-image-preview`; Jingliu switches to the second name only when the gateway reports the first one missing or without a channel. On 剧变, `gpt-image-2` gets `gpt-image-2-high` as a backup name, and `gpt-image-2.5`, `gpt-image-2.6`, `nano-banana`, `nano-banana-2.1` and `nano-banana-2-lite` can be selected but are never a default. These 剧变-only names are used only when the gateway host is `jubianai.net` or one of its subdomains. A backup name, and Gemini's switch from native `generateContent` to `chat/completions`, are used only when the upstream did not accept the request. A non-200 answer from the GPT image or Gemini endpoints is retried only for status 408 or 429. With `n` above 1, a failure after some images arrived returns those images and does not request the lost ones again. Defaults and environment variables do not change, and the new models cost the same per image as the others.
- Image price: every generated image costs 25 fen (¥0.25) instead of 15, the same for every image model. `pricing.IMAGE_PER_PIC` is the only place the price is set; the "生图 n 张 × 0.25 元" text in quotes and ledger notes is derived from it. Usage rows recorded before the change keep their price.
- A charge for every image: free-form image jobs (`kind` `image`, which the studio's image page and Muse's `jingliu_image` submit), scene views from the asset dialog and the agent tool `generate_scene_views` hold credit when they are submitted and settle on the images the job recorded; a failed job is refunded in full. Resending a `generate_scene_views` call with the same call id takes over the job it submitted and holds nothing more. These paths were free before. A free-form image job holds `n` images, from 1 to 4, and a Midjourney job always 4; a quote without `n` is the price of one image, which Muse multiplies by its image count. A scene-view quote counts the named views, or every view when none is named. Asset candidates are quoted at their image count of at most 4 instead of the project's shot count, the old synchronous stage-candidates route charges for the images it makes (at most 9), and an asset fill without `kinds` holds the missing images instead of one per shot. As for the other charged jobs, nothing is held while `FW_BUDGET_ENFORCED` is off; while it is on, a user without a credit account or with too little balance gets a 402 for these images too.
- No resend after an image request was accepted: after a 200 from the GPT image or Gemini endpoints, or once a Midjourney or RunningHub submission was accepted, every later failure other than a moderation rejection ends as `AcceptedFailure`, including a failed download, a body that cannot be parsed, a task that times out or fails, and any unexpected error. Jingliu then does not resend the request, does not switch names, does not cool the channel down and tries no further channel, and the error says 上游已受理但未取回图片，请稍后重试 instead of advising more API keys or quota. A backup name is tried only when the flags parsed from the gateway's full error body say the model is missing or has no channel; the error text alone no longer counts. A failed status query of a Midjourney or RunningHub task waits for the next query, and a network error while submitting a RunningHub task counts as a channel fault, as it does for the other providers. Gemini returns at most `n` images, drops an image that a chat response repeats, and stops sending chat requests at the first 200 without an image. Only PNG, JPEG, GIF and WebP data is saved and counted as usage; a response without any ends as `AcceptedFailure`. Every download, whether an image link, a Midjourney or RunningHub result or an http reference image, follows redirects itself for at most 5 hops; each hop must use http or https and resolve only to public addresses, and a download stops at 50 MiB or after 180 seconds. A reference image whose link contains `/media/uploads/`, `/media/outputs/` or `/media/generated/` is still loaded from Jingliu's own media storage instead of the link.

`backend/app` matches the release byte for byte apart from these changes, the Muse login overlay and the following: comments and docstrings in `app/at_refs.py`, `app/auth.py`, `app/budget.py`, `app/jobs.py`, `app/notify.py`, `app/routers/library.py`, `app/routers/shots.py` and `app/user_directory.py` use placeholders instead of the names of users and administrators, a nickname and IP addresses, and `app/config.py` defaults `feishu_notify_contact` to 管理员 instead of an administrator's name.

The overlay is not part of this tree. [`../muse-workbenches/install.py`](../muse-workbenches/install.py) applies it to a release copy at install time. The cloud release carries the overlay's login and shared-library changes but not the installer's Jianying exporter adaptation.

## Tests and static checks

The cloud runtime uses Python 3.12. Create the virtual environment outside the repository and run from `backend/`:

```sh
uv venv --python 3.12 ~/.venvs/jingliu
uv pip install --python ~/.venvs/jingliu/bin/python -r requirements.txt pytest pyflakes
~/.venvs/jingliu/bin/python -m pytest -p no:cacheprovider tests
~/.venvs/jingliu/bin/python scripts/check_undefined_names.py
```

The tests use a temporary SQLite database and data directory and make no network calls. The repository's root `pytest.ini` makes the repository root pytest's root directory, so `-p no:cacheprovider` keeps pytest from writing `.pytest_cache` there. `check_lazy_imports.py`, `check_module_attrs.py` and `check_self_misuse.py` parse `app/` without importing it. `check_undefined_names.py` runs pyflakes from the same interpreter, so pyflakes must be installed there; without it the check reports success.

## Repository attributes

The root `.gitattributes` covers eight imported files. The three `jianying_pack/*.bat` files are `-text`, so Git does not convert the CRLF line endings that Windows users receive. Five application files are exempt from `git diff --check` because they keep the trailing whitespace or final blank lines of the deployed release.

## Not in this repository

The old studio web frontend exists only on the cloud server and in the November 17 backup. Jingliu's own documents, `backend/tools/`, one-off verification and audit scripts, top-level test scripts and A/B result files, the Dockerfile and Jingliu's original README remain in that backup and the maintainers' local source copy.

## Known limitations and deferred work

Muse will remove or replace Jingliu's own model-driven steps, its LangGraph agent and Feishu bot, code that no Muse path uses, and the separate login and charging bridge between Muse and Jingliu accounts. The old website stays until the Muse web console exists.

Two static checks fail on the deployed code. `check_module_attrs.py` reports `agent_run.ResumeIn`, which `app/feishu_bot.py` calls but `app/routers/agent_run.py` does not define. `check_undefined_names.py` reports the string annotation `"asyncio.Lock"` at `app/routers/shotflow.py:448`, whose allowlist entry names line 395.
