# @deepseek-ai/dsh-client-ui-muse-account

[English](README.md) | 中文

## 概述

这个客户端插件在桌面侧栏和设置中加入 Muse 账号入口。它通过 [muse-account](../../host/muse-account/README.zh.md) 提供的已认证 Remote 服务登录、验证状态或退出；密码不会进入模型对话。

<a id="use-this-package"></a>
## 使用本包

侧栏在主区域打开 Bot 与 Skills 市场，设置保留快捷入口。发现、详情、本地发布包和创作者操作复用现有 Host Remote。内容较长时可在详情弹窗内滚动，标题和关闭按钮始终可见。下载与启用分别操作，仅在 Host 确认成功后更新本地状态。已有会话保留原绑定版本。「我的能力」按每条安装记录显示启用状态和可用操作。发现页优先匹配该发行的安装记录，若未安装该发行，则匹配内容逐字节一致的 ZIP 导入记录。

发现页同时展示已公开的发行版和 Muse 首批资源。首次进入时，指引介绍如何发现和安装资源。关闭后，当前客户端会记住选择。可通过「市场指引」再次打开。

桌面市场按目录中的摘要导入首批资源，导入后可在「发现」或「我的能力」中启用。已启用的首批 Skill 在详情中显示 Muse 对话里的调用命令。网页和桌面均保留原始资源包下载。导入的首批资源无法发布或导出为发布包。

点击已启用 Bot 卡片上的「启动 Bot」，会在当前或最近使用的工作区打开绑定到该 Bot 版本的新任务。打开前会将 Bot 的发布名称保存为会话标题。Muse Bot 模式的团队登记使用这个标题，重名时加编号。启动前须有一个工作区，当前任务与默认 Agent 保留原设置。可从 Muse Bot 侧栏底部进入市场。

市场的「制作 Skill」直接进入独立制作与上传页的 Skill 表单。可以切换到「制作 Bot」打包本地 Bot 并自动匹配角色形象，或用「上传 ZIP」选择已有发布包。表单提供上架预览，制作完成后可导出包或上传私有草稿。创作者中心集中展示云端发行和审核操作。

Bot 卡片和制作预览使用同一套方形画框。内置素材的静态图和动画帧采用统一的可见尺寸，并保留各自的宽高比例。

Skill 卡片、制作预览和 ZIP 预览根据 Skill 的名称和用途选用同一张插图。选择本地 Skill 或填写资料时，制作预览会随之更新。

[独立网页](../../../apps/market-web/README.zh.md)通过明确的浏览器适配层复用同一市场页面。它先在本地预览 ZIP 元数据，确认后才上传，并下载经过摘要校验的发布包。网页下载不会安装或启用能力。交接 Bot 的发布包摘要决定是否显示本地示意形象。

创作者中心分别展示云端发行和本地发布包。制作与导出留在本地；上传创建身份不同的云端私有草稿，重试保留同一个上传请求标识。发布团队和管理员身份来自服务端。提交、通过、填写必需意见后退回及下架都使用当前显示的修订号，仅展示服务端确认的状态。云端冲突会刷新列表，不自动重试状态转换。这些按钮不在浏览器中实施授权。

Muse 根据 Bot 的标题、描述和分类匹配内置形象，并把标识写入制作好的 ZIP。上传预览沿用 ZIP 中已绑定的形象。若 ZIP 尚无形象，Muse 会按资料匹配，并在上传云端草稿时绑定。

Bot 卡片和制作预览共享形象，在悬停、聚焦或点击时展示介绍，并支持帧图播放。减少动态效果、形象离屏、标签页隐藏和加载失败时保留静态形象。

桌面应用将本插件与 Host 的 `muse-account` 行一起加载。打开**设置 → MUSE**或侧栏的 **MUSE** 入口，选择**飞书登录**。启用飞书时，网关直接打开飞书官方授权页面。授权后确认与桌面一致的设备码，Host 保存登录状态后页面自动显示账号。连接失败后可以重开网页或检查结果，也可取消待完成的登录。关闭账号页面会取消尚未兑换的授权；已开始保存的登录先完成。首次运行面板使用同一登录流程。现有 Host 登录接口和账号数据保留。

页面每次打开时先向网关验证已保存的登录状态，再显示账号状态。重试和**验证登录状态**也会发起在线验证。网关不可用时显示错误和重试入口，保留已保存的会话；确认会话失效时显示飞书登录入口。验证成功不会作为长期可信标志持久化。重试验证成功也会推进首次登录页面。关闭页面后，页面忽略延迟返回的状态、登录和退出结果；Host 已接受的登录仍可更新已保存的会话。

仅当 Host 返回已验证的管理员身份及管理地址时，登录后的账号区域才显示**用户管理**。重新验证时立即隐藏该入口，验证成功后才重新显示；缓存身份和普通用户均不显示。按钮打开 Host 验证过的管理地址，不附加凭据。

现有桌面配置继续提供必填的 `feedbackUrl` 设置以保持兼容。它接受不含 URL 凭据的 HTTPS 页面；本地网关仅可在 `localhost`、`127.0.0.1` 或 `[::1]` 使用 HTTP，可显式指定端口，且页面路径不得为根路径。**Muse Bot 设置 → 反馈**可打开原生会话反馈表单，确认内容后由用户提交。

在 Muse 桌面中，本插件还通过 `museAccount.feedback` 为现有回答与任务反馈弹窗提供发送服务。弹窗提交使用桌面保存的登录状态，反馈进入账号意见箱。[弹窗包](../ui-message-feedback/README.zh.md)负责可选摘录、失败保留草稿及保存凭据确认。Muse 发送服务缺失时不会显示仅本地保存成功；其他配置继续使用原有本地反馈方式。

侧栏仅显示一个账号按钮，旁边保留连接和更新状态。展开时按钮包含文字，收起时显示带悬停提示的紧凑图标。

<a id="understand-the-implementation"></a>
## 实现方式

市场装配挂载生成的 `museMarket` contribution、主区域、侧栏入口、设置快捷入口及主框架持有的操作反馈。[角色媒体](src/client/market-character-generation.ts)描述市场卡片展示的预制动画帧和形象版本。原有账号装配和 Host 实现保持独立。客户端测试素材使用 `.client.ts` 后缀，防止 Host 聚合程序导入 TSX。

帧图播放器按原图坐标裁切单个图块，防止相邻帧进入留白区域。每个实例有独立的裁切 ID，卡片和作者预览可以同时展示。悬停和聚焦切换已加载的帧序列，不重新建立可见性检测，也不退回静态形象。预制帧图样例的四个图块周围保留透明间隔。

Host 与 Client 分别通过 `tsconfig.host.json` 和 `tsconfig.client.json` 编译；包根配置仅组合这两个程序。浏览器包先装载生成的 `museAccount` Remote contribution，再注册本地化文案、设置页、侧栏入口与初次运行登录面板。它仅从 Host 接收限定的状态与错误码；已保存的 cookie 和知识库 bearer 留在 Host 进程。本包不发布运行时不变量伴随插件，因为这些注册可通过其所属的 slot 与 Remote 注册表观察，无需另存状态核对。

侧栏账号按钮提供 `data-muse-account-launcher` 标记，供 Muse Bot 打开原生设置，不依赖按钮的本地化标签。

<a id="model-experience"></a>
## 模型体验

### 请求上下文与触发条件

#### 模型能看到什么

`museAccount` Remote 命名空间处理浏览器请求。这个界面插件不增加模型工具或提示词；Host 包拥有账号和知识库工具的 schema。

#### Token 影响

界面不贡献模型 token。

#### KV Cache 影响

界面不改变模型请求前缀。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 云端操作需要已配置的账号网关与市场服务。静态设计预览使用模拟操作，不能证明已连接云端。市场匹配内置素材。表单里的自定义介绍仅用于当前预览。

- 账号操作需要已配置的 Muse 网关。部署限制和同一系统用户的文件访问限制由 Host 包说明。
