# @deepseek-ai/dsh-session-coordinator

[English](README.md) | 中文

<a id="summary"></a>
## 概述

将此可选 Host 插件与只负责调度的预设组合。主会话搜索当前用户配置中的普通会话、读取相关历史，自主决定复用空闲会话还是新建执行会话。执行会话保留普通工具、历史和预设。独立任务账本保存派发与执行修订；送达回执不代表完成或用户验收。

<a id="use-this-package"></a>
## 使用此包

在 Host 加载默认导出，将 `/worker` 与普通工具共同加载；仅在指定主会话预设内组合 `/main`。Muse 提供 `main-session`，默认仍为 `short-drama`。可选[主会话导航插件](../../client/ui-session-coordinator/README.zh.md)提供固定主会话入口和启动导航。执行会话保留原生侧栏行，结果通过主会话聊天消息返回。移除 Host 插件仍保留账本文件与普通会话历史。

`mainPreset` 与 `workerPreset` 指定不同角色；`searchLimit` 限制搜索条数，`readChars` 限制每页原始历史字符数，但单个超限事件完整返回。检索权限限于当前本地配置的所有者，可跨工作目录，不会打开其他远程账号或授权读取其他用户配置。Remote 方法要求全局所有者权限，访客的局部授权不能访问任务目录。

主会话的正向工具清单允许协调工具、`ask_user_question`、`show_view` 与 `visualize`。固定入口 `coordinator_display_skill` 仅通过原生注册表读取允许模型调用的 `visualize` Skill；通用 `skill`、文件与 shell 工具仍不可用。执行守卫同时拒绝其他工具，包括后注册工具与 PTC 传输。执行会话通过普通会话控制器独立创建，不继承主会话的限制。主会话负责目标澄清、任务规划、调度决策、异常处理和复核安排；专业调研、写稿、文件修改、下载、生成和专业复核仍交给执行会话。

主会话系统提示词优先要求聊天展示清晰易读：简短结论、信息分组，以及派发安排、关键进展、交付和异常时主动展示任务汇报卡片。提示词引导模型用结构化卡片展示对比、清单、选择和表单，简短问答保留文字。这属于模型指导；任务通知不会在未调用展示工具时自行创建卡片。

调度说明标记为转交上下文；只有 Host 核对过的原始用户消息保留原用户来源与不变正文，调度者补写的说明不会成为用户授权。派发携带用户原始消息与附件、此前每次修订的要求、调度说明，以及已保存的视频模型 key。新执行会话继承主会话的对话模型选择，复用会话保留原对话模型。已保存的视频选择在送达前通过执行会话原生选择服务写入；选择服务缺失或选项失效会拒绝送达，不会静默改用默认值。

复用会话必须空闲，没有待处理输入、活跃作业或未结算协调任务。归档会话和子代理只能用作参考。无法复用时，由 Agent 选择其他执行会话。派发修订需要预期修订号，且上一轮已经结算或被明确停止，不会覆盖正在执行的任务。用户直接在被占用的执行会话中追加输入时，会使原报告失效并通知主会话，不会取消用户的新工作。

`coordinator_show_report` 将已核实所有者的任务标识、当前修订、执行会话、状态和原生文件声明保存在带版本的工具结果 metadata 中。省略或传空标识列表时选择最近任务；`searchLimit` 同时限制汇报条数，并明确返回总数与截断标记。模型结果与 metadata 的合计序列化字符数受 `readChars` 限制，只保留完整任务回执；首个任务自身超限时明确失败，不截断摘要或文件。不存在、外部所有者、重复或超限的标识会失败。模型不能填写完成状态、进度百分比或产物路径。Client 在聊天内展示卡片，并通过现有任务监听跟进被捕获的同一修订；后续修订不会替换旧回执。主会话在关键进展、交付和异常时汇报，不逐条播报执行步骤。

“新会话”下方的 Muse 小蜘蛛入口打开默认工作间中固定的主会话。创建过程使用原生工作区与会话控制器，重复点击或重新启用插件会复用同一会话。执行会话保留各自选定的项目目录。

`coordinator_reconcile` 在主会话检查空闲执行会话的完整最新日志后，请求核对原会话中的工作。它检查预期任务修订和执行会话事件位置，保存新修订，仅发送协调上下文，不重放用户业务命令，也不改变执行会话的模型或目录。当本轮任务说明与用户输入仍是当前输入时，执行守卫只允许 `read`、`read_image`、`glob`、`grep`、`present` 和 `coordinator_report`，拒绝 shell、下载、生成、写入、委派和工具传输。新的直接用户输入一经消费即恢复普通能力。执行会话核对既有工作并按新修订汇报；后续协调业务执行需要另外派发已授权任务。有待处理输入、活跃后代或作业、检查位置过期、所有者不符或请求 key 冲突时拒绝操作；相同请求重试复用已有意图与回执。

<a id="understand-the-implementation"></a>
## 实现说明

经校验的 `muse_coordination` 存储域在创建会话或发送消息前持久化任务意图。同一主会话内请求 key 唯一；完全相同的重试返回已有任务，冲突复用会被拒绝。每轮保留固定执行会话和消息标识、原始事件位置及此前回执。当前存储域写入版本 2，同时兼容读取版本 1；打开既有配置或回滚前，遵循[升级指南](../../../docs/upgrade-guide/v0.2.2-rc.2/muse-coordination-reconciliation/guide.zh.md)。

原生收件箱变更与已接收用户消息证明送达。恢复时先核对这些记录，再决定是否补发尚未送达的派发意图。有送达记录但无法确认结算时标记中断，不会自动重新提交生成。打开主会话仍能查看任务目录，调度者可读取执行会话并明确停止或修订。卸载插件会等待自身写入完成、关闭观察流，不会取消普通执行会话。

私有 `museCoordinationInput` 会话投影只保留最新已消费用户输入标识和任务说明标识，供核对守卫使用；不提供 Client 或 wire 视图，会话日志和任务账本仍是事实来源。卸载插件会同时释放守卫和投影注册。

执行会话结算使用原生 Agent 维护任务，在报告写入和通知完成前保留新排队输入。结算前已经消费的新输入会使旧报告失效；结算期间到达的输入保留在持久收件箱中，供下一轮处理。

`coordinator_report` 只接收指定执行会话已经消费的当前修订说明与核实过的用户输入。核对操作保留原用户输入标识和已检查日志位置；后续直接输入需要重新检查并修订。之后派发到其他执行会话时，会带上此前核对保留的已核实用户补充。该工具收集任务输入之后成功的原生 `present` 声明并刷盘。执行会话、其运行时后代和作业全部结束后才发布结果，包括待创建工作与外部执行清理。运行时管理器提供子树归属和非阻塞工作检查；等待子树在协调器命令队列外进行，因此停止操作仍可执行。汇报之后出现的委派执行失败需要核对并重新汇报。空闲但没有汇报时标记 `needs-report`；仅文字声称完成不会完成任务。文件保留实际来源路径，不复制文件，也不将声明视为文件内容快照。

停止操作先保存 `stopping`，移除未消费任务输入，取消任务活动、其运行时子代理和作业；确实静止后才发布 `stopped`。子树中断包括待创建工作和向调用方交付的外部执行，保留子级收件箱，并允许后续任务修订创建新的后代。执行会话若正在处理其他输入，会保留现场供核对，不直接取消。结构化回执通过有固定标识的原生持久消息唤醒主会话。界面监听账本变化，不消耗模型轮询。

<a id="model-experience"></a>
## 模型体验

<a id="routing-and-report-tools"></a>
### 调度与汇报工具

<a id="what-the-model-sees"></a>
#### 模型可见内容

主会话获得调度说明及 `coordinator_sessions`、`coordinator_read`、`coordinator_dispatch`、`coordinator_reconcile`、`coordinator_tasks`、`coordinator_stop`、`coordinator_show_report` 和 `coordinator_display_skill`。已安装的 `show_view` 与 `visualize` 保持常驻且排除于 Tool Search。执行会话先接收写入日志的 `muse-coordination` 任务说明，再接收保留原文的已核实用户消息，用 `coordinator_report` 明确汇报结果。历史页包含后续游标；回执区分准备核对、送达、执行、收尾、中断、停止和执行会话报告完成。

<a id="token-effect"></a>
#### Token 影响

历史仅按需读取。派发会在选定执行会话中包含原始任务材料及修订要求；终态回执向主会话追加一次结果说明。核对操作只向原执行会话追加协调核对请求，不重复用户消息。汇报卡片将所选的有界回执作为普通的已记录工具输出追加。任务观察流不调用模型。

<a id="kv-cache-effect"></a>
#### KV Cache 影响

稳定策略与已有消息不变，新派发、读取和回执作为普通日志输入或工具结果追加。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延后工作

- 执行会话汇报只能证明其说明和原生文件声明，不等于独立创作审查或用户验收；付费授权仍由执行流程负责。
- 协调范围为单进程、单个所有者配置，不支持跨设备执行或多人共享任务目录。
- 重启后结算不明的任务需要检查并明确续做，不会因缺少报告自动重试付费操作。

### 开发备注
