# 项目风格约束下的资产与提示词

完整阅读全剧后分两层输出：先写全局风格圣经，再写角色、场景、道具。资产要少而准，但任何镜头必需资产不能因出现次数少而删除。

## 风格判定先于提示词

生成任何资产 `prompt` 前，先调用 `drama_project action=read` 读取 `project_bible.style`，再核对当前用户对本项目的明确风格要求。风格来源按以下顺序处理：

1. 当前用户已经明确指定动漫、国漫、二维动画、三维动画、3D CG、仿真人、真人实拍或其他具体风格时，该原文是本轮目标。若它与已存 `project_bible.style` 不同，先按 `tweet-drama-project-bible` 确认并更新项目圣经，使两者一致，再写提示词；不得让旧项目值或默认模板覆盖当前要求。
2. 当前用户没有另行指定而 `project_bible.style` 已有明确值时，逐字沿用该值，不改写成更宽泛的“3D”“写实”或“短剧风”。
3. 两处都没有具体风格，或值彼此矛盾、仅写“短剧”“写实”等无法区分真人与动画的宽泛描述时，只提取并保留角色身份、年龄、五官、体型、服装、发型、配饰、状态、场景和道具事实到工作草稿；不填写可提交的最终 `prompt`，不发起付费生成，并集中询问一次具体风格。

只按上述已确认的项目值进入“真人”或“动画”分支。这是提示词生成前的路由，不是在最终提示词上做关键词替换。不得从 short-drama 预设名、本技能旧称、剧本题材、参考图是真人照片、模型名称或历史资产猜测项目风格。

生图请求同时显式提供 `image_style`：已确认真人分支用 `"live_action"`，已确认二维／三维动画、动漫或国漫分支用 `"anime"`。自定义风格保留完整原文，只在其媒介已经明确时选择对应分支；媒介仍不清楚就先确认，不猜默认值。单项放在 `jubian_video image_generate.image_style`；批量放在每项 `image_generate_batch.items[].image_style`，不能只写批次顶层。完整3D细分画风、材质与人物版本继续写在 `prompt`，该枚举不替代它们。

已确认 3D 动漫、三维动画或 3D 漫剧项目先加载 `anime-3d-assets`，以其人物版式、画风参考、PBR 材质及逐图验收规则制作资产。沿用既有项目圣经和清单；本技能的真人模板与真人审核规则不用于该分支。

## 全局风格

明确年代、地域、社会阶层、造型审美、镜头或渲染质感、灯光、色彩、材质、妆发、服装体系和禁用项。每个最终提示词以 `项目风格：{project_bible.style}` 开头并逐字继承已确认风格；角色身份、年龄、五官、体型、服装、发型、配饰和状态不得因切换风格分支而丢失。拼图、文字、字幕、Logo 和水印在所有分支禁用；“真人选角审美”“禁止动漫脸”和“塑料皮肤”只属于已确认真人分支，动画分支不得出现。

### 已确认真人风格

保留原有真人资产规则：采用真人选角审美、摄影机与镜头质感，并在审核清单中禁止动漫脸和塑料皮肤。角色与场景提示词使用下文真人模板，不因本次分支化而改变原真人项目的造型、构图、参考图、审核或确认出演流程。

### 已确认动画风格

动漫、国漫、二维动画、三维动画和 3D CG 项目保留 `project_bible.style` 的完整原文，继续细化线条、造型比例、材质、渲染方式、色彩和灯光，但不得加入“真人选角审美”“禁止动漫脸”“真人角色设定板”“真实空间”“照片级真人”等真人分支约束。参考图只提供已审核的造型、服装、配色、材质或构图元素，不能把真人照片的媒介风格带进动画提示词。

### 硬性禁用项

任何资产提示词都不得要求或允许画面出现下列内容，`negative_prompt` 必须逐项声明排除（**注意：这只进清单与审核口径，绝不拼进发给剧变的 prompt——见下**）：

- **中国国徽**、党徽、国旗等国家或政党徽标；
- **革命红色产物**：军警制服、红袖章、革命标语、领袖画像等政治或革命标志物；
- **现金**：人民币、外币等实体纸币或硬币；
- **世界地图**或可识别的国界地图；
- **现实标志性物件与建筑**：天安门、故宫、长城、东方明珠、埃菲尔铁塔、自由女神像等可辨识地标，以及真实品牌 Logo、真实机构门头。

证件、文书、票据类剧情道具必须用无违规的虚构样式：只写版式、可读字段和材质，不出现国徽、真实机关名称或真实证件编号规则。支票、汇票、协议、合同、借条等金融与法律文书**允许**出现，可写金额、日期、姓名等剧情必需字段。

**画幅要靠两处一起定，只改 modelConfig 没用。** 2026-09-20 实测：`modelConfig` 里的 `ratio`/`videoStandardId` **控制不了出图画幅**——按 1:1（`videoStandardId=187`，目录里就是 2048×2048）提交，回来的是 1728×2304（同目录 2K 的 3:4）。要同时在**请求顶层**带 `ratio`/`resolution`（产品自己的素材弹窗就是这么发的），**并且**在提示词里写明画幅，两处一起才生效；改后 1:1 得 2048×2048、16:9 得 2848×1600，六张全部命中。目录里没有的比例（如 7:10）只能出最接近的原生档位后本地微调到精确比例。

**上面那些排除项只写在清单的 `negative_prompt` 与 `review_criteria` 里，绝不拼进发给剧变的 `prompt`。** 剧变的生图请求只带 `prompt` 一个文本字段，而**文本审核读的就是这串 prompt**：把「国徽、党徽、国旗、纸币、硬币、世界地图、天安门/东方明珠一类真实地标」写进 prompt，会被直接拒 `InputTextSensitiveContentDetected`。2026-09-20 实测两次踩坑：第 3 集「结婚证」三个字让 5 个包全部被拒（改名规避后立刻通过）、海报把排除清单拼进 prompt 后第一张就被拒。请求 prompt 只写**要什么**，不写"不要什么"；"要什么"里也不要出现真实机构名、真实品牌名与证件实名。

场景资产只写 generic 空间类型与陈设（普通住宅、办公室、餐厅、街道、厂房等），不指向现实具体地标。

### 题材与受众服装门禁（仅真人分支）

写角色提示词前，必须从全剧判断题材、核心观众和情感卖点，不能把职业标签直接套成通用制服。甜宠、豪门恋爱等女性向仿真人剧中，年轻女主及重要女性角色应优先采用对女性观众有吸引力的韩系网红名媛审美：漂亮、精致、华丽但不俗艳，强调收腰和柔美女性曲线、轻盈高级面料、柔和明亮配色、精致首饰及完整妆发；职业权威应通过材质、工艺、克制配色和姿态表达，而不是默认使用深灰黑、宽肩、超大廓形、直筒裤等男性化商务模板。只有剧本明确要求中性、强硬或制服化造型时才可采用这些元素。

重要女性角色的服装参考应优先检索“题材 + 身份 + 韩系网红名媛/财阀千金/甜宠女主 + 穿搭”，逐张只提炼廓形、面料、配色和配饰，不复制品牌 Logo。若用户已确认面部而只反馈服装，重生时必须把现有正式图作为身份参考并明确“只改服装”，不得覆盖已经审核通过的五官身份。视觉审核把“与题材受众审美不符、服装过度男性化、像普通职场制服”列为失败原因并定向重生。

## 角色

同一人物按有剧本依据的服装、身份、年龄或伤病状态拆独立版本。每个版本写年龄区间、性别、地域人种、身份、脸型五官、体型、发型、妆容、上装、下装、鞋、配饰、材质、色彩和状态。服装要完整、丰富、符合场次，并保持核心身份特征一致。

提取完角色条件后，若配置了 `jubian-asset-library` 本地数据根，就按每个角色及服装版本用 `character_candidates.py` 分别检索人脸与全身造型。独立属性逐项传入 `--require`；颜色与服装须用 `--require-item` 绑定到同一件衣物。仅把 `qualified` 视为所传条件的文字命中，`needs_review` 要查原图和缺失信息；无合格候选时报告缺口，不放宽条件或把词项部分命中的高分图当成合格。给用户看实际图片、资产 ID、来源项目和匹配依据，再由用户选定两张图。检索、配对与预览都是本地只读；用户未选图时不上传，未授权本次付费生图时不生成。群像、裁图错位与两张图是否同一人须人工复核，不能只因索引写着 `status=ok` 就采用。选定后用 `style_references.py import-library` 归档两张图，并依[参考图流程](../tweet-drama-core/references/style-references.md)审核、确认与检查。

完整读剧后先按叙事重要性把人物标为 `lead`、`important_support`、`support` 或 `extra`。男女主角及决定主线走向、反复承担关键冲突的重要配角属于前两类；只有前两类必须在写最终提示词前取得参考图。先检查用户已提供且适用的图片；缺图时自主寻找有可核实使用权的网上服化道参考，找不到合格素材才暂停该角色并向用户索取。普通配角和群演仍按剧本建立所需资产，但不得无谓索取参考。

使用 `tweet-drama-core` 的 [参考图流程](../tweet-drama-core/references/style-references.md) 归档到项目并写既有 `asset_style_references.json`。网上路径用现成的 `web_search` 找来源页、`web_fetch` 阅读原页和许可条款，用 `pwsh` 或 `bash` 下载候选到项目工作区，再用 `read_image` 实看归档图；不得把搜索摘要、文件存在或图片可解码当作视觉和使用权审核。逐张判断服装版型、面料、配色、妆容、发型、角色匹配和可执行性，并记录来源页、图片直链、许可页、许可名和本次商业生成参考及向提供方上传的权利依据。缺少权利依据的图片不采用。按 `style_references.py <项目目录> <role_id> import-online` 归档网上图片，逐图填写采用和不继承的元素、具体审核理由，并以 `review_authority=agent_review` 记录角色决定；网上路径无需再向用户索取逐图确认。用户提供图仍需向用户展示选用图及提炼结果并取得当前确认；用户提供图片本身不等于批准选用。只有用户明确另选小红书且自行配置合法、独立的运行时和当前账号端点时，才调用可选 `xiaohongshu-reference`；不得自动复用旧 18060 服务或旧 Cookie。

参考图可用于服化道和抽象五官审美，例如脸型比例、眉眼走势、妆容浓淡和气质，但不得复制真人身份或一比一复刻五官。提示词必须逐张写清“参考哪些元素”和“不继承哪些元素”，禁止直接要求复制品牌 Logo、文字或独占图案。

参考图服从已确认的项目风格，不得反向决定风格分支。动画项目使用真人照片时只提取已批准元素，不加入真人摄影、真人皮肤或真人身份要求；真人项目使用插画式服装参考时同样只提取元素，不把项目改成动画。

重要角色只有在参考图逐张审核且 `style_reference_status=approved` 后，运行 `style_references.py <项目目录> <role_id> check` 成功才可提交剧变收费生图；用户图需要用户确认记录，网上图需要 Agent 的来源、权利和视觉审核记录。`style_reference_ids` 必须指向该角色采用候选的 `note_id`，提交的参考图必须来自这些候选的 `local_image_paths`。网上参考图只用于生成服化道风格，不作为角色身份图或最终入镜资产；人物身份来自当前项目已核验的正式图，或经本流程新生成、视觉审核及确认出演的资产。缺证据、空候选、图片被替换或检查失败均暂停；图片存在、检索成功、已下载或点赞高不能代替审核。普通角色不受此门禁影响；参考批准不替代收费授权，也不等于生成资产审核或确认出演。

已确认真人风格的角色 prompt 使用以下模板，替换全部占位符后才能写入 manifest；候选验收继续按 `tweet-drama-asset-vision-check` 的可用性标准，轻微背景色、视角和排版偏差不单独要求重生。

```text
项目风格：{project_style}。角色身份：{identity}；年龄、地域与五官：{appearance}；服装、发型与配饰：{costume}；当前状态：{state}。单张16:9真人角色设定板，纯白背景。左侧是同一角色的正面半身特写，清楚展示脸型、五官、发型、妆容和上装材质；右侧是同一角色、同一服装的无头正面、侧面、背面三视图，三个人体等比例并列并完整到鞋底。左右身份、服装、材质和配色一致，不出现文字标签或额外人物。
```

已确认动画风格的角色 prompt 使用以下模板，`project_style` 保留用户确认的国漫、二维动画、三维动画或 3D CG 等完整原文；不得改用真人模板。

```text
项目风格：{project_style}。角色身份：{identity}；年龄、地域与五官：{appearance}；服装、发型与配饰：{costume}；当前状态：{state}。单张16:9动画角色设定板，纯白背景。左侧是同一角色的正面半身特写，清楚展示脸型、五官、发型、妆容和上装材质；右侧是同一角色、同一服装的正面、侧面、背面三视图，三个人物等比例并列并完整到鞋底。按照{project_style}保持统一的造型比例、线条或材质、渲染方式、服装和配色，不出现文字标签或额外人物。
```

两种模板都必须保留剧本提取出的身份、外貌、服装与状态字段，且生成后的文本能直接交给剧变 gpt-image-2。风格仍未确认时两个模板都不得使用。

## 场景

按同一地点的日夜、年代、损毁、布置变化拆状态。写室内外、时段、季节、空间布局、入口与动线、关键陈设、光源方向、色调和材质。真人分支统一为 16:9 空场景单图、35mm 人眼机位、可供角色演出的真实空间；动画分支统一为 16:9 空场景单图并逐字继承项目风格，按该风格描述镜头、造型、线条或材质与渲染，不加入“真实空间”或真人摄影要求。两个分支都不使用角色设定板排版，不出现主要人物和文字。

## 道具

只提取推动剧情、承载信息、反复操作或必须连续一致的关键道具。写类型、尺寸、材质、颜色、磨损、状态变化和与人物/场景的关系。统一为 16:9 单件道具单图、干净背景、比例真实，不使用角色设定板排版，无手无人物。需要文字的剧情道具只描述版式和可读性要求，避免无关乱码。

任何道具都不得包含上文硬性禁用项。证件、证书、户口本、身份证、结婚证一类道具一律用无国徽的虚构版式；剧情必须出现的金融文书（支票、协议、合同、借条）保留剧情字段，但不出现真实银行名、真实机关名、国徽或真实凭据编号规则。

## Manifest 字段

每项至少包含 stable_id、type、name、aliases、episodes、scenes、state_or_costume、prompt、negative_prompt、review_criteria、generation_ratio=16:9、generation_layout、generation_version、remote_asset_name、jubian_asset_id、jubian_material_id、url、asset_status、review_attempts、max_review_attempts=3、review、asset_confirmation、official=false。重要角色另含 role_class、style_reference_ids 和 style_reference_status。只有风格已确认的候选才写入可生成的 manifest 记录；最终 `prompt` 必须以项目圣经中的完整风格开头，并只含对应风格分支。实际请求必须逐字读取 manifest 的生成字段，不得在提交器中另行硬编码构图或追加真人、动画风格文本。

`episodes` 与 `state_or_costume` 是登记即带、绑定时强制的两项，不能留空：`episodes` 写这个版本用于哪几集（具体集号数组，如 `[25]`；全剧通用母版写 `["all"]`），`state_or_costume` 写**阶段/体型语义**加服装与发型（如 `孕早期（孕八周）、孕期职场装、长发`；没有体型变化写 `非孕期`）。只写服装不写阶段的资产在镜头绑定时会被判「未标阶段」并点名该资产 id，同一个角色按孕周、年龄段拆分版本时，每个版本都要写清自己属于哪个阶段。这三项缺失时不要靠名字里的「孕期」之类字样顶上——名字只是名字，判定读的是登记值。

初次写出均为 candidate。生成图片、自动审核和确认出演由后续 skills 完成，提取阶段不得提前写 official=true。用户已授权完整流水线时，提示词落盘并报告批次数量后可继续批量生成，不再要求逐项人工选择。

对同一生成批次，先把所有候选的 `prompt` 与 `negative_prompt` 写入 `assets_manifest.json`，逐项检查项目风格原文、风格分支、剧本依据、类型与画幅、人物服装版本、参考图审批、禁用项、重复目标和 `idempotency_key`。动画分支发现任何真人分支约束、真人分支发现被动画模板覆盖、或项目风格仍未确认时，整批停止在提交前，不用关键词删除来掩盖上游模板冲突。只有整批检查通过且对账、预算与当前授权齐备，才由总控调用 `jubian_video image_generate_batch` 并行提交互不依赖的候选；结果逐项回填与视觉审核，不把请求已受理当作正式资产。依赖某一张身份图的服装版本等到该图审核确认后进入下一批。

## 生成前必须先跑对账

写提示词、发起生成之前，先回答"这个资产项目里是不是已经有了"。清单只记录我们自己生成过什么，不代表剧变项目里有什么——2026-09-20 就因为漏看这一层，给一张项目里 8 月就存在的正式资产重新生成了两次（1.17 元）。

- 先用 `jubian_asset materials/list/get` 只读查询当前项目完整主体设定和父资产详情，与 `assets_manifest.json` 逐条比对，保留 `_probe/asset-reconcile.json` 对账证据并列出未登记项；
- 未登记项必须逐条处置：复用项按 `tweet-drama-core` 的正式资产证据与 writer 规则登记；不需要的项记录 ignored 与理由，不删除远端资产。当前环境缺少对账证据写入或登记入口时报告依赖缺口，不伪造成功；
- **证据里还有未处置项（`blocking` 非空）就不许发起付费生成**；不能因本地清单没有记录就重复生成；
- 复用顺序：本项目远端已有 → 跨项目库（`jubian-asset-library` 技能检索）→ 都没有才生成。

## 生成策略与重试

- 按 Web 设置已锁定通道和实时目录报价估费，不用历史平台名或单价覆盖当前选择；多行未锁定时按工具错误请用户在设置选择。授权内自检项目、资产、规格、预计费用和已有任务后自主执行，超出范围才补授权。
- pending、timeout、unverified 或结果未知时回读原资产/任务与原 key，不换 key 重投。确认失败后评估根因、已花费用、修正方案和剩余授权，再决定是否定向重生；max_review_attempts=3 是上限，不是自动重试次数。新生成只对应有证据的修正，不能无限付费试错或静默换贵通道。

## 审核门禁

`review_criteria` 必须包含硬性禁用项检查：中国国徽、革命红色产物、现金纸币硬币、世界地图、现实标志性物件与建筑，以及外加字幕、标题文字、水印、Logo。发现任一禁用项即判该资产 failed 并定向重生提示词，不得因主体正确而放行。证件与文书类道具允许出现剧情必需的金额、日期、姓名，但不得出现国徽或真实机关标识。

## 当前项目统一匹配预览

提取人物、场景与已认可声线需求后，按 [匹配预览字段](../tweet-drama-core/references/match-preview.md) 保存项目内需求 JSON，调用 `drama_assets method=match_preview project_dir=<项目目录> requirements_path=<项目内需求文件>`。每项引用真实原文行与摘要，未知身份或状态保持未知，不为匹配而补写。它只检索当前项目：`reuse_ready` 是复用建议，`needs_review` 交人工确认，`blocked` 先修读取/分页/来源问题，`missing` 继续已有 `jubian-asset-library` 检索，不能据此直接付费生成。预览不登记、不确认出演、不绑定；正式采用及收费仍需当前用户审批。
