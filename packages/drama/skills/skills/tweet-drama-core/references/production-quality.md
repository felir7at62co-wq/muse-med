# 自动生成视频的质量与稳定性

适用于所有画幅、媒介和项目。首次自动制作或续跑先读本页，沿用原剧本、已确认资产、当前模型能力和已有费用授权；这些是制作与复核方法，不增加逐包审批或另一套付费门禁。

首次写卡及影响动作、道具或空间的修订，先执行[首轮生成与同一标准验收](first-pass-production.md)：从原文确定关键动作落点和道具变化，实看母版适配性，把动作阶段、同场延续状态写进实际提交内容，出片按同一依据核验。

## 表演与时间预算

先把关键动作按原文列成可观察的起点、接触或支撑变化、完成状态，再安排发声、必要反应与运镜。动作、表情和情绪不因摄影机运动而加大；不能把“放下再休息”改成“始终站着”，或删掉因果动作来掩盖生成困难。复杂动作没有统一的4秒上限，提示词短也不证明动作能在4秒完成。单包不塞入互相矛盾的动作、人物状态或场景。

完整镜头脚本交给 `drama_shot` 或 `muse_production` 解析时，复杂动作及先后发声的镜头使用四个独立预算字段；数值取自自然试读和合理动作排演，不按语速估算强迫演员快说。下面是虚构格式，不是项目剧情：

```text
动作预算：6秒
发声预算：3秒
反应预算：2秒
表演顺序：先动作后台词
```

四项各写一次；预算用非负整数秒，有发声时发声预算至少1秒，无声为0秒。`表演顺序`取`同时`、`先动作后台词`或`先台词后动作`。同时取动作和发声较长者，再加反应；先后累加三项。此例内容11秒，再由工具计算自然收束。可另写`时长：N秒`，但不得短于自己声明的预算合计。超过当前模型上限时沿原文拆成连续镜头或包，不能裁掉必要步骤。

编译输出去掉这四项和`时长`行，提交正文仍须明确谁先做什么、再做什么，不能把顺序只写在预算里。直接写卡不经编译时也须单独保留同样的核算，不把预算元数据粘进视频提示词。未写预算的旧脚本仍按现有规则估算；`advisory`只给建议，其`ok=true`不能证明时长可行。估算不是实际发声或模型切点的保证，成片必须复核。

## 空间、状态与实际提交

每场以固定环境锚点记录全部在场人物的位置、朝向、姿态、服装、伤势及持物，并记录关键道具的数量、尺度、容器内容和支撑关系。没有原文依据就延续前一状态；镜头改变不能重置人物、伤痕或物件。分别检查每包的起点和终点以及相邻包的接缝，时空跳转须有剧情依据。

取景范围内应呈现占据对应位置的人物；摄影机经过该位置时不能把人省掉，也不为避开人物擅自换位。取景没有覆盖的位置不强迫所有人同框。相机推近、拉远、横移或摇镜可独立于人物运动，先核对起终点、移动路径、遮挡及视线轴线，再选清楚呈现原文的方式。

免费准备后检查`payload.modelConfig`中的实际提示词、分段、素材顺序、正式ID、妆造、声音和时长，不能只检查本地分镜或卡片标题。原生准备保留提示词内部换行；若中间工具又压平了结构，回到实际写卡源头修复。沿原预览与key提交，提交未知沿原key对账；格式更新或新准备的key不代表可以把同一内容再收费。记录已有任务和采用版本，续跑先复用可用结果。

## 审片证据与返工

任务成功、音轨非空、少量抽帧、局部通过各自只证明其所检范围。动作缺失、穿模或人物消失的判断须回看对应连续片段；必要时加密抽帧并记录时间码。没有看到不等于没有发生，正当切镜、遮挡、出入场和时空转换须结合前后文判断。两次舀水应先辨明取水、倒水与排水，不能只按动作次数判成重复剧情。

对照正式参考实看人物脸、发型、服装和道具；检查凭空增加的帽子、配饰、人物和物件，以及跨切点丢失的伤势、湿衣、持物或容器内容。逐句听校对白、旁白与心声的原文、说话人和发声方式；转写仅供辅助，音轨存在不能代替听校。ASR故障须有当前实际调用证据，旧批注不是当前服务状态；已有匹配文件哈希的结果优先复用，未知收据沿原ID查询，不为巡检重新收费。

每个结论记录当前选用文件及哈希、时间区间、原文要求、观察事实、结论和未核项；区分已证实缺陷、待核对疑点与审美偏好。复核推翻旧判断时更正当前结论，保留依据，不继续重复旧的失败或通过。用户确认采用现状后保留其选择，不自行启动修复；未核项仍如实说明，不能把疑点写成已证实缺陷。

只修有依据且在授权范围内的受影响包。保留已通过的内容和原文因果，说明本次修改针对的根因，再核对原缺陷、新增问题与两侧接缝。替换后确认整集、字幕、草稿及导出实际引用新版本；禁止只更新路径说明却交付旧片。文本检查和这些指令都不能保证生成画面正确，缺乏实看或实际听校时保持待验。
