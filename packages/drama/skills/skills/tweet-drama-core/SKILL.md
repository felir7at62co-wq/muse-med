# 仿真人流水线 Core

pipeline_state.json 是唯一流程状态源，assets_manifest.json、matches 和 video manifest 是业务产物。所有状态原子写入；并行分片由总控统一合并。上游输入变化时只把受影响下游标为 stale。

## 标准阶段

source、episodes、style、asset_prompts、asset_candidates、official_assets、shots_and_matches、video_tasks、reviewed_videos、draft、export。

## 谁写这个文件

从本技能实际目录执行下列命令；其他工作目录使用技能加载器给出的完整脚本路径，不假定个人安装副本的位置。

技能资源只按**本次加载返回的技能目录**解析：脚本、参考文件和素材写相对路径，需要绝对路径时用加载结果里那个基目录拼出来。不要照搬任何写死的安装路径（安装根、`node_modules` 布局、别人的磁盘路径）：打包形态不同（`app.asar` 与 `app.asar.unpacked`、版本化运行时目录、npm 布局），升级或换机器后旧路径即失效，而加载器每次都会给出当前有效的目录。定位不到脚本时报告缺失并给出期望路径，不改从猜测的安装目录里枚举。

- `python -B scripts/pipeline_state.py <项目目录> sync` —— **产物投影**：按磁盘上的产物重算每个阶段（completed / review / pending），写 `status_source: "projection"`。**开工第一件事就是跑它**，把「现在在哪一阶段、哪几集走到哪」报出来再动手，不要凭记忆推进。
- `… set --stage <阶段> --status <状态>` —— **人工批注**：写 `status_source: "manual"`，此后 `sync` 只报告不覆盖，用来表达产物看不出来的事（预算、批准、已知缺口、阻塞）。
- 状态 = 产物投影 + 人工批注；手写自述必然腐烂，所以不要手改 JSON，也不要指望谁记得回写。
- 后段阶段（脚本匹配 / 生成 / 审片 / 草稿 / 成片）以**声明工作范围**为口径：范围内全部分集完成才算 completed，否则是 review。`note.completion_scope=work_scope` 只代表分工完成，不能报告整部剧完成；未声明分工的旧项目仍按整剧核对。

多集镜头的覆盖证据是业务产物，不是第二套流程状态。先根据用户或正式分工确认 `episodes/manifest.json` 的 `work_scope.episode_ids`；`expected_episode_count` 始终表示整剧总集数，不能把 300 改成分工的 80。用户只负责 140–219 集时显式列出这 80 个原始集号，不补做 01–139 或 220–300，不从现有最小/最大集号推断授权或完整性。schema、逐行来源映射和旧记录迁移见 [Core I/O contract](references/io-contract.md#episode-work-scope-and-coverage)。

运行 `python -B scripts/episode_coverage.py <项目目录> audit` 只读核对，再运行 `accept <本集号...>` 为已通过的集签发绑定当前依赖的记录。显式分工允许独立集先验收，其他集缺镜头映射时 `accept_status=passed` 与工作范围 `status=pending` 可同时成立；范围内原文缺失或 SHA 变化仍阻断签发。`gate <集号...>` 是新多集自动付费清单的前置检查，只放行本次范围内有当前有效验收的集。缺映射、格式无法独立识别或依赖摘要变化时不放行；不能用 Agent 自述、手工 `set completed` 或文件存在代替 `gate`。机器可识别的书面物件动作不因“说明书/问卷/答题卡”中的单字判为发声，含糊的“说明来路”“一边铺纸一边说”等仍保留待核对；本检查不判定动作表演和视频视觉质量。

## 逐集生成质量流程

所有画幅和媒介的自动制作先读[自动生成视频的质量与稳定性](references/production-quality.md)，执行可计算的表演预算、跨包状态延续、实际提交核对与有时间码的审片。复杂动作不受统一4秒限制，先后动作与台词须累加；不能用删掉原文动作、盲目重抽或仅凭稀疏抽帧的结论解决生成问题。

首次写卡按[首轮生成与同一标准验收](references/first-pass-production.md)确定原文支持的动作落点与道具变化，核对实际参考图和提交内容；生成前后使用同一标准。复杂动作保留起点、接触支撑和落点，同场关键对象跨镜跨包延续，不能靠静态改写或反复重生绕开真实动作。

按[动作依据与用途规则](references/first-pass-production.md#动作依据用途与手部状态)区分实际动作、对白中的表演括注与台词里的教学、命令和条件；确定执行者和发生时机，再统一动作、手部、道具路径与落点。真实示范和剧本明确的失误保留，不把讲解擅自演成操作，也不以生活常理改掉既定笑点。

旧项目续做先按[既有项目迁移](references/io-contract.md#existing-project-migration)核对当前授权范围；整剧旧模式会检查前序覆盖记录，不能把缺记录说成所有旧视频不合格。当前只提交一集时，补真实来源映射，再用`accept <本集号> --episode-only`和`gate <本集号> --episode-only`核对本集，无需改整剧`work_scope`或总集数；缺本集证据、原文完整性失败、错人漏词或OS/VO歧义仍阻断。真正的分工调整才改工作范围，不能为绕过失败而缩范围。不改原文、不批量标通过、不重复生成历史成片。人物名单和已列角色的普通括号表演说明可解析，身份或发声歧义仍待核对；原有`EP13-9x16.md`可直接映射，无需改中文文件名。门禁阻断收费提交，不阻断免费预检和问题修复。

原文与分镜中已列角色的捂肩吸气、抹汗、舀水、擦汗等括号动作只在比较时归一为角色名，完整原文和映射`source_text`保持不变，不要求为通过检查删掉动作说明。标记动作行末尾对已列人物的“质问/询问/追问”等描述，只有紧接同一已列说话人的独立对白、且动作行没有台词文本或身份歧义时才按动作识别；跨场、换人、OS/VO、引号或冒号中的发声不能据此略过。未支持的表达继续核对，不添加跳过`pending`的开关。

对所有题材共用结构识别，不按某部剧的人物、道具或动作词白名单放行。已确认角色后的成对括号、方括号及嵌套表演说明只在比较时归一；原文、动作、表情、情绪、台词与发声方式完整保留。人物表可用人物/出场人物/登场人物/角色等标签；没有人物表时只从独立无括注对白确认身份，不从待判括注自证身份。身份/时期变化、OS/VO混合说明、额外引语、未知备注和待定信息仍须核对，不把喃喃自语改成心声。解析缺口应补识别支持，不删改原文凑格式，不以人工备注或跳过门禁代替验收。

普通姿态、面部表情、口头表达和物件操作括注与单独的OS/VO标记可以共同识别，例如`甲 VO（声音发颤）`；不把`（OS，声音发颤）`等混合说明猜成明确发声方式。动作末尾的说/喊引导只在紧邻同一已列角色对白且没有额外发声内容时按动作处理；相邻说话人不一致时保留待核对，不能猜补台词。精确的`【下集钩子】`和`【全剧终】`按标题保留来源行，不能为省事删除。

标记动作行中的物件拟声须有受支持的声音、成对引号及明确声响后缀或物理撞击依据；“铛”的一声、门的“吱呀”一声、枝叶的“沙沙”断裂声和砸碎物体时的“砰！砰！”可按动作识别，完整原文保留。同一行剩余的发声提示、其他引语或冒号内容仍待核对，不能因一处拟声略过台词，也不能把整段动作当作说话人。未知声音、人物喊声和括注引语不据此放行。具体识别范围见[原文分类规则](references/io-contract.md#episode-work-scope-and-coverage)。

开工先从本次加载的 Core 目录运行`python -B scripts/episode_coverage.py <项目目录> source-scan`，提前扫描本次声明工作范围的全部剧本；原文完整性或格式、身份、发声与归属歧义先解决。建映射再运行`source-lines <集号>`，使用完整`entries`，核对后逐行补真实镜头编号。这些命令与`preflight/audit/accept/gate`共用上下文分类，`kind: null`和缺OS/VO子类型行保留待核对，不能`continue`丢弃。不要导入单行内部函数重建映射或据旧探针断言未更新。已有完整映射先`audit`；输入变更后重跑实际`preflight`，更新映射后重新`accept`和`gate`，不沿用旧失败摘要或用跳过门禁替代修复。

首次制作和续做单集都先对照 `episodes/<集号>.txt`，不要把旧分镜当作原剧本。写卡前从本次加载的 Core 目录运行 `python -B scripts/episode_coverage.py <项目目录> preflight <集号> --script <完整镜头脚本>`，核对有序发声原文、说话人及对白/非当场发声方式；缺词、增词、换人或发声方式变化先修正。`pending` 表示来源表达仍需核对，不是通过。此只读检查不签发完整覆盖验收，不替代已有来源映射的 `audit/accept/gate`、OS/VO语义、动作审核或实际听校；不要求重做已验收的历史成片。修改原文、镜头或准备提交的提示词后重查受影响集，最终准备内容中的台词也须与已核对版本一致。

分包前先自然试读，再按动作安排时间。可同时完成的发声与动作取较长项，必须先后完成的累加，另外保留必要反应和自然收束。编译语速是可配置估算，Muse默认5个有效字/秒，不能当作演员应达到的语速；长提示词和多镜不必然失败，但逐句发声、关键动作和情绪停顿都必须有空间。人物按原文不动时仍可合理推近、拉远或移镜，不靠新增表演凑运镜。

每场记录全部在场人物的固定空间位置、剧本允许的移动、朝向、手持物与身体状态；切镜、改景别和换主体都不重置这些状态。摄影机的起终点与路径要和场景布局相容，经过某人的位置必须正确呈现本人。按[场景时段规则](references/first-pass-production.md#场景时段进入每个独立包)将原文时段落实到每个独立包，并核对参考图光照；切镜不推进时间，原文次日或蒙太奇推进仍须保留。伤势、湿衣和持物跨镜延续到有依据的变化。

关键道具在选材和写镜头时执行[道具与剧情动作适配](../tweet-drama-asset-vision-check/SKILL.md#道具与剧情动作适配)：对照原文动作实看选用母版，核对相对尺度、结构与使用方式，保留适用依据。身份正确不等于动作成立；冲突或证据不足时暂停受影响包的付费生成，继续独立工作，不靠提示词强行放大道具或改动人物表演补救。母版更换后重查首次出现、实际使用及相关包的绑定和免费预览。

提交前核对完整提示词、引用顺序、真实素材ID、角色版本、包时长和当前模型能力，再使用既有授权与幂等提交；`advisory` 的 `ok=true` 不证明内容验收通过。区分可解释的风格提示、解析误报与真实漏词/错绑，不以警告数量为零作为目标。收费结果未知先沿原key对账，提供方连续故障先停该通道核对，不反复收费试生。

生成完成先回读任务、下载和测量，再看关键动作及相邻包接缝，逐句听校对白、旁白、心声与口型。抽帧通过和音轨非空不能代替声音核验；ASR不可用时可实际听校，未听校则明确保留待验，不能标为最终通过。替换包后检查整集、字幕、剪映草稿和导出是否仍引用旧版本；禁止素材按SHA检查。交付另验字幕校时、音量、画质和实际导出规格，不把高清画布当成高清源。

验收区分任务成功、局部画面/声音检查和剧情合理性，也区分已证实缺陷、待核对疑点与审美偏好。有证据的原文动作或因果缺陷未修时不能宣称整体通过；未核实项保持待验。用户确认采用现状后保留其选择，不自行重做，也不把疑点当成确定缺陷反复要求修改。发现既有记录误判时保留依据并更正当前结论，不能继续沿用旧的失败或通过。

## 资产硬字段

stable_id、type、name、aliases、episodes、prompt、review、review_attempts、max_review_attempts、jubian_asset_id、jubian_material_id、url、asset_confirmation、official。正式资产必须 official=true；非本地生成候选确认响应可追溯，本地正式主体使用总控规定的实时独立门禁证据，不伪造 material_id 或确认响应。

## 资产参考搜索

缺角色（含主角）、场景、道具或全剧视觉参考时，Agent 先查本项目正式资产与已指定参考，仍缺时主动用 `web_search` 搜索、`web_fetch` 阅读来源，依据剧本事实和项目风格提炼参考元素，不重复收费重生。角色服化道按[参考图流程](references/style-references.md)实看、归档和审核：网上图用 `style_references.py import-online`，已确认的人脸与全身素材对用 `import-library`；收费生图前运行 `style_references.py <项目目录> <role_id> check`。场景和道具在项目参考记录中保存来源、采用元素与使用判断，不伪装成角色传给此脚本。没有可用结果才报告具体缺项并向用户索取；不自动启动小红书。网上参考只辅助生成，不能直接作为正式资产或真人身份；生成后仍按正式资产流程审核与确认。

## 视频禁用标签

`drama_video` 的 ban/unban/list/inspect 统一管理本项目 `video-bans.json`；ban 按实际文件 SHA256 标记具体版本，labels 至少一个自由可读标签（如“人物对调”），reason 可选，不要索取证据。同字节副本同样禁用；同路径换成不同字节不是旧版本。查标签、没有标签或 unban 都不等于审核通过，保留现有 hashreview 与 QA。标错用 unban；旧文件已替换时用 list 中旧 SHA256 解除，不删媒体、不删清单。

官方 Python render、draft、delivery 和状态投影通过 `scripts/video_bans.py` 只读检查同一清单，坏清单拒绝继续。状态人工批注保留，但必须同时看 projected 与 note 中的禁用标签；旧 completed 不覆盖禁用。禁止用通用 FFmpeg、项目手写脚本或直接复制绕过禁用；本门禁是项目范围的官方路径检查，不是对任意外部命令的拦截。无标签不证明历史成片没有使用旧禁用源，缺来源映射须核查实际母版。

## 校验

- 归一化本地路径和剧变 URL，不凭文件名猜资产。
- matched JSON 只引用正式资产。
- 每镜1–4秒、8字/秒、36字是节奏建议，超出记录警告并复核，不删除原文或改变说话人；每镜建议不限制整包长度或镜头数量。单包按剧情、对白与表演安排，充分使用已核实模型支持的时长；支持30秒时可直接生成完整30秒段落，不因提示词长或切镜多的泛化担忧默认缩到10–14秒或省略必要信息，也不强行凑满上限。
- 打包服从当前分镜和实时模型目录约束，包含收束；不覆盖项目已确认模型、分辨率或交付规格。
- 编辑输入须通过内容审核；pending 仅可作明确标注非最终的草稿/预览，由模型安排后续回读。最终选用文件必须 clean 或 not_required，并有对应实际文件的内容、字幕清理、分辨率与音画 QA；未知或失败不能放行。替换来源后重新审核。
- 续跑时先审计磁盘与远端 IDs，避免重复收费生成。
