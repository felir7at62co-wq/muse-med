# 首轮 CG 提交规范

## 统一生成语言

所有生成和编辑提示词以项目确认的正向媒介（默认“3D动漫／风格化三维动画”）及“次世代高精度建模 CG，物理可信 PBR 材质”开头，结尾按资产类型使用下方质量锁定句。人物、场景、道具共用质量基准，各自保留本次交付内容，禁止开头写 CG、结尾又拉回简化风格。

允许且必须保留明确的正向媒介描述：3D动漫、3D国漫、三维动漫、3D动画、三维动画、风格化三维动画、3D anime、stylized animation。用户明确要求的动漫媒介不能被删除、仅留在技能路由或移到负面排除中；PBR、CG、引擎名、8K、电影级是技术与质量描述，不能替代媒介。造型、皮肤、发束与色彩保留动画设计感，细节丰富不等于真人摄影或扫描级写实。用户明确要求的卡通、toon、三渲二或 cel shading 可在项目风格内保留，不能擅自作为默认风格注入。检查用户原话、上游模板、工具自动补词和翻译后的最终实际文本，删除与本项目动漫媒介冲突的真人、摄影及 photorealistic 正向指令；负面排除只用于补充。

## 首轮必须具备的视觉证据描述

按资产类型选择适用项：五官、皮肤、毛发与服装展示用于人物；场景正文描述环境构件、陈设与光照，人物基准仅用于本地比对。道具只写本次所需结构、材质与展示条件。

- 人物：按剧本年龄与身份独立设计的骨相及软组织转折；眼睑厚度、唇缘、鼻翼过渡清楚；自然皮肤微起伏、局部肤色和粗糙度变化，克制皮下透光，不用均一亮面或磨皮。
- 毛发：大发束建立体积，束内细丝、发梢疏密和方向性高光；具体发型服从时代，不用加长或炸毛代替精细度。
- 衣物：按面料给出纤维组织、缝线、折边、厚度、叠压和受力褶皱，磨损仅在合理部位；棉衣保持真实蓬松结构，不能以单层噪声布纹代替体积。
- 场景与道具：构件厚度、倒角、拼接、接触关系和空间尺度准确；木石布金属按各自粗糙度和反射区分。正常农村保持日常维护痕迹，画面无人，精细不等于破败。
- 光照：有方向的柔和主光与适度补光，保留骨相、衣褶和材质微起伏；柔和接触阴影与可读暗部，避免平光磨平细节，也不靠锐化噪点伪造质感。

## 发出首个请求前完成

1. 读取剧本与时代，固定本次身份／空间方案；新角色写独立五官组合，同角色沿用已通过身份。
2. 实际查看两张正向参考，落实质量描述。人物只传入隔离身份的风格参考；工具不能隔离时选无脸材质局部。场景另按 [无人场景参考规则](scene-assets.md#实际参考输入) 检查全部实际输入，完整人物图和仍留人形的无脸裁剪不能提交。不把拒收图传给生成器，不复制参考五官或服装。
3. 展开最终提示词，清掉所有未填写占位符与上游冲突，保留明确的正向动漫媒介。使用下方通用开头和按资产类型选择的结尾，不依赖聊天上下文。
4. 对账模型能力、实际参考输入、宽高参数和细节档位。使用工具已支持且预算允许的高质量档位，不虚构参数；避免低分辨率整板挤掉面部细节。若既往整板难以保留质量，首轮即分区域制作再合成，不先浪费一次低质整板。
5. 人物明确左侧完整头顶至胸部或上衣／外衣下摆的正面人物展示（中间自然取景亦可），右侧正／严格侧／背三格仅衣领肩部至鞋底，无头无断面；三格同尺度同服装。场景默认横向 16:9，其他比例须有明确用户依据。
6. 将以上检查证据写入现有 review.checks 的 workflow_02；未通过先修文本和配置，不提交生成。完成后仍逐图执行 workflow_03 至 workflow_07，不能以减少重试为由降低验收。

## 可直接复用的开头与分类结尾

开头：3D动漫／风格化三维动画，次世代高精度建模 CG，物理可信 PBR 材质，自然比例、精细结构与连续曲面转折，材质微结构、厚度、局部粗糙度和反射层次清晰，柔和主辅光保留体积与接触阴影。严格对齐实际传入正向参考的质量，参考仅用于风格材质，不提供人物身份。

人物结尾：最终保持3D动漫／风格化三维动画媒介、次世代高精度建模 CG 与物理可信 PBR 质感，人物、服装与所需道具具有一致的建模精度、细节密度和光照逻辑。

场景结尾：最终保持3D动漫／风格化三维动画媒介、次世代高精度建模 CG 与物理可信 PBR 质感，建筑、陈设、道具、材质和光照具有一致的建模精度、细节密度和光照逻辑，保持纯环境场景的交付范围。

道具结尾：最终保持3D动漫／风格化三维动画媒介、次世代高精度建模 CG 与物理可信 PBR 质感，道具结构、材质与展示光照匹配本项目已确认的质量基准。

道具提示词在统一首尾之间写明：剧本时代地域、用途与获取条件、尺寸和交互参照、结构与可动部位、材质分区、实际状态、展示角度及背景。禁止无依据加入现代零件。人物和场景使用 design-and-prompts.md 对应模板，并补齐本页适用细节。

修正只针对已观察问题，先判断是参考污染、提示冲突、分辨率不足还是局部结构失败；可局部编辑时不重生整板。不得通过盲目换种子、追加空泛质量词或无限重试改善首轮。仍遵守每问题周期最多三次新生成与用户预算，不能把次数清零。

人物首轮提交前另按 [五官结构差异](face-differentiation.md) 核对结构对照与实际参考绑定；将目标面部描述放在短 CG 前缀后。无脸参考只能减少参考身份污染，不能代替独立五官设计。

## 提交前检查

此检查适用于首轮生成、重试和编辑。先保留完整参考计划再上传，成功后把实际 URL 填回原条目；失败条目继续保留失败状态、原因和尝试证据，不通过删除条目或补写成功绕过检查。上传失败、尺寸校验失败、超时或结果未知时停止受影响请求并报告原因；只继续设计草稿或修复参考上传，不静默降级纯文字生成。批量调用任一项未就绪时整批不提交，修复后重新核对。

在既有 `generation.prompt_parts.medium` 填入开头使用的媒介词，例如 `3D动漫` 或 `风格化三维动画`（其他允许值见检查脚本的 `MEDIA`）。其余风格子项和材质结构仍写入正文。`generation.final_prompt` 保存最终实际工具参数中的完整 prompt，不能只保存上游草稿。非 `local_review` 参考均为本次计划提交项，逐张记录 `purpose`、`submitted`、`upload_status`（`pending/failed/unknown/uploaded`）和 `url`；只有实际上传成功且取得可用 HTTPS URL 后才能记 `uploaded`、`submitted=true`。`local_review` 仅本地审阅，必须 `submitted=false`。沿用 schema 2 的开放对象，不是新增 API 参数。

`jubian_video image_generate` 显式提供 `image_style: "anime"`，批量调用则在每个 `items` 项提供；3D动漫细分风格继续完整保留在 prompt 中。剧变的生图媒介参数独立于提示词，`anime` 对应动漫，不得按真人默认值提交。回执中的 `image_style` 只是本次解析的请求选择，仍须回读远端与查看实际图像；它不证明生成质量。

自然写实 CG 的画风验收应与已确认的项目母版或随包目标参考比较，记录造型风格化程度和跨人物一致性。没有噪点、皮肤光滑或白底不能单独证明三维动漫媒介；照片般难以区分或偏离目标参考时，记为待确认，不能因参数是 `anime` 就判画风通过。

保存即将调用的 `jubian_video` 完整参数为 `request.json`，从本次加载的 Skill 目录运行：

```sh
python -B scripts/validate_generation_request.py --request request.json --records record.json
```

单条 `image_generate` 提供一份记录；`image_generate_batch` 按 `items` 顺序传入全部记录，遗漏任何一项都会失败。脚本只读、不联网、不修改 prompt 或参考、不调用模型；检查正向媒介开头和 PBR、最终文本一致性、至少一张风格参考上传成功，以及完整计划与实际有序参考 URL 一致。明确的禁止／不使用 PBR 指令不能作为正向材质要求；开头之外同样不得追加矛盾禁用要求。正向真人摄影／photorealistic 指令会失败，直接的“不要真人摄影”“not photorealistic”等排除语句不因出现这些词而失败；2D、cel shading 等用户风格词不被这项摄影检查删除或改写。这些是有限文本规则，不是自然语言或图像的完整语义审核，完整工具字段仍由现有 `jubian_video` 校验。仅退出码0且 `generation_ready=true` 才可按原样提交；Agent、persona、preset 或翻译若再次改写参数，须重新保存并检查。上传检查失败不能改为空引用重投。原有本地结构检查仍允许未生成的规划记录通过，但不代表生成已就绪。

这是 Skill 工作流的提交前条件，不是剧变 API 或全局工具拦截。摄影冲突检查要求明确的摄影媒介目标，例如 photorealistic portrait photography、photorealistic人物摄影或真人实拍；photorealistic 仅描述 CG 灯光和 PBR 材质时不据此断言真人风格。通过检查仅代表记录和候选参数符合这些条件；远端可访问性、参考隔离、实际像素及3D动漫风格仍需真实工具结果和看图验收。
