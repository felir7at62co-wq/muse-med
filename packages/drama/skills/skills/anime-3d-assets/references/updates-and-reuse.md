# 修改、版本与复用

## 三种身份

- `asset_id` 是逻辑资产身份，例如 `CHAR-001`；姓名或描述变更不重建 ID。
- `variant_id` 是同时存在的剧情版本，例如 `base`、`winter-coat`、`injured`；不是生成次数。
- `revision` 是同一变体的技术修订，例如 `r001`、`r002`；换提示词、换文件或纠错产生新修订。回退后仍从历史最大序号递增，不复用旧编号。

“新增冬装”创建变体；“把现有冬装的领口修好”创建修订；“加一个不同人物”创建逻辑资产。项目级风格另有 `style_revision`，每个生成修订记录使用的风格版本。

## 修改步骤

1. 读取原资产、当前修订和真实文件，记录修改基线；不存在时明确缺项，不臆造原设定。
2. 从用户请求提取 `preserve`、`change` 与 `scope`。存在无法同时满足的要求才提问；其余直接执行已授权修改。
3. 查找引用该修订的镜头与派生资产，形成影响列表。没有镜头清单时写“影响范围未知”，不能写“无影响”。
4. 在新修订目录保存设定、提示词和新产物，保留旧文件。用基线图或工程作为编辑输入。
5. 审核变更是否实现，也审核保留项是否漂移。候选未通过不替换当前指针；通过后按已有采用授权切换，否则等待选择。
6. 写入修改原因、父修订、采用依据和受影响引用。真正需要换用的镜头显式修改绑定；未重生的视频仍指向旧版，不声称历史视频已经自动修好。

更新前重新核对清单 `manifest_revision` 与读取基线。发生其他写入时重读并合并，不能覆盖新内容；单个流程集中写清单，避免多个执行者同时保存各自旧副本。先写完新文件和记录，再更新当前指针。

## 影响判断

| 变更 | 主要复核范围 |
|---|---|
| 描述或检索标签纠错，视觉未变 | 清单与查找结果 |
| 某服装变体修正 | 绑定该变体的镜头与相邻连续镜头 |
| 人物基础身份变化 | 派生服装、表情、身体局部参考及相关镜头 |
| 场景布局变化 | 派生日夜版、反打、人物站位与接触关系 |
| 道具尺寸或形制变化 | 持握、接触、开合、近景以及关联模型 |
| 全局风格变化 | 使用旧风格的资产和镜头，逐项评估是否需要重做 |

受影响表示需要复核，不等于全部删除或全部重生成。

## 跨集和跨项目

每次复用先按 [画风与质量规则](style-and-quality.md) 检查实际文件。仿真人资产不可直接成为 3D 动漫正式资产；只能按结构参考规则提炼信息，再制作和审核独立的 3D 派生版本。普通修改保留 `style_family=3d_anime` 及已选子风格，不能因“增强质感”切换到摄影写实。

跨集复用同一修订时扩充适用集数与场次并记录原因；发生时间跳跃或状态不符时选对应变体。`["all"]` 只用于确认全剧可用的版本，未知适用范围不能填全剧。

跨项目先检查来源与允许的使用范围，并查看实际文件。原样引用用 `source.mode=reference`，锁定来源项目、资产、变体、修订和文件摘要；修改生成用 `source.mode=derived`，在目标项目新建自己的记录。两种方式均需按目标项目风格与镜头用途审核，来源库的通过状态不直接继承。来源不明时保留候选，不标记为正式可用。

复用排序：当前项目合格精确版本 → 当前项目可改版本 → 跨项目可用版本 → 原创新建。源文件不可访问时报告缺文件，不假装根据缩略图已经取得完整资产。

## 历史资产库检索必须有界

复用检查用于减少重复制作，不是生成的无限前置任务。当前项目资产清单、用户指定的必用资产与可选历史库分别处理；远端当前项目为 0 资产不证明历史库存在，也不要求安装历史库。

1. 优先使用用户提供、项目配置或已加载工具明确返回的库入口。没有入口且必须判断本地库是否存在时，只检查一个有明确来源的默认索引／目录一次。路径不存在、索引缺失、权限拒绝或工具不可用即结束本轮可选历史库检查，记录“不可用／未检索”，继续新建设计。禁止猜测多个盘符、遍历磁盘、递归搜索用户目录、安装依赖或编写 find_library.py 等探测脚本。
2. 可用历史库对本批同类资产最多两轮检索：第一轮以时代、资产类型与场景用途精准查询；零命中才允许第二轮适当放宽关键词。只放宽检索词，不降低时代、CG 质量、身份与来源条件。第二轮无匹配、候选均不合格或查询失败即结束，不追加同义词轮询或“再确认索引”第三轮。不得按每个资产重置次数重复查同一库；不同资产类别可各自记录检索范围，不能宣称未查类别也已查完。
3. 若需调用命令，设置单次最长 30 秒的真实执行超时；工具支持超时参数时显式设置。两轮等待总计不超过 60 秒。运行任务超过限额时，仅在工具允许时取消本次查询，否则记录“仍在运行／结果未知”，不继续轮询、不重复提交查询，转做不依赖其结果的设计工作。工具不支持取消时不得谎称已取消。此限额不适用于已提交的付费图片生成任务，其去重与回查规则仍然有效。
4. 结束时在当前 workflow_01 的证据中记入口、检索词、实际轮数、返回情况和下一步。使用既有 pass/fail/not_checked：确实执行了有界检查可将该流程项记 pass，并注明仅代表复用决策完成；未查到的库仍明确写“未检索”，不是“库中没有资产”。无匹配、不可用或超时不触发正式资产采用，也不虚构搜索成功。
5. 对可选历史库已无可复用项时，将相关资产决策记 create，简短说明后继续已授权的新建、提示词和生成，不额外询问是否继续。缺少新生成授权时仍可完成设定与提示词，不能因检索失败扩大付费权限。

例外：用户明确要求“仅复用，禁止新建”，或指定必须沿用某角色身份、某场景布局但原文件不可访问时，保留 unresolved 并说明具体缺项；不能用新资产替代。当前项目清单查询失败且会影响去重或覆盖安全时，也不能套用历史库退出规则盲目提交，只继续不依赖该清单的工作。只有用户明确要求修复资产库时，才进入单独排障范围。

同一批已记录的不可用入口不再因调用其他技能而重新检测。使用其他辅助能力时同样只完成上述有限检索，不把资产库安装、修复或全盘查找自动扩展为本任务。每次有新入口、用户提供文件或权限变化时才重新评估。

## 回退

用户要求回退时核对目标历史修订及其文件，写回退事件并更新指定变体的当前指针。新修订及费用、审核和历史镜头记录保留。只有本轮明确要恢复的绑定才回退；其他已完成镜头保持原引用。

## 行为自检示例

- “只把女主外套改红”：新增原变体修订，保持身份及其他服装，旧图和旧镜头绑定保留。
- “第二集也用第一集的厨房”：先核对状态与布局，合格时引用同修订，避免重新生成。
- “把上一部女主改成新人物”：新建目标项目角色，记录派生来源，不改上一部角色或继承其正式状态。
- “恢复昨天那版”：以可确认的修订选择回退；只有日期且存在多个候选时列出差异后确定，不按文件名猜。

## 检索退出自检

- 当前项目 0 资产，默认历史索引不存在：一次存在性检查后记录历史库不可用，继续 create，不写探测脚本。
- 精准与放宽两轮均无结果：两轮后停止，不增加第三次索引确认，继续新建。
- 历史查询超时：记录未知并结束等待，不重复发起，继续独立设计。
- 命中场景但跨时代或材质低质：拒绝复用，检索预算用尽后新建，不降低标准。
- 用户要求仅复用或指定身份母版缺失：unresolved，报告缺文件，不擅自生成替代身份。
- 远端当前项目查询失败：不能据此断言 0 资产；保留去重约束，仅推进独立工作。
