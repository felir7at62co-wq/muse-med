# 3D 动漫漫剧资产

围绕同一套身份设定与风格规则维护资产。先复用已有合格资产，再补缺项；修改保留旧版本和镜头引用。默认交付资产清单、设定卡和可执行提示词；用户要求且工具可用时才继续生成图像或制作模型。写了提示词不等于已经生成资产。

默认制作标准为次世代 PBR 质感的精致风格化 3D 漫剧，人物、场景与道具统一执行，具体材质证据按画风质量规范验收。男主落实“土得干净、土得帅、有特色”，以剧本身份与时代为前提；不能仅写“高质量、下沉、PBR”就视为合格。

每次生成、编辑与验收必须读取 [图二基准与交付审查](references/reference-standard.md) 并实际查看目标图。图二的高精度 CG 造型和次世代 PBR 细节是必达标准，图一式简化卡通不得采用。人物交付固定为正面半身像加无头身体正、侧、背三视图，具体范围按该规范逐项检查。

图二只供画面风格与质量参考，禁止复制或高度复刻其五官。脸部按剧本、用户提示词、人物设定与下沉准则独立设计；同脸锁定仅用于本项目独立且通过的身份母版。身体正／侧／背三视图逐格检查，任一出现头部均拒收，按 [参考与版式审查](references/reference-standard.md) 分视图修正并复审。

新增男主图已归档为画风、质量与无头身体版式参考，必须按 [参考分工及五官差异规则](references/reference-standard.md) 实际查看。新角色和选角候选先设计独立五官组合并与可访问的已有候选对照，禁止只换种子重复同脸；同一已采用角色的换装和角度变化仍锁定本项目身份。两张正向参考均不得提供五官身份。

随包图片位于本技能的 `references/images/`：男主参考 `male-quality-layout.png`、质量基准 `target-quality.png`、女主参考 `female-quality-reference.png`。按技能返回的基目录拼接这些真实路径并读取；Markdown 相对链接以该 Markdown 所在目录解析。安装目录可能是符号链接，未跟随链接的目录搜索结果不能证明图片缺失，不扩大到用户其他文件夹寻找替代品。

## 人物生成与撞脸修复

人物交付图左侧取景：左侧人物展示须保留完整头顶、发型、面部与颈肩，正面展示；取景下边界可到胸部，也可延伸至所穿上衣／外衣下摆，胸部至下摆之间（含腰部）的自然取景均可。无需统一固定到腰部，不因合格胸像或下摆取景而重生。不得裁掉头顶，或用仅脸部特写替代。右侧无头身体正面、严格侧面、背面至完整鞋底的要求不变。

女主设计、生成或验收时，同时读取 [女主画面风格与质量参考](references/female-quality-reference.md) 并打开原图。只学习画面质量，不继承五官、服饰、发型或版式；防撞脸与同角色身份保持规则继续执行。

人物设计、独立选角或撞脸修复时，先读 [五官结构差异与身份保持](references/face-differentiation.md)。新身份先做结构对照，生成后实际比较面部；衣服、发型和行为差异不能替代五官差异。已确认身份的换装继续保持同脸。

## 首轮 CG 质量约束

每次生成前必读 [首轮 CG 提交规范](references/first-pass-cg.md)。所有人物、场景、道具和编辑提示词保留明确的3D动漫／风格化三维动画正向媒介，同时使用次世代高精度建模 CG 与物理可信 PBR 材质。内部 `3d_anime` 是路由分类，不能代替最终提示词中的动漫媒介。首轮即按正向参考质量制作，禁止先出低质草图再反复提质；最终提交文本与工具默认风格必须先对账。既有逐图验收、时代和独立五官规则继续生效，不能保证模型每次一次通过。

## 每次调用必须完整执行交付流程

调用本技能生成或编辑图片时，每张图片、每个资产修订必须逐项完成下列适用流程并保留证据，禁止跳步、只出图不验收、批量抽检代替逐图检查，或先标记完成再补审。复用图片也必须按当前要求重新核对适用项；历史通过、同名、同模型或同批次不能替代本次证据。

| 顺序 | 必须完成的流程 | 证据落点 |
|---|---|---|
| 1 | 读取剧本和当前项目，确定身份、时代、状态、资产类型、画幅与交付版式，检查现有资产和依赖；需要非默认场景比例时取得使用者明确答复或沿用已有明确要求 | script_evidence、设定卡、dependencies、generation.prompt_parts |
| 2 | 实际查看图二目标参考和适用身份母版，核对风格参考用途、可访问文件与实际提交引用；检查完整最终提示词、模型与尺寸参数、任务去重和当前生成授权 | generation.references、final_prompt、attempts |
| 3 | 提交生成并记录实际任务；未知或处理中按原任务回查，取得真实结果文件后测量尺寸并记录文件信息 | generation.attempts、files |
| 4 | 逐张打开实际文件，对照图二检查画风、PBR、下沉可读性、时代、画幅、结构及交付内容；人物检查正面半身与无头身体正侧背至鞋底，场景检查无人画面、实际参考隔离、画风匹配及正常环境状态，道具检查形制和交互尺度 | review.style_gate、review.quality_checks，各项含具体观察与文件路径 |
| 5 | 对 fail 定向修正，保留旧尝试并重新检查修改影响的全部项目；遵守既有预算和重试上限。not_checked 先补齐证据，不得当作通过 | 新修订、generation.attempts、change、更新后的实际审核记录 |
| 6 | 逐项对账本批交付清单、数量、文件、修订、依赖及审核；全部适用检查通过后才按已有授权采用并更新当前指针；需要平台确认时执行确认和真实回读 | review.checks、adoption、索引；平台集成时另记 remote |
| 7 | 交付实际可访问文件、设定与提示词、审核记录及状态，明确列出通过、失败、待生成、待审核和受影响镜头；未完成项不得藏在“全部完成”汇报中 | 本次交付清单与结果报告 |

每次调用开始在当前资产记录的 `review.checks` 中列出流程检查项，使用 `workflow_01` 至 `workflow_07` 为维度，沿用 pass/fail/not_checked 与证据结构，不另建第二套资产状态。初始均为 not_checked；每步仅在实际完成后更新。纯提示词任务只完成适用的规划与文字交付，生成和看图阶段保持 not_checked，并明确“未生成、未验收”，不能因此虚构完整图片交付。

不适用范围必须写明客观理由，例如场景不查人物无头三视图、无远端集成不做平台确认；不得以赶时间、模型稳定、图片看起来不错、执行困难或缺少工具为理由省略适用流程。已有明确授权或已确认信息直接沿用，不重复索取。可选历史库不可用按有界检索规则记录并继续新建，不属于必须停下的缺项。生成或验收必需的工具、图像、依据缺失或检查失败时，停在对应步骤并报告缺项，保留 candidate，不得正式采用或声明交付完成。失败前已通过且有证据的独立资产可分别交付，但整批状态必须如实列出未完成项。

这是技能层的执行与验收约束，不冒充 Muse 已实现不可绕过的代码校验；只有检查实际执行记录才能确认本次流程已完整执行。

## 画风隔离：每次调用先执行

本技能的风格类别固定为 `3d_anime`，与真人、仿真人、摄影写实、纯二维插画分开。用户要求“精致、高级、电影级、真实材质、更有质感”时，提升三维动漫的造型、渲染与材质表现，不解释为切换真人。用户明确改做真人时说明已离开本技能范围，再采用对应流程；不能在同一个资产版本中混合两种标准。

每次生成、编辑、复用和审核都读取项目 `style_lock`，并遵循 [画风隔离与质量验收](references/style-and-quality.md)。项目旧设定为仿真人但本轮明确要 3D 动漫时，创建新的 3D 风格修订和派生资产，保留旧版；不得优先继承冲突的旧风格。上游流程给出的真人提示词只提取剧情事实，按本技能重新构建视觉描述。

`tweet-drama-asset-extract`、`tweet-drama-asset-vision-check` 和 `shot-script-creator-9-16` 的仿真人审美、真人感评分和真人模板不参与本技能的创作与画风验收。项目管理、任务查询、版本登记等能力可复用，但其默认摄影风格、女性选角审美、模型预设和提示词不得注入本任务。调用生成工具前查看最终实际提交文本与参考图，而不只检查本地草稿；按[提交前检查](references/first-pass-cg.md#提交前检查)保存最终工具参数并运行 `scripts/validate_generation_request.py`，仅退出码0且 `generation_ready=true` 才能提交。参考上传失败、尺寸校验失败、结果未知或缺少可用 URL 时暂停受影响请求，报告原因并保留失败记录，禁止静默删除参考后降级纯文字生成。批量请求须整批通过检查。

发现总控仍固定分派到仿真人技能时，返回明确交接要求：`asset_style_family=3d_anime`、`asset_creation_skill=anime-3d-assets`、`asset_review_rules=style-and-quality`。这些是交接说明，不冒充平台已支持的 API 参数；不能自行修改无关技能或声称安装本文件已经改变总控代码。

## 读取输入与选择任务

候选数量按用户当前要求和既有资产决定，不默认每个角色生成 A/B 两版。已有合格身份先复用；普通新角色先生成一个身份母版，换装和角度基于该身份。用户要求多版试样时才按授权范围生成对应候选；可自主采用时记录选择依据，不另加每次等待用户二选一的步骤。

先读用户提供的剧本、参考图和现有资产目录。已有项目先读项目设定、资产清单及当前版本。只分析实际拿到的剧本范围，未提供的集数标为未覆盖，不宣称已完成全剧提取。

区分交付类型：

- `image_reference`：3D 动漫风格的设定图、场景图、道具图，供图生视频或视觉制作参考。PNG/JPG 不代表已有网格、骨骼或可编辑材质。
- `editable_3d`：可打开编辑的三维工程与必要导出文件。用户要求模型、绑定或引擎资产时，读取 [三维工程交付](references/editable-3d.md)。
- `both`：两类产物分别记录、分别验收，不把渲染图审核当作模型验证。

未指定时采用 `image_reference` 并说明假设。风格细分、交付画幅和关键角色参考会显著影响结果时集中询问缺项；仍可先做剧本资产提取。没有参考图也能起草原创设定，不强制用户先找图。新项目的建议参数记为待确认，不能伪称已锁定。

按任务读取：新建或补资产读 [设计与提示词](references/design-and-prompts.md)；修改、复用、回退读 [版本与复用](references/updates-and-reuse.md)；登记和交接读 [数据规则](references/data-rules.md)。模板在 [项目模板](assets/project-template.json) 与 [资产模板](assets/asset-template.json)，复制到目标项目后填写，不把具体剧目内容写回技能模板。

## 母版继承与真实核验

资产规划与成品核验共用同一修订记录：剧本和用户设定决定需要什么，已查看且通过的母版决定什么必须保持。计划、提示词和文件名不作为实际图片证据；生成受理与结构检查不作为采用依据。

场景按 [家族、色卡与受控变体](references/scene-continuity.md) 建立家族、区域、机位和环境变体。固定布局、陈设、材质、色卡与机位明确登记；天气派生只改变时间光照、天气及直接物理反馈，不新增煤油灯、门窗或家具。场景主体、陈设状态与无人参考隔离同时检查，逐图写 `scene_continuity`。只提供片段时保留覆盖范围与未知连接，不虚构完整建筑。

角色和道具按 [身份库与真实交接](references/identity-and-grounding.md) 复用审核通过的母版，固定块完整复写，变化块限定本次视角、服装或状态。多视图优先使用合格单图并逐张审核；组合板仍执行原有严格人物版式，视频参考不得无条件提交拼板。身份、风格、布局与编辑底图用途分开，并核对工具实际收到的输入。

材质和灯光按 [可观察的表面与光源](references/material-and-lighting.md) 写明部位、材料行为、固有色和真实光源，避免统一塑料反光、夜景改色及无依据发光。已完成资产向下游交接时实际查看本次文件，只描述确认可见空间和身份，镜头路线不能穿越未知或不可达区域；两种任务的 [完整案例](references/production-examples.md) 可按当前项目依据改写。

新记录或交付前从本次加载的技能目录执行 `python -B scripts/validate_asset_records.py --project-root <项目根> <本批record.json及全部依赖记录>`。按 [结构检查范围](references/data-rules.md#本地结构检查) 处理结果；脚本只读，不生成、不采用、不替代视觉审核。外部方法的来源及适用限制见 [参考资料](references/research-notes.md)，外部服务和模型流程不自动启用。

## 建立风格与身份

所有任务先按 [时代一致性与穿帮检查](references/era-consistency.md) 提取剧本时代、地域和世界观，人物、服装、道具、建筑及背景细节逐项核对；禁止跨时代穿帮。参考图只锁定其适用的画风和质感，不自动证明服化道符合剧本。男主参考的具体学习结论及同画风场景要求见 [设计与提示词](references/design-and-prompts.md)，不将参考中的脸型、姓名、伤疤、衣物或年代作为全剧通用模板。

角色、场景与道具设计必须遵守 [下沉市场视觉准则](references/market-design.md)：题材与身份易辨、情绪可读、生活环境有依据、重要角色有稳定识别点、目标画幅的小屏预览仍可用，不能因此改变资产画幅。该准则是本项目创作要求，不代表所有观众的固定偏好或市场效果保证。保留剧本年龄、性别、职业和身体差异，不用同款仙侠脸、统一刀削下颌或固定厚实体格覆盖人物。

发送给生成服务的提示词不使用第三方动画作品名、角色名或画师名充当风格捷径，也不要求第三方片名、Logo、水印。只描述可观察的造型与渲染特征；素材来源及可用范围仍须单独核对，去掉名称不等于已证明原创或取得使用权。

沿用已有项目中与 `3d_anime` 一致的权威设定；新项目才建立 `project.json`。记录 3D 风格细分、年代与世界观、人体与头身比例、五官概括程度、轮廓语言、色板、材质、着色方式、光照和需避免的视觉偏差。不要默认所有 3D 动漫都用大眼、塑料皮肤或同一种面部模板。

角色分为稳定身份和可变版本。身份固定脸型、五官比例、基础发色、物种及识别特征；服装、发型变化、年龄阶段、体型、伤病和变身记录为有剧本依据的变体。普通表情、站姿和镜头角度优先作为使用参数，不为每个动作新建角色。服装修改保持身份参考与其他已认可特征。

场景固定平面布局、门窗位置、主要动线、陈设尺度与材质，日夜、季节、损毁作为状态。道具固定形制、尺寸关系、材质及功能；开合、持握、破损记录状态。反复入画的动物、坐骑、机械主体和具有固定外观的特效单独登记，不混入背景。

场景生成、编辑、复用和验收先读 [无人场景资产与参考隔离](references/scene-assets.md)。默认交付纯环境场景单图，画面无人；生活痕迹通过陈设与维护状态表达，人物站位和动作留在镜头脚本与本地布局说明。人物母版只做本地画风对照，实际风格/布局参考必须隔离完整人形及可辨识身体局部，明确清人的待修编辑底图按该规范单独登记。逐图记录 `scene_clean_plate` 和 `scene_reference_isolation`，误入人物、人影或人物倒影不得正式采用；用户明确要求的带人物构图参考单独交付，不替换无人基础版。

场景资产按 [场景优化规范](references/design-and-prompts.md) 默认采用 16:9 横向单图，需要其他比例先询问使用者；已有明确指定或确认不重复询问。场景画风和质量须匹配已通过的人物母版。农村等生活场景默认保持正常维护与生活痕迹，禁止无依据过度破旧破烂；建筑、陈设和背景物件严格匹配时代，穿帮不得采用。

## 道具必须匹配人物场景与剧本

道具资产生成、修改和验收必须执行 [道具设计与提示词](references/design-and-prompts.md#道具设计与提示词)。画风、建模精度、PBR 材质细节与光照语言同时匹配本项目已通过的人物和场景，不能把低精度道具或产品摄影拼入。具体外形、结构、尺寸、用途、操作方式和剧情状态以剧本及时代世界观为准；未写明的外观细节标为美术选择，不得改动剧情所需功能。人物或场景基准缺失时可以先做候选，但不得声称完成跨资产匹配。

## 提取、对账、制作

1. 为需求标注剧本位置、适用集数及场次。合并别名，保留身份不同但同名的主体；歧义未解决前不自动绑定。只提取镜头必需、影响叙事或需要连续一致的资产。
2. 查当前项目清单和实际文件；接入远端平台时也查询当前项目真实资产。可选历史库按 [有界检索与退出规则](references/updates-and-reuse.md#历史资产库检索必须有界) 执行：有明确入口才检索，最多精准一次、放宽一次；缺库、无匹配或超时即记录并继续已授权新建，不猜路径、不全盘扫描、不编写探测脚本。历史库缺失不阻塞生成；当前项目去重失败、用户限定仅复用或必需母版缺失则保留 unresolved，不能擅自替代。
3. 每项给出 `reuse`、`adapt`、`create` 或 `unresolved`，说明依据。复用检查实际画面或模型、风格、剧情状态、可用视角与来源使用范围，名称匹配仅用于筛选。
4. 优先制作身份母版和场景基础版，审核后再制作依赖它们的换装、多视图及场景状态。没有已通过的身份图，不声称后续独立生成天然保持同脸。
5. 每条提示词按 [设计与提示词](references/design-and-prompts.md) 的固定顺序构建，包含完整 3D 动漫风格前缀与结尾锁定句；单条脱离聊天上下文也应明确画风。保留结构化片段和最终实际发送文本，逐条检查矛盾词、参考图用途及上游风格污染。模型、尺寸、参考文件及实际任务信息在有真实结果后记录。
6. 生成前核对已有任务和用户授权范围；服务端结果未知先查原任务，不以新任务重复提交。修正重生必须对应可观察问题，记录尝试及费用，不无限自动重试。没有可用生成工具时交付提示词与待生成清单，不虚构图像、任务或远端 ID。

## 视觉验收与正式采用

实际查看候选文件，先执行独立的 3D 动漫画风门禁，再按 [质量验收规则](references/style-and-quality.md) 检查制作质量，逐项记录 `pass`、`fail` 或 `not_checked` 以及证据。实拍人像、实拍背景或偏离图二的简化卡通直接失败；自然比例、细微皮肤纹理与细致 PBR CG 材质不单独判为真人，高清与美观不能抵消画风错误。不能看图时保持未验收。核对：

- 时代、地域、身份获取条件与世界观一致性，记录 `era_consistency`；穿帮或关键项未核实不得采用。
- 次世代 PBR 材质质量 `pbr_material_quality`、跨资产画风一致性 `cross_asset_style_consistency`、下沉可读性 `market_readability`；男主须逐项满足清爽、朴实、自然帅气与角色辨识要求。
- 角色身份、同版多视图、体型、完整服装、手足与关键轮廓，以及原设定的 3D 风格。
- 场景几何、空间关系、光照逻辑及预留可用空间；按 [场景逐图验收](references/scene-assets.md#逐图验收) 核对无人画面与实际参考输入，任一未查或失败保持候选。
- 道具结构、尺度、持握或接触点、功能状态；特效的颜色、形态与作用范围。
- 图像伪影、误入主体、意外文字、水印、裁切及参考图不该继承的背景。剧情必需文字单独核对或作为后期图层制作。

错误身份、错误状态、严重畸形、空间冲突或关键结构缺失需要修正。轻微背景色、留白与视角偏差按用途判断，不为模板整齐而反复重生。提示词、相同随机种子或相同角色名均不能替代实际一致性审核。

本地资产通过审核且满足当前采用要求后，才更新 `current_revision`。如果用户已授权自主采用，可直接采用合格版本并记录依据；没有该授权则交付候选供选择。接入有“确认出演”机制的平台时，还需平台实际确认与回读，不把本地通过写成远端正式采用。

## 修改与复用

先读取待改资产的当前修订，列出保留项、修改项及受影响集数或镜头，然后按 [版本与复用](references/updates-and-reuse.md) 生成新修订。用户已明确“只改衣服”时直接执行该范围，无需再次确认；不擅自更换脸、体型、发色、声音或全剧风格。

每个镜头锁定明确的资产修订，禁止运行时以 `latest` 静默替换。回退修改当前指针并保留历史；新候选失败时旧的可用版本继续有效。跨项目引用记录来源修订，目标项目再审核，修改时创建目标项目自己的派生资产，不反向修改源项目。

## 交付

交付可编辑的项目设定、资产登记、设定卡、提示词和审核记录；已生成的文件按修订归档。报告哪些可用、哪些待生成或待审核，以及本次变更影响的镜头。文件结构与字段按数据规则，已有工程采用其既定目录并记录映射，不强行重建项目。

技能自身的复用靠保留通用规则和模板，剧目内容只落在项目中。维护本 skill 时修改这份 `SKILL.md` 及对应参考或模板，保持字段一致；必要时增加明确的数据迁移说明，不批量改写已有项目。
