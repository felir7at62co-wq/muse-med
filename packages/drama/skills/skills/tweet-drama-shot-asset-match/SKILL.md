# 镜头正式资产匹配

镜头设计与资产选择是一个逻辑阶段。写每镜时就从当前剧变项目“主体设定”的实时父资产中确定角色服装版本、场景状态和关键道具，禁止从本地候选目录、旧分镜、历史视频或名字相似项猜图。

镜头写作与匹配使用这套原生工具，不另写按图片序号猜人的匹配脚本。资产名带项目、集号或母版版本前缀时，用 `character_name` 登记稳定的剧情人物名；同一人的多个妆造版本共用它，姐妹和不同人不得共用。

逐镜明确 `出镜人物`：名单决定入画的人类角色，台词提到的人、画外说话人不因此绑定。没有名单才从画面动作与主体追踪确定入画者。把称呼通过资产清单的 `aliases` 解析到正式角色，再按本集 `episodes` 与角色身体状态选择唯一服装版本；具体完整名优先于它内部命中的短名，不能把同一角色的多个版本一起挂上。资产匹配有歧义时列出候选父资产 ID 与状态，补明确资产名或修正登记，继续其他独立镜头；不按目录顺序猜。人物未登记时先补正式资产或更正出镜名单。右手、脚部、背影与姿态描述可沿用该角色的已登记版本，不因身体局部或动作字词单独要求新资产或新状态。

场景按本镜实际内外、动作与正式图片布局匹配，不靠同名资产认定；炕上起身用室内图，走出门后的镜头才用院外图，跨内外拆镜。`vo` 不替代原文 OS/心声与记忆音语义：最终提示词写清内心独白、不对口型或回忆中的声音，不强迫声源入画。由 Agent 组织画面与发声描述，不要求固定导演文本格式。

每包检查全部入画实体，包括反复出镜的动物；不能只检查人的名单。画面或主体追踪写「目光落在小鸡身上」「小鸡啄米」时，小鸡需要该项目当前正式动物资产和 `@[正式名](key)`，不能用场景或人物图代替。清单以 `type: "动物"` / `"animal"`，或角色行的 `subject_kind: "animal"` 明确标记动物，登记「小鸡」等 `aliases` 与实际 `episodes`；已有首集素材也要核实本集覆盖并加入本包素材名与 key。动物不填写人的孕期、年龄、服装来通过门禁，但仍须官方确认、实际父资产与素材 ID、URL；画外或纯台词提及不绑定。多个动物版本用完整资产名或明确适用集数确定唯一；漏登记先补料，不把资产名字猜成动物或拿相似图顶替。

由 Agent 编写各包完整 prompt，明确已选人物、动物、场景、道具的用途，引用采用 `@[正式名](key)`。复用稳定 key，同一人物不重复上传或复制；将完整提示词保存到 modelConfig.prompt，按引用首次出现的顺序去重组装 jubian_storyboard select_assets 的 selections，使用真实父资产、材质 ID 与 URL，并回读确认身份和顺序。旧引用写错人或沿用另一妆造的 key 时，修正提示词与选源后重新免费预览，不只修改显示名称冒充改绑。

只有明确标为 `reference_scope: "identity"` 的身份母版可以服装变化：参考本人面孔与身份，妆造、服装、动作和表情依本镜正文；仍核对年龄、孕期阶段和本人身份。专用妆造图保持默认 appearance，不因衣服相似就把姐妹或不同人物混用。同一角色有符合本镜状态的正式妆造版本时优先使用它；身份图回退不是制造或确认新资产。人物的妆造变化写在其本人身体状态段，不写到另一人物名下。


逐镜对照原文与正式资产的角色身份、年龄、孕期、服装和发型；同一角色的多个版本按实际集数和身体状态选用。身份母版仅参考本人身份，妆造与动作仍按本镜正文；专用妆造图核对对应服装。缺少适用资产时检查用户已指定的可用素材或按授权生成登记，再通过 drama_assets reconcile 核对。不得为通过检查删改原文或把母版服装强加给剧情，不要求固定身体状态行或额外编译步骤。

每个绑定至少包含正式名、类型、适用集和场、视觉提示词、数字 `jubian_asset_id/materialAssetId`、剧变 URL、`official=true` 和主体设定实时详情证据。生成资产还必须包含 `jubian_material_id`、确认时间和确认出演响应；`isLocal=1` 的主体设定直接上传资产可以没有生成 material ID，但必须属于同一 `scriptId`、`delFlag=0` 且实时父资产 URL 有效。

matched JSON 只能记录主体设定当前版本；分镜中的 `materialAssetId`、`assetId`、URL、名称/缩略图和提示词映射必须共同指向该版本。生成资产的字符串 `assetId=asset-...` 不得当作父资产查询 ID。

候选图、仅自动审核通过的生成图、缺确认响应的生成图一律拒绝。人物必须选择当前场次正确服装和阶段；场景、道具必须符合当前时空。同一镜头引用顺序必须和视频提示词中的人物映射一致。出现新旧字段混合、已删除资产或缺少核心资产时，回到主体设定重新选择或资产生成与确认出演，不得用相似图顶替。

## 绑定前集中核对

优先通过 `drama_assets match_preview` 汇总本集人物与场景复用建议，输入与状态见 [匹配预览字段](../tweet-drama-core/references/match-preview.md)。同名、缺少既有角色身份关系、服装/身体状态冲突或场景条件不足不得当作匹配成功；`blocked` 暂停受影响项，`needs_review` 集中提交人工确认。当前项目的 `missing` 不等于历史库无素材。`reuse_ready` 不批准正式采用，也不写分镜；人工确认后仍按原文与实际资产核对和 `select_assets` 实时身份/顺序回读绑定，不跳过既有门禁。

### 集中复用计划

多镜头选材按「匹配预览 → 复用建议 → 用户确认 → 模型调用原有 jubian_storyboard.select_assets」处理。先用 `drama_assets method=reuse_preview`，复用 requirements_path；有已建分镜时可传 plan_path，按稳定身份、状态及条件集中展示 groups、候选和原因。needs_review 先澄清并重做预览，missing 继续既有素材库检索，blocked 停止受影响项。输入和绑定参数见[匹配预览字段](../tweet-drama-core/references/match-preview.md#用户确认后使用现有绑定工具)。预览不审批、不写关系、不自动绑定；reuse_ready、already_bound 和 fingerprint 不是用户授权，apply_allowed=false 只表示预览本身不授予写入权限。取得覆盖具体项目、分镜和素材版本的真实用户授权后，模型可以调用原 select_assets；同一身份状态与适用范围的确认可用于已列出的多镜头，来源、状态或计划变化后重新核对。禁止 Agent 自填 approved，未授权不得绑定；继续素材身份、顺序、幂等和回读校验，声线仍走 audio_preview → audio_apply。
