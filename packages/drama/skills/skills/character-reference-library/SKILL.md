# 公共人物参考库

公共人物库提供可复核的创作参考，不提供已经确认出演的剧变资产。先用 `drama_character_reference_project` 确认当前项目和角色；Session 已在项目根目录时也可用 `drama_project action=read` 阅读圣经，不要把一次读取当作嵌套项目选择。角色身份只使用稳定 `character_id`，素材身份只使用 `catalog_asset_id`，供应商身份只使用远端返回的 ID，三者不得互换。

## 检索、看图与自主选择

为每个角色读取项目权威的 `role_class`；若尚未登记，可根据真实剧本和出场方式暂作类型判断，先进行标明不确定性的只读检索与看图，不因缺少分类就要求用户先登记。不要把角色类型写成 Catalog 素材属性。主角、配角和群演都可检索；是否值得找参考图由你根据用户目标、出场方式和跨镜头一致性决定，不要求用户判断。已有具体剧情依据时可作为 `supporting_use_reason` 记录，但它不是检索许可或素材使用授权；不要编造理由，也不要把它写回 Catalog metadata。若后来选中了本人上传的待审核图片，素材授权仍要求正式登记 `role_class`：依据剧本能明确判断时，按 `drama_project` 的 read、preview、update 流程只补该角色类型并保留其余身份和设定；真实依据不足或类型有实质歧义时再请用户决定，不把暂定检索类型冒充为权威登记。

如果 Session 已直接位于项目根目录，或工作区中只有一个经 Host 验证的有效项目，人物库可直接使用该项目。需要读取角色清单时，先用 `drama_character_reference_project action=list` 查看 Host 校验的项目，再用 `action=select` 取得唯一项目的角色 ID、名称、类型和已有项目主绑定资产 ID，不需要用户额外选择；结果不暴露本机路径。若存在多个有效项目，必须由用户在当前对话中明确指出项目名称或剧变项目 ID，再用 `action=select` 选定对应项目；不能依靠最近一次 `drama_project read`、目录顺序或角色名猜测。结合当前剧本提取角色需求，再调用 `drama_character_references` 获取有限候选。后续人类消息如果明确指名另一个项目，先重新选定。若 Session 本就在项目根目录，也可用 `drama_project action=read` 阅读圣经；该读取本身不会绑定嵌套项目。人物库工具每次都会重新读取选定圣经。检索请求只包含 `character_id`、角色描述、角色类型，以及已经明确的年代、风格和可观察特征；它不接受项目路径、本地索引路径或任意 TOS key。不要编造缺失特征。文字评分只用于初排，不代替人物面容判断。

按角色需求自主决定查看哪些候选；从同一候选结果取得 `catalog_asset_id` 和 `image_sha256`，把后者原样作为 `expected_sha256` 交给 `drama_character_reference_view` 获取实际图片内容块，不编造摘要或用后来返回的新摘要代替原选择。再根据看见的面容和角色要求选择或放弃。若选定角色已有项目主绑定资产，先把其现行主图作为同一人物的身份锚点：在工具允许时实际查看主图并比较候选的面容、脸型与年龄观感，不因职业、服装和风格相符就认作同一人。明显不是同一人时放弃该库图，沿用项目自有身份资产走无库图生成；若无法实际看到主图，说明身份一致性尚未核实，不声称候选已匹配，也不把判断转交用户。不要把文字推荐、图片文件名或未打开的预览当作已看图，也不要按分数、编号或目录顺序机械选中。文字检索返回 `no_match` 时，可把已核实的长描述拆成较短、可观察的特征再检索。若返回 `candidate_limit_reached` 且已看的前三张都不合适，依据当前项目已明确的年代、风格和可观察外观收窄条件后至多再检索一次；不要只凭前三张就宣称全库没有合适素材，也不要编造新特征。仍无可靠匹配就走无库图生成，不反复要求用户改关键词。检索报 `UNCONFIGURED` 或读取认证失败时，说明公共库此刻不可用，而不是声称库中没有合适图片；用户仍要求生图且已授权费用时，独立按项目资料走无库图生成。说明选择理由、不确定项和审核状态；不把候选列表交给用户代替 Agent 判断。

`pending_review` 可以参加推荐，但推荐结果本身仍不可发布、复用、绑定或发送给供应商。不要把它写成“已批准”“已绑定”或“可直接使用”。本人上传图的逐项目自授权是下面的单次例外，不会改变公共库审核状态。

生图成功不等于画质通过。回读实际像素后先由 Agent 自主检查清晰的身份面容、角色一致性、肢体与服装完整性、当前交付物的画幅和版式；项目已有主绑定资产时，再与其现行主图比较新图的主肖像，明显换脸即判为不合格候选。主肖像缺脸、错脸、多余肢体或未要求的拼版等明显瑕疵直接判为不合格候选，不把这类判断转交用户。若交付物明确是供后续补脸的角色设定板，主肖像面容清晰且身份一致时，正反面身形或服装视图中的空白脸只是占位，不单独判为失败，也不能当作已完成的面容参考。不要因供应商返回 `succeeded` 就宣称可交付或执行 `confirm_casting`。合格候选再交用户做最终审看；不合格图保留为可追溯记录，并说明具体瑕疵。单次授权已消费或生成结果未知时，不为补救画质而自动重用授权、重投原键或换键。
同一通道多次出现相似瑕疵时停止重复付费尝试，报告复现的请求形态和画面；没有请求体或供应商实现证据，不断言是 Host 注入固定模板还是模型忽略提示词。
若参考图生图已明确失败或回读画面不合格，而当前用户仍需要可用人物图，不围绕同一库图继续换模型碰运气。先只读核对原任务最终状态、当前项目角色、已有资产及剩余预算；只有当前用户对一笔独立的无库图生成也有明确费用授权时，才按下文回退路径从项目圣经、剧本和项目自有合格素材准备新候选。这不是原请求的重试：不要沿用已消费的图片使用授权、托管上传、参考图 URL 或幂等键，也不要把未获生产资格的库图带入新请求。原任务结果未知、费用授权未覆盖新请求或项目身份不明时停止付费并说明；合格结果仍由用户做最终审看。

## 审核与项目绑定

人物参考工具的推荐不构成审批。只有部署已经提供明确的库级审核结果和项目级使用批准，并且批准记录同时绑定同一项目、`character_id`、`catalog_asset_id`、图片 SHA-256 与当前审核指纹时，才可以继续项目绑定。跨项目、跨角色、图片摘要变化、审核指纹变化或已经拒绝、撤销的记录全部失效。不要自动批准上传后仍为 `pending_review` 的素材；缺少上述权威状态时停止该公共库素材的使用，不要因此阻断独立的无库图生图流程。

没有有效审批时不得调用 `jubian_asset upload_reference`，不得把人物库图片直接放进 `jubian_video image_generate` 或批量生图的 `references`。本人上传图走下述 Host 托管路径，不走 `upload_reference`，不从 Agent 提供 URL。公共库正式审批通过后仍只把图片作为生成参考；生成图需要单独视觉审核、`confirm_casting` 回读和正式资产登记，人物库记录本身不成为正式出演资产。

若没有外观合适且具备使用资格的公共库图片，而当前用户要求制作人物图，就按当前项目圣经、剧本和已有项目自有资产继续生成，不把 `pending_review` 候选或它的 URL 混入提示词和 `references`。已有正式图可以作为身份参考，但除非用户明确要求替换该资产，不要填写 `parent_asset_id`，以免把新候选重生到旧资产下。创建新候选前先只读核对项目内已有资产名；同名已存在时给候选取能对应当前角色、但在该项目内唯一的名称，不为规避未知结果而改名重投。先区分人物设定板与成片镜头：成片按项目圣经或配置的画幅；设定板按明确的角色资产规格，若该规格待确认，可根据实时目录和已验证的同风格设定板方案选择画幅（例如 16:9），并说明它不是成片画幅。不能把成片竖屏自动套给设定板，也不能沿用上一项目比例或目录默认值。先核对当前用户的付费授权、预算和已有任务；未授权时先询问，不借用旧用户的许可。提交一次带固定幂等键的 `jubian_video method=image_generate`，结果未知时只对账原请求，不换键重投。若受理回执缺任务或资产 ID，同名旧资产及其图片不能证明本次出图；若请求明确携带 `parent_asset_id`，只读核对该原资产的新任务与新材质，旧的 Active 材质也不是本次结果。无法证明就停止并如实报告。回读已确认属于本次请求的生成图并交由用户审看；视觉验收前不执行 `confirm_casting`。这条回退是创作路径，不会提高任何公共库素材的审核或复用资格。

### 本人上传图的逐项目自授权

若用户本人委托生成并亲自上传了仍为 `pending_review` 的图、并要求用它辅助当前项目生图，先实际看图确认原图身份。调用 `jubian_character_reference_authorize`，仅提交当前 Host 项目 ID、登记角色 ID、精确 Catalog ID 和看图返回的完整 SHA；Host 会向当前 Muse 用户直接展示项目、角色、Catalog、SHA、来源与权利问题。Agent 的代答、聊天推断或素材 metadata 都不能代替用户在界面的确认。拒绝或无界面时停止该图的上传，可继续独立的无库图生图路径。

用户确认后，授权只绑定当前会话、项目、角色、原图 SHA，并只允许一次托管上传和一次项目内参考生图。按工具返回的 `authorization_id` 与版本调用 `jubian_asset method=upload_character_reference`；随后仅将返回的 `managed_reference_id` 与同一授权身份交给一次 `jubian_video method=image_generate`。托管生图可省略 `asset_name`，Host 以已核验的角色名称为准，并为新候选追加唯一后缀；不要自行添加“参考”或编号，前文无库图回退的自定义候选名规则不适用于这里。生图前重新读取当前项目风格、成片画幅和角色资产规格；不要把成片的 9:16 直接强加于设定板。若角色资产规格待确认，可经实时目录核价后选用角色设定板方案：清晰的身份肖像与同一人的正面、侧面、背面身形或服装视图；需后续补脸时，次要视图可保留空白脸占位，但主肖像必须有清晰面容。若交付物是单画面全身人物图，则使用面容可见的单画面，不自动拼版。未要求拼版时也明确单画面，排除多视图拼接、文字和空白面罩。不传本机路径、TOS key、对象 key、URL、`references` 或 `parent_asset_id`。付费预算仍需单独核对；结果未知只对账原幂等键，不换键重投。衍生图需用户另行审看，不能自动 `confirm_casting`、正式绑定、发布、他人或跨项目复用。原图保持 `pending_review`。

### 隔离 QA 单次例外

`pending_review` 在生产规则下仍不可发布、复用、正式绑定或作为生产参考。只有运行中的 Host 已经提供隔离 QA 专用的一次性授权，而且该记录精确绑定当前项目、`character_id`、`role_class`、`catalog_asset_id`、原图 SHA-256 和审核版本时，Agent 才能在该记录的范围内进行一次技术验证。聊天确认、推荐结果或 Agent 判断不能创建、批准、撤销或扩大这项授权。

先调用 `jubian_asset method=upload_character_reference`，提交 Host 授权要求的 `authorization_id`、`authorization_version`、当前项目 `script_id`、`character_id`、`catalog_asset_id`、`image_sha256` 和固定的 `idempotency_key`。不得提交本机路径、TOS key、对象 key、URL，也不得改用 `upload_reference`。Host 返回 `managed_reference_id` 后，只能把它连同相同的授权、项目、角色、Catalog 和 SHA 身份交给一次 `jubian_video method=image_generate`；不要传 `references` 或 `parent_asset_id`，不要跨项目或跨角色复用，不要自动重试或更换幂等键。结果未知时只按原幂等键对账，不得调用 `confirm_casting`，不得正式绑定或发布。

这项例外只产生隔离 QA 证据。素材仍为 `pending_review`，生产发布、复用与绑定资格保持关闭；生成结果也不构成生产素材审批。

## 只读范围

当前人物库只提供检索与看图，不提供入库、审核或项目绑定工具。人物匹配任务不以入库为前置。用户要求新增素材时如实说明当前能力，不声称已经写入 TOS，也不把本地草稿或测试数据描述成云端素材。

## 安全边界

人物库工具不得删除、移动、复制或公开分享云端对象，不生成签名 URL。搜索、预览和推荐不调用付费供应商。剧变上传与生图沿用现有预算、幂等、实时目录和未知结果门禁；审批不能替代这些门禁。
