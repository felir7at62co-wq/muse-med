# 剧情选曲与切点

用于给已生成的完整视频配乐。目标是支持当前剧情和观众的感受，同时保持对白清楚；场景数、镜头数不决定曲数。

## 从剧情确定音乐意图

先读原剧本、项目圣经和用户配乐反馈，再核对当前采用视频的实际时间线、原声与台词。剧本表达和生成内容有差异时明确标出，不靠音乐掩盖剧情错误。剧情时间由采用视频的实际内容定位，不能把剧本估时当作成片切点。

按情节转折划出有意义的段落，先通读整集再安排整条配乐序列。记录正文起止、人物关系、当前发生的事、观众此刻知道什么、前后情绪变化、关键对白原文及其真实含义、音乐作用、希望和避免的气质、对白密度及原声已有音乐。反讽、掩饰、误会和口是心非按上下文理解；台词说“英雄”不代表胜利，提到“死”不代表悲伤。对白原文保持不变，解释另存 `dialogue_context`。可以留在现有计划内，不另加报告或批准门禁。

音乐跟随剧情含义和表演强度。人物说“我要打你”但尚未动手，不自动选择打斗热血；玩笑、假哭和反讽不按孤立字词选择悲情；克制的家庭争执不因冲突就选史诗宣传。悬念尚未揭开时，不提前用团圆或胜利的音乐泄露答案。揭示、和解和拥抱可以共用一条音乐的合适发展段，不能每个镜头都重新起曲。

时代、题材和人物关系约束配乐气质，但不要求所有古装只能用古乐。不得由曲名、扩展名、情绪标签或较低能量推断“纯器乐”“无鼓”“适合对白”或“时代已匹配”；这些需核对实际音频。用户认可的曲目与混音优先沿用，Agent 不能把自己的新判断写成用户意见。

## 先建立可回读的依据

每次生产选曲先读取当前项目对应集、对应段的剧本，再查看当前实际采用视频的关键画面及转折前后；已有画面检查记录只有在视频 SHA-256 一致时才可复用。以实际采用视频和对白时间线确定段落，不凭记忆补剧情、不把场景名当情绪、不引用另集对白。剧本和视频有差异时分别记录事实，先保留原声并说明差异，不能改写剧情迁就音乐。

向 `bgm_match.story.evidence` 传入 `script` 与 `visual_review` 两类项目内依据，每条包含 `kind`、`file`、`quotes`。script 引用本段真实对白及动作原文；无对白场景引用动作描写，不依赖说话人/括注解析。现成转写可额外用 transcript，但不能代替剧本。quotes 必须复制真实原文；解释、潜台词和音乐作用另写 intent，禁止把解释伪装成对白。

visual_review 为实际观察后保存的 JSON，最少包含 `video`（实际采用视频的项目相对或绝对路径）、`video_sha256`（真实文件 SHA-256）和 `observations`（实际看到的动作、表情、关系、转折与时间位置）。引用其中真实观察文字。工具逐次读取文件、匹配原文并流式核对视频摘要；视频换版时重新看画面，不能只改摘要沿用旧观察。记录可以放在项目已有 qa 目录，不要求人工审批；工具只核验文字来源和视频版本，不能据此声称已自动验证画面理解或听感。

生产预设要求上述两类依据。缺依据返回 needs_source_evidence；对白/动作引用找不到或视频已换版返回 needs_source_correction，并列出真实缺项，不给正式选曲候选。按返回路径修正本段依据后重查，不删掉依据退回纯情绪查询绕过核验。无 story 的查询只作 reference_only 曲库浏览。出处对上后仍需核对观众视角和音乐用途；evidence_matched 不等于剧情或听感验收通过。

角色笑、调侃或自我得意不等于观众应当觉得喜剧。砸物、推搡受害者、受害者担心生活、随后被长辈严厉制止，不能概括成轻松买卖或市井抬杠；音乐应支持实际冲突、受害者处境和训斥的变化，也不自动升级为英雄凯旋或史诗战斗。家庭人物出场不自动选温情，进山/夜景不自动选日常/悬疑。需要反讽喜剧时必须有本段真实叙事和画面依据。

单曲覆盖整集是正常方案。音乐作用和情绪需求保持一致时，可一次检索覆盖多个连续场景；只有实际剧情需要才换曲，不因换场景、镜头或分析分段强制换曲。即使分段核对，同一曲确实适合各段也可继续沿用，连续区间优先合并，避免反复重起同一首。情绪或人物关系不同且音乐作用随之变化的段落分别调用一次 match，不能把多场戏或多集压进一个 intent 得到一组曲目后直接套用。按实际对白和动作落点安排音乐进入、变化和退出，避免提前提示和解、胜利、悲剧或反转。先满足本段事实与画面，再考虑同集衔接、相邻集不重复和曲库多样性。

## 检索候选

每个需要音乐的情绪段分别传 `story.intent`、`desired_tags`、`avoid_tags`、`dialogue_density` 和适当的 valence/arousal 目标。希望标签按剧情重要性从高到低排列，例如亲情为主、温柔为辅用 `family` 在 `gentle` 之前；同类证据依此比较，避免“舒缓”抢走“亲情”的优先级。标签使用当前工具 schema 的枚举；`context_tags` 仍是读取本项目用户反馈的场景标签，两者用途不同。以下为亲情揭示后的一次检索示例，项目路径、标签和坐标须按实际情节替换：

相接的配乐段检索时传 `previous_track_id`，使用上一段实际选定的曲库 `track_id` 或本地音频 SHA-256。工具从同一曲库读取真实测量和标签；返回 `continuity_reference` 与各候选 `continuity_fit`，不手填上一曲的情绪向量。缺失曲目或标签表示证据不足，不能写成已通过衔接检查。默认情绪距离为 V/A 绝对差之和，上限 3；标签集合交并比下限 0.2，可由部署配置调整。这些是异常提示，不是创作适配分数或门禁。

```json
{
  "method": "match",
  "project": "<绝对项目路径>",
  "context_tags": ["家庭", "和解"],
  "valence": 5,
  "arousal": 3,
  "intended_use": "unknown",
  "story": {
    "intent": "母亲说出牺牲后，母女从误解转为克制的理解，不把场面放大为英雄凯旋",
    "desired_tags": ["family", "gentle"],
    "avoid_tags": ["epic", "comedy"],
    "dialogue_density": "dense"
  }
}
```

上面的示例仅展示意图字段；生产调用还须填写当前项目的真实 evidence，不能照抄示例台词或省略依据。先核对 `story_request` 是否符合这段剧情，再比较候选的 `story_fit`、原始情绪测量和许可。有 `audio_profile` 时先看音频推断与实际采样时间窗，再看曲名和宽泛 moods；`supported` 表示有候选证据，不表示听感合格。音频/曲名/情绪证据分别列出，`missing_tags`、`unknowns`、`audio_conflicts` 和 `mood_conflicts` 保留未解决点；高情绪距离仍需解释，不能因标签合适就忽略能量过强或情绪相反。`human_reviewed=false` 明确表示未人工试听，原始 similarity 不能改成适配百分比；配器和人声只是模型候选。抽样未覆盖的源曲片段仍须检查，不能把采样窗直接当成已认可的乐句切点。

`review_candidates` 保留曲名与避免意图冲突的候选；`withheld_candidates` 保留本语境下用户明确否决的候选。不得为了用排名第一而改写剧情意图、删掉避免标签或覆盖用户否决。缺少积极证据时先保留原声或留白；若真实试听支持，也可说明依据采用未确认候选。库里没有合适曲目就说明缺口，不凭空编造曲名、音乐属性或适配分数。

## 相邻两集避免重复

为第 N 集选曲前，读取本项目第 N−1 集及已经制作的第 N+1 集的实际配乐计划或摘要绑定的合成记录，收集整集使用过的 `track_id`／`source_sha256`，传给 `bgm_match.adjacent_episode_track_ids`。它与同一集上一段的 `previous_track_id` 分开使用：前者优先避免跨集重复，后者保持本集音乐衔接。曲名变化、复制文件或另取同曲片段都不等于换了一首；优先按稳定 ID／音频摘要判断。相隔集数更多的复用不按本条处理。

先保证剧情、对白含义与本集前后音乐衔接，再优先选择相邻集未用且情绪合适的候选。工具在这些条件下给相邻集已用曲增加透明的排序惩罚，原始情绪距离保持不变；只有旧曲适合时仍可选择，不能为了换曲改成不合剧情的音乐、提前泄露反转或强塞额外曲目。跨集连续场景、明确主题回扣或缺少合适替代时，可以复用，在现有选曲 `reason` 记录实际依据，不另加审批。

计划按项目既有分集目录保存，同一批计划放在工具可核对的计划目录；`drama_bgm preview` 的 R7 会提醒编号相邻两集的重复曲目。邻集尚未制作或明确 `music_decision: "none"` 属于正常情况；已有邻集但找不到记录时说明未核对，不能声称已确认无重复。R7 是复核建议，不要求提示清零，也不禁止剧情需要的连续配乐。

## 选择真实片段并安排进出

仅下载准备使用的实际 track_id，沿用返回的许可和 SHA-256。预选时检查真实源曲的开头、拟用段和尾部，确认人声、配器、密度、能量变化和可用长度；整曲平均情绪不代表选定的十几秒都合适。没有播放能力时如实写“待试听”，不得将元数据检查写成听过。`human_reviewed=false` 是标签的证据属性，不是禁止自动选曲的条件；Agent 按剧情和已有音频证据完成候选选择、合成与参数核验，保留听感不确定项，不把全部选曲工作交回用户。

在 `drama_bgm` 计划中记录正文 `start_seconds/end_seconds`、真实源曲 `source_start_seconds`、选曲理由，并复制候选实测 `valence/arousal` 和实际 `tags`；用 `story_context` 记录情节发展和观众感受，`dialogue_context` 记录对白含义。不能编造缺失的测量或标签。起播点按真实音频的自然乐句选取；自动 onset 只检测起音，不等于识别高潮、节拍或合适乐句。相接段落各需预留 `crossfade_seconds/2` 的额外源曲长度，`crossfade_seconds` 必须大于 0；不能用 0 绕过片长不足。曲长不足时换片段、合理缩短覆盖，或显式 `music` 留出真实原声间隔；不挪动剧情转折，不默认任意循环自然。

连续的关系和情绪发展优先沿用同一曲的合适片段；确实需要换曲时，同时核对上一段、本段和下一段，避免逐段贪心选到整条序列忽强忽弱。先满足本段剧情和对白含义，再在合适候选中优先选择情绪、标签、配器、速度及响度相近者。`drama_bgm preview` 的 R6 提醒相接段落的情绪或标签跳变。真实揭示、危机爆发等明确转折允许较大变化，在 `transition_reason` 写出实际剧情和发生时刻，并检查衔接两侧的真实音频；理由不会清除异常提示。延长淡化不能修复选错音乐，必要时保留原声或留白，禁止为了平滑而改变剧情情绪或提前泄露反转。

例如 0–22 秒争执对白密集、22–38 秒读信但牺牲尚未揭示、38 秒才说出真相、54–60 秒拥抱：若前 38 秒原声已含合适悬念音乐，可以不新增该段音乐；亲情候选在真实揭示附近进入，延续到拥抱，不能从读信一开始就提示团圆。38 秒只是该示例，实际以台词和镜头落点为准。转折处可先留一瞬原声，不能为“卡点”截断关键台词或提前变化人物情绪。

计划明确 `music_decision: "music"` 时可留空白区间；整集不加音乐用 `none`，不制作假静音 BGM。先预览合成计划，再使用其真实输出，不把选曲记录里尚未支持的字段直接塞进合成工具。

工具使用部署传入的 FFmpeg/ffprobe 绝对路径，不要求它们同时出现在系统 PATH。若 `drama_bgm` 调用报找不到命令，核对真实错误及 `DSH_FFMPEG_PATH`、`DSH_FFPROBE_PATH` 配置；不能仅因 shell 查不到 `ffmpeg` 就跳过工具，也不悄悄改用手写 FFmpeg 后声称有正式合成记录。

## 相对源音乐的音量

Muse 自动配乐以每首源音乐的实际采用片段为基准，最终后加 BGM 至少衰减 10 dB。当前创作部署的 `drama_bgm` 设置 `maxSourceGainDb: -10`，工具返回的逐段 `applied_gain_db` 必须 ≤ −10（这是输出证据，不手写到计划中伪造增益）；归一化不能先提升源曲。最终混音及原生剪映草稿的后续 BGM 增益均封顶 1，对白闪避只可继续衰减。总变化为 `applied_gain_db + 20*log10(后续线性增益)`，增益 0 表示静音；例如 −10 dB 后再乘 0.24，约为 −22.4 dB，而不是“在当前混音再减 10 dB”。对白和原声增益单独处理。

使用本次配置重新合成的新 BGM，并在 `audio_preview` 传入对应 `bgm_generation`，核对摘要绑定的源曲增益与实际 `music_gain`。旧的已增益音乐床、直接传原曲、外部编辑器再次增益均不能据此认定满足源曲衰减要求；需要复用时先核实来源和总增益，不覆盖已认可版本。`music_stem` 已含混音/闪避增益，再导入草稿时用增益 1，不重复处理。参数与实际音频测量核对后，仍需检查对白是否清楚以及音乐是否过轻或过强；不因满足衰减数值就声称听感合格。

## 核对成片中的效果

沿用主技能的 `audio_preview` 和正式渲染流程，在对白最密处、揭示/反转前后、音乐进入退出及最终收尾比较 `selected_mix` 与 `without_added_music`。已有原声含配乐时重点听双曲叠加；情绪不合适不能只靠调小音量解决。只修改实际有问题的源曲片段或混音，保留已认可候选和用户决定。

音频分析、候选排名和参数预览不能代替听感。没有实际试听或用户确认时，在交付说明中保留未确认项；有低信心问题时集中一次给出真实可播放对比。复用已有素材，不为选曲购买新视频，不强迫用户逐首审批，也不新增配乐门禁。
