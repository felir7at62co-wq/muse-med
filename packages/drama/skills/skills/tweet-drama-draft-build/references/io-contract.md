# Draft build I/O contract

Input:

- The validated `path` returned by `drama_draft_dir`, passed as `drafts_dir`. Read Settings before draft creation; ask for the installed editor root only when missing or invalid, save through the tool, and use its readback. Existing draft names refuse replacement; choose a unique prefix for a new candidate.
- Ordered reviewed Jubian videos with subtitle_cleanup=clean or not_required; pending requires explicit draft=True and an unfinished-preview label.
- Shot/task source mapping, original spoken text, speech_type and speaker identity: dialogue, vo, os, 心声, 旁白 and 解说 are retained when actually voiced. Actions and unvoiced descriptions are not subtitles.
- Complete actual_speech_start/end audio evidence for every final spoken cue. Only explicit drafts may use marked 9-effective-characters-per-second estimates.
- Project root and an approved per-episode music-only BGM bed containing the selected emotion-matched tracks; keep the segment selection and listening record with the project. A dialogue+BGM review mix is a listening artifact, not the editable BGM track.
- One timeline per episode supplied through the request's `timeline` path, with `clips: [{shot: 1, start_us: 0, duration_us: 10080000}]` and optional `body_end` in seconds, matching the document written by `drama_render prepare`. Clips must cover a continuous body timeline; derive `body_end` from the last clip end, not MP4/AAC container duration. A discrepancy within the existing 0.2 s tolerance is normalized to clip microseconds with a warning, without editing the input file. An explicitly included two-second ending remains distinct. Match the measured main audio within 0.2 s. Missing or invalid clips fail; there is no deliverable based on default shot durations. The `delivery` snapshot contains optional `visual_medium: "animation_3d" | "photorealistic"`, positive safe even integer `width`/`height`, and integer `fps` from 1 to 240. It determines the draft canvas and frame rate. Legacy `canvas: {width: 2560, height: 1440}` remains supported but must agree with snapshot dimensions. Without a snapshot, the default remains 1440×2560 at 60 fps. Source dimensions remain unchanged; ordinary segments keep unit scale.
- `project_bible.visual_medium` and the timeline snapshot select the [shared delivery policy](../../tweet-drama-background-render/SKILL.md#媒介与交付策略). Either explicit value may supply the choice; conflicting values require prepare again, invalid values fail, and missing values retain the legacy ending and AI mark with a warning. Free-text style and aspect ratio never select the medium.
- `animation_3d` drafts contain only the body: no generated watermark, ending image, ending audio/effect, or ending-tail evidence. Selected ending asset arguments and stale `06_ending` contents are ignored, including missing files. A `body_end` outside the clip-end tolerance is rejected; prepare body-only sources again. Existing source marks are not removed.
- `photorealistic` and legacy projects append a two-second ending. If the last input clip already contains the ending, retain the original `body_end`: it must be exactly two seconds before the last clip's end. The draft replaces those two seconds with an editable image clip without lengthening the programme or adding ending sound again. Do not identify an existing ending by filename, audio length, or a static scene alone.
- For photorealistic and legacy projects, optional selected ending files, shared with the final render, supplied as absolute `ending_audio` and `ending_effect` paths in the request. They occupy separate tracks from `body_end`, at normal speed, trimmed to two seconds. Ending audio remains separate from BGM and must not also start at zero. The effect uses screen blending. No ending audio is added when the input's full-length main audio already covers an explicitly included ending.
- A subtitle file with separately aligned cues that follow the shared text rules (one line, at most 14 effective characters). The draft path removes punctuation and writes `<draft>/<episode>.normalized.srt` without changing cue times. Long cues and other quality findings return review warnings while preserving the candidate; split the line plan and rerun recognition alignment instead of distributing time by character count. The burned delivery follows the same text rules.

Project draft typography:

- Save `project_bible.delivery.draft_style` through `drama_project` preview/update, then prepare the timeline. For example, `{"watermark":{"font_size_ui":7},"subtitle":{"font_family":"山海经","font_size_ui":11,"border_width_ui":20,"transform_y":-0.465625}}`. A saved `timeline.delivery.draft_style` wins as a whole, including `{}`; only an absent section inherits the project. Omitted fields keep the old draft defaults: watermark UI 6, subtitle UI 11, black border UI 20, vertical position -0.465625 and the editor's system font. Font sizes are finite and positive through 100, border width is 0–100, and vertical position is -1–1. These units are not `delivery.subtitle` render pixels; draft choices do not change the formal MP4 style. Animation still omits watermark and ending tracks.
- A requested font name is trimmed, nonempty, at most 128 characters and contains no controls. Exact free-resource matches write the library reference with an availability/license review warning; metadata is not proof the font is installed or commercially licensed. Unsupported or membership resources use a visible system-font fallback without downloading, purchasing or blocking the draft. The editor owns the actual default family. `muse-review.json` records resolved UI values, requested/resolved font and fallback/reference status. Preview both editor and MP4 before claiming matching appearance.
- The optional ending overlay video is explicitly muted, independently of the selected ending sound. It remains an editable screen-blended video, not a native parameterized Jianying effect; its duration still follows the selected source and existing ending policy. A nonzero or unspecified effect volume is a review warning, not evidence the source has audible audio.

Output:

- Editable draft with body video clips. Photorealistic and legacy drafts also contain a separate two-second tail-frame image clip and an independent lower-right white text track reading exactly `内容由AI生成` for the entire programme including the ending; 3D animation contains neither. No top-right notice is added; the AI notice is not a speech subtitle and does not enter the SRT.
- After the independent dialogue segment is successfully added, body video segments have zero audio volume to avoid replaying embedded dialogue. Track checks report each body video's nonzero or unspecified volume alongside an independent main-audio segment as a possible duplicate-dialogue warning; the candidate and separate dialogue track remain available. An unspecified volume does not prove audible playback, and this check does not analyze the samples. If main-audio import fails, body videos retain their original volume with the missing-main-track review warning, not a duplicate-dialogue finding. The independent main audio and music-only BGM use explicit `project_config.json.project_bible.delivery.audio.master_gain` / `bgm_gain` when selected. A timeline `delivery.audio` section, including `{}`, wins as a whole; only an absent section inherits the project section. Missing fields keep the SDK's old unit gains, not the formal renderer's deployment defaults. Both gains must be finite linear values from 0 through 8, including zero to mute; set both to match the formal candidate. Ending audio gain is unchanged.
- When the editor library reports a video shorter than its timeline interval by at most 0.2 s, a separate verified last-frame image fills that small body gap. Shot starts, dialogue and SRT clocks remain unchanged; videos keep unit speed and source files are not rewritten. Larger gaps or failed frame verification retain the existing video with a review warning instead of automatic padding. `body-tail-evidence.json` records each generated hold's shot, source and image hashes, decoded-frame hash and timing. These short body holds also apply to 3D animation; they are not the optional two-second ending and do not add an AI notice.
- For photorealistic and legacy drafts, `Resources/last_video_tail_frame.png` and `ending-evidence.json` record the selected source interval, source/image SHA-256, last decoded RGB frame MD5, body end, total duration, and whether an input ending was already included. The image must match the last decoded frame of the interval actually placed in the draft; a same-numbered storyboard PNG cannot substitute for it.
- Ordered media manifest, SRT, preview MP4 and warnings.
- Subtitle cues only for actual spoken content, preserving original text and speaker.
- No additional transitions or effects beyond an explicitly selected ending effect.

Generation duration and resolution follow the current selected model and project, not fixed historical shot limits. Export dimensions are separate from source resolution and paid enhancement. See the two skills' SKILL.md files for review requirements and delivery styling.

## Desktop request

Write one JSON request with absolute file paths, then call `jianying_draft` with its `request_file` and the existing `drafts_dir` returned by `drama_draft_dir`. The request contains `project`, positive integer `episode`, a unique `name_prefix`, `audio` (full clean dialogue without mixed BGM), `videos` (selected clips in shot order), `subtitle_srt`, and `timeline` (the renderer's episode timeline). Optional `bgm` is the selected music-only bed; declare `bgm_role: "music_only"`. A declared `"dialogue_music_mix"` is not added as a separate BGM track; the draft is retained with a warning to select pure music. An omitted or `"unknown"` role remains backward-compatible with a warning, not acoustic proof of music-only content. `ending_audio` and `ending_effect` follow the same delivery policy. Only the named episode is generated. Retained inputs live under the project's `editing/draft-materials/`; keep them because the editable draft references them.

The Desktop calls its packaged Python directly. A successful result lists saved drafts, upstream library version and `editor_open_verified: false`; it confirms saved JSON readback, not native-editor opening or arbitrary-version compatibility. Existing drafts are never overwritten. Each request selects one episode; submit a separate request for another episode and preserve successful results when a later request fails.

When source video contains visible dialogue, use the renderer's `subtitle_overlay` decision with the actual sources and aligned SRT. Pass its `resolved_srt` as `subtitle_srt` and its `decision_report` as optional `subtitle_overlay_report`. The request validates episode, resolved subtitle hash and the selected videos against that report, retains the report beside the draft's material inputs, and copies its warnings and editability scope into the saved review and tool result. These fields are caller-declared evidence, not an OCR or native-editor attestation. Embedded source text stays non-editable and its size, punctuation and position cannot be changed with subtitle-track styling. Uncertain visual recognition is a review warning, not permission for paid erasure.

When every original cue is explicitly retained in source pixels, a source-bound report with zero overlay cues permits a blank resolved SRT for that episode only; the original SRT hash and cue count must still match. The draft adds no empty subtitle track and reports the non-editable retained text. Without that complete report, blank or unparseable SRT input remains invalid.

For a full-window ending effect, the shared timeline can declare `ending_effect_fit: "stretch_to_window"`. The complete selected effect plays once at measured source duration divided by the two-second target duration; ending audio keeps normal speed and the independent freeze remains two seconds. The ending evidence records the measured source duration, target duration and speed. Without this field the existing `source_once` treatment remains unchanged; 3D animation still adds no ending.
