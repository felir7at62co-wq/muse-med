# Draft build I/O contract

Input:

- The validated `path` returned by `drama_draft_dir`, passed as `drafts_dir`. Read Settings before draft creation; ask for the installed editor root only when missing or invalid, save through the tool, and use its readback. Existing draft names refuse replacement; choose a unique prefix for a new candidate.
- Ordered reviewed Jubian videos with subtitle_cleanup=clean or not_required; pending requires explicit draft=True and an unfinished-preview label.
- Shot/task source mapping, original spoken text, speech_type and speaker identity: dialogue, vo, os, 心声, 旁白 and 解说 are retained when actually voiced. Actions and unvoiced descriptions are not subtitles.
- Complete actual_speech_start/end audio evidence for every final spoken cue. Only explicit drafts may use marked 9-effective-characters-per-second estimates.
- Project root and an approved per-episode music-only BGM bed containing the selected emotion-matched tracks; keep the segment selection and listening record with the project. A dialogue+BGM review mix is a listening artifact, not the editable BGM track.
- One timeline per episode supplied through the request's `timeline` path, with `clips: [{shot: 1, start_us: 0, duration_us: 10080000}]` and optional `body_end` in seconds, matching the document written by `drama_render prepare`. Clips must cover a continuous body timeline; derive `body_end` from the last clip end, not MP4/AAC container duration. A discrepancy within the existing 0.2 s tolerance is normalized to clip microseconds with a warning, without editing the input file. An explicitly included two-second ending remains distinct. Independent-audio requests match the measured main audio within 0.2 s. Missing or invalid clips fail; there is no deliverable based on default shot durations. The `delivery` snapshot contains optional `visual_medium: "animation_3d" | "photorealistic"`, positive safe even integer `width`/`height`, and integer `fps` from 1 to 240. The independent-audio generator sets these canvas and frame-rate values; legacy `canvas: {width: 2560, height: 1440}` must agree with snapshot dimensions, and an absent snapshot retains 1440×2560 at 60 fps. Windows embedded mode resolves exact dimensions to a supported named ratio, including `16:9` and `9:16`; unsupported custom ratios fail before creation. It sets the ratio through the installed CLI and applies exact geometry only when that CLI exposes the relevant flags; unsupported width, height or fps returns a warning requiring editor verification. Source files remain unchanged. Windows native placement maps shared cumulative body boundaries to the fixed 30 fps project grid, keeps adjacent segments continuous and maps shot-local subtitle times through the actual native shot offset without stretching speech. `timeline_timing` records original/saved intervals and the maximum endpoint difference; `timeline_times_preserved` is false for any difference. The original timeline and SRT remain intact.
- `project_bible.visual_medium` and the timeline snapshot select the [shared delivery policy](../../tweet-drama-background-render/SKILL.md#媒介与交付策略). Either explicit value may supply the choice; conflicting values require prepare again, invalid values fail, and missing values retain the legacy ending and AI mark with a warning. Free-text style and aspect ratio never select the medium.
- Independent-audio `animation_3d` drafts contain only the body: no generated watermark, ending image, ending audio/effect, or ending-tail evidence. Selected ending asset arguments and stale `06_ending` contents are ignored, including missing files. A `body_end` outside the clip-end tolerance is rejected; prepare body-only sources again. Existing source marks are not removed.
- Windows embedded mode appends a two-second ending only for `9:16`, including animation projects; `16:9` and other supported ratios have no ending and ignore ending asset arguments without loading them. Watermark selection still follows the medium. Independent-audio `photorealistic` and legacy projects append a two-second ending. Windows embedded mode requires body-only selections and rejects an already included ending. For independent-audio requests, if the last input clip already contains the ending, retain the original `body_end`: it must be exactly two seconds before the last clip's end. The draft replaces those two seconds with an editable image clip without lengthening the programme or adding ending sound again. Do not identify an existing ending by filename, audio length, or a static scene alone.
- When the selected mode and ratio require an ending, optional selected ending files, shared with the final render, supplied as absolute `ending_audio` and `ending_effect` paths in the request. They occupy separate tracks from `body_end`, at normal speed, trimmed to two seconds. Ending audio remains separate from BGM and must not also start at zero. The effect uses screen blending. No ending audio is added when the input's full-length main audio already covers an explicitly included ending.
- A subtitle file with separately aligned cues that follow the shared text guidance (one line, preferably at most 14 effective characters). The independent-audio path removes punctuation and writes `<draft>/<episode>.normalized.srt` without changing cue times. Windows embedded mode preserves the supplied corrected SRT file and text. Its current native project-create API uses a 30 fps timeline without a frame-rate setter, so the adapter rounds measured start and end boundaries separately to their nearest native frames. Readback verifies those placements and reports every original/saved span and the maximum endpoint difference; `subtitle_times_preserved` is false when any boundary differs. Prepare display text before the request. Long cues and other quality findings return review warnings while preserving the candidate. Split display lines at existing measured word boundaries and reuse the matching cloud evidence for placement; do not submit recognition again solely for a split or spelling correction, or distribute time by character count. Without a measured split, preserve the longer candidate and record the timing gap. The burned delivery follows the same text guidance; see [cloud subtitle guidance](cloud-subtitles.md).

Project draft typography:

- Windows embedded `16:9` uses editor font size `7`, `X=0`, and `Y=-879` in Jianying; the adapter reads the actual canvas height before converting the requested editor Y to an internal position. These two values override older saved project typography and position for this ratio. A deployment can configure the size and editor Y through the Desktop Host settings. Other ratios retain the project/default style; inspect the actual editor before acceptance. Save `project_bible.delivery.draft_style` through `drama_project` preview/update, then prepare the timeline. For example, `{"watermark":{"font_size_ui":7},"subtitle":{"font_family":"山海经","font_size_ui":11,"border_width_ui":20,"transform_y":-0.465625}}`. A saved `timeline.delivery.draft_style` wins as a whole, including `{}`; only an absent section inherits the project. Omitted fields keep the old draft defaults: watermark UI 6, subtitle UI 11, black border UI 20, vertical position -0.465625 and the editor's system font. Font sizes are finite and positive through 100, border width is 0–100, and vertical position is -1–1. These units are not `delivery.subtitle` render pixels; draft choices do not change the formal MP4 style. Animation omits the watermark; Windows ending tracks follow the ratio rule.
- For independent-audio drafts, a requested font name is trimmed, nonempty, at most 128 characters and contains no controls. Exact free-resource matches write the library reference with an availability/license review warning; metadata is not proof the font is installed or commercially licensed. Unsupported or membership resources use a visible system-font fallback without downloading, purchasing or blocking the draft. The editor owns the actual default family. `muse-review.json` records resolved UI values, requested/resolved font and fallback/reference status. Windows embedded mode applies supported native text styling, retains the requested font as a review warning and uses the editor's default family without selecting or downloading a font resource. Preview both editor and MP4 before claiming matching appearance.
- The optional ending overlay video is explicitly muted, independently of the selected ending sound. It remains an editable screen-blended video, not a native parameterized Jianying effect; its duration still follows the selected source and existing ending policy. A nonzero or unspecified effect volume is a review warning, not evidence the source has audible audio.

Output:

- Editable draft with body video clips. Photorealistic and legacy drafts also contain a separate two-second tail-frame image clip and an independent lower-right white text track reading exactly `内容由AI生成` for the entire programme including the ending; 3D animation contains neither. No top-right notice is added; the AI notice is not a speech subtitle and does not enter the SRT.
- In Windows `embedded` mode, body clips retain their source bytes, original speed and embedded audio. `master_gain` applies to these video segments; there is no separate whole-episode dialogue track. BGM and ending sound remain separate editable segments. Independent-audio requests instead mute body-video audio after the selected main track imports successfully; failed imports retain embedded sound with a review finding. Gain values come from `project_config.json.project_bible.delivery.audio.master_gain` / `bgm_gain`: an existing timeline `delivery.audio` section, including `{}`, wins as a whole; only an absent section inherits the project. Missing fields retain unit gain, not the formal renderer's deployment defaults. Both gains must be finite linear values from 0 through 8, including zero to mute. Structural source and gain checks do not establish audible playback.
- The legacy independent-audio generator spreads a short difference between decoded video duration and its timeline interval across the moving segment, within 0.2 s and 5% of the decoded duration. Larger gaps retain the source and warn about possible flashes. Windows `embedded` mode does not add body still frames or retime clips; the selected native source interval and saved cut positions remain visible in readback. The optional two-second ending is separate from body-gap handling.
- For the independent-audio generator, when every body source has verified constant cadence at the project fps, shared absolute shot boundaries map to project frames and the draft records the source and target windows in `body-tail-evidence.json`. Dialogue, music and SRT times remain unchanged; a bounded shortfall may be retimed within that frame window. Unsupported or unverified cadence keeps the microsecond timeline with a review warning. Opening and export still require editor verification.
- For independent-audio photorealistic and legacy drafts, `Resources/last_video_tail_frame.png` and `ending-evidence.json` record the selected source interval, source/image SHA-256, last decoded RGB frame MD5, body end, total duration, and whether an input ending was already included. The image must match the last decoded frame of the interval actually placed in the draft; a same-numbered storyboard PNG cannot substitute for it. Windows embedded mode instead retains `ending.png` and its decoded-frame/hash evidence under the selected materials directory in `aa-plan.json`; the native readback and `muse-review.json` record the placed ending image and review state.
- Ordered media manifest, SRT and warnings. Generate an MP4 only when the user requests a preview or finished video; draft-only work does not require encoding one.
- Subtitle cues only for actual spoken content, preserving original text and speaker.
- No additional transitions or effects beyond an explicitly selected ending effect.

Generation duration and resolution follow the current selected model and project, not fixed historical shot limits. Export dimensions are separate from source resolution and paid enhancement. See the two skills' SKILL.md files for review requirements and delivery styling.

## Desktop request

Windows source-audio requests set `audio_mode: "embedded"` and omit `audio`. The same `jianying_draft` entry selects Muse's bundled aa剪映 adapter and uses the installed Jianying `lyra-cli.exe`; no third-party engine binaries are shipped. The adapter probes the actual CLI commands and retains a new candidate plus readback and source hashes. Missing required CLI commands fail explicitly instead of switching to an approximate renderer. This mode requires source intervals beginning at zero and speed 1; it rejects requested source offsets or body retiming. The Mac backend does not accept this mode.

Write one JSON request with absolute file paths, then call `jianying_draft` with its `request_file` and the existing `drafts_dir` returned by `drama_draft_dir`. The request contains `project`, positive integer `episode`, a unique `name_prefix`, `videos` (selected clips in shot order), `subtitle_srt`, and `timeline` (the episode timeline). Omitted `audio_mode` and explicit `"independent"` retain the released pyJianYingDraft path, which requires `audio` containing the complete main audio without mixed BGM. Optional `bgm` is the selected music-only bed; declare `bgm_role: "music_only"`. A declared `"dialogue_music_mix"` is not added as a separate BGM track; the draft is retained with a warning to select pure music. An omitted or `"unknown"` role remains backward-compatible with a warning, not acoustic proof of music-only content. `ending_audio` and `ending_effect` follow the selected delivery policy. Only the named episode is generated. Retained inputs live under the project's `editing/draft-materials/`; keep them because the editable draft references them.

Request JSON, timeline JSON and SRT files accept UTF-8 with or without a byte-order mark (BOM). Reading and retaining these inputs does not remove or rewrite their original bytes. Malformed JSON and invalid timeline fields still fail.

The Desktop calls its packaged Python through the managed subprocess provider. A successful result lists saved drafts, actual implementation identity and `editor_open_verified: false`; it confirms saved readback, not native-editor opening or arbitrary-version compatibility. Windows embedded-audio results identify `backend: "aa-jianying"`, retain the actual CLI path/version/hash and report structural verification separately from listening. Existing drafts are never overwritten. Each request selects one episode; submit a separate request for another episode and preserve successful results when a later request fails.

For requests whose source video contains visible dialogue, use the renderer's `subtitle_overlay` decision with the actual sources and aligned SRT. Pass its `resolved_srt` as `subtitle_srt` and its `decision_report` as optional `subtitle_overlay_report`. The request validates episode, resolved subtitle hash and the selected videos against that report, retains the report beside the draft's material inputs, and copies its warnings and editability scope into the saved review and tool result. These fields are caller-declared evidence, not an OCR or native-editor attestation. Embedded source text stays non-editable and its size, punctuation and position cannot be changed with subtitle-track styling. Uncertain visual recognition is a review warning, not permission for paid erasure. Windows embedded mode uses the same caller-declared decision and permits a blank overlay SRT only when the report binds all original cues and source identities; it does not claim to have inspected those pixels.

For independent-audio requests, when every original cue is explicitly retained in source pixels, a source-bound report with zero overlay cues permits a blank resolved SRT for that episode only; the original SRT hash and cue count must still match. The draft adds no empty subtitle track and reports the non-editable retained text. Without that complete report, blank or unparseable SRT input remains invalid.

For a full-window ending effect, the shared timeline can declare `ending_effect_fit: "stretch_to_window"`. The complete selected effect plays once at measured source duration divided by the two-second target duration; ending audio keeps normal speed and the independent freeze remains two seconds. The ending evidence records the measured source duration, target duration and speed. Without this field the existing `source_once` treatment remains unchanged; 3D animation still adds no ending.
