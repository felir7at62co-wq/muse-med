# 短剧剪辑与字幕

旧独立音轨草稿与正式成片遵循同一[媒介与交付策略](../tweet-drama-background-render/SKILL.md#媒介与交付策略)：明确 `animation_3d` 时不添加水印、片尾 2 秒末帧定格、片尾音或特效；`photorealistic` 保留这些交付元素。媒介缺失的旧项目警告并保留旧版行为，不从风格文字或横竖比猜测。

Windows 原声草稿按画幅选择片尾：只有 `9:16` 在整集末尾追加两秒，`16:9` 及其他比例不追加，也不加载片尾音或特效；水印仍由项目媒介决定。 Windows 原声草稿的 `16:9` 字幕使用剪映字号 `7`、位置 `X=0`、`Y=-879`；工具根据实际剪映画布高度换算内部位置，覆盖旧项目保存的字号和位置，颜色与描边沿用原要求。`9:16` 继续使用项目已配置的样式或原有默认值，实际打开剪映核对。Windows 草稿默认将选定原视频按剧情顺序入轨、保留视频自带对白和音效；BGM、字幕与适用的整集片尾分别可编辑。调用同一 `jianying_draft`，请求写 `audio_mode: "embedded"` 并省略 `audio`，由随包 aa剪映后端执行。不为加字幕或配乐先提取整集音频、预混 BGM 或重编码正文视频，不为凑时长在正文剪口补静帧或主动改速。用户明确要求配音、替换声音或其它剪辑时按其要求处理。未声明模式的旧请求仍需独立主音频；Mac 暂沿用该路径，不能把它冒称为保留内嵌原声。具体字段与 Windows 运行要求见[输入输出](references/io-contract.md#desktop-request)。

## 剪映草稿目录

仅在准备生成剪映草稿时调用 `drama_draft_dir {}`，读取 Settings 的 `jianyingDraftDir`。返回 `ready` 就使用返回的 `path`，不再询问用户；返回 `unconfigured` 或路径失效时，用 `ask_user_question` 询问“请提供本机剪映专业版设置里的草稿保存根目录”。不要猜测其他机器的路径，也不要替用户创建一个假定的编辑器根目录。把用户回答传给 `drama_draft_dir {path: ...}`；工具验证已有绝对目录可读写、保存同一 Settings 字段并回读，成功后才能生成草稿。工具或保存失败时说明原因并修正，不改写其他设置，不用另一份配置文件绕过。这个步骤不阻塞写作、分镜或视频生成。

生成剪映草稿统一调用 `jianying_draft`，将 `drama_draft_dir` 成功结果的 `path` 原样作为 `drafts_dir`，不用让用户手写 PowerShell 或另装 Python。先用 `write` 保存[单集请求文件](references/io-contract.md#desktop-request)，再传其绝对路径为 `request_file`。Windows 原声模式用 aa剪映调用已安装剪映的 CLI；独立音轨请求沿用打包的 `GuanYixuan/pyJianYingDraft`。工具只处理指定一集，返回草稿路径、保留素材目录与实际实现身份。`editor_open_verified=false` 表示尚未在本机剪映打开验证；不能因已有草稿是密文就断言新草稿无法打开，也不能宣称任意版本均兼容。工具失败时按实际错误调查，不静默换引擎。当前实例缺少此工具时，核查 Muse 版本与安装状态。

历史会话续做或 Muse 更新后恢复草稿制作时，重新读取本技能，以当前原生工具为准。历史记录中成功过的 `DraftGenerator`、`sys.path`、`.desktop-build` 和绝对开发目录不是当前生成入口；即使仍能启动，也可能绕过现版音轨处理与保存校验。原生工具报错时核查当前错误和打包资源，不静默改用旧脚本或另装依赖。此为 Agent 操作指导，不新增用户审批；不会自动修改已生成草稿，需要修复时另存唯一名称的候选，保留原稿。

保留已有草稿；名称冲突时为新候选选择唯一 `name_prefix`，不得删除或覆盖旧草稿。

草稿对白与纯配乐可读取 `project_config.json.project_bible.delivery.audio: {master_gain?, bgm_gain?}`，prepare 写入时间线后以快照为准。快照存在 `audio` 节（包括 `{}`）时整节优先，不从项目补缺字段；缺字段保留 SDK 原默认 1，缺整个节才读取项目。增益参数为 0–8 有限线性数值，零静音；Muse 草稿通过部署 `maxBgmGain: 1` 对 BGM 增益封顶，不放大已衰减的配乐，独立脚本默认上限 8。没有显式配置的旧请求仍为 1/1。与正式成片匹配时显式指定两项，不假定正式渲染的部署默认也适用于草稿。片尾音增益和字幕 SDK 样式不随项目音频字段改变。

源视频可能已有对白烧录字。Windows 原声与旧独立音轨路径沿[源画面文字与字幕叠加流程](../tweet-drama-background-render/SKILL.md#源画面文字与字幕叠加)抽样 OCR 与画面预览，并用 `drama_render subtitle_overlay` 或实际 `render` 的字幕处理报告确定叠加集合。保留烧录字时，将工具返回的 `resolved_srt` 作为请求的 `subtitle_srt`，把对应 `decision_report` 绝对路径传为 `subtitle_overlay_report`；请求中的 timeline 和视频必须与该报告同源，不得再传回全部原 SRT。工具核对 SRT 与所选视频字节，保存报告并返回不可编辑范围。识别不确定只提示、预览和保留候选，不自动付费去字。Windows 原声模式同样接受有依据的叠加报告，并保留烧录字幕不可编辑的提示；只有报告确认全部原字幕都由源画面保留时才允许空的叠加 SRT。

烧录在像素中的文字不可编辑，字号和位置也无法由草稿字幕轨统一；其余后加字幕仍为可编辑轨。交付逐项说明保留烧字的镜头与时间，不能把“有可编辑字幕轨”写成“整集字幕均可编辑”。只有获得无字素材后才能实现全片统一的可编辑字幕。

运行前检查 [外部依赖与授权](references/dependencies.md) 和 [输入输出](references/io-contract.md)；此源码包不附带第三方 Python 库、可执行文件或媒体。建议每集草稿与成片采用同一套综合剧情、对白含义和前后衔接选择、经实际试听的配乐；源曲衰减与片段选择见相邻 `tweet-drama-background-render/references/story-bgm-selection.md`。已含混音增益的 `music_stem` 导入时使用增益 1，不重复增益；传给草稿 `bgm` 的必须是**不含对白的纯音乐轨**，可带对白时段的音量压低包络，并声明 `bgm_role: "music_only"`。含对白与配乐的审查混音仅供试听，不可再叠到草稿的独立 BGM 轨，否则会重复对白；声明 `bgm_role: "dialogue_music_mix"` 时保留草稿但不添加独立 BGM 轨，并返回待换纯音乐轨的提示。用途未知或旧请求未声明时仅提示，生成器不据此声称已分析证明没有对白。生成器使用一份配乐轨不意味着整集只能有一首。多集共用配乐只提示试听，不默认禁止。传入 BGM 目录时每集只能有一份选定配乐；多份不能按文件名猜选。配乐覆盖不足或导入轨道失败时保留候选并返回待核说明，不冒称该轨已经导入或验收。生成时长和分辨率取当前所选模型与分镜，不以历史固定镜头秒数或字数限制替代。

输入按任务和镜头排序并通过内容审核。clean/not_required 可进入时间线；pending 仅用于明确标注“未完成，非最终交付”的草稿/预览，由模型安排后续回读并替换来源，不把等待交给用户。未知或 failed 需核查恢复，不得假称完成。最终选用文件必须 clean/not_required 且通过实际文件内容、字幕清理、分辨率和音画 QA。

字幕覆盖全部真实发声，保留原文与说话人：dialogue/台词、vo/画外音，以及已确认实际发声的 os/心声/旁白/解说。少用旁白是创作建议，不是删除原文的许可；未确认发声时先核查音频，不把心理或叙述说明直接变字幕。动作、表情、场景和摄影说明不出字幕。内嵌字幕与后加字幕分别记录，避免重复。去字幕清理的是源视频中不需要的生成文字，最终设计字幕仍按项目已批准要求制作，clean 不表示最终成片必须无字幕。

只要求草稿时交付可编辑草稿、SRT 和镜头/任务来源映射，不为了验收额外编码整集预览。另需成片时复用相同选源、字幕文字与时间。`drama_render subtitles` 消费台词计划、逐镜来源和已有对齐时间写出 SRT，不执行语音识别或测量发声时间。`scripts/build_spoken_subtitles.py` 只构造 cues；显式草稿可保留标为预估的时间，但预估不等于最终校时。

字幕检查采用软提示：缺对齐、声文不符、样式问题、配乐不足或未导入均列出具体镜号、路径和原因，由 Muse 自主判断。`drama_render subtitles` 有疑点时写独立 `.draft.srt`，保留原字幕；`.review.txt` 与旧 `.blocked` 只供后续读取提醒，不禁止准备或渲染。检查完整返回的证据和实际草稿，不把保存成功或 `ok: true` 当作质量验收。

## 视频禁用标签

先用 `drama_video` list/inspect 查项目 `video-bans.json`。labels 至少一个自由可读标签（如“人物对调”），reason 可选，ban 不要证据。标错用 unban；查询无标签或 unban 不等于审核通过。禁用版本不得进入草稿或预览，禁止通用 FFmpeg、手写脚本和直接复制绕过。门禁按本项目实际 SHA256 检查，同字节副本也命中，同路径新字节不继承旧禁用。

`jianying_draft` 的请求必须指定项目根目录 `project`；工具在准备素材与创建草稿前检查所选视频，不能把外置素材无法定位项目当作无禁用继续。输入素材保存在项目独立目录，已有草稿拒绝覆盖。

## 字幕交付样式

- **先复用云端时间轴**：优先查找当前选定视频已有的已完成云转写收据、原始 JSON 与字幕文件，核对源文件 SHA-256 和剪辑位置。同源、时间有效的结果直接复用，不因制作草稿或纠错再提交转写。未结束任务沿原收据查询；缺少可用结果时才按已有费用授权调用 `audio_transcribe start`，用途为 `subtitles`，不换 ID 或用途重复提交。收据映射与现有脚本用法见[云转写字幕](references/cloud-subtitles.md)。
- **剧本纠字，声音定时间**：对照剧本纠正云转写的人名、同音字和明显错字，只写派生字幕文字，保留原始收据、识别 JSON 和对应实际字词起止时间。纠错后不按字数重算或均分时长；视频实际漏说、改说或额外发声时先核听，不能把剧本未说出的内容补成字幕，也不把真实说错的话伪装成识别错字。存疑处保留待核说明，不要求提示清零。
- 已核实错字可将[纠错映射](references/cloud-subtitles.md#corrections-and-measured-spans)传给 `align_subtitles.py --corrections`：按原始词序、源视频与转写摘要定位，显式替换错字并保留该词原始时间；这不表示脚本已经核听。
- **沿真实切点落位**：显示字幕按语义分条，起止取对应的已有字词边界；只有整句时间时先保留整句，不按字数猜内部切点。整集时间由镜头内时间按实际入点裁切、平移，明确变速时按实际速度换算；更换源视频或剪辑时更新受影响的字幕。脚本若因识别错字漏掉句首或句尾，核对原云时间轴后修正派生对齐，不能把缩短后的匹配区间当作完整句时间。文字纠错本身不改变声音时间。
- **离线只作显式选择**：用户确需离线且自行准备好依赖和模型时，可传 `--model-dir`，或 `--model-url` 与固定 `--model-sha256`。默认安装包不含 Whisper 模型与推理依赖；不自动下载安装。独立脚本仍支持 `MUSE_WHISPER_MODEL_DIR` 的模型解析，以及 `${DSH_HOME:-~/.dsh}/cache/models/faster-whisper` 和 `--cache-dir` 缓存配置。离线识别保持单线程、temperature 0。
- **单行、无标点、按语义切分**。用空格分隔语义组代替逗号句号；1080×1920 设计帧在 40px 边距内可用 1000px，未配置项目覆盖时成片 ASS 正文字号 40。单条建议不超过 14 个有效字（空格按半字计；正式渲染字族/名义像素字号/底边距可由项目配置覆盖，见 `tweet-drama-background-render`）。超长优先在真实字词切点拆成连续单行；缺切点时保留原句候选并标明待核，不为字数要求编造时间。
- 不合并不同说话人的句子；动作和未发声的心理描写不出字幕。
- **逐镜核对覆盖情况**：读取 `subtitle_line_coverage`、`subtitle_timing` 及实际音轨；漏句、额外发声、未核实和阅读速度问题只作提示，Muse 自行选择重听、重对齐或保留候选，不要求警告清零或用户逐项审批。

最终渲染和草稿导入前，对完整显示字幕调用 `drama_render method=speech_coverage`，传同一 `shots`、`timeline`、`subtitle_srt` 和 `speech_transcripts` 收据映射。它逐个实际识别字词与最终字幕双向比较，包含一两个字、剧本外发声、有字无对应识别及时间不一致，不用波形猜词。逐项核听后补字幕或明确记录不加的理由；额外发声另存字幕，不擅改正式剧本。需要保留决定时，用返回的 `evidence_sha256` 绑定 `speech_decisions` 中各 finding ID、decision、reason、observed_text 和实际核听区间；源、转写或 SRT 变化后重新比较，不复用旧决定。`listening_verified=false` 始终表示工具未作声学验收，即使识别全部匹配也不能写成听看通过。没有证据时保留未核实提示，不自动购买转写。

MP4 与草稿复用同一最终文本和词级时间；长句只在已有同源字词切点按语义分条，不按字数均分，不逐条缩小字号。同一时刻重复 cue 和字幕无发声都需实际复看。保留源画面烧字时，声文核对用包含该文字的完整显示 SRT，真正叠加仍使用 `resolved_srt` 与其报告；不能把已保留的像素文字误报成漏字或再次叠上。

## 剪映草稿字幕样式

剪映草稿未配置时用系统默认字体、字号 `11`、字间距 `0`、黑色描边参数 `20`，位置 `transform_y=-0.465625`；独立水印字号默认 `6`。项目可通过 `drama_project` 的 preview/update 保存 `delivery.draft_style`，例如 `{"watermark":{"font_size_ui":7},"subtitle":{"font_family":"山海经","font_size_ui":11,"border_width_ui":20,"transform_y":-0.465625}}`，再运行 prepare。时间线已有 `delivery.draft_style` 时整节优先，包含 `{}`；只有缺整个节才继承项目。未指定字段保留草稿旧默认；Windows 原声 `16:9` 的字号和位置按上述画幅要求覆盖，不从成片的像素字号推导，不修改其他项目或已有草稿。动画不加水印；片尾按当前 Windows 画幅规则或旧独立音轨媒介规则选择。

**这些是剪映 UI 值，量纲与 `draft_content.json` 里的数字不同**：旧独立音轨库将字号原样写出（`11` → `11.0`），字间距乘 0.05（`0` → `0.0`），描边除以 100 再乘 0.2（`20` → `0.04`），行间距写为 `0.02 + UI 值 × 0.05`。数值映射不代替编辑器实际外观验收。未指定字体时不写 `styles[0].font`，只能说明由剪映选默认字体，不能证明实际字族。显式字体仅精确匹配打包库目录；未支持或会员字体回退剪映默认并返回具体提示，不下载或购买字体。目录内免费资源也只写引用，并提醒本机资源和许可尚未验证，不能把目录元数据当作已安装或已获商用授权。`muse-review.json` 保留本次解析样式和字体请求／回退记录；普通缺字体不阻断草稿。Windows 原声模式通过原生 CLI 设置可用文字样式，显式字体仅记为待核提示，由剪映使用默认字族；不能声称已应用旧库字体资源或已验收相同外观。

仿真人和未声明媒介的旧项目，草稿与成片都只保留右下角「内容由AI生成」，不加右上角提示。草稿将它写为独立可编辑的白色无描边文字轨，覆盖正文与片尾，按字号调整右下位置；估算可能越界时提示并保留项目字号，仍需实际预览确认。它不属于发声字幕，不写进 SRT 或台词覆盖率。

**字幕可读性建议两条路径保持一致**：建议去标点、按语义切分、单行、单条不超过 14 个有效字（空格按半个字计），以实际发声为准、对照剧本纠正识别错字。缺对齐、声文不符、样式或配乐问题只返回具体路径与原因，由 Muse 判断如何处理；不要求提示清零，也不新增批准步骤。旧独立音轨路径的 `normalize_subtitle_text` 写出独立 `.normalized.srt`，Windows 原声模式则逐字保留传入 SRT，需提前完成显示文字整理；超长字幕保留原文与时间，不按字数猜切点。`drama_render subtitles` 有疑点时写 `.draft.srt` 并保留原字幕；`.review.txt` 与旧 `.blocked` 只作提醒，准备和渲染可继续。保存成功不表示已完成质量验收。**字幕外观两条路径分别配置**：成片用 `delivery.subtitle` 的像素设置或部署默认；草稿用 `delivery.draft_style` 的 UI 设置或上述旧默认。改变一边不自动联动另一边，需分别预览核对。

项目需要两套输出统一观感时，使用[共享视觉配置与真实字形预览](../tweet-drama-background-render/SKILL.md#共享字幕视觉配置)，不要把 ASS 像素直接当剪映 UI 值。选中 `draft_style.subtitle` 显式设置的 `transform_y` 是剪映独立校准位置，缺省才使用公共中心；变更后重新 prepare，回读完整时间线快照再生成新候选。14 字仅为阅读建议，不代表当前字体必然放得下；读取 `subtitle_layout` 的真实预览与超宽结果，并在剪映实际打开、播放、关闭和重开检查。普通字体回退记在 Agent 结果与草稿审查中，不为默认系统字体另弹用户确认或下载安装字体；只有确实影响用户要求时集中说明差异。

经过素材帧时间戳验证且帧率一致的项目，正文剪点按项目帧时钟对齐；无法验证的素材沿用原时间线并提示核对。

**交付前校验**：回读实际视频、声音、BGM、字幕与片尾轨道，并核对剪口和字幕开始、结束时的实际发声；不能把字幕与旧 SRT 数值一致当成声画已对齐。原声保留和原速要求以实际轨道为准，工具自动调整也需如实说明，不能仅凭请求内容宣称满足。Windows 原声草稿的横版正文结束即止，竖版两秒片尾只在整集末尾出现；旧独立音轨路径继续按媒介选择。AI 标识按适用的媒介覆盖完整草稿。检查情况、未查看画面和未试听区间按实际记录；未在剪映打开、播放、关闭重开时明确未验证。技术检查与提示保留在 `muse-review.json`，不以保存成功代替验收，已有草稿不覆盖。

剪映主轨按项目剪辑计划使用任务视频，保留必要收束；字幕预排可参考脚本相对时间，最终逐句按真实音频校正，不以等比例映射代替真实发声时间。保留项目已确认字幕与草稿样式。

## 可编辑末帧定格

以下片尾步骤适用于 Windows 原声模式的 `9:16` 草稿，或旧独立音轨路径的仿真人与未声明媒介项目；Windows 横版与旧路径的 3D 动画跳过，不生成片尾定格图或片尾证据。正文片段的短尾差处理与片尾不同，见[输入输出](references/io-contract.md)。适用集在正文后保留 **2 秒真实末帧定格**，不是同编号的分镜参考图。生成器从实际最后一个选定视频的入轨区间顺序解码，抽取该区间最后一帧，并用 RGB `framemd5` 与原视频校验；旧独立音轨路径将 `Resources/last_video_tail_frame.png` 作为独立可编辑图片片段加入主轨，同时写出 `ending-evidence.json`；Windows 原声模式保留材料目录内的 `ending.png`，将源区间、图像摘要和解码帧校验记在 `aa-plan.json`，并回读原生图片片段。源视频或提取失败时报告原因，不交付空片尾。若同镜头编号同时有视频和参考图片，只使用选定视频，不重复铺图。

时间线沿用 `clips` 与 `body_end`：通常 `body_end` 应等于最后片段的 `start_us + duration_us` 换算成秒。拼接 MP4 的容器或 AAC 音轨可能比所选视频片段多几十毫秒，不得把它们的 `ffprobe format.duration` 直接填为 `body_end`；误差在既有 0.2 秒音画容差内时，生成器按片段末尾校正并提示，不改变原时间线文件。适用片尾的草稿总长再加 2 秒；Windows 原声模式仅接受纯正文选段，已有片尾需单独整理后再请求；旧独立音轨路径若已选媒体的最后片段已经含片尾，明确保留原正文 `body_end`，片段末尾只能比它多 2 秒。生成器把这 2 秒替换为可编辑定格，保持总长，不再次追加；已有整段音轨里的片尾音也不重复叠加。不要仅凭静止画面、文件名或音轨较长就猜测已有片尾。

使用与成片相同且已选定的片尾音/特效时，在单集 JSON 请求中传 `ending_audio`、`ending_effect` 的绝对路径。适用片尾的新候选默认在同一 timeline 显式写 `ending_effect_fit: "stretch_to_window"`，项目已经明确选择原速短特效时遵从原选择。完整特效源按实际时长变速覆盖片尾，1.020 秒素材速度为 0.51，音频仍按原速取前 2 秒；不循环，也不以黑色填充假称特效延长。省略该字段保留原速播放一次的旧行为。特效仍独立滤色叠加，覆盖视频自身音量为 0，独立片尾音保留；这是视频素材，不是剪映原生参数化特效。`ending-evidence.json` 记录源时长、目标时长与速度；不要把定格、音效或 AI 标识预先烧进正文素材再叠一次。旧独立音轨路径的草稿画布与帧率取时间线 `delivery: {visual_medium, width, height, fps}`；旧 `canvas` 仍兼容，但不能与快照尺寸冲突。缺少快照时默认 `1440×2560 @60fps`。画布分辨率与源视频、付费增强分别记录，不给正文片段重复叠加按分辨率算出的缩放。Windows 原声模式按已安装 CLI 能力设置画幅比例，宽高和帧率能力缺失时如实返回提示，实际画布与字体仍需在剪映核对。
