# 短剧剪辑与字幕

草稿与成片遵循同一[媒介与交付策略](../tweet-drama-background-render/SKILL.md#媒介与交付策略)：明确 `animation_3d` 时不添加水印、片尾 2 秒末帧定格、片尾音或特效；`photorealistic` 保留这些交付元素。媒介缺失的旧项目警告并保留旧版行为，不从风格文字或横竖比猜测。

## 剪映草稿目录

仅在准备生成剪映草稿时调用 `drama_draft_dir {}`，读取 Settings 的 `jianyingDraftDir`。返回 `ready` 就使用返回的 `path`，不再询问用户；返回 `unconfigured` 或路径失效时，用 `ask_user_question` 询问“请提供本机剪映专业版设置里的草稿保存根目录”。不要猜测其他机器的路径，也不要替用户创建一个假定的编辑器根目录。把用户回答传给 `drama_draft_dir {path: ...}`；工具验证已有绝对目录可读写、保存同一 Settings 字段并回读，成功后才能生成草稿。工具或保存失败时说明原因并修正，不改写其他设置，不用另一份配置文件绕过。这个步骤不阻塞写作、分镜或视频生成。

生成剪映草稿统一调用 `jianying_draft`，将 `drama_draft_dir` 成功结果的 `path` 原样作为 `drafts_dir`，无需 PowerShell 或用户另装 Python。先用 `write` 保存[单集请求文件](references/io-contract.md#desktop-request)，再传其绝对路径为 `request_file`。此工具沿用打包的 `GuanYixuan/pyJianYingDraft`，只处理请求指定的一集，返回保存后读回一致的草稿路径、保留素材目录与库版本。`editor_open_verified=false` 表示尚未在本机剪映打开验证；不能因已有草稿是密文就断言新草稿无法打开，也不能宣称库会自动解决所有版本的加密格式。工具失败时按实际错误调查，不把 PowerShell 启动失败外推成所有进程均不可用。当前实例缺少此工具时，核查 Muse 版本与安装状态。

历史会话续做或 Muse 更新后恢复草稿制作时，重新读取本技能，以当前原生工具为准。历史记录中成功过的 `DraftGenerator`、`sys.path`、`.desktop-build` 和绝对开发目录不是当前生成入口；即使仍能启动，也可能绕过现版音轨处理与保存校验。原生工具报错时核查当前错误和打包资源，不静默改用旧脚本或另装依赖。此为 Agent 操作指导，不新增用户审批；不会自动修改已生成草稿，需要修复时另存唯一名称的候选，保留原稿。

保留已有草稿；名称冲突时为新候选选择唯一 `name_prefix`，不得删除或覆盖旧草稿。

草稿对白与纯配乐可读取 `project_config.json.project_bible.delivery.audio: {master_gain?, bgm_gain?}`，prepare 写入时间线后以快照为准。快照存在 `audio` 节（包括 `{}`）时整节优先，不从项目补缺字段；缺字段保留 SDK 原默认 1，缺整个节才读取项目。增益为 0–8 有限线性数值，零静音；没有显式配置的旧请求仍为 1/1。与正式成片匹配时显式指定两项，不假定正式渲染的部署默认也适用于草稿。独立对白成功导入后源视频静音，避免叠播；失败时保留原声及待核提示。片尾音增益和字幕 SDK 样式不随项目音频字段改变。

源视频可能已有对白烧录字。沿[源画面文字与字幕叠加流程](../tweet-drama-background-render/SKILL.md#源画面文字与字幕叠加)抽样 OCR 与画面预览，并用 `drama_render subtitle_overlay` 或实际 `render` 的字幕处理报告确定叠加集合。保留烧录字时，将工具返回的 `resolved_srt` 作为请求的 `subtitle_srt`，把对应 `decision_report` 绝对路径传为 `subtitle_overlay_report`；请求中的 timeline 和视频必须与该报告同源，不得再传回全部原 SRT。工具核对 SRT 与所选视频字节，保存报告并返回不可编辑范围。识别不确定只提示、预览和保留候选，不自动付费去字。

烧录在像素中的文字不可编辑，字号和位置也无法由草稿字幕轨统一；其余后加字幕仍为可编辑轨。交付逐项说明保留烧字的镜头与时间，不能把“有可编辑字幕轨”写成“整集字幕均可编辑”。只有获得无字素材后才能实现全片统一的可编辑字幕。

运行前检查 [外部依赖与授权](references/dependencies.md) 和 [输入输出](references/io-contract.md)；此源码包不附带第三方 Python 库、可执行文件或媒体。建议每集草稿与成片采用同一套按情绪分段、经逐集试听的配乐；传给草稿 `bgm` 的必须是**不含对白的纯音乐轨**，可带对白时段的音量压低包络，并声明 `bgm_role: "music_only"`。含对白与配乐的审查混音仅供试听，不可再叠到草稿的独立 BGM 轨，否则会重复对白；声明 `bgm_role: "dialogue_music_mix"` 时保留草稿但不添加独立 BGM 轨，并返回待换纯音乐轨的提示。用途未知或旧请求未声明时仅提示，生成器不据此声称已分析证明没有对白。生成器使用一份配乐轨不意味着整集只能有一首。多集共用配乐只提示试听，不默认禁止。传入 BGM 目录时每集只能有一份选定配乐；多份不能按文件名猜选。配乐覆盖不足或导入轨道失败时保留候选并返回待核说明，不冒称该轨已经导入或验收。生成时长和分辨率取当前所选模型与分镜，不以历史固定镜头秒数或字数限制替代。

输入按任务和镜头排序并通过内容审核。clean/not_required 可进入时间线；pending 仅用于明确标注“未完成，非最终交付”的草稿/预览，由模型安排后续回读并替换来源，不把等待交给用户。未知或 failed 需核查恢复，不得假称完成。最终选用文件必须 clean/not_required 且通过实际文件内容、字幕清理、分辨率和音画 QA。

字幕覆盖全部真实发声，保留原文与说话人：dialogue/台词、vo/画外音，以及已确认实际发声的 os/心声/旁白/解说。少用旁白是创作建议，不是删除原文的许可；未确认发声时先核查音频，不把心理或叙述说明直接变字幕。动作、表情、场景和摄影说明不出字幕。内嵌字幕与后加字幕分别记录，避免重复。去字幕清理的是源视频中不需要的生成文字，最终设计字幕仍按项目已批准要求制作，clean 不表示最终成片必须无字幕。

输出可编辑草稿、SRT、预览 MP4 和镜头/任务来源映射。SRT 由 `drama_render subtitles` 写出（台词计划 + 成片清单 → `editing/<集>.srt`），它同时把每镜的 `actual_speech_start/end` 测出来。`scripts/build_spoken_subtitles.py` 的 build_spoken_cues 默认只接受 clean/not_required；pending 必须显式 draft=True。默认所有发声（包括编译为 vo 的旁白/心声）必须有完整 actual_speech_start/end，否则报缺少音频证据，不静默漏句；仅显式 draft=True 可用带 timing_source=9_chars_per_second 标记的预估时间。该函数只构造 cues，8字/秒预排不是最终校时，也不代替成片 QA。

字幕检查采用软提示：缺对齐、声文不符、样式问题、配乐不足或未导入均列出具体镜号、路径和原因，由 Muse 自主判断。`drama_render subtitles` 有疑点时写独立 `.draft.srt`，保留原字幕；`.review.txt` 与旧 `.blocked` 只供后续读取提醒，不禁止准备或渲染。检查完整返回的证据和实际草稿，不把保存成功或 `ok: true` 当作质量验收。

## 视频禁用标签

先用 `drama_video` list/inspect 查项目 `video-bans.json`。labels 至少一个自由可读标签（如“人物对调”），reason 可选，ban 不要证据。标错用 unban；查询无标签或 unban 不等于审核通过。禁用版本不得进入草稿或预览，禁止通用 FFmpeg、手写脚本和直接复制绕过。门禁按本项目实际 SHA256 检查，同字节副本也命中，同路径新字节不继承旧禁用。

`jianying_draft` 的请求必须指定项目根目录 `project`；工具在准备素材与创建草稿前检查所选视频，不能把外置素材无法定位项目当作无禁用继续。输入素材保存在项目独立目录，已有草稿拒绝覆盖。

## 字幕交付样式

- **时间必须来自语音识别对齐，用 `drama_render subtitles` 落位**：先对该镜**自己的**成片（此时还没有任何 BGM 混进来）跑一次语音识别，把每一句的起止时间写成逐镜、镜内相对的对齐文档 `{"shots":[{"shot":1,"cues":[{"text":"识别文本","start":0.0,"end":0.8}]}]}`，再连同 `lines` 一起传给 `drama_render subtitles`。`lines` 是按原文顺序去标点、按语义拆分后的显示字幕计划，每项单行且不超过 14 个有效字；原文覆盖记录另行保留，不能因拆字幕漏字、改数字或改语义。长句的每条显示字幕要分别取得同源字词时间，不能把整句时长均分。**本工具不做识别、不测能量、不估算时间**：能量门限只能说明有人在说话，说不出具体哪句在哪里，估算出来的时间正是字幕压错句的原因。cue 时间 = 该镜在时间线上的起点 + 镜内偏移；字幕显示文字来自 `lines`，识别文本只用于核对是不是同一段表演。缺某一镜的对齐、段数与台词条数不符、识别文本与显示字幕对不上、或该镜的策略不是 `asr_aligned`，都会按 warning 报出并提示该对哪一镜重跑识别；有识别结果却没声明台词同样返回提醒。写出的 cue 还会检查时长、重叠、越界与阅读速度（>20 有效字/秒重点提醒，>12 警告）。识别本身的准确度由调用方负责，`speech_alignment` 永远留在 `not_checked`。8 个有效字/秒只作为**草稿预估**，不得用于最终交付。
- **默认使用 Muse 云端字词时间戳**：对每个有实际发声的镜头原视频调用 `audio_transcribe start`，明确传 `purpose: "subtitles"` 使用极速识别，再对返回的同一收据调用 `inspect` 只查询原任务，直到完成或返回明确阻断。`status` 可能按网关恢复指示补传同 ID 音轨，只在获得相应费用授权后使用。独立镜头可并行提交，服务端按账号共享额度排队；未知结果沿用原收据查询，不换 ID 或用途重投。输入必须是该镜头尚未混入 BGM 的真实选定视频，不用整集混音代替。原始收据与 JSON 保持不修改。
- **用云端收据生成对齐**：写 `<项目>/_probe/epNN-cloud-transcripts.json`，格式为 `{"shots":[{"shot":1,"receipt":"<audio_transcribe 返回的绝对收据路径>"}]}`，每个镜头（含声明无台词的镜头）各一项。运行 `python -B <技能目录>/scripts/align_subtitles.py --project <项目根> --episode <集号> --cloud-transcripts <映射文件> --strict`。脚本核对视频 SHA-256 与收据、读取每个字词的实际时间，把当前剧本台词匹配到该镜头音轨；`asr_aligned` 或经收据核查的 `no_lines` 提供较完整证据，其他状态保留提醒。缺字词时间、源视频变化、台词未匹配、识别到至少四个连续的未映射字，或一句已锚定的台词仍缺少连续四字时，报告具体镜头并给 Muse 提醒；先人工核听，不用整句均分或预估时间替代。没有收据的无台词镜头不能证明静音，建议核听并补充同源证据。
- **离线只作显式选择**：用户确需离线且自行准备好依赖和模型时，可传 `--model-dir`，或 `--model-url` 与固定 `--model-sha256`。默认安装包不含 Whisper 模型与推理依赖；不自动下载安装。独立脚本仍支持 `MUSE_WHISPER_MODEL_DIR` 的模型解析，以及 `${DSH_HOME:-~/.dsh}/cache/models/faster-whisper` 和 `--cache-dir` 缓存配置。离线识别保持单线程、temperature 0。
- **单行、无标点、按语义切分**。用空格分隔语义组代替逗号句号；1080×1920 设计帧在 40px 边距内可用 1000px，未配置项目覆盖时成片 ASS 正文字号 40。单条不超过 14 个有效字（空格按半字计；正式渲染字族/名义像素字号/底边距可由项目配置覆盖，见 `tweet-drama-background-render`）。超长必须按语义拆成连续两条并分别校时，不许压成两行。
- 字幕文字用剧本原文，不改写、不省略、不合并不同说话人的句子。
- **逐镜核对覆盖情况**：读取 `subtitle_line_coverage`、`subtitle_timing` 及实际音轨；漏句、额外发声、未核实和阅读速度问题只作提示，Muse 自行选择重听、重对齐或保留候选，不要求警告清零或用户逐项审批。

## 剪映草稿字幕样式

剪映草稿未配置时用系统默认字体、字号 `11`、字间距 `0`、黑色描边参数 `20`，位置 `transform_y=-0.465625`；独立水印字号默认 `6`。项目可通过 `drama_project` 的 preview/update 保存 `delivery.draft_style`，例如 `{"watermark":{"font_size_ui":7},"subtitle":{"font_family":"山海经","font_size_ui":11,"border_width_ui":20,"transform_y":-0.465625}}`，再运行 prepare。时间线已有 `delivery.draft_style` 时整节优先，包含 `{}`；只有缺整个节才继承项目。未指定字段保留草稿旧默认，不从成片的像素字号推导，不修改其他项目或已有草稿。动画仍不加水印或片尾。

**这些是剪映 UI 值，量纲与 `draft_content.json` 里的数字不同**：库将字号原样写出（`11` → `11.0`），字间距乘 0.05（`0` → `0.0`），描边除以 100 再乘 0.2（`20` → `0.04`），行间距写为 `0.02 + UI 值 × 0.05`。数值映射不代替编辑器实际外观验收。未指定字体时不写 `styles[0].font`，只能说明由剪映选默认字体，不能证明实际字族。显式字体仅精确匹配打包库目录；未支持或会员字体回退剪映默认并返回具体提示，不下载或购买字体。目录内免费资源也只写引用，并提醒本机资源和许可尚未验证，不能把目录元数据当作已安装或已获商用授权。`muse-review.json` 保留本次解析样式和字体请求／回退记录；普通缺字体不阻断草稿。

仿真人和未声明媒介的旧项目，草稿与成片都只保留右下角「内容由AI生成」，不加右上角提示。草稿将它写为独立可编辑的白色无描边文字轨，覆盖正文与片尾，按字号调整右下位置；估算可能越界时提示并保留项目字号，仍需实际预览确认。它不属于发声字幕，不写进 SRT 或台词覆盖率。

**字幕可读性建议两条路径保持一致**：建议去标点、按语义切分、单行、单条不超过 14 个有效字（空格按半个字计），文字取剧本原文。缺对齐、声文不符、样式或配乐问题只返回具体路径与原因，由 Muse 判断如何处理；不要求提示清零，也不新增批准步骤。草稿路径的 `normalize_subtitle_text` 写出独立 `.normalized.srt`；超长字幕保留原文与时间，不按字数猜切点。`drama_render subtitles` 有疑点时写 `.draft.srt` 并保留原字幕；`.review.txt` 与旧 `.blocked` 只作提醒，准备和渲染可继续。保存成功不表示已完成质量验收。**字幕外观两条路径分别配置**：成片用 `delivery.subtitle` 的像素设置或部署默认；草稿用 `delivery.draft_style` 的 UI 设置或上述旧默认。改变一边不自动联动另一边，需分别预览核对。

**交付前校验**：正文镜头与主音频按原时间线校时（容差 0.2 秒）；源视频尾差不超过 0.2 秒且不超过实测片长的 5% 时均匀分摊到该运动片段，较大缺口保留原片并提示剪口可能闪屏，不在每个剪口添加定格图片。3D 动画主视频轨只含正文镜头，总时长等于正文，检查无生成的片尾轨、片尾定格素材或 AI 标识；仿真人和旧项目主轨另含一个 2 秒片尾定格，AI 标识覆盖完整草稿。两者均校验字幕条数、样式与文本，质量差异返回提示由 Muse 决定。BGM 和片尾音是叠加轨，不把它们的时长相加来判定音画同步。质量发现保留草稿并写出 `muse-review.json`；无法写文件等技术失败只清理本次新建目录，保留已有草稿。时间线缺失或字段名不符时报错，不按默认每段 5 秒交付。

剪映主轨按项目剪辑计划使用任务视频，保留必要收束；字幕预排可参考脚本相对时间，最终逐句按真实音频校正，不以等比例映射代替真实发声时间。保留项目已确认字幕与草稿样式。

## 可编辑末帧定格

以下 2 秒末帧和片尾步骤仅用于仿真人与未声明媒介的旧项目；3D 动画完全跳过，不生成片尾定格图或 `ending-evidence.json`。正文片段的短尾差处理与片尾不同，见[输入输出](references/io-contract.md)。适用集在正文后保留 **2 秒真实末帧定格**，不是同编号的分镜参考图。生成器从实际最后一个选定视频的入轨区间顺序解码，抽取该区间最后一帧，并用 RGB `framemd5` 与原视频校验；生成的 `Resources/last_video_tail_frame.png` 作为独立可编辑图片片段加入主轨，同时写出 `ending-evidence.json`。源视频或提取失败时报告原因，不交付空片尾。若同镜头编号同时有视频和参考图片，只使用选定视频，不重复铺图。

时间线沿用 `clips` 与 `body_end`：通常 `body_end` 应等于最后片段的 `start_us + duration_us` 换算成秒。拼接 MP4 的容器或 AAC 音轨可能比所选视频片段多几十毫秒，不得把它们的 `ffprobe format.duration` 直接填为 `body_end`；误差在既有 0.2 秒音画容差内时，生成器按片段末尾校正并提示，不改变原时间线文件。仿真人和旧项目的草稿总长再加 2 秒；若已选媒体的最后片段已经含片尾，明确保留原正文 `body_end`，片段末尾只能比它多 2 秒。生成器把这 2 秒替换为可编辑定格，保持总长，不再次追加；已有整段音轨里的片尾音也不重复叠加。不要仅凭静止画面、文件名或音轨较长就猜测已有片尾。

使用与成片相同且已选定的片尾音/特效时，在单集 JSON 请求中传 `ending_audio`、`ending_effect` 的绝对路径。新建仿真人候选默认在同一 timeline 显式写 `ending_effect_fit: "stretch_to_window"`，项目已经明确选择原速短特效时遵从原选择。完整特效源按实际时长变速覆盖片尾，1.020 秒素材速度为 0.51，音频仍按原速取前 2 秒；不循环，也不以黑色填充假称特效延长。省略该字段保留原速播放一次的旧行为。特效仍独立滤色叠加，覆盖视频自身音量为 0，独立片尾音保留；这是视频素材，不是剪映原生参数化特效。`ending-evidence.json` 记录源时长、目标时长与速度；不要把定格、音效或 AI 标识预先烧进正文素材再叠一次。草稿画布与帧率取时间线 `delivery: {visual_medium, width, height, fps}`；旧 `canvas` 仍兼容，但不能与快照尺寸冲突。缺少快照时默认 `1440×2560 @60fps`。画布分辨率与源视频、付费增强分别记录，不给正文片段重复叠加按分辨率算出的缩放。
