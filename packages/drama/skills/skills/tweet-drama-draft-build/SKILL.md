# 短剧剪辑与字幕

草稿与成片遵循同一[媒介与交付策略](../tweet-drama-background-render/SKILL.md#媒介与交付策略)：明确 `animation_3d` 时不添加水印、末帧定格、片尾音或特效；`photorealistic` 保留这些交付元素。媒介缺失的旧项目警告并保留旧版行为，不从风格文字或横竖比猜测。

## 剪映草稿目录

仅在准备生成剪映草稿时调用 `drama_draft_dir {}`，读取 Settings 的 `jianyingDraftDir`。返回 `ready` 就使用返回的 `path`，不再询问用户；返回 `unconfigured` 或路径失效时，用 `ask_user_question` 询问“请提供本机剪映专业版设置里的草稿保存根目录”。不要猜测其他机器的路径，也不要替用户创建一个假定的编辑器根目录。把用户回答传给 `drama_draft_dir {path: ...}`；工具验证已有绝对目录可读写、保存同一 Settings 字段并回读，成功后才能生成草稿。工具或保存失败时说明原因并修正，不改写其他设置，不用另一份配置文件绕过。这个步骤不阻塞写作、分镜或视频生成。

将成功结果的 `path` 原样传给 `DraftGenerator.process(..., drafts_dir=path)` 或 `generate_draft(drafts_dir=path, ...)`，不能继续使用脚本里另写的目录。保留已有草稿；名称冲突时为新候选选择唯一 `name_prefix`，不得删除或覆盖旧草稿。

运行前检查 [外部依赖与授权](references/dependencies.md) 和 [输入输出](references/io-contract.md)；此源码包不附带第三方 Python 库、可执行文件或媒体。每集草稿采用与成片一致的已审核 BGM 混合音轨（至少两首，按情绪分段），不把生成器的单文件输入误解为允许一首循环。传入 BGM 目录时每集只能有一份选定混音；多份不能按文件名猜选。选定混音必须覆盖正文全长，导入轨道失败则草稿失败，不能交付无配乐的半成品。生成时长和分辨率取当前所选模型与分镜，不以历史固定镜头秒数或字数限制替代。

输入按任务和镜头排序并通过内容审核。clean/not_required 可进入时间线；pending 仅用于明确标注“未完成，非最终交付”的草稿/预览，由模型安排后续回读并替换来源，不把等待交给用户。未知或 failed 需核查恢复，不得假称完成。最终选用文件必须 clean/not_required 且通过实际文件内容、字幕清理、分辨率和音画 QA。

字幕覆盖全部真实发声，保留原文与说话人：dialogue/台词、vo/画外音，以及已确认实际发声的 os/心声/旁白/解说。少用旁白是创作建议，不是删除原文的许可；未确认发声时先核查音频，不把心理或叙述说明直接变字幕。动作、表情、场景和摄影说明不出字幕。内嵌字幕与后加字幕分别记录，避免重复。去字幕清理的是源视频中不需要的生成文字，最终设计字幕仍按项目已批准要求制作，clean 不表示最终成片必须无字幕。

输出可编辑草稿、SRT、预览 MP4 和镜头/任务来源映射。SRT 由 `drama_render subtitles` 写出（台词计划 + 成片清单 → `editing/<集>.srt`），它同时把每镜的 `actual_speech_start/end` 测出来。`scripts/build_spoken_subtitles.py` 的 build_spoken_cues 默认只接受 clean/not_required；pending 必须显式 draft=True。默认所有发声（包括编译为 vo 的旁白/心声）必须有完整 actual_speech_start/end，否则报缺少音频证据，不静默漏句；仅显式 draft=True 可用带 timing_source=9_chars_per_second 标记的预估时间。该函数只构造 cues，8字/秒预排不是最终校时，也不代替成片 QA。

`drama_render subtitles` 对齐失败时会留下 `<集>.srt.blocked`，即使同名旧 SRT 仍在也不得复用。草稿素材整理和草稿生成都会在覆盖或新建草稿前拒绝该标记；字幕导入失败也必须停止，不能把无字幕的草稿报为交付成功。只有字幕重新对齐全部通过并清除标记后才能继续。

## 视频禁用标签

先用 `drama_video` list/inspect 查项目 `video-bans.json`。labels 至少一个自由可读标签（如“人物对调”），reason 可选，ban 不要证据。标错用 unban；查询无标签或 unban 不等于审核通过。禁用版本不得进入草稿或预览，禁止通用 FFmpeg、手写脚本和直接复制绕过。门禁按本项目实际 SHA256 检查，同字节副本也命中，同路径新字节不继承旧禁用。

`DraftGenerator.prepare_materials` 在删除旧素材目录前检查实际选源；`jianying_draft.main_with_args` 在创建新草稿前检查视频，已有草稿拒绝覆盖。`prepare_materials`、`process`、`generate_draft` 可传 `project`；`main_with_args` 可传 `args.project`。未传时只从素材或视频目录祖先的 `project_config.json` 定位项目；外置素材无法定位时明确补 project，不能当作无禁用继续。纯图片流程不要求该映射。这是官方路径检查，不拦截外部命令。

## 字幕交付样式（固定，不得自行发挥）

- **时间必须来自语音识别对齐，用 `drama_render subtitles` 落位**：先对该镜**自己的**成片（此时还没有任何 BGM 混进来）跑一次语音识别，把每一句的起止时间写成逐镜、镜内相对的对齐文档 `{"shots":[{"shot":1,"cues":[{"text":"识别文本","start":0.0,"end":0.8}]}]}`，再连同 `lines` 一起传给 `drama_render subtitles`。`lines` 是按原文顺序去标点、按语义拆分后的显示字幕计划，每项单行且不超过 14 个有效字；原文覆盖记录另行保留，不能因拆字幕漏字、改数字或改语义。长句的每条显示字幕要分别取得同源字词时间，不能把整句时长均分。**本工具不做识别、不测能量、不估算时间**：能量门限只能说明有人在说话，说不出具体哪句在哪里，估算出来的时间正是字幕压错句的原因。cue 时间 = 该镜在时间线上的起点 + 镜内偏移；字幕显示文字来自 `lines`，识别文本只用于核对是不是同一段表演。缺某一镜的对齐、段数与台词条数不符、识别文本与显示字幕对不上、或该镜的策略不是 `asr_aligned`，都会按 failure 报出并提示该对哪一镜重跑识别；有识别结果却没声明台词同样报 failure。写出的 cue 还会检查时长、重叠、越界与阅读速度（>20 有效字/秒失败，>12 警告）。识别本身的准确度由调用方负责，`speech_alignment` 永远留在 `not_checked`。8 个有效字/秒只作为**草稿预估**，不得用于最终交付。
- **默认使用 Muse 云端字词时间戳**：对每个有实际发声的镜头原视频调用 `audio_transcribe start`，明确传 `purpose: "subtitles"` 使用极速识别，再对返回的同一收据调用 `inspect` 只查询原任务，直到完成或返回明确阻断。`status` 可能按网关恢复指示补传同 ID 音轨，只在获得相应费用授权后使用。独立镜头可并行提交，服务端按账号共享额度排队；未知结果沿用原收据查询，不换 ID 或用途重投。输入必须是该镜头尚未混入 BGM 的真实选定视频，不用整集混音代替。原始收据与 JSON 保持不修改。
- **用云端收据生成对齐**：写 `<项目>/_probe/epNN-cloud-transcripts.json`，格式为 `{"shots":[{"shot":1,"receipt":"<audio_transcribe 返回的绝对收据路径>"}]}`，每个镜头（含声明无台词的镜头）各一项。运行 `python -B <技能目录>/scripts/align_subtitles.py --project <项目根> --episode <集号> --cloud-transcripts <映射文件> --strict`。脚本核对视频 SHA-256 与收据、读取每个字词的实际时间，把当前剧本台词匹配到该镜头音轨；只有 `asr_aligned` 或经收据核查的 `no_lines` 可进正式字幕。缺字词时间、源视频变化、台词未匹配、识别到至少四个连续的未映射字，或一句已锚定的台词仍缺少连续四字时，报告具体镜头并阻止正式字幕；先人工核听，不用整句均分或预估时间替代。没有收据的无台词镜头不能证明静音，必须补齐同源收据。
- **离线只作显式选择**：用户确需离线且自行准备好依赖和模型时，可传 `--model-dir`，或 `--model-url` 与固定 `--model-sha256`。默认安装包不含 Whisper 模型与推理依赖；不自动下载安装。独立脚本仍支持 `MUSE_WHISPER_MODEL_DIR` 的模型解析，以及 `${DSH_HOME:-~/.dsh}/cache/models/faster-whisper` 和 `--cache-dir` 缓存配置。离线识别保持单线程、temperature 0。
- **单行、无标点、按语义切分**。用空格分隔语义组代替逗号句号；1080×1920 设计帧在 40px 边距内可用 1000px，成片正文字号 40。单条不超过 14 个有效字（空格按半字计；字体族由部署配置决定，见 `tweet-drama-background-render`）。超长必须按语义拆成连续两条并分别校时，不许压成两行。
- 字幕文字用剧本原文，不改写、不省略、不合并不同说话人的句子。
- **一集内不得漏句**：交付前逐镜核对 `drama_render subtitles` 的结果——`subtitle_line_coverage` 必须为空，既不能有「声明了台词却没有这一镜的对齐」，也不能有「有识别结果却没声明台词」。具体字词有没有读对（漏读、串词、同音字）只能靠试听判定；`align_subtitles.py` 的识别结果留给对齐用，不参与校核台词对错。

## 剪映草稿字幕样式

剪映草稿字幕固定用系统默认黑体、字号 `11`、字间距 `0`、黑色描边参数 `20`，位置 `transform_y=-0.465625`。**这些是剪映 UI 值，量纲与 `draft_content.json` 里的数字不同**，`pyJianYingDraft` 写文件时按它自己的映射换算：字号原样写出（`11` → `11.0`）；字间距 = UI 值 × 0.05（`0` → `0.0`）；描边 = UI 值 ÷ 100 × 0.2（`20` → `0.04`）；行间距恒为 `0.02 + UI 值 × 0.05`，所以文件里的 `0.02` 是基线而不是设置。核对草稿时按这两列对照，不要拿 `20` 去文件里找。**字体名在草稿文件里没有对应字段**：不给 `styles[0].font` 就是「用剪映系统默认」，没法从文件证明用了哪个字体；`jianying_draft.py` 顶部的 `SUBTITLE_*` 常量是这套值的唯一出处，改样式改那里。它与 FFmpeg 成片的字幕字号相互独立（成片见 `tweet-drama-background-render`，字号 40），改一个不得联动另一个，两边各有测试钉住。仿真人和未声明媒介的旧项目，其剪映草稿与成片都只保留右下角「内容由AI生成」，不加右上角提示。草稿将它写为独立可编辑的白色无描边文本轨，覆盖正文与片尾；它不属于发声字幕，不写进 SRT，不参与字幕条数和台词覆盖率。横竖画布均保留右下安全边距。

**字幕文本规则两条路径只有一套，不得分叉**：去标点、按语义切分、单行、单条不超过 14 个有效字（空格按半个字计），文字都取剧本原文。草稿路径由 `jianying_draft.py` 执行（`normalize_subtitle_text`），写出 `<草稿目录>/<集>.normalized.srt`，按它导入草稿、并按它核对字幕条数；成片路径执行同一套文本规则。**两条路径唯一允许的差异是字体/字号/字间距/描边**：成片按部署配置的字体（默认 SimHei）、字号 `40`、字间距 `-2`、描边按成片像素推导；草稿用剪映系统默认黑体（`draft_content.json` 里不写 `font` 字段）、字号 `11`（UI）、字间距 `0`（UI）、描边 `20`（UI）。改一边不得联动另一边。

**交付前校验**：正文镜头与主音频按原时间线校时（容差 0.2 秒），3D 动画主视频轨只含正文镜头，总时长等于正文，检查无生成的片尾轨、定格素材或 AI 标识；仿真人和旧项目主轨另含一个 2 秒定格，AI 标识覆盖完整草稿。两者均校验字幕条数、样式与文本。BGM 和片尾音是叠加轨，不把它们的时长相加来判定音画同步。失败只清理本次新建草稿，保留已有草稿。时间线缺失或字段名不符时报错，不按默认每段 5 秒交付。

剪映主轨按项目剪辑计划使用任务视频，保留必要收束；字幕预排可参考脚本相对时间，最终逐句按真实音频校正，不以等比例映射代替真实发声时间。保留项目已确认字幕与草稿样式。

## 可编辑末帧定格

以下末帧和片尾步骤仅用于仿真人与未声明媒介的旧项目；3D 动画完全跳过，也不生成定格图和证据文件。适用集在正文后保留 **2 秒真实末帧定格**，不是同编号的分镜参考图。生成器从实际最后一个选定视频的入轨区间顺序解码，抽取该区间最后一帧，并用 RGB `framemd5` 与原视频校验；生成的 `Resources/last_video_tail_frame.png` 作为独立可编辑图片片段加入主轨，同时写出 `ending-evidence.json`。源视频或提取失败时报告原因，不交付空片尾。若同镜头编号同时有视频和参考图片，只使用选定视频，不重复铺图。

时间线沿用 `clips` 与 `body_end`：通常 `body_end` 等于正文最后镜头结束，草稿总长再加 2 秒；若已选媒体的最后片段已经含片尾，明确保留原正文 `body_end`，片段末尾只能比它多 2 秒。生成器把这 2 秒替换为可编辑定格，保持总长，不再次追加；已有整段音轨里的片尾音也不重复叠加。不要仅凭静止画面、文件名或音轨较长就猜测已有片尾。

使用与成片相同且已选定的片尾音/特效时，在 `DraftGenerator.prepare_materials` 传 `ending_audio`、`ending_effect`，或把文件分别放在 `06_ending/ending_audio.mp3` 和 `06_ending/ending_effect.mp4`。它们从 `body_end` 起以原速单独入轨，最多覆盖 2 秒，特效采用滤色叠加；不要把定格、音效或 AI 标识预先烧进正文素材再叠一次。草稿画布与帧率取时间线 `delivery: {visual_medium, width, height, fps}`；旧 `canvas` 仍兼容，但不能与快照尺寸冲突。缺少快照时默认 `1440×2560 @60fps`。画布分辨率与源视频、付费增强分别记录，不给正文片段重复叠加按分辨率算出的缩放。
