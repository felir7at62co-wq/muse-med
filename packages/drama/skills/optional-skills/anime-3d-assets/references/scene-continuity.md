# 场景家族、色卡与受控变体

本页与 [无人场景与参考隔离](scene-assets.md) 同时用于场景规划、生成和复用。已有项目继续使用权威资产清单；以下字段写入 schema 2 的既有 `generation.prompt_parts`、`identity`、`state` 和 `dependencies`，不另建采用状态。

## 先建立可追踪空间

读取实际拿到的全部剧本范围，将地点别名归并到场景家族。堂屋、厨房和院落属于同一住家时共享建筑语法、色卡和结构版本，但各区域保留独立资产。逐条标明原文明示、用户确认、美术建议或未知；只有片段时记录覆盖集数，不冻结未提供的全剧布局。

空间说明至少包含区域连接、出入口、楼层与高差、固定物、视线遮挡及可用通道。文字中的“右边”和图片中的“画面右侧”均需写观察基准；没有地图或依据时不用东南西北。角色路径留在本地说明，生成正文改写为门洞、净空、通道和无遮挡区域，不带入角色姓名或动作。单张图看不见的区域按 [真实资产交接](identity-and-grounding.md#实际资产到分镜的交接) 保留未知。

## 一个资产一个职责

| `scene_continuity.role` | 用途 | 继承范围 |
| --- | --- | --- |
| `SCENE_FAMILY_MASTER` | 建筑或地点共同结构与美术基准 | 已知总体关系，不臆造隐藏户型 |
| `ZONE_MASTER` | 厨房、堂屋等可独立拍摄区域 | 家族年代、构件、材质与色卡 |
| `CAMERA_VIEW` | 同一区域的反打或新视角 | 只改变相机，固定结构与陈设不变 |
| `STATE_VARIANT` | 同机位日夜、雨雪雾等环境版本 | 只改变登记的环境因素与直接物理反馈 |
| `DETAIL_INSERT` | 已有构件的剧情局部 | 不重新设计构件 |
| `CONTINUITY_MAP` | 平面、连接或轴测说明 | 作为内部空间说明，不冒充场景成图 |

结构变化、增减家具、灾后损毁和新增灯具属于有剧情或用户依据的结构／内容状态修订；使用新的 `ZONE_MASTER` 修订或独立状态资产明确列出变化，不伪装成天气派生。临时酒菜、手持物和单集摆设不冻结为全季基础陈设。需要复用的手持物单列道具；固定灶台可以属于区域布局。

## 项目色卡与中性基准

沿用 `style_revision` 和 `project.style.palette`，登记色名、适用材质、主辅与强调色、饱和度、对比及暗部倾向；有已确认色号时保留 HEX/RGB，没有则不编造锁定值。色号辅助沟通和后期，不能保证生成模型逐像素复现。物体固有色与照明颜色分开记录，雨夜的冷光不能把灰蓝木门改成另一种漆色。

优先建立清楚展示结构与固有色的白天母版。全剧只有雨天时可用雨天白天基准，不为凑晴天增加制作；现有合格母版直接复用。夜戏仍登记真实夜晚用途，白天基准不改变剧情时间。若用户只要求某个夜景且没有母版，先交付该候选和依赖缺项，不能把制作白天基准当作未经授权增加付费任务的理由。

## 锁定块与变化块

每条提示词保持3D动漫媒介与 CG/PBR 开头与场景专用结尾。中间按“家族与色卡 → 当前区域固定结构 → 本次变化 → 机位与共享锚点 → 输出与排除项”展开。固定块在同一版本内使用相同文字，变化块只写本次确实改变的内容；完整复写，不能依赖“同前”。

`generation.prompt_parts.scene_continuity` 使用 `role`、`family_id`、`locked`、`delta`。`locked` 至少含 `layout`、`materials`、`palette`、`camera`，可添加 `fixtures`、`connections`、`scale` 等已确认固定项。`delta` 是变化字段到具体目标的对象。该对象保存结构化计划，完整最终提示词仍写 `final_prompt`，不得将 JSON 当成平台参数。

`CAMERA_VIEW` 的 `delta` 仅含 `camera`，`locked.camera` 写目标机位；其他锁定字段与父版一致。`STATE_VARIANT` 保持所有 `locked` 字段一致；`delta` 仅使用 `time`、`weather`、`lighting`、`wetness`、`visibility`、`snow` 中适用项。湿润只影响露天或真实进水表面，雨夜不让完好室内凭空漏雨。只点亮父版已有且符合时代的灯具，不增减灯、门窗、家具、动物或车辆。

父版写入 `dependencies`，标 `purpose=scene_parent`，包含明确 `project_id/asset_id/variant_id/revision`。这是派生来源；`parent_revision` 仍只表示同一资产变体被修改的前版，不用来替代跨资产依赖。生成前查父版真实文件与审核，计划中的父子依赖不等于已绑定参考。父版候选未通过时可以写派生草案，不能提交依赖它的正式生图。

## 生产与复核

先审核母版，再制作依赖母版的视角或状态；不同家族的独立母版可按当前工具与授权并行。每项有唯一修订、完整提示词、预期文件与独立任务记录。批量上限按当前工具 schema 和目录，不照搬外部示例的十张、九并发或旧报价。一次多项请求不保证后一项已经引用前一项；只有真实上传或服务端引用记录才能证明绑定。

逐张比较门窗、家具、数量、尺度、材质、固定色卡、共享锚点及当前允许变化；沿用 `review.quality_checks` 新增 `scene_continuity`，记录观察和文件。基础结构或色卡版本改动时，将依赖它的子版与镜头记录为待复核，保留旧修订，不自动覆盖或重生。具体提示词和两个可运行记录见 [生产案例](production-examples.md)。
