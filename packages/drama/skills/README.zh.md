# @deepseek-ai/dsh-drama-skills

[English](README.md) | 中文

分镜编写按集保存原文到镜头的对应记录，核对台词、说话人、动作与表演信息。Agent 读取项目已确认的画幅与风格，使用会话选择的视频模型与分辨率，按镜头计算各包时长，整批检查后并行提交。

## 概述

创作和审核短剧脚本、复用资产、维护项目状态、准备可编辑草稿、渲染分集、组装整剧交付，以及认领剧变剧本池里新放出的剧本。入口是按当前任务选择的 `skills/*/SKILL.md` 文件。Python 脚本与必要静态资源一起分发，其中包括渲染器要用的片尾特效与片尾音。用户项目、凭据、逐项目媒体及本地运行环境不随包分发。

## 使用本包

镜头脚本技能的元数据说明创作、改写及原稿转分镜的适用任务，分别面向已确认的 9:16 竖屏仿真人与 16:9 横屏 3D CG 项目。媒介或画幅不明确时先核对已有项目设定；技能选择不改变这些设定，也不将镜头脚本指导用于普通分场剧本排版。

[首轮制作流程](skills/tweet-drama-core/references/first-pass-production.md)让准备与审片使用同一套有原文依据的动作及道具要求，覆盖身体支撑阶段、素材适配、同场状态延续、实际准备提示词以及收费修复前的局部证据。它不保证随机生成器的首轮结果，也不替代实际听校和视觉审核。

动作有争议时，巡检技能的`video_review_evidence.py`在新本地目录生成带现有音轨的连续区间、每页最多六帧的拼图，以及源文件和证据哈希。它依赖Pillow与本地FFmpeg/FFprobe，保留现有文件，不发起网络请求，媒体审核始终为待验。见其[输入输出规则](skills/tweet-drama-project-inspect/references/io-contract.md#motion-evidence-extraction)。

[通用视频质量流程](skills/tweet-drama-core/references/production-quality.md)覆盖各项目的表演时间、场景与跨包连续性、实际准备提示词、基于证据的音画审核及局部返工。镜头脚本可用[编译器表演字段](../tool-shot-script/README.zh.md#script-and-timing)声明同步或串行的动作、发声与反应预算。未审核实际结果时，这些检查和指令不能证明生成音画质量。

[项目检查技能](skills/tweet-drama-project-inspect/SKILL.md)提供只读本地巡检`inspect_evidence.py <project>`。它核对收据源文件哈希和原始转写输出，给出复用候选，并提示明确宣称可交付却仍承认未听校的矛盾。JSON输出是审核依据，不代表媒体通过、提供方实时健康或新增收费门禁；它不改项目文件，也不发起网络请求。

覆盖审核和发声预检共用对原文已列人物的普通括号表演说明的识别，适用于原文和分镜的说话人前缀。面向已列人物的提问动作描述，紧接同一人物的独立对白时可保留为动作；引号中的内容、身份和发声歧义仍须检查。完整原文、说话人、台词和OS/VO仍须一致。现有`shots/EP13-9x16.md`可直接映射，无需另建改名副本。[既有项目迁移](skills/tweet-drama-core/references/io-contract.md#existing-project-migration)可对显式指定的范围内单集使用带`--episode-only`的`accept`和`gate`，不改项目范围、不省略本集证据检查。默认的前序检查保持不变；历史验收缺失不要求重做已经完成的视频。

建映射时，`episode_coverage.py <project> source-lines <ID>`使用同一上下文分类返回每条非空原文。待核对行也保留可见；该只读命令不替换映射、不分配镜头、不签发覆盖验收。使用其结果，不用独立内部函数的单行结果建映射；核对镜头归属，修改映射后重新验收。

写分集前使用`episode_coverage.py <project> source-scan`核对原文完整性，提前暴露整个声明工作范围的待识别表达。结果定位到具体集和原文行，不修改原文、范围、映射或验收。各题材共用相同准备要求；原文依据的验收标准在首次提交前确定，媒体审查沿用同一标准。

已确认身份使用结构化表演括注，包括成对及嵌套分组，不依赖题材或动作词字典。人物表标签支持多种写法；没有人物表时可从独立无括注对白确认身份。表演说明旁单独明确的OS/VO标记保留发声身份，原文与分镜共用规则且不改文件。标记动作行可识别有声响后缀或物理撞击依据、成对引号包裹的受支持物件拟声；剩余发声提示、引语或冒号内容仍待核对。末尾发声引导要求紧邻同一已列角色的对白，精确结构标记保留为标题行。诊断区分未支持格式或备注与身份、时期、发声方式、引语和相邻说话人歧义；修复识别支持，不为凑格式改原文，不以人工备注替代验收，也不提供绕过选项。见[原文分类规则](skills/tweet-drama-core/references/io-contract.md#episode-work-scope-and-coverage)。

[后台成片技能](skills/tweet-drama-background-render/SKILL.md#剧变视频转高清)指导已授权的 SeedVR2 / RunningHub 转高清。默认在指定分集和视频包内选最新生成结果，使用其当前处理后的视频，提交一次并后台观察受理任务。高清结果成功、归属匹配且有当前输出地址后直接采用；仅在另行要求时增加画面、音频和元数据检查。已有明确高清授权不逐条重复确认，仅有分辨率提示不授权付费。其[剧情配乐指南](skills/tweet-drama-background-render/references/story-bgm-selection.md)根据采用视频的情节转折确定音乐意图，保留已有原声音乐和用户反馈，通过 `bgm_match.story` 查询候选，并区分曲名/标签证据与真实片段、混音试听。

解析本包的 `package.json`，再把同级 `skills` 目录交给现有技能加载器。本资源包不注册 Service、Tool 或插件。仅安装 npm 包不会激活技能。参考图可来自用户文件或已有的网页搜索、抓取工具；技能目录不包含小红书客户端及服务配置流程。

[16:9 横屏 3D 镜头脚本技能](skills/shot-script-creator-16-9-3d/SKILL.md)与[9:16 竖屏仿真人镜头脚本技能](skills/shot-script-creator-9-16/SKILL.md)提供用户选定的镜头语言、主体状态追踪与创作示例。它们引用的[导演文本示例](skills/tweet-drama-early-shot-script/references/director-format.md)演示入画主体、人物身份与发声，不包含编译器调用或资产 manifest 登记。Muse 在每集编写前加载适用技能，通过剧变原生视频卡预览、保存和回读；操作以会话视频选择与当前工具 schema 为准，不因加载技能改变项目媒介或画幅。分包依据剧情、表演和所选模型已核实的能力，不设固定十五秒信息密度规则。

按任务选择相关技能，调用脚本前先读取。保留技能目录相邻：草稿、渲染和交付共用 core 的视频禁用检查。使用 Python 3.11 或更新版本。图片辅助模块需要 Pillow，文档辅助模块需要 python-docx，草稿生成需要 pyJianYingDraft；其他可选依赖由各技能说明。同名草稿已存在时拒绝生成，不删除旧目录；每个候选版本须使用不同的 `name_prefix`，且不能包含路径分隔符或 Windows 保留字符。包内不附带 Python 解释器、依赖环境或 FFmpeg 二进制。

内置的 [3D 动漫资产技能](skills/anime-3d-assets/SKILL.md)为短剧提供人物、场景与道具设计指导，默认保留次世代 CG、物理可信 PBR 风格前缀。[风格参考](skills/anime-3d-assets/references/design-and-prompts.md)支持自然语言美术设计和可选题材修饰；资产版式遵循调用方系统提示词与用户明确要求。人物设定板左侧为面部特写，右侧为保留完整头部、发型与脚部的正、侧、背全身三视图；仅右侧可见脸部覆盖纯白，背面保留后脑与头发。这是提示词指导，不增加生成校验或重试。随包图片和本地记录辅助工具是可选资源，不是生成前置条件。3D 与仿真人都以故事、情绪与视觉吸引力为创作目标，不要求固定五官描写、提示词顺序、审美分数或独立审核报告。既有项目状态、付费额度和真实确认出演记录仍是权威依据。

[项目圣经技能](skills/tweet-drama-project-bible/SKILL.md) 用一次集中问题询问缺少的创意与实时 SD 模型选择，复用已给答案，并通过 drama_project 保存审阅后的更新。媒介题提供仿真人、3D 和其他（自行输入）；保存风格时保留用户自填原文。[受众与影视风格指导](skills/tweet-drama-project-bible/references/audience-and-style.md)结合实际剧本和用户认可的参考，设计人物魅力、关系张力、情绪回报与美术方向。创作假设与市场证据保持区分，不要求固定分析模板、额外报告或模型轮次。生成分辨率与交付尺寸分开；可选角色声音指导伴随说话人核对与实际听音审核。Wiki 参考指导写作，不阻塞启动。已有项目保留稳定视频包/分镜身份、已完成任务和版本记录。

Agent 按剧本与已确认项目要求准备角色、场景和道具需求。[视觉审核技能](skills/tweet-drama-asset-vision-check/SKILL.md)依据当前明确要求与 `project_bible.style` 检查候选；预设名、参考图媒介与模型名称都不提供默认风格。审核同时核对已定观感、身份与材质质量。仿真人玄幻生物可采用电影级特效；非人类资产保留剧本物种与尺度，不套用人类面部设定板版式。

[资产匹配技能](skills/tweet-drama-shot-asset-match/SKILL.md)区分稳定角色、父资产与已采用图片版本。新增换装或状态图时显式复用已认可人脸参考，素材记录保留材质 ID、URL 与审核依据。候选不自动替换已认可出演。分镜保存的图片引用冲突时明确重选来源，而不是再次付费生成；普通视觉不确定性采用集中预览，不新增审批工具。共享参考可减少可避免的身份变化，但不保证生成模型始终保留同一张脸。

草稿生成通过 `drama_draft_dir` 读取本机设置；编辑器根目录缺失或无效时询问用户，再通过同一工具保存用户提供的路径。请求 JSON、时间线 JSON 与 SRT 接受带或不带 BOM 的 UTF-8，保留输入原始字节。字幕对齐默认使用已完成的 Muse 云端收据，核对字词时间戳与源文件 SHA-256。全部匹配的台词保留实测时间；锚点无效、重叠或超出镜头时失败，不改写时间后仍标为已对齐。草稿字幕导入同样保留起止时间，拒绝没有逐句对齐时间的长句，详见[输入要求](skills/tweet-drama-draft-build/references/io-contract.md)。显式离线识别需要另行准备依赖和模型。

[草稿技能](skills/tweet-drama-draft-build/SKILL.md)通过同一工具选择 Windows `audio_mode: "embedded"`，保留视频原声和独立 BGM；未声明模式时兼容独立音轨请求。随包 aa剪映适配器使用已安装剪映的原生 CLI，检查实际能力，失败时明确报告而不换用其它渲染器。[云转写字幕指引](skills/tweet-drama-draft-build/references/cloud-subtitles.md)复用同源收据与实测时间戳，在派生文件中显式纠错并保留字词时间和原始证据。制作草稿本身不要求重新提交转写或编码预览。 Windows 原声模式仅为 `9:16` 添加片尾，`16:9` 在正文结束；原文件保留与原生帧落位偏差分别记录。

旧独立音轨草稿按项目明确的视觉类型交付：`animation_3d` 在正文结束，不添加水印或片尾轨；`photorealistic` 保留两秒可编辑定格，并在右下角用独立文字轨全程显示纯白无描边“内容由AI生成”。旧项目未注明类型时给出警告并保留后者行为，不去除源素材已有标记。[草稿输入要求](skills/tweet-drama-draft-build/references/io-contract.md)说明已含片尾的输入如何使用 `timeline.body_end`，避免重复追加。已存在的草稿目录保持原样。有独立对白轨且正文视频音量非零或未声明时，轨道检查提示可能重复对白，保留候选和可编辑对白。Windows 解码器启动返回 WinError 2 或 5 且没有 filename 时，在原错误说明后追加选中的可执行文件路径。

项目 `delivery.draft_style` 独立保存剪映 UI 单位的字幕和水印设置，不与正式渲染像素混用。时间线已有该节时整节优先，缺字段保留草稿旧默认。字体引用和明确回退记录在 `muse-review.json`，不下载字体或宣称已获许可。片尾覆盖视频静音，独立片尾音保留；它是视频图层，不是编辑器原生参数化特效。详见[草稿输入要求](skills/tweet-drama-draft-build/references/io-contract.md)。

旧独立音轨路径中，全部正文素材均为视频，且各选定源时窗的实际画面时间戳确认其帧率恒定并与项目 fps 一致后，草稿生成将共享镜头边界和尾帧补齐放到完整项目帧上。正文、片尾和AI标识使用同一目标时钟，证据保留原正文时钟及取整差值。不改写源文件、对白、配乐或字幕时间。帧间隔不支持、依据不足、正文含非视频素材或镜头量化为零帧时，保留原微秒路径并给出审阅提示。保存文件的验证不能替代剪映中的打开、重开和导出。

[声线参考技能](skills/tweet-drama-voice-continuity/SKILL.md) 让同角色不同服装版本复用认可的声音样本。没有样本时，从该角色首次生成的视频中提取已试听、清晰的单说话人区间；默认 2 秒，参考上限 15 秒。脚本保留源文件，拒绝已有输出，报告实测时长与哈希；确认说话人需要实际听音，Agent 不能检查音频时由用户确认。上传和绑定保留原分镜 ID。音频参考用于引导生成，不能保证 SD 各次输出的音色完全一致。

选定参考图的导入使用 `tweet-drama-core/scripts/asset_library` 中的只读辅助模块。它们优先使用 `JUBIAN_ASSET_LIBRARY_ROOT`，否则使用 `$DSH_HOME/data/jubian-asset-library`，其中 home 默认是 `~/.dsh`。媒体路径从当前数据根解析。core 的 `import-library` 仅把用户选定的人脸与全身图配对归档到项目，保留原库，并要求审核与可追溯的用户确认后才能进入付费生成。

分集覆盖检查和流程状态投影共用[显式工作范围规则](skills/tweet-drama-core/references/io-contract.md#episode-work-scope-and-coverage)。协作者可以完成已分配的集，不必补做前面的集，也不能因此宣称整剧完成。分工拆分保留其他协作者的清单条目和文件；验收仍校验当前原文、映射与镜头摘要。支持独立工作目录后合并产物，不协调同一本地项目的并发写入。

[逐集生成质量流程](skills/tweet-drama-core/SKILL.md#逐集生成质量流程)在写卡前运行离线检查 `episode_coverage.py <project> preflight <episode> --script <shot-script>`，也适用于只做单集的任务。支持标准镜头标记及逐包 Markdown 镜头标题和列表；分集原文不在 `episodes/` 时可用 `--source` 指定文件。检查有序发声内容、说话人及对白/非当场发声方式，报告漏词、增词，无法识别的来源表达保留pending。它不签发验收记录，不替代带映射的动作/OS/VO覆盖、收费保护、听校或视觉审核；输入变化后重查受影响集。[道具与剧情动作适配](skills/tweet-drama-asset-vision-check/SKILL.md#道具与剧情动作适配)在生成前对照剧本使用方式核对选用图的相对尺度与结构，并在成片中检查接触和连续性。影响剧情成立的未修缺陷使整体不能通过，即使用户暂缓修复也一样。这属于Agent审核指引；发声检查脚本不识别图片，也不提供全局收费工具拦截。

交付使用自带 `assets/template.json`，保留 `01` 到 `9999` 的规范集号，`14` 和 `140` 是不同文件名。显式 `TWEET_DRAMA_TEMPLATE` 必须是已有目录；它不替换九目录名，也不导入第三方文件。组装会删除受管输出分区中的过期文件。项目内输出必须留在 `delivery` 下；项目祖先、上游重叠及已有输出内的链接会被拒绝。报告输出到 stdout，不写报告文件；复制不等于 SHA256 核对或完整媒体 QA。

剧本池查询与认领使用[抢本技能](skills/jubian-snatch/SKILL.md)。认领是真实的远端写操作，会把剧本归到调用账号名下。池子读取会翻页，读不完时如实报告，而不是把某一页当作整个池子。启动基线读取失败或读不全时，在发出任何认领之前就退出，认领范围不会因此被悄悄放大。每次认领都过两阶段本地账本：已确认或结果未知的剧本绝不重复提交。认领后的回读只认「行里写着本账号」这一种证据，剧本从池中消失不算。

共用的[动作依据流程](skills/tweet-drama-core/references/first-pass-production.md#动作依据用途与手部状态)区分实际动作与台词条件，保留明确示范和剧本失误，提交前统一双手、物件用途及落点。维护者可在独立技能测试中使用[跨题材样例](tests/fixtures/action-intent-cases.json)；预期检查项是审阅依据，不是自动语义或媒体评分器。

在本包目录运行离线迁移检查：

```sh
npm test
```

随包 `prepare_voice_assets.py` 还在视频成功下载后提取完整混合音轨及缺声线角色候选，保留当前 voice_profile，并按任务/来源/角色/区间身份继续执行。操作系统释放的锁和原子清单合并保留其他样本及音轨记录。整段长音轨留供剪辑，含背景声的两秒讲话参考允许选用；没有区间时报告缺口，不猜说话人。请求字段和选用流程由声线技能负责。

## 理解实现

<details>
<summary>维护与打包</summary>

本目录是维护源码。初始输入来自操作者 `.dsh/skills` 中同名技能的指定 `SKILL.md`、`scripts`、`references` 及相关测试。仅保留这些 DSH 技能实际使用的依赖。已安装的个人副本保持独立，不自动同步。

`package.json#files` 逐文件列出分发内容，不使用家庭目录整树或宽泛目录 glob。包排除凭据、cookies、缓存、日志、虚拟环境、可执行文件、用户索引、逐项目媒体和第三方模板 PDF；包内唯一的用户媒体是渲染器要用的两份片尾素材。测试只保留在源码中，不打包。这个私有、未授权许可的资源包没有 Cordis 入口或 TypeScript 项目。不发布运行时 invariant 伴随模块，因为静态技能文件没有可独立变化的运行时观测。

完整的 `anime-3d-assets` 资源树随包提供给文件系统技能加载器。更新源码不会同步个人技能副本或已安装版本。

发布检查会逐一比对实际 npm 压缩包与文件清单，遗漏、未登记或内容过期的资源会在桌面端打包前报错。镜头提示词与视频包由 Agent 自主编写，经原生分镜预览检查，不内置镜头编译技能。

<a id="model-experience"></a>
## 模型体验

### 加载后的技能指令

#### 模型看到什么

加载技能会通过消费应用的技能加载器加入维护中的 `SKILL.md` 指令。检索结果和脚本输出仅在请求时进入上下文。本包不注册工具，也不自行发起模型调用。付费视觉标注脚本仍是显式维护动作；项目模型规格与交付设置仍是依据。

#### Token 影响

每次加载技能会加入其指令文本；请求的脚本输出会增加结果文本，大小取决于操作与项目。仅安装资源文件不会增加 token。消费应用的技能加载器和工具执行路径负责选择与输出限制。

#### KV Cache 影响

加载指令或返回脚本输出会通过消费应用追加上下文。资源包不改写已有消息，也不控制提示词顺序；缓存复用取决于该应用的加载器和上下文策略。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- 可选的动漫请求预检是既有本地记录流程的只读辅助工具，普通资产生成无需执行，也不是全局工具拦截。它接受正向媒介前首行内精确的项目风格前缀，拒绝实际请求中提供的非 `anime` 生图选择。有限文本规则拒绝明确的 PBR 禁用要求和正向摄影媒介指令，保留直接的摄影排除语句与已提供的动画方向。它不改写提示词、不校验全部工具字段、不发起提供方请求，也不能证明生成图片的视觉质量。
- 当前 Web profile 仍需消费方显式配置技能加载器、凭据注入和 Python 依赖。本包不改变根配置，也不宣称正在运行的 Web 会话已使用这些资源。
- 草稿脚本使用调用方指定的输出目录；它既不会定位组员已安装剪映的真实草稿根目录，也不会自动将渲染的 MP4 与经过验证的可编辑草稿配对。
- 操作者已明确授权公开再分发维护中的技能源码和两份片尾素材。`private: true` 与 `UNLICENSED` 不向其他人授予修改或再分发本包的许可；外部 Python 库、字体、模型及其他媒体仍须分别确认权利。
- 当前 DSH 短剧工具负责模型目录、视频卡编辑、付费提交和凭据访问。本包不提供这些工具，也不恢复旧应用的独立状态文件。重要角色的用户图片需视觉审核和用户确认；无适用图片时，Agent 自主检索网上素材，核对来源页、许可、本次商业生成参考与向提供方上传的权利及视觉适用性，归档图片并记录自身审核，再运行 core 的 `style_references.py` 检查。缺少可用证据只暂停受影响角色。网上照片仅作生成参考，不成为最终入镜主体。这是技能工作流前置，不是付费工具内部拦截或付费授权。可选小红书须用户明确另选且提供合法配置、已确认账号归属的端点，不自动安装、下载浏览器或复用旧服务，登录态不分发。
- 迁移测试不执行提供方请求或真实项目组装。资产数据迁移须单独保留或显式重映射已存绝对路径。媒体 QA 和复制哈希核对仍由调用方负责。
- 抢本技能不随包分发 PyQt6 桌面客户端，也不含源项目的联网人工探针，两者仍是本机工具。其认领路径只有针对假传输层的离线测试覆盖，因此迁移期间没有发起过真实认领，也没有对线上服务做过端到端验证；账本、分页与回读规则同样只在离线得到验证。
