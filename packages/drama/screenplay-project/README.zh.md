# @deepseek-ai/dsh-screenplay-project

[English](README.md) | 中文

## 概述

`screenplay_project` 导入不可变的小说原文或带时间码的语音，分配来源片段编号，并从已审校事实生成结构化剧集。默认采用独立审校；显式配置的创作部署可以改为记录同会话分轮自检。验收逐集推进，后续工作读取已验收状态，不依赖模型自行编写的进度摘要。

## 使用本包

### 何时选择

小说、视频和换梗改编项目需要以来源为依据逐集独立验收、中断后恢复时，使用本工具。不需要分集验收的自由创作可以直接使用现有写作技能。

### 最小配置

在已挂载 `fs`、`tools`、`attachments` 和 `llm` 的 `dsh` profile 组合中添加：

```yaml
- id: screenplay-project
  name: '@deepseek-ai/dsh-screenplay-project'
  config: {}
```

| 字段 | 默认值 | 含义 |
|---|---|---|
| `reviewMode` | `independent` | `self-check` 显式将新创作项目设为同会话分轮自检 |
| `refinementMode` | `disabled` | `source-preserving-v1` 显式开放创作精修分支；禁用时保留原模型参数定义 |
| `storyFaithfulMode` | `disabled` | `story-faithful-v2` 开放限于当前作品的视频创作与定位明确的分轮语义自检 |
| `maxSourceBytes` | `16777216` | 单份原件的最大字节数 |
| `maxProjectBytes` | `33554432` | 项目文件的最大字节数 |
| `maxReadUnits` | `100` | 一次操作的来源片段、事实或场次文件数量上限 |
| `maxReadBytes` | `65536` | 来源窗口或单个场次文件编码后的最大字节数 |
| `maxFactBatch` | `20` | 一次原子修改可提交或独立审校的最大事实数量 |

[配置目录](../../../docs/config-catalog.zh.md#deepseek-aidsh-screenplay-project) 维护接受的配置字段。这些预算不限定剧集或章节数量。

### 故事忠实视频创作

显式创作部署配置 `storyFaithfulMode: story-faithful-v2`、`reviewMode: self-check` 及可信 `video_inspect` 证据。新视频转剧本任务采用故事忠实目标；逐字稿、字幕任务仍走普通严格路径。`init_story_faithful` 绑定最新真实用户请求、实际视频原件版本、每个视频的对应集号、集号范围及有限补充类别。单视频单集范围自动关联，多个视频或集号须明确关联。模型须核对用户要求的作品与范围，原话真实性本身不证明授权语义。同一作品范围内的情绪、口语对白、反应和可拍表达强化可复用授权，无须逐句询问。重大事件、动作结果、关系、立场、动机、条件、因果或揭晓顺序变化需要新的明确范围。改编模式和自由理由不能授权这些变化。

作者直接从原作品整理当前集来源事实与故事清单，无须先制作完整逐字剧本。清单五维覆盖事件、动作结果、情绪冲突、关系立场和因果揭晓；确实不适用的维度须说明理由。每项保留已审来源事实与真实片段定位、关键/未知状态、因果依赖及必要听者。清单编写、实际来源/清单读回和审校分属不同模型轮。`story_notes` 将每项映射到真实成稿场/节拍/文字，为全部本集来源事实说明保留、合并或非故事性省略，记录来源到成稿的变化、场次安排及批注采纳状态。新作品使用来源定位，不捏造 before 文本；修改真实输入稿时保存有界的准确候选快照，多轮修改不递归嵌入全部历史快照。

故事忠实候选允许拆合场及调整原来源表现渠道，同时保留关键行动、真实归属、叙述层和人物知情。原 ASR、观察片段与来源事实保持不变。获准的短 OS、反应或承接对白保持 `origin: adaptation`，通过 `story_supplement` 绑定实际作品授权与本集上下文；作者分析来源不能重标为角色心理。关键公开发声不能改为私人 OS 却仍让听者获得其含义。来源动作保留原行动者和实际画面证据，来源发声保留文字证据。

`video_inspect` 先探测实际时长并规划完整区间，再生成真实采样帧清单。Host 核对成功工具结果、每级外层 PTC 成功结果，以及后续成功图像模型请求确实包含全部帧。模型自行填写的 metadata 或 `verified_readback` 不能证明这些事实。本集所关联完整原视频的每个探测窗口须有实际图片证据，模型填写的 coverage 区间不能裁掉其余时段。本版本不支持将同一原视频按裁剪区间拆为多集。采样不代表连续观看。V2 可以不耗尽非关键启发式候选点，但关键未知证据仍为 pending。普通严格/V1 视频保留原有待查点补齐要求。新增来源/帧版本或相关来源事实使未验收清单失效；后续集追加来源时已验收集保留其绑定版本。状态报告未解证据，中断的当前集可重新 inspect、读回并提交新清单。

候选 A 编写后，B 实际读回完整当前候选、清单、本集原来源及必要已验收前情。后续 C 模型轮提交 `semantic_report`：重新复述事件、情绪冲突、关系立场、因果揭晓，并逐项给出准确来源/成稿定位判断。Host 派生策略、清单、候选及本集范围摘要，绑定报告与最终验收。任何声明偏差或未核实判断都会阻止批准。机器核对引用、位置、摘要、真实分轮及声明偏差；艺术和故事语义仍由模型判断，不是自动语义检测。commit 等待 C 工具及每级外层程序成功，不能在一个尚未结束的 PTC 程序中 review 后直接绕过此要求。

`fork_story_faithful` 从普通原项目显式建立新分支，保留已验收前缀及原审校身份，准确保留原演绎事实但不授予新的补充权限，将旧来源索引关联到获授权视频，并保存选定的真实输入候选。它不要求完整逐字基线，也不修改原项目。现有 `source-preserving-v1` 分支不能直接切换策略，可从保留的原作品新建 V2。export 保持正文纯净，另交付最终版本绑定的修改说明。正式 export、Word 和呈现消费方须先通过 `validateAcceptedStoryEvidence` 核对可信检查与成功 C 轮原日志，再使用 `acceptedScripts`。已验收冷恢复核对原 Session 事件引用与当前来源字节，无须重新抽帧；原日志缺失会阻止正式验证。保留的旧独立审校前缀沿用原检查，无须 V2 证据戳。

### 保源精修

显式配置的创作部署可设置 `refinementMode: source-preserving-v1`，并须有实时 `sessionProjections`。`fork_refinement` 指定实际基线候选编号、连续集号范围、范围说明、当前可见真实 `source: user` 消息中的准确原话、模型的授权语义判断，以及 `performance_detail`、`minimal_os`、`supporting_dialogue` 的明确子集。空子集仅允许有来源依据的表达和展示调整。Host 根据实际会话生成消息编号、序号和摘要；附件、工具、助手及第三方材料不能授予权限。原话匹配只核对文本真实性，不证明授权语义。模型须逐项核对用户本人的意图与类别；同一项目范围内可复用一次授权。旧版阻塞式提问工具的普通返回值不构成真实用户证据，须使用用户直接回复。改编模式和改编理由都不自动允许补充。

分支保留原项目与来源文件、原事实正文、模式、方向及历史审校类型，保存实际输入候选的完整快照，并为限定策略生成摘要。此版本只精修场次元数据不变的节拍，拒绝修改场次数、地点、时间、人物、叙述层及转场。实际基线的来源编号、覆盖窗口和必保留表达清单保持不变。原来源事实保留唯一首次出现顺序、表达渠道、人物、可闻性、见证者和知情条件；完全重复的表达可合并。这些结构检查不证明剧情语义保持。新事件、关系、动机、关键台词及揭示顺序变更须另行确认流程。

获准补充事实仍标为 `origin: adaptation`，保留理由、本集原基线来源引用，以及 `supplemental` 中的类别、策略摘要与授权摘要。表演细节属于指定人物的动作，最小 OS 属于本人的心理，承接对白属于本人的发声。原来源事实不能重标。原作者分析保留原表达，明确获准的本人心理可另建为改编事实。视频转剧本仍保留正常来源要求；只有明确且有效的精修候选可使用限定补充例外。禁用部署拒绝精修写入。

每次精修 `stage` 或 `stage_files` 须提供 `modification_notes`：准确定位的原文与改后节拍及理由、编辑意见的采纳/部分采纳/未采纳/未知状态、未解决与未处理工作，以及有限语义和视觉检查范围。每条变更的基线节拍须有原文位置，每条变更的新节拍须有改后位置；错误文本和空模板均被拒绝。视觉声明只能引用输入或输出范围内的真实图像片段。Host 先生成输入/输出版本引用、正文摘要、补充归属和机器检查范围，再为完整候选计算摘要。同会话候选重读包含完整基线及两个版本事实、知情前提和来源窗口的并集；继承的历史审校保持原上下文摘要。

可选动作 `sync_with` 使用 1 起始序号指向同场相邻发声节拍，并填写 `synchrony_reason`；仅有效的明确精修候选可用。渲染器保留动作事实及原顺序的人物知情更新，在同一人物发声括注中只显示一次动作，并在来源行索引保留两个渠道，不能把动作改成对白或补造 OS/VO。`rendered.script` 与已验收 Markdown 保持纯剧本，可选 `modification_notes` 单独提供说明。`export` 在剧本和来源索引旁写入 `episode-<episode>-<candidate>.modification-notes.md`，保存准确文件名及摘要。固定《修改说明》列实际最终候选摘要、基线、范围、变更、意见、补充授权与待查工作，区分起草时的有限检查和后来真实版本审查。读取、审查、加载、验收与交付拒绝过期正文、策略或说明；说明使用恰好一个末尾换行。

### 项目操作

新创作项目可使用 `reviewMode: self-check`，并需要可用的 `sessionProjections`。`init` 从部署配置保存 `review_mode: self-check`，模型参数不能设置该字段。旧项目未记录模式时仍采用独立审校，即使当前部署启用自检也不例外。自检项目中，下文独立审校规则适用于历史独立记录；新事实和候选稿由原会话执行并明确记录自检。编写轮先产出事实或候选稿，后续模型轮通过 `read_source`、`read_fact`、`list_facts` 或 `read_candidate` 完整读回当前所需来源片段、事实或候选稿，再由下一模型轮作出审校决定。读操作可在同轮批量组合；同一次模型回复内的不同 `run_code` 不算新模型轮。自检不代表独立审校。

自检读操作将规范文本和图像带入下一模型轮上下文，即使 PTC 程序未打印中间返回值也如此。只有最终成功的读取、成功的外层程序及未经修改的可见上下文才能提供证据。审校绑定当前项目修订号和字节、不可变事实或候选摘要、包括知情前提在内的完整引用事实、来源引用与声明的覆盖窗口，以及宿主生成的模型轮序号。窗口只证明实际返回的条目；文件变更、过期修订、缺少重读、同轮决定、被拒绝或被替换的读结果及失败的外层程序均被拒绝。重启或上下文被丢弃后须重新读回。审校保留真实会话身份、`kind: self-check` 和证据，已验收状态与导出结果明确返回该类型。旧记录省略审校类型时仍检查独立身份。回放核对内容绑定与模型轮顺序；证据中的项目编号和修订号记录原审校发生位置，在修订分支中原样保留，不与归零后的分支修订号比较。

视频转剧本使用 `workflow: video_to_screenplay` 初始化。起草本集前，导入画面与发声事实并独立审校。两种候选写入方式都必须提供 `coverage.windows`，声明完整的本集来源范围，以及 `coverage.required_beats`，将每条已批准来源事实映射为动作、对白、OS 或 VO。范围内的全部已批准事实必须进入清单并出现在对应正文中；待审事实阻止起草。画面动作必须引用声明范围内的实际帧；指定行动人物时必须匹配已审校归属。动作事实即使同时引用核对文字，也必须保留为动作行，不能用于生成对白或 OS/VO。对白及 OS/VO 须有范围内已核对文字，不能只凭帧引用推断。默认来源转写拒绝改编新增事实，仅上述另行授权的精修提供限定例外。

没有动作段落的视频候选，批准时须填写独立 `zero_action_reason`，记录实际来源复核依据。经核实的纯对白素材可以通过，补造动作会被拒绝。覆盖清单随候选摘要、场景文件合稿、验收和导出保留。恢复读取已保存的来源范围和审校记录。不使用该可选流程的项目保留原有行为。机械检查覆盖已整理清单；独立审校仍须核对原件中未分类事件、情绪、身份及实际 OS/VO。 导入的视频元数据保留抽样区间、请求时间码与实际解码时间码，以及尚未查看的自适应观察点。窗口可通过 `interval` 声明视频清单内的本集范围；省略时保守地检查完整清单范围。只有本集区间内的待查点会阻止起草、审校通过、验收和导出，直到来源窗口包含同一视频版本在该时间点请求的补充采样。抽样区间仅说明检查范围，不代表连续画面覆盖；旧清单未记录的区间仍视为未声明。

`propose_facts` 批量提交保留独立归属的事实；`review_facts` 为每条事实携带独立决定与具体理由。每次批量操作只发布一次并推进一个修订号。空批次、超预算、内容无效或重复审校时整批不写入。批量审校仍须阅读并分类完整来源上下文，不能省略语义核对；单条接口继续可用。


本插件需要 `fs`、`tools`、`attachments` 和 `llm`；限制文件操作的文件系统还需要 `sandboxPolicy`。修改采用发起会话的既有沙箱策略。`project` 指向一个 JSON 项目文件，而非目录。`init` 记录用户方向及忠实或改编模式。`import_source` 接受 UTF-8 文本、`audio_transcribe` 原生片段数组包含 `segments` 的账号返回值，或 `video_inspect` 实际生成的抽帧清单。来源 SHA-256 依据原始字节计算。片段从 1 编号，保留原始行或语音片段顺序；可用的发声时间和说话人编号在导入时保留。

事实区分动作、发声、角色心理和作者分析。引用文字必须实际存在于对应片段中。新增改编事实需要项目处于改编模式并明确说明理由，或采用上述明确获准的限定精修。帧读取在时间码旁返回经过验证的原始图像附件，要求当前模型支持图像，并拒绝已变更的视频原件。另一会话审校语义、归属和叙述层。`stage` 接收完整场次，动作、对白、OS、VO 均引用已批准事实。OS 必须属于该人物自己的心理；作者分析属于无角色归属的评论。连续场次保持地点、时间和叙述层；进入闪回及从闪回返回现实须显式标记，`return_present` 也用于梦境或想象场次返回现实。

人物知情由已验收 beat 推导。声明的见证者可以看见动作或听见对白。OS 与仅观众可闻的 VO 不带场内见证者；电话或播放语音等实际画外发声声明 `audible_in_scene: true`，并在 `witnesses` 中列出实际听见的人物。这一声明必须引用有归属且已批准的发声事实，不能让心理或作者分析变成可闻话语。未声明或为 false 时保留原有的仅观众可闻行为。现实、闪回、梦境、想象的知情分别存储；这些记录只表达已获得的信息，不声称所有人物都不知道未列出的事情。跨层回忆或改变事件需要在目标层单独提出并审核事实。

场次 `characters` 和正文 `actor` 保留准确的纯人物名。`voice_only_characters` 列出本场仅通过 VO 发声的参与人物；渲染器在人物行中为这些名字加上 `（VO）`。重复名字、不在 `characters` 的名字、没有 VO 发声或还被归属其他正文类型的人物均被拒绝。省略该字段保留原人物行；标注本身不让听者获得信息。

`list_facts` 按原始顺序恢复完整事实与审校记录，在 `maxReadBytes` 内返回请求前缀，并用 `next` 指出续读位置；调用方按该位置读到 null，不能用请求数量推定已读完。单条事实超过字节预算时拒绝，不裁剪内容。`read_candidate` 返回准确的结构化版本、生成正文和所引用事实，供审校使用。审校绑定程序分配的候选编号及 SHA-256。只有下一集独立审校通过后才能提交验收。`status` 返回下一集及已验收版本，用于恢复。`export` 生成已验收 Markdown 和来源索引，包含渲染器计算的行号及程序记录的时间。重复导出保留相同文件并拒绝已修改文件；导出中断后，可重复相同命令完成。 新候选将来源编号绑定到内容摘要，因此后续导入来源不会改变已验收导出。旧候选保留原有摘要和原先导出所有来源的行为。后续导入后，已有规范格式的旧版来源文件可保留较早的已验证来源前缀，但须覆盖所有渲染引用，其他字节须完全一致。旧版来源清单未绑定摘要，因此无法区分无关末尾来源被移除，还是历史上确实较短的清单。

-----

`stage_files` 按文件列表顺序读取场次 JSON，每个文件包含一个完整结构化场次。工具确认文件存在、解析字段，发布前再次核对文件版本；文件数量使用 `maxReadUnits`，单文件字节使用 `maxReadBytes`。候选保存场次的完整副本，沿用 `stage` 的来源归属和独立审校规则。写作会话可逐场保存；输出截断后读回文件继续，不重生成一条巨大的工具参数。台词事实保留独立发声轮次，跨另一人物提问合并回答的稿件须拒绝。

`fork_project` 从指定已验收集或下一集之前创建新的修订项目文件，保留原方向、已核实来源、事实历史和此前的验收集，并记录父项目原文件的准确摘要及修订号。起点后的集数须按顺序重写并独立审校；原项目和导出文件保持不变，已有目标文件不可覆盖。

`withdraw_fact` 独立撤销错误的已批准事实，同时保留原审核。撤销事实仍可读取，但不能用于新场次。事实已有任何候选引用时（包括人物知情前提），须先从最早受影响集之前创建修订项目；原候选与导出仍可在原项目读取。编写者重新提出更正事实，交由独立审校。撤销记录由宿主生成，拒绝原提交者自行更改，不能改变候选历史。 显式自检项目中，原提交者仅可撤销原批准同样为自检的事实：在批准后的模型轮重新读取当前已批准事实及来源，再由下一模型轮说明更正理由并撤销。原批准记录保留，另行记录自检撤销。已有候选引用时仍须先建立修订分支；替代事实分配新编号并重新审校。独立批准和撤销不能使用该例外。

渲染使用真实集号与场次顺序、经来源核实的内外景，以及明确的中文叙述层标记。未填写内外景时明确显示待核实，程序不根据地名猜测。编写会话可用 `hook` 标记最后场次的一处来源悬念，独立审校核对依据；来源索引行号包含集号、场次和钩子标记。新的渲染不修改此前导出的文件。

## 理解实现

<details>
<summary>实现内部细节——点击展开</summary>

每次修改通过当前文件系统原子替换一个已验证项目文件，同时检查文件版本和调用者预期修订号。因取消或过期文件版本而被拒绝的写入不能推进持久化项目。外层程序失败不会撤销此前已成功的修改，须通过 `status` 恢复实际状态。操作前重算来源摘要，原件变化或索引不一致时失败。读取项目时核对候选正文摘要。被拒绝和被替代的候选仍然保留，已验收版本不被覆盖。项目格式版本 1 独立于已发布的 Session 代次，命令及规范结果使用已有工具事件记录。 单条目内容哈希缓存复用已验证项目、已验收人物知情状态和来源索引。每次调用仍读取并计算项目与来源字节哈希、检查视频版本并保留文件系统的比较交换保护；使用前复制缓存结果。验收历史回放一次建立事实与候选索引，避免反复搜索完整数组。

过大的读取会失败，需缩小窗口，不会悄悄截断原文。

## 模型体验

### `screenplay_project` 工具

#### 模型看到什么

[工具目录](../../../docs/tool-catalog.zh.md#deepseek-aidsh-screenplay-project) 维护操作参数及说明。规范结果包含受预算约束的来源窗口、程序分配的编号与修订号、候选正文、审校、已验收状态或导出路径。这些内容作为普通工具结果记录，使用通用持久化工具卡片。

#### Token 影响

挂载后的参数定义增加固定请求成本。来源读取受配置约束，候选读取包含完整单集正文及引用事实。调用追加结果，不在每次请求中放入整份来源。自检重读还追加规范上下文，使下一请求增加所选读回内容。

#### KV Cache 影响

结果追加到对话历史。修改参数定义或说明会改变可复用的请求前缀；项目修改不重写旧消息。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

机械检查仍需配合语义审校及适当的存储预算。

- **语义审校** — 准确引用和归属类型不能证明改写保留了原意。审校者须阅读原件、完整候选和已确定改编方向；创作自检仍具有同模型审校的局限。说话人分离编号本身不能证明角色姓名。
- **项目记录** — 已验证项目是本工具的续写依据。审校证据不是密码学签名，直接外部编辑不属于审校；智能体仍可使用通用文件工具，本工具无法让任意文件对该权限不可变。
- **存储规模** — 原件和剧集版本存入一个受版本保护的 JSON 文件。很大的项目需显式增加内存预算，当前实现尚未分片存储历史。 默认项目上限仍为 32 MiB；写入与变更项目的校验仍遍历完整文件，来源哈希成本仍随原件字节数增长。有界读取缓存不代表无限集数容量。
