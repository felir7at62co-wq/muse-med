# @deepseek-ai/dsh-tool-episode-render

English | [中文](README.zh.md)

## Summary

Turn selected shot videos into a delivered episode without hand-written FFmpeg commands. `drama_render` measures each line's times from the shot that speaks it, prepares inputs, renders the medium-specific delivery style, and checks measurable output properties. `drama_video` records reversible user bans for exact video versions and exposes their labels and reasons. A ban needs no review evidence; neither an unbanned version nor a successful technical check means content approval.

## Use this package

Mount the plugin as one row of a short-drama preset; it needs only the tool registry, and `ffmpeg` plus `ffprobe` on `PATH`:

```yaml
- id: tool-episode-render
  name: '@deepseek-ai/dsh-tool-episode-render'
  config:
    ffmpegPath: ffmpeg          # default
    ffprobePath: ffprobe        # default
    masterVolume: 1.45          # episode master gain, default
    bgmVolume: 0.24             # BGM gain, default
    preferNvenc: true           # probe h264_nvenc before each render, default
    fontsDir: 'C:/Windows/Fonts' # where libass finds SimHei, default
```

| Field | Default | Meaning |
|---|---|---|
| `ffmpegPath` | `ffmpeg` | The ffmpeg executable to start |
| `ffprobePath` | `ffprobe` | The ffprobe executable to start |
| `masterVolume` | `1.45` | Gain applied to the episode's own master audio; 0–8 |
| `bgmVolume` | `0.24` | Gain applied to the BGM bed; 0–8 |
| `preferNvenc` | `true` | Whether the GPU encoder is probed at all |
| `fontsDir` | `C:/Windows/Fonts` | Directory libass resolves the subtitle font from |
| `subtitleFontFamily` | `SimHei` | ASS subtitle font family |
| `watermarkFontFamily` | `Microsoft YaHei` | ASS watermark font family |

Font families are deployment configuration, not model tool parameters. Both must be nonblank strings without commas or line breaks; invalid values fail Config validation. Deployments providing Noto Sans CJK SC can set both families to `Noto Sans CJK SC`. This does not change `fontsDir` or install fonts: libass must have access to the selected families. When the medium requires a mark and ending, the single ASS burn follows their concatenation and uses the same watermark family throughout.

### Reversible video bans

Call `drama_video` with `project` and `method: "ban"`, an existing local `video`, and a nonempty string list `labels`, for example `["人物对调","字幕错误"]`; `reason` is optional. No image evidence is required. The tool hashes the file itself: byte-identical copies share a decision, while regenerated bytes at the same path remain independent. `inspect` reads one decision, `list` returns all decisions including released ones, and `unban` releases a mistaken or withdrawn ban without changing source-review records. `inspect` and `unban` accept either `video` or the exact `sha256` returned by the list when the old file no longer exists. Do not release a ban merely to make an export pass.

The project owns one `video-bans.json`: `{version:1,videos:[{sha256,labels,reason,banned,updated_at,video}]}`. SHA256 is lowercase, `video` is the absolute path recorded at ban time, `updated_at` is ISO time, and an absent reason is `""`. Unban retains labels and reason with `banned:false`; it never means approved. Writers reuse the atomic-write library's `<file>.lock` and same-filesystem atomic replacement. Invalid JSON, unsupported versions, duplicate hashes and malformed rows fail closed; write failures preserve the previous manifest. A leftover lock needs operator recovery, not automatic deletion.

`prepare` checks selected source bytes before probing, again before copying, and after copying. `render` checks current prepared sources before media work, checks actual encoded-cache bytes before use, and rechecks the source hashes consumed by this render before publishing its staged output under the manifest writer lock. A late ban leaves the previous delivery untouched. `verify` never deletes files: `video_bans` reports a directly banned output, or “当前选片含禁用素材，已有输出需复核” for currently selected sources. Without an immutable output source record, `output_source_mapping` remains in `not_checked` rather than certifying which versions an older output contains.

Every relative project input and output path resolves from `project`, including manifests, subtitle plans, alignment, subtitles, BGM, ending files, and explicit output. Absolute paths remain unchanged. Pass an absolute `project` across tools; a relative project root is resolved once from the process working directory. Ending assets outside the project use their installed absolute paths. Binary and font deployment configuration is unchanged.

Tool calls use the snake_case parameter names above; the registered executor maps them to the renderer's internal camelCase arguments. Common required arguments are checked before opening files; ending arguments are required only after the asynchronous medium resolution selects a marked delivery. Everything that makes a render impossible — a missing input, a failed command, an ending file whose bytes are not the shipped asset's, an ending effect longer than the ending window, a tail frame that cannot be proved — throws with a Chinese repair instruction. The delivered file's own properties do not throw: they come back as checks, so one call reports every defect while still handing back the measurement.

### Explicit audio profiles and auditions

Pass `mix_profile` explicitly to select a project-owned JSON file. `schema_version` is `1`; `mode` is `legacy`, `no_bgm`, or `ducking`; `analysis_window_ms` is 10–1000. Optional `original_gain` and `music_gain` accept 0–8 and otherwise capture the existing deployment gains. `ducking` requires explicit `threshold_db` (−60–0), `ratio` (1–20), `attack_ms` (0.01–2000), `release_ms` (0.01–9000), and `knee` (1–8) under its `ducking` object. No profile means the existing fixed-gain render, without new report fields.

`no_bgm` never requires or opens `bgm`, `bgm_plan`, or a composition receipt. It preserves the source's own sound, including any existing music or effects; it does not separate speech or remove embedded music. `ducking` uses original-audio RMS energy as its sidechain, not semantic voice activity detection. Attack and release smooth the added-music gain, and the original signal enters the mix once. Explicit-profile renders require new project-owned output paths and publish a separate, already-gained music-only `<output-name>.music-stem.wav` when music is enabled; existing outputs are not replaced.

`audio_preview` requires the profile, timeline and explicit audition interval. It processes from body zero with the final render's filter builder, then trims the outputs, so the sidechain history at the audition offset is retained. Trimming uses rounded 48 kHz sample bounds and rebuilt output timestamps, preventing overlapping AAC join timestamps from stretching an A/B window. The new preview directory contains `selected_mix.wav`, `without_added_music.wav`, an optional `music_stem.wav`, and `analysis.json`; repeated calls create different directories. Profile and audition paths must remain project-owned after resolving links. The music stem never includes the original audio.

The analysis separates frame RMS/sample peaks in dBFS from EBU R128 momentary (400 ms) and short-term (3 s) loudness in LUFS. Loudness observations occur every 100 ms relative to the audition start; incomplete windows return null with explicit warmup flags. These measurements do not establish listening approval. The report retains track names, intervals, declared licenses and use risks from an optional `bgm_plan`; absent metadata stays unknown. A hash-matched `bgm_generation` additionally supplies each source's measured mean and applied composition gain, distinct from the final `music_gain`.

### Medium and delivery snapshot

`project_config.json.project_bible.visual_medium` explicitly selects `animation_3d` or `photorealistic`; free-text `style` and aspect ratio never select a policy. `prepare` writes `delivery: {visual_medium?, width, height, fps}` into the timeline using project-bible delivery values, defaulting omitted geometry fields to 1440x2560 at 60 fps. Width and height must be positive even integers; fps must be a positive integer no greater than 240. Present invalid values, including null, fail before media work.

`render` and `verify` preserve snapshot geometry. An explicit snapshot medium wins when the project omits it; an explicit project medium supplies a missing snapshot medium. If both explicitly disagree, the operation requires a new `prepare` rather than silently changing the timeline. Old timelines without delivery metadata retain legacy geometry. When neither source declares a medium, reports warn and retain the legacy marked output. An explicit `canvas` conflicting with snapshot dimensions is rejected; animation also rejects a declared `body_end` differing from the clip end, requiring a body-only timeline to be prepared again.

`animation_3d` outputs only the body duration, adds no watermark style or event, mixes only master and BGM, and never opens ending assets, extracts a tail frame or concatenates a stale ending. Body subtitles remain enabled. `photorealistic` and unclassified legacy projects keep the following marked delivery behavior. Every method's `expected_duration_seconds` includes only its selected ending length.

### Marked delivery prerequisites: the two ending files

Marked `render` requires both shipped ending assets and validates their bytes before media commands. Missing or substituted files block only that delivery mode; the diagnostic identifies an incomplete installation when the correctly hashed sibling proves the asset directory arrived.

| Asset | Path inside the skill package (`packages/drama/skills/skills/`) | Bytes | SHA-256 |
|---|---|---|---|
| Ending effect | `tweet-drama-background-render/assets/ending_effect.mp4` | 904,502 | `49308bce84b964c5ec6768655e84920731dcaabe14509a0d84b4c92aea590010` |
| Ending sound | `tweet-drama-background-render/assets/ending_audio.mp3` | 83,432 | `d1649e9c9231283a93ee3d28816c741ac3d389528654fca5ac69d75139943c0f` |

The marked ending lasts exactly two seconds (`ENDING_SECONDS = 2`). Its sound contributes only its first two seconds, delayed to body end. The effect plays once at its own speed; an effect longer than the window fails instead of being truncated. Both ending arguments are required for this mode.

### What subtitles does

`subtitles` reads the complete line plan and clip-relative recognition alignment, preserves the supplied text, and places valid measured spans on the episode clock. It does not recognize speech, infer words from audio energy, invent missing timing, or redistribute invalid spans.

Single-line, punctuation-free cues of at most 14 effective characters are readability suggestions. Multiline, punctuated, empty or long cues remain unchanged and produce warnings. Invalid SRT timestamps still fail parsing because they cannot identify a renderable interval. The screenplay source remains unchanged.

Alignment text is compared with the supplied line plan and never replaces authored dialogue. Missing evidence, text mismatches, undeclared speech and fast reading rates are advisory findings for Muse; they do not require approval or a warning-free report.

A build with alignment or readability findings writes `<subtitle_srt>.draft.srt` and leaves the existing SRT untouched. `<subtitle_srt>.review.txt` records the latest attempt, including pending work after interruption; the candidate receives its own review note. `prepare` and `render` return those notes and legacy `.blocked` markers as warnings while continuing with the explicitly selected readable SRT. A successful complete alignment writes the requested SRT and clears its observations. Saving, rendering and `ok: true` do not establish creative acceptance.

The written file is plain SRT, so a line can be hand-edited before `prepare` installs it and `render` burns it.

### What prepare writes

`prepare` copies each source video to `video/<集>/shot_00N.mp4`, lays the timeline out from the ffprobe-measured durations rather than declared ones, assembles the episode master by placing each shot's own sound at its own start (no gain, no per-shot resampling, one 48 kHz lossless write), and installs the subtitle at `editing/<集>.srt`. It encodes no picture. A cue that ends after the assembled picture is reported as a warning.

After successful preparation, `editing/<集>-sources.json` records `{shots:[{shot,package?,video,audio,sha256}]}` with absolute source paths and the prepared video's SHA-256. `package` is an optional explicit 1-based position in `episode_packages/<集>/package.json`'s `video_tasks`; it is never inferred from `shot`. Multiple clips may map to one package. The previous selection record is removed before inputs are changed, so failed preparation cannot leave it claiming completion. Source selection is evidence of copied bytes, not content approval. Explicitly mapped rows also record `package_sha256` when the episode package file exists: its full-byte SHA-256, including the referenced shot content. Review records must carry the same measured hash to count as current; any package-file change, including formatting, conservatively invalidates that episode's evidence. Missing package files leave this field absent rather than blocking legacy preparation.

Per-shot encoding caches require a matching source-byte hash, executable and exact encoding arguments, including duration. Cache identities are published only after a successful nonempty encode; missing identities and changed sources/settings re-encode automatically. `force` still bypasses reuse.

A supplied BGM plan contains `episodes:[{episode:"02",body_duration_seconds:12,segments:[{track:"name",source:"music.mp3",start_seconds:0,end_seconds:12,reason:"scene mood"}]}]`. Duration must match the current body; segments must have valid, ordered, in-bounds times. Gaps, overlaps, one track and recurring motifs remain creative choices. Repeat advice compares resolved source paths in order within this plan, without case folding or audio fingerprinting. The reported bed hash binds the declaration to this render input; it does not establish that the bed contains those tracks or fits the scene.

`bgm_plan` also preserves the episode's optional `intended_use`, segment `track_id`, and `license_info`, and returns normalized per-track `license_records`. The [license metadata library](../bgm-license-info/README.md) defines unknown facts and use-risk warnings. Warnings remain advisory and are included in the render report; declarations do not certify rights or replace model-license requirements. A declared `source_sha256` is retained without rehashing each source track. Methods that do not read a plan, including `verify`, return unknown intended use and empty license records, with `bgm_license_info` in `not_checked`.

| Audio | Episode master at 1.45, BGM at 0.24 to the body end, when marked, the ending sound's first 2 seconds delayed to the body end, `amix` normalised off, `alimiter=0.95` |

### The three known traps

- **The tail frame.** `-sseof -0.05` returns exit code 0 without writing a file on some sources, so the frame was silently wrong. This package always seeks with `-sseof -0.1`, and it does not trust the result: the extracted frame's `framemd5` must equal the last frame of a full sequential decode. When it does not, the frame is re-extracted by index; when that still does not match, the render stops instead of freezing an unproved frame. The evidence is returned in `tail_frame`.
- **The GPU encoder.** A driver too old for NVENC, a missing build, or a busy GPU session all fail the probe the same way. The probe encodes one frame of a 256x256 source — some NVIDIA generations reject smaller frames — and a failure falls back to `libx264` by design, with the probe's own output recorded in `encoder_fallback_reason` and in the render log.
- **The frame rate after the burn.** The burn runs on the source's own time base, so an `fps` filter placed before `ass`/`subtitles` does not survive into the encode: the container still reports the delivery rate while a fraction of the frames decode. The burn chain therefore ends on `fps=F,setpts=N/(F*TB)`, where `F` is the snapshot frame rate (60 for legacy timelines). Body encoding, effect rate conversion and subtitle burning hold the last decoded frame for one frame at EOF, then cap output to the declared clip or delivery duration and explicitly set the output rate; this preserves the original tail without adding a 3D ending. Truncated picture still fails verification, and nothing trusts metadata alone — `decode_probe` decodes a frame at the head, the middle, and just inside the tail.

### Check codes

`render` runs the five delivery checks, `verify` runs all checks in the table, and `subtitles` runs its own two. `ok` means only that the executed failure-severity checks passed. `not_checked` explicitly lists unmeasured QA, including speech alignment, unwanted source-embedded subtitles, content review and BGM listening. Removing unwanted provider captions is separate from the intended final SRT burn-in; neither operation disables the delivery subtitle style.

| Code | Severity | Passes when |
|---|---|---|
| `duration` | failure | The measured duration is within 0.15 s of body end plus the ending |
| `video_stream` | failure | Snapshot geometry and H.264 |
| `frame_rate` | failure | Snapshot fps within 0.01 |
| `audio_stream` | failure | An AAC 48 kHz audio stream is present |
| `bitrate_floor` | failure | The overall bitrate reaches 4.6 Mbps |
| `decode_probe` | failure | A frame decodes at the head, the middle, and 0.1 s inside the tail |
| `black_frames` | failure | No black stretch reaches 1.0 s |
| `fade_to_black` | warning | No black stretch reaches 0.3 s |
| `silence` | failure | No silent stretch reaches 3.0 s |
| `long_pauses` | warning | No silent stretch reaches 1.0 s |
| `subtitle_bounds` | failure | Every cue lies inside `0`–`body_end` and inside the file |
| `subtitle_present` | warning | The subtitle carries at least one cue |
| `subtitle_line_coverage` | failure | Every declared line has an alignment entry in its own shot, and every shot with recognized speech declared a line |
| `subtitle_timing` | failure | `subtitles` only: every cue is non-empty, ordered, inside `body_end`, and below 20 spoken characters per second |

### Design philosophy

The package is built on four commitments:

- **Enforce the delivery where it is produced.** The picture geometry, the rate control, the subtitle style, the ending, and the audio mix are the operator-approved specification. Validated project and timeline metadata select geometry and medium treatment, and the operation that writes the file is the operation that checks it.
- **Report the artifact, throw on the obstacle.** A delivered file that misses the bitrate floor is a domain outcome: the operator still needs the file, so it comes back with `ok: false` and one repair line per failed check. A missing input or a failed command is an environment problem: it throws, because there is nothing to hand back.
- **Prove the tail frame.** The ending is the one frame nobody can inspect afterwards, so its source record is a returned value rather than a comment. The `-sseof` result is compared against a sequential decode every time, and a mismatch is either repaired by index or refused.
- **One injected process edge.** Every module takes a `MediaToolkit`; only one function starts a process. The whole pipeline therefore runs in tests against a stub channel, and the real channel is exercised by its own three-process spec.

## Model Experience

### The render and video-decision tool schemas

#### What the model sees

The request includes `drama_render` and `drama_video`, with parameter and result schemas reproduced in the generated [tool catalog](../../../docs/tool-catalog.md#deepseek-aidsh-tool-episode-render). Render results expose measurements, failed checks and unmeasured QA. Video-decision results expose labels, reason, current ban state and `review_status: "not_assessed"`; for `list`, top-level `banned` means at least one listed version is banned. Both tools render their result as formatted JSON and register no additional prompt text.

#### Token effect

The render result contains one `clips` row per shot and up to thirteen checks, including the optional ban check. `drama_video` adds a fixed schema; its `list` result grows by one row per recorded version, while other methods return only the selected decision. A render of a nine-shot episode returns nine clip rows whatever the encode cost, and a passing delivery leaves `failures` empty and every `fix` an empty string. Explicit audio profiles add `audio_mix`; frame measurements stay in its analysis file instead of expanding the tool result.

#### KV Cache effect

Append-only. The tool registration carries a stable name, description, and schema, so a mounted row keeps the request prefix reusable; only a change to this package's description or schema invalidates it. A call's result is appended as that call's own tool result and rewrites no earlier message.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

These limits define what this package is and what it is not. They are current constraints, not a task backlog.

- **ffmpeg and ffprobe are external** — the package starts whatever `ffmpegPath` and `ffprobePath` name. A build without `libass`, `minterpolate`, or the `screen` blend mode fails at the command that needs it, and only that command's stderr is reported.
- **Delivery metadata does not expose arbitrary filters** — project-bible geometry and explicit medium are validated and snapshotted; rate control, subtitle style, shipped ending hashes and limiter remain fixed. Only binaries, gains, encoder preference and fonts are plugin `Config` fields.
- **Cache and log writes are not transactional** — failed renders can leave intermediate files for the next run to overwrite. Legacy final MP4 publication uses a staged sibling and rename after ban checks; explicit audio profiles publish MP4/music stems without replacement. Failures before publication retain the old delivery.
- **Bans are not a global media filter** — generic FFmpeg tools and arbitrary external transcodes are not intercepted. Prepared copies are checked by their actual SHA256; official rendering associates encoded caches with the currently hashed source. Missing or stale mappings never establish an arbitrary transcode's original version.
- **A required ending is rebuilt on every marked render** — the tail frame is re-extracted and re-proved, and the ending clip is re-encoded, even when the cache holds both. The proof is the point, and a cached ending could predate a re-cut.
- **`prepare` copies, it does not link** — every source video is copied into the project, so a nine-shot episode needs room for the reviewed cuts twice. Hard links would break as soon as the source is rewritten.
- **One episode per call** — `last_shot` bounds a render to the body shots it delivers, but a call never renders several episodes, and no method reads `pipeline_state.json`.
- **Auditions are not automatic mastering or speech separation** — short-window dBFS and LUFS measurements require `audio_preview`; legacy rendering and `verify` do not add them. Source-driven ducking can react to effects and embedded music, and no measurement certifies musical suitability or removes source-internal music.
- **Subtitle bounds are checked, not corrected** — `verify` reports a cue that runs past `body_end`; nothing clamps it, because where a line should end is the subtitle author's decision.
- **`subtitles` trusts the recognizer's times** — the alignment settles when each line is spoken, and this package checks that it covers every declared line and that its text is the script's, but it cannot judge how accurate the recognizer was. `speech_alignment` stays in `not_checked` for exactly that reason, and producing the alignment is the caller's step.

### Dev Note

<details>
<summary>Working context for maintainers — click to expand</summary>

This Dev Note is working context for maintainers: open questions and directions that are not decided. It is explicitly non-authoritative — shipped behavior, limits, and accepted rationale live in the sections above, the package code, and the linked documents.

This package is a port of the pipeline's Python renderer (`tweet-drama-background-render/scripts/render_episode.py`). The Python script remains the production path until sessions move over, so both exist during the transition.

The ported behavior differs from the Python in five recorded places: the tail-frame seek is `-0.1` instead of `-0.05` and every extraction is proved against a sequential decode; the encoder probe failure is recorded as a reason instead of being a silent fallback; the ASS line endings are normalized to `\n` instead of following the host platform; the ending frame and clip are rebuilt on every render instead of reused from the cache; and the render log is a new file, while the Python's `exports/render_tasks.json` state file is deliberately not written.
