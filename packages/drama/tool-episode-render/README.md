# @deepseek-ai/dsh-tool-episode-render

English | [中文](README.zh.md)

## Summary

Turn selected shot videos into a delivered episode without hand-written FFmpeg commands. `drama_render` measures each line's times from the shot that speaks it, prepares inputs, renders the medium-specific delivery style, and checks measurable output properties. `drama_video` records reversible user bans for exact video versions and exposes their labels and reasons. A ban needs no review evidence; neither an unbanned version nor a successful technical check means content approval.

## Use this package

Mount the plugin as one row of a short-drama preset; basic methods need the tool registry, and `ffmpeg` plus `ffprobe` on `PATH`. Strict source review also needs the current Host filesystem, sandbox policy, and Session projections. Missing review services stop strict rendering with `SOURCE_QA_HOST_UNAVAILABLE`; they do not disable basic methods.

```yaml
- id: tool-episode-render
  name: '@deepseek-ai/dsh-tool-episode-render'
  config:
    ffmpegPath: ffmpeg          # default
    ffprobePath: ffprobe        # default
    masterVolume: 1.45          # episode master gain, default
    bgmVolume: 0.24             # BGM gain, default
    preferNvenc: true           # probe h264_nvenc before each render, default
    fontsDir: 'C:/Windows/Fonts' # where libass finds SimHei, default
```

| Field | Default | Meaning |
|---|---|---|
| `ffmpegPath` | `ffmpeg` | The ffmpeg executable to start |
| `ffprobePath` | `ffprobe` | The ffprobe executable to start |
| `masterVolume` | `1.45` | Gain applied to the episode's own master audio; 0–8 |
| `bgmVolume` | `0.24` | Gain applied to the BGM bed; 0–8 |
| `maxBgmVolume` | `8` | Effective BGM gain ceiling after project/profile overrides; Muse creative presets use 1 |
| `preferNvenc` | `true` | Whether the GPU encoder is probed at all |
| `fontsDir` | `C:/Windows/Fonts` | Directory libass resolves the subtitle font from |
| `subtitleFontFamily` | `SimHei` | ASS subtitle font family |
| `watermarkFontFamily` | `Microsoft YaHei` | ASS watermark font family |

Font families above are deployment defaults, not model tool parameters. Both must be nonblank strings without commas or line breaks; invalid values fail Config validation. A project can override the body subtitle family as described below, but not the watermark family. Deployments providing Noto Sans CJK SC can set both defaults to `Noto Sans CJK SC`. Selecting a family does not change `fontsDir` or install fonts: libass must have access to it, or may fall back to a different installed font. When the medium requires a mark and ending, the single ASS burn follows their concatenation and uses the same watermark family throughout.

### Reversible video bans

Call `drama_video` with `project` and `method: "ban"`, an existing local `video`, and a nonempty string list `labels`, for example `["人物对调","字幕错误"]`; `reason` is optional. No image evidence is required. The tool hashes the file itself: byte-identical copies share a decision, while regenerated bytes at the same path remain independent. `inspect` reads one decision, `list` returns all decisions including released ones, and `unban` releases a mistaken or withdrawn ban without changing source-review records. `inspect` and `unban` accept either `video` or the exact `sha256` returned by the list when the old file no longer exists. Do not release a ban merely to make an export pass.

The project owns one `video-bans.json`: `{version:1,videos:[{sha256,labels,reason,banned,updated_at,video}]}`. SHA256 is lowercase, `video` is the absolute path recorded at ban time, `updated_at` is ISO time, and an absent reason is `""`. Unban retains labels and reason with `banned:false`; it never means approved. Writers reuse the atomic-write library's `<file>.lock` and same-filesystem atomic replacement. Invalid JSON, unsupported versions, duplicate hashes and malformed rows fail closed; write failures preserve the previous manifest. A leftover lock needs operator recovery, not automatic deletion.

`prepare` checks selected source bytes before probing, again before copying, and after copying. `render` checks current prepared sources before media work, checks actual encoded-cache bytes before use, and rechecks the source hashes consumed by this render before publishing its staged output under the manifest writer lock. A late ban leaves the previous delivery untouched. `verify` never deletes files: `video_bans` reports a directly banned output, or “当前选片含禁用素材，已有输出需复核” for currently selected sources. Without an immutable output source record, `output_source_mapping` remains in `not_checked` rather than certifying which versions an older output contains.

### Render and audio audition methods

| Method | Reads | Writes | Use it for |
|---|---|---|---|
| `subtitles` | The shot-sources manifest and the per-shot line plan | `editing/<集>.srt` | Giving already-written lines their times from each shot's own audio, without speech recognition |
| `prepare` | The shot-sources manifest and the subtitle | `video/<集>/shot_00N.mp4`, `audio/<集>.wav`, `editing/<集>-timeline.json`, `editing/<集>.srt` | Building every input a render reads, without encoding picture |
| `render` | The timeline, prepared shots, master, subtitle, BGM, and medium-required ending assets | The delivered MP4 and `exports/.render_cache/<集>/render.log` | Producing the delivery and returning its measured parameters |
| `verify` | The delivered file, its timeline, and its subtitle | Nothing | Checking a delivery after the fact, or re-checking one from an earlier session |
| `stage_delivery` | A full resumable render, its timeline and burned subtitle, and a saved draft with a matching episode receipt | The episode's MP4-only upload folder and a sibling receipt | Collecting a technically verified candidate for content review |
| `audio_preview` | Project-owned original sound, timeline, explicit mix profile and optional music metadata | New aligned WAV auditions, music stem and analysis JSON under `audio/previews/` | Comparing added music against retained original sound before rendering picture |
| `subtitle_overlay` | Prepared sources, timeline, original SRT and explicit retained-text decisions | New overlay SRT and source-bound decision report | Avoiding duplicate overlays without changing burned-in text |
| `subtitle_layout` | Timeline and final SRT with an explicit shared visual style | New layout report, natural-width probes and delivery-sized PNGs | Measuring actual libass typography without changing cues |
| `speech_coverage` | Sources, timeline, complete displayed SRT and existing same-source word transcripts | Nothing | Reviewing speech-to-subtitle coverage in both directions |

|---|---|---|
| `method` | always | One of the methods above |
| `project` | always | Project root holding `video/`, `audio/`, `editing/`, and `exports/` |
| `episode` | always | Episode number; padded to two digits on every path |
| `shots` | `subtitles`, `prepare`, `speech_coverage` | Shot-sources manifest: `{"shots":[{"shot":1,"video":"media/02/p1-clean.mp4","audio":"optional"}]}` |

| `timeline` | `render`, `verify`, `audio_preview`, `subtitle_overlay`, `subtitle_layout`, `speech_coverage`, `stage_delivery` | Timeline JSON, normally the one `prepare` wrote |
| `subtitle_srt` | `prepare`, `render`, `verify`, `subtitle_overlay`, `subtitle_layout`, `speech_coverage`, `stage_delivery` (`subtitles` optional) | The SRT to write, install, burn, or check; coverage needs the complete displayed SRT, and staging needs the exact burned SRT. `subtitles` defaults to `editing/<集>.srt` |

| `speech_decisions` | optional, `speech_coverage`, strict `stage_delivery` | Project-owned listening declarations bound to this review's complete evidence hash; not a Host-issued listening certificate |
| `last_shot` | `render` | Last body shot this delivery covers; the timeline must hold exactly that many clips up to it |
| `bgm` | music-enabled `render`, `audio_preview` | The BGM bed, looped to the body end; ignored and unopened by an explicit `no_bgm` profile |
| `bgm_plan` | strict `render`; optional, other `render` and `audio_preview` | Existing episode plan; strict staging reads the explicit music decision and reason. Reports declared track sources, times, reasons, bed hash and same-sequence episodes without claiming listening approval |
| `mix_profile` | `audio_preview`; optional, `render` | Project-owned versioned audio profile; omission preserves legacy rendering |
| `audio` | optional, `audio_preview` | Project-owned original audio; defaults to `audio/<集>.wav` |
| `start_seconds`, `duration_seconds` | `audio_preview` | Nonnegative body offset and positive audition duration of at most 60 seconds, without crossing body end |
| `bgm_generation` | strict `render` with music; optional, `audio_preview` | Project-owned composer receipt. Its media SHA-256 must match the actual BGM bed |
| `intended_use` | optional, `audio_preview` | `commercial`, `non_commercial`, or `unknown`; overrides the plan's declared use for advisory license-risk reporting |
| `ending_audio` | marked `render` | The ending sound; only the shipped `tweet-drama-background-render/assets/ending_audio.mp3` is accepted. The ending plays its first 2 seconds, delayed to the body end |
| `ending_effect` | marked `render` | The shipped `tweet-drama-background-render/assets/ending_effect.mp4`; default `source_once` plays it at original speed, while explicit timeline `stretch_to_window` fits the complete source across the 2-second ending |
| `output` | `verify`, `stage_delivery` (`render` and `subtitle_overlay` optional) | The delivered file, or a new project-local overlay SRT; explicit overlay exports use `<output>.decision-report.json` and never replace either file |
| `force` | optional | `render` ignores its per-shot cache and re-encodes every clip |
| `resume` | optional, full-episode `render` | Reuse a verified delivery for the exact current inputs, or publish a new candidate under the project |

With `resume: true`, render binds the selected videos, master audio, timeline, source SRT, supplied mix and subtitle plans, active music and ending files, and effective settings to a request SHA-256. Reuse requires a matching source record for the same episode and path and an independent `verify` pass. Current-file checks also cover derived display subtitles and glyph reports before reuse or publication. An occupied path without matching evidence is preserved and a new candidate is allocated. Repeat the call with the same requested `output`, and use the returned `output` for downstream work. An explicit subtitle overlay is resolved again for the draft handoff.

Stage the exact returned render and saved draft together. The upload folder contains only `第<集>集.mp4`, with its receipt beside the folder. Staging preserves existing files if the episode, input bytes or an existing package conflict. The returned candidate is ready for content and editor review.

Staging rechecks source and draft receipts before publication and removes temporary copies after failure. If interruption leaves a matching receipt and an empty upload folder, the same request resumes without replacing the receipt.

Staging rejects symbolic links and junctions in a file or directory path, including its ancestors. A Windows short-name alias of a regular entry remains acceptable.

Every relative project input and output path resolves from `project`, including manifests, subtitle plans, alignment, subtitles, BGM, ending files, and explicit output. Absolute paths remain unchanged. Pass an absolute `project` across tools; a relative project root is resolved once from the process working directory. Ending assets outside the project use their installed absolute paths. Binary and font deployment configuration is unchanged.

Tool calls use the snake_case parameter names above; the registered executor maps them to the renderer's internal camelCase arguments. Common required arguments are checked before opening files; ending arguments are required only after the asynchronous medium resolution selects a marked delivery. Everything that makes a render impossible — a missing input, a failed command, an ending file whose bytes are not the shipped asset's, a `source_once` effect longer than the ending window, a tail frame that cannot be proved — throws with a Chinese repair instruction. The delivered file's own properties do not throw: they come back as checks, so one call reports every defect while still handing back the measurement.

Project-root aliases are accepted for audio paths; inputs and existing output parents must still resolve inside the real project. Explicit audio-profile gains in auditions and renders override project gains, which override deployment defaults; the render preview reports these same effective gains.

`maxBgmVolume` caps the effective project, deployment or explicit-profile music gain in both previews and renders. It does not reduce original-audio gain. Muse creative presets use 1 with composer source gain at most −10 dB, so later mixing cannot boost a newly composed bed back above the source attenuation. This ceiling alone does not verify older beds or direct source imports; use a hash-matched composer receipt and the actual music gain for source-relative accounting.

### Explicit audio profiles and auditions

Pass `mix_profile` explicitly to select a project-owned JSON file. `schema_version` is `1`; `mode` is `legacy`, `no_bgm`, or `ducking`; `analysis_window_ms` is 10–1000. Optional `original_gain` and `music_gain` accept 0–8 and otherwise capture the existing deployment gains. `ducking` requires explicit `threshold_db` (−60–0), `ratio` (1–20), `attack_ms` (0.01–2000), `release_ms` (0.01–9000), and `knee` (1–8) under its `ducking` object. No profile means the existing fixed-gain render, without new report fields.

`no_bgm` does not require or open a music bed or a composition receipt. Strict staging still needs its explicit `bgm_plan` decision. It preserves the source's own sound, including any existing music or effects; it does not separate speech or remove embedded music. `ducking` uses original-audio RMS energy as its sidechain, not semantic voice activity detection. Attack and release smooth the added-music gain, and the original signal enters the mix once. Explicit-profile renders require new project-owned output paths and publish a separate, already-gained music-only `<output-name>.music-stem.wav` when music is enabled; existing outputs are not replaced.

`audio_preview` requires the profile, timeline and explicit audition interval. It processes from body zero with the final render's filter builder, then trims the outputs, so the sidechain history at the audition offset is retained. Trimming uses rounded 48 kHz sample bounds and rebuilt output timestamps, preventing overlapping AAC join timestamps from stretching an A/B window. The new preview directory contains `selected_mix.wav`, `without_added_music.wav`, an optional `music_stem.wav`, and `analysis.json`; repeated calls create different directories. Profile and audition paths must remain project-owned after resolving links. The music stem never includes the original audio.

The analysis separates frame RMS/sample peaks in dBFS from EBU R128 momentary (400 ms) and short-term (3 s) loudness in LUFS. Loudness observations occur every 100 ms relative to the audition start; incomplete windows return null with explicit warmup flags. These measurements do not establish listening approval. The report retains track names, intervals, declared licenses and use risks from an optional `bgm_plan`; absent metadata stays unknown. A hash-matched `bgm_generation` additionally supplies each source's measured mean and applied composition gain, distinct from the final `music_gain`.

### Medium and delivery snapshot

`project_config.json.project_bible.visual_medium` explicitly selects `animation_3d` or `photorealistic`; free-text `style` and aspect ratio never select a policy. `prepare` writes project-bible geometry and any explicit subtitle/audio sections into `timeline.delivery`, defaulting omitted geometry fields to 1440x2560 at 60 fps. Width and height must be positive even integers; fps must be a positive integer no greater than 240. Present invalid values, including null, fail before media work.

`render` and `verify` preserve snapshot geometry. An explicit snapshot medium wins when the project omits it; an explicit project medium supplies a missing snapshot medium. If both explicitly disagree, the operation requires a new `prepare` rather than silently changing the timeline. Old timelines without delivery metadata retain legacy geometry. When neither source declares a medium, reports warn and retain the legacy marked output. An explicit `canvas` conflicting with snapshot dimensions is rejected; animation also rejects a declared `body_end` differing from the clip end, requiring a body-only timeline to be prepared again.

`animation_3d` outputs only the body duration, adds no watermark style or event, mixes only master and BGM, and never opens ending assets, extracts a tail frame or concatenates a stale ending. Body subtitles remain enabled. `photorealistic` and unclassified legacy projects keep the following marked delivery behavior. Every method's `expected_duration_seconds` includes only its selected ending length.

### Project subtitle and audio settings

Keep approved settings under `project_bible.delivery` in `project_config.json`, not a root-level `delivery`. This is a partial example, not a replacement project file. Read and narrowly edit the existing file, preserving its schema version, revision, history, budget and remote bindings; `drama_project.changes.delivery` accepts geometry and the separate draft-style section below, not these formal-render subtitle/audio fields:

```json
{"project_bible":{"visual_medium":"animation_3d","delivery":{"width":480,"height":854,"fps":24,"subtitle":{"font_size_px":30,"margin_bottom_px":18},"audio":{"master_gain":1,"bgm_gain":0.1}}}}
```

`subtitle.font_family` optionally selects an already available, nonblank ASS-safe family without commas or line breaks. `font_size_px` is a positive finite nominal output-pixel size, not a measured glyph height; `margin_bottom_px` is finite from zero through output height. The renderer converts these into ASS design coordinates and rounds the bottom margin to an integer design unit. Alignment, spacing, outline and watermark remain unchanged. `audio.master_gain` and `audio.bgm_gain` are finite linear gains from 0 through 8; zero mutes that input. Source selection, mixing, normalization, limiter and ending gain are unchanged.

Outside the product's forced subtitle policy, each subtitle/audio section resolves as a whole: an explicit timeline section, including `{}`, wins over the current project section. A field absent from that selected section uses deployment or legacy defaults, not a field from the other section. A missing timeline section may inherit the current project section. The short-drama product enables `enforceSubtitleVisual` for portrait body subtitles, so old project and timeline subtitle styles no longer override the product visual; landscape and square layouts and audio settings retain their normal priority. This selects the output style without changing the project file or an existing approved video. Review actual output; an SRT alone does not record approved appearance.

Editable drafts read the same explicit audio sections with the same section priority. Without explicit gains their SDK defaults remain 1/1, independently of the formal renderer's deployment defaults; set both gains when matching the two paths. Draft typography uses separate editor units and is not changed by these formal-render subtitle fields. No font is installed or copied by these settings.

### Actual words and final subtitle coverage

Call `speech_coverage` with `shots`, `timeline`, final displayed `subtitle_srt`, and `speech_transcripts` to compare every existing same-source timed word, including one- or two-character and script-extraneous speech. The read-only report distinguishes recognized words without subtitles, subtitles without corresponding recognition, and time mismatches. Complete cues matched to whole words tolerate up to one delivery frame at each edge plus SRT millisecond rounding. Source bytes, transcript receipts and raw results must match. The operation uses existing ASR evidence and makes no provider calls.

When a cue partially overlaps an exact phrase in the same clip, a nearby edge word outside the cue can produce one timing mismatch with the measured word IDs. The overlap matches stay unchanged. A word already matched to another cue, an ambiguous claim, or a gap over 300 ms next to the missed word keeps the findings separate.

Optional `speech_decisions` binds caller-declared listening decisions to the complete evidence hash. A changed source, transcript, timeline, subtitle or mapping invalidates that binding. Listen before adding, adjusting or explicitly retaining an omission, and use the same final displayed SRT for MP4 and draft checks. Retained source-embedded text belongs in this full SRT even when the overlay-only SRT omits it. Findings remain advice; `listening_verified: false` never becomes a Host-issued human acceptance claim.

### What subtitles does

`subtitles` reads the complete line plan and clip-relative recognition alignment, preserves the supplied text, and places valid measured spans on the episode clock. It does not recognize speech, infer words from audio energy, invent missing timing, or redistribute invalid spans.

Outside an active visual profile, single-line, punctuation-free cues of at most 14 effective characters are readability suggestions. Deployments without `normalizeSubtitleText` preserve input text. When enabled, ordinary dialogue punctuation, physical line breaks and literal ASS `\N`/`\n` breaks become spaces in a separate display candidate; decimal and numeric grouping separators remain intact and the source SRT stays unchanged. The editable-draft normalizer uses the same rule. Without an overlay plan, `render_preview.subtitle.path` identifies a candidate shared by rendering and editable drafts. With existing source-bound `speech_transcripts`, prepare measures the actual font width and may split an overwide matching cue at complete non-overlapping word starts; incomplete evidence or unavailable measurement leaves the cue unchanged for review, and an unresolved active-visual render cannot pass. With an overlay plan, render resolves the original SRT and plan, while the draft uses the hash-bound resolved SRT and report; both use the same display text rule, and long cues need separate review. Long cues are not split by fabricated character-based times; listen and check both outputs. Invalid SRT timestamps still fail parsing because they cannot identify a renderable interval. The screenplay source remains unchanged.

Alignment text is compared with the supplied line plan and never replaces authored dialogue. Missing evidence, text mismatches, undeclared speech and fast reading rates are advisory findings for Muse; they do not require approval or a warning-free report.

An alignment row's supplied `source_sha256` must match the shot's selected sound file, including a separate audio source when selected. A mismatch leaves that shot's cues out of the new candidate. Existing alignment rows without a source digest remain compatible with ordinary subtitle builds. Source-bound automatic repair still requires every shot's digest. The alignment script requires measured word boundaries before certifying cue times, including when one recognition segment contains multiple lines.

A build with alignment or readability findings writes `<subtitle_srt>.draft.srt` only when usable cues exist, leaving the existing SRT untouched. With no usable cues, it writes only the latest attempt's `<subtitle_srt>.review.txt`, explicitly reports that no candidate was generated, and preserves any existing candidate and its review note. Otherwise, the candidate receives its own review note; the attempt note also records pending work after interruption. `prepare` and `render` return those notes and legacy `.blocked` markers as warnings while continuing with the explicitly selected readable SRT. A successful complete alignment writes the requested SRT and clears its observations. Saving, rendering and `ok: true` do not establish creative acceptance.

Each generated SRT or candidate has an adjacent `.clock.json` receipt for its exact bytes, episode, selected video and audio bytes, and ordered clip durations. Keep the two files together. `prepare` checks the receipt before replacing prepared assets and copies it alongside the installed SRT. `render` checks the selected receipt against the prepared pictures, selected audio and requested timeline before encoding or reusing an export. If the selected clips or timing change, run `subtitles` again with the current manifest and source-aligned timing. An intentionally hand-edited SRT can be selected as a separate manual file. SRTs without receipts remain supported and their alignment is unverified.

Pass `lines` and `alignment` together to `prepare` to allow one repair of a generated SRT whose bytes still match its receipt but whose source clock changed. Every alignment row must record `source_sha256` for the exact current audio file. The repair keeps the original text and order, saves the original SRT and receipt beside the rebuilt candidate, and checks the rebuilt clock before installing it. Incomplete alignment, changed dialogue, or an edited SRT requires review.

### What prepare writes

`prepare` copies each source video to `video/<集>/shot_00N.mp4`, lays the timeline out from the ffprobe-measured durations rather than declared ones, assembles the episode master by placing each shot's own sound at its own start (no gain, no per-shot resampling, one 48 kHz lossless write), and installs the subtitle at `editing/<集>.srt`. It encodes no picture. A cue that ends after the assembled picture is reported as a warning.

`subtitles` and `prepare` use the whole-frame picture duration when a single video stream starts at zero, its measured frame count and duration agree at the delivery rate, and the container runs longer by at most one frame. Otherwise they keep the measured container duration. They round each absolute cut once so small audio tails and repeated rounding cannot shift successive picture cuts, the master audio and newly aligned subtitles. The draft uses the prepared timeline. After changing the selected footage or delivery frame rate, rebuild clip-relative subtitles from their alignment before preparing the episode again. Externally supplied SRT timestamps are preserved.

`render` rejects a cut that needs more frames than a verified source at the same frame rate provides. Rebuild the timeline, master audio and generated subtitles together before rendering again. This keeps a stale container-duration timeline from repeating a shot's final frame at the next cut.

`prepare` and `render` return `render_preview`: effective delivery geometry, the subtitle file and font, ASS design values and nominal output-pixel equivalents, and the explicit master/BGM/plan paths and gains. `render` writes the same facts into its log. Other methods return null rather than claiming to reconstruct a prior render's inputs. Missing prepare music inputs and an omitted optional plan produce advice, not a new approval requirement. An empty `bgm_plan` means no declared plan was checked, not that no music was mixed. SRT carries cue text and timing, not the approved review video's font style; compare the preview with the approved version before rendering. Nominal pixel values are scaled design values, not measured glyph bounds or a visual verdict. The tool does not identify pure music or verify that a bed contains its declared tracks by listening.

After successful preparation, `editing/<集>-sources.json` records `{shots:[{shot,package?,video,audio,sha256}]}` with absolute source paths and the prepared video's SHA-256. `package` is an optional explicit 1-based position in `episode_packages/<集>/package.json`'s `video_tasks`; it is never inferred from `shot`. Multiple clips may map to one package. The previous selection record is removed before inputs are changed, so failed preparation cannot leave it claiming completion. Source selection is evidence of copied bytes, not content approval. Explicitly mapped rows also record `package_sha256` when the episode package file exists: its full-byte SHA-256, including the referenced shot content. Review records must carry the same measured hash to count as current; any package-file change, including formatting, conservatively invalidates that episode's evidence. Missing package files leave this field absent rather than blocking legacy preparation.

When the episode has approved package reviews, `prepare` checks the current package revision, explicit package IDs, and the selected video paths and SHA-256 values before probing or writing the timeline. When a review names an audio source, its `audio_path` and `audio_sha256` must match the selection. A subtitle-cleaned picture may retain independently approved original audio. The prepared manifest binds the approved audio and review hashes to the assembled master and its exact clip cuts. Working previews remain possible without audio approval.

`stage_delivery` requires the prepared selection manifest and rechecks its approved sources and master cut times. Existing pending or rejected reviews and distinct unapproved or banned audio prevent candidate publication. An approved separate audio selection requires the draft to use the same independent master as the render. A positive `jubian_script_id` or `project_bible.schema_version: 1` requires current source review, speech coverage, measured audio/video boundaries and independently checked draft tracks before staging. Missing or false project/timeline flags cannot disable these checks, including when the tool uses an episode directory below the marked project. Unmarked projects without reviews may still stage candidates after re-preparing from embedded video audio. `verify` continues to check the media technically. Picture, dialogue, and native editor playback require content review.

When `delivery.require_source_review` is enabled, formal rendering and staging require current `source_qa` evidence for every package. `source_qa.version: 1` contains `selected` and, for a cleaned picture, `original` plus `affected_intervals`. Each source binds `media_path`, `media_sha256`, `ocr: {path, sha256}` and `inspection: {path, sha256, session_id, review_id}`. The Host verifies the actual successful OCR execution and complete durable video observations. Missing execution evidence requires a fresh inspection. Complete OCR coverage and observed frames must match the current source. Artifact records must be JSON objects, and every shot needs evidence before an episode summary can be issued. The Host proof scope is released with its service providers and reacquired when they return. Every remaining OCR segment needs an exact `text_decisions` entry with `segment_index`, `text`, source `start_seconds` and `end_seconds`, `kind` (`non_dialogue_text` or `disclosure_watermark`), `reason` and `observation_frame_ids`. Text classification remains a model judgment. Cleaned media requires observed before-and-after frames inside each affected interval and retained original audio. ### Existing picture text and overlay exports

Subtitle exports accept aliases above or at the project root, including macOS system directory aliases. Links within the project output path remain rejected, and existing output files are never replaced.

Inspect source text with the existing offline [video inspection tools](../../perception/tool-video-inspect/README.md) before authoring `subtitle_plan`. Its JSON uses `schema_version: 1` and `decisions` containing `shot`, actual `source_sha256`, shot-local `start_seconds` and `end_seconds`, `text`, `action: "retain_embedded"`, `reason`, and optional `evidence_paths`. These references remain caller declarations, not Host-issued OCR or acceptance receipts. Missing or ambiguous OCR needs preview, not a paid erase or regeneration request.

`subtitle_overlay` requires prepared `video/<集>/shot_00N.mp4` inputs and hashes every selected timeline source. It omits an external cue only when the decision covers the complete cue and its punctuation-normalized text matches. Partial overlap, unmatched text and empty observations leave the complete cue in place with review advice; the resolver does not split or invent timing. A source-hash mismatch or invalid shot-local interval fails as stale input. The original SRT remains unchanged. `prepare` and `render` accept the same optional plan; rendering burns only the resolved external cues.

The result's `subtitle_overlay` binds the plan, original SRT, new `resolved_srt` and all selected videos by SHA-256, and names the full `decision_report`. A draft consumer must reuse that resolved SRT and report rather than filtering again. `retained_embedded` entries describe text already in video pixels: they are not editable subtitle clips and cannot inherit external font size or position. The authored transcript remains separately available. Technical success does not certify that every source frame is free of other text.

Before publication, the resolver rechecks the original SRT, plan and selected video hashes. If report publication fails, rollback removes only its newly written, unchanged regular SRT; changed bytes, links and concurrent report files remain. A failed rollback reports both errors.

### The three known traps

- **The tail frame.** `-sseof -0.05` returns exit code 0 without writing a file on some sources, so the frame was silently wrong. This package always seeks with `-sseof -0.1`, and it does not trust the result: the extracted frame's `framemd5` must equal the last frame of a full sequential decode. When it does not, the frame is re-extracted by index; when that still does not match, the render stops instead of freezing an unproved frame. The evidence is returned in `tail_frame`.
- **The GPU encoder.** A driver too old for NVENC, a missing build, or a busy GPU session all fail the probe the same way. The probe encodes one frame of a 256x256 source — some NVIDIA generations reject smaller frames — and a failure falls back to `libx264` by design, with the probe's own output recorded in `encoder_fallback_reason` and in the render log.
- **The frame rate after the burn.** The burn runs on the source's own time base, so an `fps` filter placed before `ass`/`subtitles` does not survive into the encode: the container still reports the delivery rate while a fraction of the frames decode. The burn chain therefore ends on `fps=F`, where `F` is the snapshot frame rate (60 for legacy timelines), preserving the concatenated timestamps. Body and ending color properties can differ and trigger a filter rebuild; rewriting timestamps from filter-local frame counts would restart them at zero and cause the encoder to drop the ending. Body encoding, effect rate conversion and subtitle burning hold the last decoded frame for one frame at EOF, then cap output to the declared clip or delivery duration and explicitly set the output rate; this preserves the original tail without adding a 3D ending. Truncated picture still fails verification, and nothing trusts metadata alone — `decode_probe` decodes a frame at the head, the middle, and just inside the tail.

### Check codes

`render` runs the five delivery checks, `verify` runs all checks in the table, and `subtitles` runs its own two. `ok` means only that the executed failure-severity checks passed. `not_checked` explicitly lists unmeasured QA, including speech alignment, unwanted source-embedded subtitles, content review and BGM listening. Removing unwanted provider captions is separate from the intended final SRT burn-in; neither operation disables the delivery subtitle style.

`verify` checks the output source record against the requested episode, normalized absolute output path, and actual file SHA-256. A record bound to another episode or path fails even when the MP4 bytes match. If the record or its binding is missing, technical checks can still pass and `output_source_record` stays a failed warning. Reuse during automated recovery requires a passing `output_source_record` and independently matched current inputs.

### Design philosophy

The package is built on four commitments:

- **Enforce the delivery where it is produced.** The picture geometry, the rate control, the subtitle style, the ending, and the audio mix are the operator-approved specification. Validated project and timeline metadata select geometry and medium treatment, and the operation that writes the file is the operation that checks it.
- **Report the artifact, throw on the obstacle.** A delivered file that misses the bitrate floor is a domain outcome: the operator still needs the file, so it comes back with `ok: false` and one repair line per failed check. A missing input or a failed command is an environment problem: it throws, because there is nothing to hand back.
- **Prove the tail frame.** The ending is the one frame nobody can inspect afterwards, so its source record is a returned value rather than a comment. The `-sseof` result is compared against a sequential decode every time, and a mismatch is either repaired by index or refused.
- **One injected process edge.** Every module takes a `MediaToolkit`; only one function starts a process. The whole pipeline therefore runs in tests against a stub channel, and the real channel is exercised by its own three-process spec.

## Model Experience

### The render and video-decision tool schemas

#### What the model sees

The request includes `drama_render` and `drama_video`, with parameter and result schemas reproduced in the generated [tool catalog](../../../docs/tool-catalog.md#deepseek-aidsh-tool-episode-render). Render results expose measurements, failed checks and unmeasured QA. Video-decision results expose labels, reason, current ban state and `review_status: "not_assessed"`; for `list`, top-level `banned` means at least one listed version is banned. Both tools render their result as formatted JSON and register no additional prompt text. The tool description states operation choices, evidence requirements and result limits. Parameter descriptions own their input formats; `project` states the shared path rule once. Fixed FFmpeg recipes and delivery details live in this reference rather than repeating in every model request.

#### Token effect

The render result contains one `clips` row per shot and up to thirteen checks, including the optional ban check. `drama_video` adds a fixed schema; its `list` result grows by one row per recorded version, while other methods return only the selected decision. A render of a nine-shot episode returns nine clip rows whatever the encode cost, and a passing delivery leaves `failures` empty and every `fix` an empty string. Explicit audio profiles add `audio_mix`; frame measurements stay in its analysis file instead of expanding the tool result.

#### KV Cache effect

Append-only. The tool registration carries a stable name, description, and schema, so a mounted row keeps the request prefix reusable; only a change to this package's description or schema invalidates it. A call's result is appended as that call's own tool result and rewrites no earlier message.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>

These limits define what this package is and what it is not. They are current constraints, not a task backlog.

- **ffmpeg and ffprobe are external** — the package starts whatever `ffmpegPath` and `ffprobePath` name. A build without `libass`, `minterpolate`, or the `screen` blend mode fails at the command that needs it, and only that command's stderr is reported.
- **Delivery metadata does not expose arbitrary filters** — project-bible geometry, explicit medium and shared subtitle targets are validated and snapshotted; rate control, legacy subtitle outline, watermark, shipped ending hashes and limiter remain fixed. Only binaries, gains, encoder preference and fonts are plugin `Config` fields.
- **Cache and log writes are not transactional** — failed renders can leave intermediate files for the next run to overwrite. Legacy final MP4 publication uses a staged sibling and rename after ban checks; explicit audio profiles publish MP4/music stems without replacement. Failures before publication retain the old delivery.
- **Bans are not a global media filter** — generic FFmpeg tools and arbitrary external transcodes are not intercepted. Prepared copies are checked by their actual SHA256; official rendering associates encoded caches with the currently hashed source. Missing or stale mappings never establish an arbitrary transcode's original version.
- **A required ending is rebuilt on every marked render** — the tail frame is re-extracted and re-proved, and the ending clip is re-encoded, even when the cache holds both. The proof is the point, and a cached ending could predate a re-cut.
- **`prepare` copies, it does not link** — every source video is copied into the project, so a nine-shot episode needs room for the reviewed cuts twice. Hard links would break as soon as the source is rewritten.
- **One episode per call** — `last_shot` bounds a render to the body shots it delivers, but a call never renders several episodes, and no method reads `pipeline_state.json`.
- **Auditions are not automatic mastering or speech separation** — short-window dBFS and LUFS measurements require `audio_preview`; legacy rendering and `verify` do not add them. Source-driven ducking can react to effects and embedded music, and no measurement certifies musical suitability or removes source-internal music.
- **Subtitle bounds are checked, not corrected** — `verify` reports a cue that runs past `body_end`; nothing clamps it, because where a line should end is the subtitle author's decision.
- **Embedded text remains picture content** — explicit overlay decisions do not erase text, make it editable, unify its style or establish continuous OCR coverage. Uncertain decisions produce review advice without blocking the episode.
- **`subtitles` trusts the recognizer's times** — the alignment settles when each line is spoken, and this package checks that it covers every declared line and that its text is the script's, but it cannot judge how accurate the recognizer was. `speech_alignment` stays in `not_checked` for exactly that reason, and producing the alignment is the caller's step.

### Dev Note

<details>
<summary>Working context for maintainers — click to expand</summary>

This Dev Note is working context for maintainers: open questions and directions that are not decided. It is explicitly non-authoritative — shipped behavior, limits, and accepted rationale live in the sections above, the package code, and the linked documents.

This package is a port of the pipeline's Python renderer (`tweet-drama-background-render/scripts/render_episode.py`). The Python script remains the production path until sessions move over, so both exist during the transition.

The ported behavior differs from the Python in five recorded places: the tail-frame seek is `-0.1` instead of `-0.05` and every extraction is proved against a sequential decode; the encoder probe failure is recorded as a reason instead of being a silent fallback; the ASS line endings are normalized to `\n` instead of following the host platform; the ending frame and clip are rebuilt on every render instead of reused from the cache; and the render log is a new file, while the Python's `exports/render_tasks.json` state file is deliberately not written.
