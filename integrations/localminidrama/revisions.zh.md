# Muse 内容编辑记录

[English](revisions.md) | 中文

## 概要

制作页面的**编辑记录与恢复**对话框可比较项目内容版本，并在检查当前版本后恢复选定内容快照。恢复不会生成媒体、切换已采用的媒体版本或恢复付费生成状态。原生 HTTP 接口和对审计业务字段的直接 SQL 写入使用同一份只追加 SQLite 日志。

## 审计内容

白名单涵盖项目、分集、角色、场景、道具、分镜及帧提示词。内容字段包括剧本、对白、旁白、提示词和角色描述。媒体地址、本地路径、已采用帧引用，以及分集或分镜的角色和道具关联只供审计。认证、供应商配置、凭据和生成状态表不进入此日志。资产库编辑不属于项目内容白名单。

启用时为现有对象创建明确标为接入快照的基线，不能找回启用前的编辑。后续原生写入记录变更前后值。已删除对象在当前项目保留只读历史，恢复不能重建对象或已删除项目。原生直接 SQL 写入不携带用户或工具身份，因此无法标注操作人。

日志会遮盖常见凭据键、Bearer/API Token 格式、明确标注的密码及签名地址参数，不读取供应商密钥或认证存储。这些格式匹配无法识别写入正文的所有任意秘密。脱敏正文不能自动恢复。快照过大或日志写入失败会在同一数据库事务中中止业务写入。

## 恢复与失败

选择业务对象并比较版本的变更前后值。对话框冻结读取时的当前版本；后续编辑会使恢复失败，用户需要刷新并核对当前内容。恢复只写入内容白名单并新增一条审计版本，保留媒体采用、关联关系及付费状态。图片、视频和声音历史使用各自专用且经过验证的采用操作。

每次恢复使用按数据库区分的稳定 `operation_id`。相同请求重放只返回原回执，不覆盖后续编辑；同一标识携带不同输入会失败。HTTP 响应未确认时必须使用原标识核对结果。浏览器的操作缓存只存指纹和 UUID；缓存持久化失败会停止恢复请求。选定内容与操作回执共同提交。

API 前缀为 `/api/v1/muse/revisions`：`GET /entities?project_id=…` 列出项目对象，`GET /history?project_id=…&kind=…&entity_id=…` 返回分页历史，`POST /restore` 接收 `{project_id,kind,entity_id,revision_id,expected_revision,side,operation_id}`。`side` 为 `before` 或 `after`。关联历史没有可恢复字段。其他项目的对象返回 404，版本已变化返回 409。

## 生成记录

`GET /usage?project_id=…` 按完成状态统计原生图片、视频和独立 TTS 生成记录。这些行不等于已核实的供应商请求次数或账单。Token 总数及费用保持 `null`，并标记 `usage_status: unreported`；缺少历史表时返回 `available: false`。对话框不根据时长、成功状态或配置估算费用。

## 集成与验证

`planMuseRevisions(root, readSource)` 在 `planCloudPrefix` 和 `planMuseAudio` 之后、后期处理修改之前运行。它在原生接口处理器前注册服务，并读取最新待应用源码。重复应用或锚点变化会失败。此模块在单调递增的 `muse_revision_schema` 第 1 版下执行包含触发器的完整 SQL，不修改上游按分号拆分的迁移。应用新结构前需同时备份 SQLite 数据库与媒体存储。

`muse_revisions.max_snapshot_bytes` 默认为 2,097,152，接受 1,024 至 16,777,216 的整数。每个执行审计写入的数据库连接都必须注册此服务的 SQLite 函数；未初始化连接会失败，不能绕过日志。白名单外写入不记录版本。

运行 `node --test integrations/localminidrama/tests/muse-revisions.test.mjs`。所属本地测试使用固定版本上游迁移、独立真实 SQLite 数据库、回环 HTTP 原生分镜处理器及 Vue 编译，验证恢复、冲突、重放、脱敏、日志失败、仅关联变更和不可用计费值，不使用供应商凭据或付费调用。预期输出位于[版本测试夹具](tests/expected/muse-revisions.json)。
