# Cloud hit transcription

English | [中文](README.zh.md)

This worker takes one Hongguo series at a time from the Muse data station. The data station owns candidate ranking and lease expiry. Muse reviews a claimed candidate when the station requests it, downloads and checks the complete series, transcribes each episode in a dedicated SDK Session, and records progress on the data station.

Workshop uploads use the same episode runner and delivery verification. See the [Workshop integration](../../services/muse-workbenches/README.md).

## Requirements

- Use Python 3.11 or newer with the matching Harness Python SDK on its import path. Use the built `dsh` and Node from a qualified Linux source release.
- Provide a dedicated SDK home and its cloud transcription patch. Compose the existing speech, video inspection, OCR, manuscript checking, and Word export plugins in that patch. Provide the account session and the qualified media and Office runtimes through the same isolated deployment.
- Install the ordinary Hongguo plugin package in a separate `hongguo` profile. Configure its FFmpeg and FFprobe paths for Linux. See [Hongguo command line](../../third_party/plugins/muse-hongguo-download/CLI.md).
- Give the worker read access to the data station's private service token file. The station API listens on loopback. Use a new private state directory on the worker host.

## Start and inspect

Copy [config.example.json](config.example.json) to the deployment directory and populate its paths. `excludeCatalogs` reads the series IDs in each existing manual queue so the worker skips those series. `onlySeries` limits a pilot to selected series IDs. An empty list allows any eligible unclaimed series. Persist `stateRoot`, `workerId`, and both profile homes together across restarts.

1. Run `python3 -B worker.py /absolute/worker.json --check-runtime` to boot both profiles without a model request.
2. Run `python3 -B worker.py /absolute/worker.json --inspect` to read station counts and preview the next eligible series.
3. Run `python3 -B worker.py /absolute/worker.json --once` for the pilot. Use `--run` in a dedicated service for continuous work. Run it as the dedicated worker account with a process-group shutdown policy and write access to the state directory and the two profile homes.

`publishChecked` set to false retains the complete draft for content review and records the station outcome as 待处理. Use true for an authorized publication run. The station accepts the full Markdown screenplay, while the worker retains each episode's checked Word document. Automatic checks bind the Word and Markdown to the video, speech result, complete video review, and OCR. Content review is a separate step from these checks.

## Recovery

Keep the active receipt and the series directory after interruption. A restart checks the same station job and claims it with the same worker identity. Downloads resume the downloader's own task after the configured cooldown. Muse reuses checked episodes and resumes an incomplete episode in its original Session, with the original source, workspace, model, and profile. The speech tool admits one start for that episode and reads the existing job thereafter. Ambiguous ownership, a changed source, missing validation, or exhausted attempts require inspection. A series this worker retired as failed or 待处理 resumes with its downloads, checked episodes and episode records when the station queues it again (立即转写); any other existing series directory is never claimed. When the Muse account gateway refuses a model or speech call because Jingliu credits are used up (`quota_exhausted`), the series stops as 待处理 with 「额度已用完，请找组长划拨后再继续」 and that round does not count against the episode's attempts; when it refuses because Jingliu's balance cannot be read (`quota_unavailable`), the round retries in the same Session every 30 seconds, up to 10 times, before stopping the same way. A provider's own 402 is an ordinary failure.

Progress renews the lease. A lost lease stops the current native process. A failed report can be reconciled against the station on restart. Immutable episode receipts, the full-script manifest, and the station outcome remain in the private series directory.

## Agent production

[agent_runner.py](agent_runner.py) runs the same station queue with Muse agents doing all transcription. It claims one series and keeps the lease, takes a checksum-verified download already on the server (`mediaCaches`) or runs this worker's downloader under the worker account (`--child <series> download`), and copies the series into a cloud Muse workspace as `原片/NNNN.mp4`. For each batch of `batchSize` episodes it opens a cloud Muse session on `preset` in that workspace and sends one request naming the batch and the delivery paths (`episodes/第N集.md`, `qa/第N集-待核.md`, `final/第N集.docx`); the agent chooses its skills and sub-agents. When no session in the workspace has run for two polls, a mechanical check requires each episode's script with scene headings, a complete frame review, a speech result and a Word file, and advises on a missing 待核 file or dialogue far from the speech result (`minSpeechCoverage`). Gaps go back to the same session by episode, up to `followUps` times; a batch still incomplete marks the series 待处理 with the reason and keeps the workspace. A batch running past `batchTimeoutMinutes` is cancelled and checked. A complete series is published to the station as one Markdown screenplay, after which its videos are deleted from the workspace and the worker's download. The runner reaches cloud Muse through its own web API with the launch token from the `museUnit` journal, so it runs as root.

The supervising Bot and operators steer the runner through `<workspaceRoot>/.production/control.json`, which the runner creates with its defaults and gives to `workspaceOwner`: `paused` holds every series at its next batch boundary while the leases stay alive and stops new claims, `dramasAtOnce` sets how many series are worked on at once (1 up to the config's `maxDramasAtOnce`, default 1; each slot claims under its own worker id, `workerId` then `workerId-2` and so on, and a slot above the new number finishes its series before it stops), `onlySeries` limits claims to those series, and `skipSeries` never claims them (Hongguo ids, with or without `hongguo:`); an unreadable file keeps the last valid request. The runner writes `status.json` beside it at every poll: the control in effect, `maxDramasAtOnce`, one row per slot with its worker id, `stage` (`claimed`, `preparing`, `transcribing`, `paused`, `idle` or `error` with its code and message) and current series with its workspace and batches, and the last ten outcomes with their `retries`. A series queued again after it stopped keeps its finished batches and starts each unfinished one over in a fresh session; `retries` counts these. When a batch's session goes idle, the runner reads how its last turn ended from the session log under `museSessionsRoot`. A completed turn is checked. A turn that an interruption ended (aborted, for example by a cloud Muse restart, an error such as a provider or adapter failure, or a turn that never ended) is resumed in the same session without counting a follow-up, after a wait that doubles with each consecutive interruption up to `resumeBackoffMaxSeconds`; a model call refused for used-up credits (`quota_exhausted`) stops the series as 待处理 instead. The batch request and each follow-up open a `batchTimeoutMinutes` window, which is the only limit on resumes. No request goes out until cloud Muse has been active for `museWarmupSeconds` (systemd's start time read with `--timestamp=unix`). Follow-ups count only after a completed turn. When the only gaps are episodes whose speech receipt the service has not answered (`prepared`, `processing`, `uncertain` and the like), the runner waits `asrRetrySeconds` and asks the agent to query those receipts again, without counting a follow-up. Every request tells the agent to reuse existing speech results and receipts and to run at most three sub-agents at once. A queued series this runner retired earlier is taken back even when another worker's expired lease spent an attempt on it. With `library.enabled`, every finished batch stores episodes 1 to its last episode as a new version of the drama's Script Workshop library entry, titled by `library.title` (default `{title}【转写稿】`, rights 授权改编, origin the Hongguo work), through `script_finalize` in a short session of its own; a failed upload is recorded as `libraryFailed` and the next batch stores every episode again.

## Transcription desk for Bots

[desk.py](desk.py) (转写工作台) is the station plumbing that transcription Bots in cloud Muse call as tools; the Bots decide which drama, which Bot, how to transcribe and when it is done. It serves one JSON request per line on a Unix socket (`socketPath`, group `socketGroup`), and [desk_mcp.py](desk_mcp.py), registered as a DS Bot MCP capability, exposes the operations: `reserve_list` lists the 储备库 queue in station order, what is being worked on and the desk's dramas; `drama_claim` claims a drama for a named Bot under `deskWorkerId`, keeps its lease alive, prepares the complete series in the background exactly as the agent runner does (selection review when asked, a verified local download or the worker's downloader, `原片/NNNN.mp4` in a cloud Muse workspace) and points the Bot's working folder there, refusing a Bot that already holds a drama; `drama_status` reports preparation, the lease, and the runner's per-episode check as advice, and refreshes the station progress; `drama_publish` publishes the combined screenplay once every episode passes the required check and deletes the videos; `drama_release` hands the drama back as 待处理 with the Bot's reason and keeps its work. State is `<stateRoot>/<series>/desk.json`; after a restart the desk claims its held dramas again under the same worker, which the station answers with the same lease, and resumes preparing. Every `watchSeconds` the desk records when each episode of a drama in work first passes the check (`doneAt`, so 剧本管理 can report minutes per episode) and, when the Bot's chat is idle and its last turn ended by an interruption for two passes in a row, sends the Bot one message to continue, waiting twice as long before each further nudge up to `resumeBackoffMaxSeconds`.

## Local verification

Run `python3 -B -m unittest discover -s integrations/muse-hit-transcription -p 'test_*.py'` from the repository root. The tests use a loopback station and scripted native stages, covering claim loss, restart, media integrity, retention of partial downloads, and publication response loss. Verify the actual Linux media paths with `--check-runtime` and a narrow pilot before continuous use.
