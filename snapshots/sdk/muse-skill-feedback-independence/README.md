# Independent Skill rejection and product feedback

English | [中文](README.zh.md)

This keyless SDK scenario runs completed file tasks through the shipped profile and two tool-free native review Sessions. Both reviews return an invalid Skill name with independently valid product feedback. The plugin records failed Skill validation without creating proposals, versions or Skill files. Its production account client sends one authenticated request to an owned loopback inbox, retains the receipt and suppresses the repeated candidate.

The fixture awaits idle reviews through the native permission command. A fixture tool calls the production status handler, checks its failed validation and feedback states, and verifies the audit hash against the exact logged review input before returning stable observations to the model. The ordinary feedback management tool also exposes the retained receipt and duplicate. The complete workspace retains the task files and an evidence summary. No normalization rule or historical Session fixture changes for this scenario.

The dedicated replay provider has no real-model fallback. The model backend and central inbox are local fixtures; review persistence, Skill validation, account transport and feedback retention use production code. `MUSE_SKILL_EVOLUTION_PACKAGE` selects an unpacked plugin archive for packaging checks. An inbox receipt confirms intake, not a PR, merged fix or release.
