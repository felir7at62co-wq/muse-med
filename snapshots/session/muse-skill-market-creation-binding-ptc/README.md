# Market Skill versions in the creation preset

English | [中文](README.zh.md)

The shipped Headless profile loads the actual creation preset, its isolated Skill registry, creation adapter and tool policy. A Skill deliberately outside the built-in creation allowlist is available only through its explicitly selected market publication. The primary Agent loads version one. At the next model-request barrier, an external fixture operator creates a blank creation Agent, switches the real activation default to version two, then starts that blank Agent and a fresh creation Agent. Both load version two; the primary then loads version one again.

All four actual tools.skill dispatches retain the unchanged creation guard. Every complete typed Skill result reaches the next model request in its own Session. The fixture checks the three required binding events, projections, exact archive identities, original reference bytes, catalog metadata and muse-creation provider results. Its independent workspace proof records three, two and two model requests. No fixture tool bypasses the policy, and no resource or provider request executes.
