# Skill release selection per Session

English | [中文](README.zh.md)

The shipped Headless profile loads the production local publication and activation services. Two complete publications contain different instructions and reference resources for the same Skill. The primary Agent loads version one, then an explicit compare-and-set changes the default to version two. Its next real Skill load retains version one. A blank Agent created before the change first executes afterward with version two; a fresh Agent also executes with version two. Both children run through the actual Agent registry, loop, Skill tool and recorded model adapter.

Each complete Skill result is checked in its subsequent model request. The fixture compares the required muse-market/bound event, Session projection, provider metadata, exact archive SHA and selected reference bytes for all three Sessions. A workspace proof records those checks and the full lifecycle tool results reach the primary Agent's next request. Missing-cache and historical-reader refusal matrices remain owned by package tests. This case makes no provider request or resource execution.

The [PTC sibling](../muse-skill-market-version-binding-ptc/README.md) exercises the same three-Session lifecycle through actual programmatic tool dispatch.
