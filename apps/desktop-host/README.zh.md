# Muse Desktop Host

[English](README.md) | 中文

## 本机 Hindsight 记忆

桌面组合注册 `hindsight_memory`，供 Agent 保存创作偏好和项目决定。Agent 自行判断用户已确认的偏好、纠正或决定是否有长期复用价值，有明确来源即可保存，不必等待另一次“记住”指令。`user` 范围属于当前安装；默认的 `project` 范围对会话的规范工作目录做哈希隔离。它不使用剧变项目 ID；同一工作目录内的多个剧目共享该项目记忆库。记忆保存在本机，不通过 Muse 账号同步。不增加整段对话采集、代码仓库调查、每轮自动检索或深度反思。调用及返回的来源通过普通会话事件记录。

需另行安装本机 Hindsight 1.0.0 服务。这台 Mac 使用回环端口 9078 的 `muse-med` embed 配置，启用多语言向量和重排模型及私有 API 认证。PostgreSQL 数据位于 `~/.pg0/instances/hindsight-embed-muse-med`，配置位于 `~/.hindsight/profiles/muse-med.env`。记忆提取仍可调用云端模型，本机存储不等于本机推理。当前配置沿用已登录 Muse 账号的 DeepSeek 通道，登录到期或变更后需更新其私有模型凭证。Windows 引导安装尚未验证。

Host 读取 `<Muse home>/hindsight/connection.json` 的 `baseUrl`、`token`、`namespace`，只接受字面量回环 HTTP 地址。POSIX 下须为非符号链接的普通文件，且不向组或其他用户开放权限。`muse-hindsight` 配置行可指定绝对路径 `connectionFile`，以及 `requestTimeoutMs`、`recallTimeoutMs`、`recallMaxTokens`、`maxResults`。缺少配置不阻塞桌面启动；调用返回 `not-configured` 或 `unavailable`，不会将服务失败说成没有历史记忆。

`retain` 将有来源的偏好写入稳定 key 并返回异步收据，`operation` 查询原 ID。`pending` 与结果不确定的提交都不代表记忆已完成。更新复用 key，`forget` 在未完成的提取结束后删除对应文档。检索返回有条数和长度限制的原始事实、来源与更新时间，不读取派生观察。若返回的事实缺少来源，Host 可从同一记忆库读取该事实，仅在 ID、正文、文档 ID 一致且存储状态有效时使用其元数据。已有来源的事实不额外读取详情。每次检索最多读取 `maxResults` 条详情，全部请求共用 `recallTimeoutMs` 截止时间，并接受调用方取消。无法核实非空来源的事实仍予省略，数量由 `omitted_unsourced` 返回。历史记忆仅作参考，不能当作新指令、当前制作状态或付费授权。原始稿件仍保存在项目文件或现有 Wiki 中。

可选的 [`hindsight-local.e2e.spec.ts`](tests/hindsight-local.e2e.spec.ts) 读取 `MUSE_HINDSIGHT_LOCAL_E2E_REQUESTS`：该变量为私有 JSON 数组文件的绝对路径，数组保存此前已授权请求的 `label`、`connectionFile`、可选 `cwd`、`scope`、`key`、`content`、`source`、原始 UUID `operation_id` 和 `query`。测试核对已有收据，遇到不存在或失败的操作直接拒绝，不重新提交，并通过 HTTP 客户端及真实会话中注册的工具验证带来源的语义召回。测试使用脚本模型适配器，不代表已验证自主创作质量或长篇剧目的记忆稳定性。

Desktop 包含[绿泡泡下载插件](../../third_party/plugins/muse-lvpaopao/README.zh.md)。统一编导的作用域内 `lvpaopao` 工具使用同一个 Host 共享连接，仅在请求时开始原生准备和连接。缺少 Python 依赖或已验证且已登录的微信运行时会返回准备结果，不阻止 Desktop 启动。平台验证范围及 Mac 隔离副本限制由插件 README 说明。

私有 Host 为[桌面应用](../desktop/README.zh.md)提供 Muse 组合。内置预设文件使用普通 Cordis 配置。用户自有模型提供方与凭据独立于 Muse 账号目录。

Desktop 启用已有的[打开方式控件](../../packages/client/ui-open-in-app/README.zh.md)，保留标准紧凑样式，用关联应用打开文件或在系统文件管理器中显示其位置。

Desktop 默认组合包在用户配置补丁之前注册[短剧设置](../../packages/drama/drama-settings/README.zh.md)。剪映专业版草稿根目录保存在用户配置中，并在重启后恢复；显式 home 和命令行覆盖仍保持优先级。保存此设置不授予草稿导出的文件系统访问权限。

桌面账号组合通过 [`excludedProviderIds`](../../packages/host/muse-account/README.zh.md#minimal-configuration) 排除独立 Gemini 提供方 `aa`，并将 `yunying` 加入 `hiddenProviderIds`：云映路由继续为已保存的 Session 注册，但新模型选择只展示账号提供的官方 DeepSeek 与智谱 GLM。个人提供方及其他已注册提供方保持不变。已有对话若选用了独立 Gemini，须在下次请求前选择可用模型；操作见[迁移指南](../../docs/upgrade-guide/v0.2.1-alpha.1/muse-gemini-provider/guide.zh.md)。

桌面账号组合还从新会话可选目录精确排除云映的 `claude-opus-5-5`、`claude-fable-5-1`、`gpt-6-astra`、`glm-5.3-flash`。网关私有目录及其他提供方（包括智谱官方 GLM 路由）保持不变。已有会话保留原模型 ID；当目录不再提供该路由时，选择器提示先切换模型。

桌面账号组合将网关与知识库请求的 `requestTimeoutMs` 设置为 60,000 毫秒，包含项目参与组合扫描。个人覆盖文件可修改这一经过验证的账号配置；底层插件默认值仍为 15,000 毫秒。超时仍报告服务不可用，不能据此判断远程写入是否完成。

<a id="compaction-defaults"></a>
短剧交付按项目明确类型和已准备画布执行；选择方式与旧项目行为见[项目圣经](../../packages/drama/drama-settings/README.zh.md)。

Muse 内置 Codex 订阅插件，并在设置中提供 ChatGPT 登录入口。独立订阅登录使用官方 Codex OAuth 提供方；Muse 账号登录不授予此权限。凭据保留在本地 Host 凭据服务中，浏览器账号响应不包含令牌。仅在连接账号时列出订阅模型。升级会恢复内置组合包，不替换已保存的订阅设置或凭据。此订阅接入不包含或启用可选 Codex CLI 子代理提供方。产品覆盖继续停用 Agent 笔记设置页及其 Host API；工程笔记文件与 Muse 知识库功能仍可使用。

## 用户返稿对照

Office 组合全局注册 `manuscript_revision`，对照实际上一稿与返回的 Markdown、UTF-8 文本或 Word 文稿。同一会话此前交付的文件在下一次真人输入时检测外部变化，修改者保持未确认。改名文件可以通过明确路径关联；缺少基线时如实说明，不声称已经识别历史修改。

对照展示新增、改写和删除的段落。可选候选稿对照返回差异，不拒绝写入、导出或交付。Agent 依据用户当前要求和最新返稿处理；旧授权记录仍可读取，但不作为前提。

只读 `measure` 动作通过显式 `source_paths` 与 `candidate_paths` 比较同一故事范围，不建立返稿基线。结果包含文件哈希、各文件与合计计数、差额及增幅。计数含标题和人物名，分别统计文字数字数与非空白字符数，两者均不估算 Word 字数或净正文。`max_growth_percent` 传入用户的增幅上限；纯 ASR 对白不能充当含画面动作剧本的等量来源。

本地记录保留在工作区的 `.muse/manuscript-revisions/` 下。Office 的 `manuscriptRevisions` 设置控制资源限额，对照不静默截断。差异作为已记录的上下文进入模型。参见[迁移指南](../../docs/upgrade-guide/v0.2.1-alpha.1/muse-manuscript-protection/guide.zh.md)。

## 内置桥接选择

Host 从内置桥接包的 remote 导出解析 `muse-desktop-bridge`，并将原有 `feishu-channel` 配置项交给内置 `@xmanrui/dsh-im` 提供方。IM 配置项的规范包名也用于发现其原生浏览器模块。正式包的 profile 通过安装目录回退解析 Host 和浏览器两部分，不创建 profile 包链接；开发环境指向同一包的链接也可使用。启动时先对 profile 原文件做私有字节备份，再迁移已知旧包名的匹配条件；凭证、启用开关、发送者策略和无关字节保持不变。共享 home patch 中仍有旧包名匹配条件，或 profile 安装的 IM 包遮蔽了内置产物时，启动会停止并给出诊断。内置导出缺失时，组合阶段会明确报出受影响的入口；其他 profile 插件仍按普通规则解析。

[飞书迁移辅助模块](src/feishu-migration.ts)依据内存或已持久化的 Session 头部核实先前的 `activeSessionId`，并保留头部记录的工作目录。它优先检查原有 profile，再检查 `dsh-bridge/config.json` 中同一应用及扫码者的状态；它不复制凭证，也不编辑 Session 日志。旧状态没有持久化聊天归属，因此恢复需要授权聊天中的明确选择。已有聊天绑定优先，一个旧 Session 只能绑定一个聊天。

## 短剧身份

[短剧预设](presets/short-drama/agent.cordis.yml)的制作前缀说明模型时长、镜头节奏、原文对白、素材用途和视频包上下文独立性。Harness 插件动态补入当前工具指导，后缀在请求时插入工作目录。工具 schema、运行时上下文和技能目录继续提供；身份文本不决定实际模型。Muse 不注册 drama_shot，也不内置其编译技能；视频生成直接使用原生分镜预览与提交，免费预览返回生成前检查提醒。制作前缀要求按项目画幅设计镜头，规定白底角色图、场景图与道具图规格，按需使用站位图，并禁止面部光效或变色描写。视频包描述不写国旗、国徽等敏感标识及内容；否定句、负面提示、反例与备注也不写入禁用词，Agent 检查实际提交文本，不把禁用清单复制进去。原台词首次逐字提交；仅确认生成失败与对应词语有关时，才对该处作最小修改，其余台词保持原文。技术性失败不授权修改台词。创作与制作剧本按实际正文分析受众兴趣与情绪预期，再区分媒介、题材、情绪观感和美术方向。受众假设不作为市场事实，也不授权修改台词。仿真人玄幻可采用电影级灵兽，非人类资产按自身形态展示，不套用人类版式；普通转写与格式转换不增加受众分析阶段。

视频包在所选模型已核实的能力范围内按剧情连续性、对白、表演与节奏安排。先确定内容分包再映射已有视频卡，多余空卡保留不用，不足时才新增。每镜节奏建议不限制单包长度，也不授权省略必要内容。编导与短剧系统提示词均将配速限定在视频包内部，修改已有包或任务卡的配速须有用户明确要求。单集总长按实际采用的视频包与实际剪辑扣减汇总；单集目标不授权重新分配包时长，要求不清楚时先澄清再修改。这些指导不增加工具审批或执行检查。

内置的 16:9 横屏 3D 与 9:16 竖屏仿真人镜头脚本技能在任务匹配时通过 `skill` 加载，提供逐镜格式与创作规则。系统提示词负责全局创作方向、分包和素材引用。技能使用 `jubian_storyboard` 预览、保存和回读，视频模型与分辨率以会话选择为准。预设通过[裁剪器配置](../../packages/compaction/compaction-tool-result-pruner/README.zh.md)避免机械截掉 `skill` 结果中段；后续摘要仍可能移除完整指导。技能目录只含简介，不自动重新加载以前读过的正文。技能可用与裁剪保护不证明整部剧持续保持创作质量。

[Todo 工具](../../packages/todo/tool-todo/README.zh.md)记录计划与单项任务变化。工具说明和成功结果提醒 Agent 核实阶段产物、更新当前工作，并区分生成与剪辑、质量检查和交付。界面展示记录中的任务状态，不根据其他工具调用自动推断完成或验收通过。

每镜用到的已有角色、场景、道具、音频均在对应画面、动作或声音描述中内联引用，后续镜头再次提及时继续引用，不能只在包首列素材。名称与 key 来自实际查询并与选材绑定一致；图片按 key 首次出现顺序去重绑定一次。原文对白内部不插标记。编写视频包与检查引用不自动补生成资产或站位图，缺少关键参考时如实列明。

站位图提供当前包的空间关系参考，适用于空间关系决定动作、文字容易混淆且场景与主体相对位置基本稳定的情况。简单近景优先文字；走位、进出、换场或变形导致固定图失效时写清路径，不为用图拆包。使用前实际看图核对身份、空间和风格；无合适现成图时不自动补图，并说明原因。

固定自检清单在系统提示词中持续提供，覆盖分包范围、逐镜引用和原台词、风格与空间、真实写入回读，以及生成任务的授权范围与费用。最终回复提供包与卡片对应、时长、引用、真实回读及保存内容证据；已有完整回读直接复用。Host 为免费写卡预览与生成准备配置剧变字面命中提示，返回词语、卡号和上下文，包括否定句与引号内文字。Agent 对照来源核实原台词，修正自行描述后核对保存回读并重新准备。提示不引入审批或拦截，也不代表完整审核通过；见[剧变提示词检查](../../packages/jubian/tool-jubian/README.zh.md)。

## 统一编导 Agent

Muse 新任务使用同一个短剧编导 Agent，处理写作、改稿、转写与视频制作。旧 editing 预设在已有会话中解析到同一组合，无需改写日志。产品隐藏 Agent 预设设置页、模式选择器及会话模式标签，同时隐藏插件管理导航和页面。智能体团队、自动授权审查、实验性检查器与语音输入均不加入默认 profile。统一预设通过现有[子代理运行时](../../packages/subagent/subagent/README.zh.md)支持全新上下文与继承对话的子代理，并提供追问、列表与中断工具。子代理继承父级模型与创作预设，委派权限遵循运行时策略，并排除提醒工具。Host 设置保留默认一层深度和八个活跃可续接子代理的容量。workflow 与计划模式工具仍不加入，产品关闭计划界面。

文稿格式与返稿指导放在系统提示词中。人物情绪波动时，对白通过语气、神态或同步短动作括注呈现情绪。视频转写的神态与动作以画面、语气以原声为依据，画面不清楚时先抽帧查看，再据实写入。创作写作与审稿技能退出内置目录，Office、转写与视频制作技能仍可用。Agent 遵循用户要求，不规定写作或审批顺序。

视频查看采用[整集观察](../../packages/perception/tool-video-inspect/README.zh.md)：工具自动保留全部检测到的切镜和画面变化候选，逐批呈现，并要求图片真正进入模型请求及留下逐图记录。有疑点时补入数量受限的邻近观察点。所属会话仍有未完成扫描或观察时，限制正式 Word 导出和 `present`，中间稿仍可保存。全部完成后返回观察报告，供后续写稿查阅；这不要求加载写作 Skill，不批准创作质量，也不代表连续观看了视频。

默认写作入口不挂载可选的来源审校实现，也不追加保存后审校提醒。`manuscript_revision` 对照实际上一稿与返稿，跨轮保存版本差异，并可选对照候选稿。差异提示不阻止写入、导出或交付；缺少基线时明确说明。

忠实转写记录原声与实际事件。改编指导保留主线、人物关系和关键因果，允许后续非关键桥段、推进方式和对白沿改编方向变化。默认篇幅提示目标为对应原稿的 100%—110%，用户另有要求时从其要求。篇幅报告不拦截交付，不用重复、空泛描写或编造事实凑字。

Desktop 产品在原生窗口和浏览器访问中均关闭上游 Web 预览版说明。

Muse 忙碌时，Enter 和发送按钮默认插话，Cmd/Ctrl+Enter 将消息排队到下一轮。用户在设置中的明确选择会覆盖此产品默认值。

新会话默认完全权限（`danger-full-access`，审批策略 `never`）。对话中的权限选择器和 `/permission` 修改当前会话；设置 → 常规选择后续新会话的默认权限，重启后继续生效。已有会话保留日志中的权限，直到用户主动修改。产品权限默认值位于可编辑的用户配置之下，升级保留已保存的默认选择。

文字稿件默认交付 Word（.docx），用户指定其他格式时按其要求。Agent 保留 Markdown 源稿，加载 office-docx，优先用 screenplay_export_docx 转换分场剧本并交付检查后的 Word，不重复转写或重写正文。视频制作要求仅用于视频工作；普通稿件自主核对来源，只有任务采用受管项目时才执行对应验收。

内置的[微短剧剧本审核技能](skills/reviewing-micro-drama-scripts/SKILL.md)用于用户要求的剧本内容安全审核及相关创作咨询。技能按需加载，随包包含用户提供的[平台创作规范参考](skills/reviewing-micro-drama-scripts/references/platform-guidelines.md)。该本地参考不能证明平台当前的官方规则或审核结论。添加技能不改变系统人设，也不增加工具层审批要求。

## 创作模式

`creation` 预设将编辑与短剧的原生工具合并到 PTC `run_code`，由一个模型执行，不提供委派、工作流模型或团队工具。现有预设与 `short-drama` 默认值保持可用。此模式使用隔离的创作与 Office 已审核技能目录，不发现目录名单外的技能名，包括插件编写技能名。名单内技能的项目或全局同名覆盖仍沿 Host 注册表的通常优先级；名称目录不认证指令正文来源。后续工具注册仍受已审核白名单约束，包括 Agent 自身作用域的贡献。

创作预设只补入媒体操作与收据说明；分场格式和返稿差异使用共用编辑系统段。

默认写作入口不挂载受管剧本项目流程。已有项目记录保留在磁盘上，显式采用项目部署时仍可读取。

分场格式包含集号、场次、人物、动作、对白、OS/VO 和闪回标记，用户指定格式优先。Word 转换使用 `office-docx` 与 `screenplay_export_docx` 处理已保存正文。

创作预设通过共用的 `muse:short-drama-production` 系统段执行短剧制作要求：每镜1–4秒、每秒8个有效字、无声反应镜更快。仅场景固定、在场人物固定、人物位置保持不变的视频包可用站位图；剧本或视频提示涉及走动、靠近、后退、换位等任何人物位置移动，或有人物进出场景、换场时，整包不用站位图。摄影机移动、切镜或因取景画外不算人物走位，也不为配图强行拆包。使用时一包一张实际看过的完整全景，展示全部在场角色、每人唯一实体、空间关系与固定环境锚点；阵容、布局和环境相同且各包均适用时才可复用。生图明确沿用项目已确认风格和既有资产，包括脸型比例、材质、服装与场景渲染，3D不能变真人摄影，真人也不能强改3D。绑定视频前必须实际看图确认画风，文字或style字段不能替代；不符时按既有付费规则修复或重生成并复审。站位图约束身份和空间；站立、蹲下、坐下、姿势、情绪与动作由每镜脚本和视频提示决定，不能照搬静态姿势或让人物提前起身，姿势或表情变化无需重做站位图。每镜出镜名单优先于全包参考图。拍摄时间只进入本地预算元数据和生成参数；提交的视频提示词不含控制分镜时长的要求，原台词中的时间信息保持不变。

成片切点和身份需与项目已确认资产实际并列比对。父资产ID、材质ID及确认状态须与当前项目一致，并记录时间码和可见差异；历史图、候选图或未核图不能替代正式参考或提高通过置信度。服装相似本身不能确认身份。未解决的身份或画风差异保持失败或待确认，直到获明确授权接受或复检解决；关键参考缺失或关键检查未解决时，包整体不得通过，不绑定、不推进依赖该验收的收费操作。已核实的合理摄影机、姿态、光照及普通构图变化可以接受，但低清、光照或可能版本不同不能豁免未解决的身份或画风变化。画风相符须对照造型比例、材质表现、渲染质感与强弱，3D或CG等大类标签不足以判定。细项差异未解释或细节不足时保持待确认，不强迫风格标签，不因已核实合理的光照和机位变化判失败。照片感或低清未呈现的纹理不能证实制作来源。

视频准备从真实元数据与整段时长检查计划开始。每个输入视频关联对应集；本策略当前检查完整输入，不支持把同一个视频裁成跨集任务。仅创作模式启用的检查选项将实际采样窗口、解码帧时间和图像附件绑定到原图像能力路由的后续模型请求；纯文本或已卸载图像不能算看过。默认60秒概览不是全片检查。正式交付按原Session证据重核来源版本和已验收检查记录；进行中实时观察在冷启动后须重新建立，已验收证据可不重抽帧、不重跑模型审校而核验。原日志或模型路由信息缺失、视频或附件变化均拒绝放行。抽样不证明连续观看或完整理解事件。ASR不能证明试听，本次没有新增独立环境声观察通道。

显式严格自检部署须先让 C 轮审校的 PTC 程序成功结束，再在后续模型程序 commit 或 export；该顺序不是 Muse 建议型审校的前置要求。外层程序失败不能证明审校成功，须保留实际失败历史。带补充批准的旧精修项目不能直接升级，因为批准绑定原策略与基线。保留该项目及其报告，再从原视频和来源账准备新的故事忠实项目。

有修改的作品遵守[创作共用规则](src/creation-guidance.ts)：保留原件，交付最终成稿绑定的独立《修改说明》，含可定位改动、批注采用、获准补充、未解决项与实际验证范围。新写没有旧剧本时使用真实来源和成稿位置，不伪造前后引文。原保源精修分支继续绑定真实Host用户输入、基线版本与有界类别授权；同步动作保持typed事实与覆盖，避免重复显示。

已验收剧本、Word 与知识库正文只包含剧本。《修改说明》是独立的验收候选 sidecar，绑定同一版本；新精修 Word 收据另记说明摘要。没有标记的普通文档保留原行为；Muse 对旧受管项目也应用建议型审校，不改写历史记录。

严格 Word/交付配置下，约定受管 `final/` 目录内的正式精修或故事忠实交付须同时 present 剧本或 Word 与同候选精确匹配的修改说明；说明可单独补送。目录外带收据的 Word 补送保留单独正文/版本校验。校验器没有首次交付历史，不机械保证任意迁移文件成对；创作流程仍要求首次完整交接并列交付两者。

## 压缩默认值

Host 默认值与 `standard`、`ptc`、`cordis`、`short-drama`、`creation` 预设为[选定目录](../../services/muse-accounts/README.zh.md#selected-model-budgets)中的账号模型声明精确策略。每条策略预留 16,384 tokens 的额外压缩余量，将摘要上限设为 8,192 tokens；正常对话保留提供方输出预算。其他路由继承后端默认值；`minimal` 不挂载自动压缩。

每个创作预设拥有隔离的压缩后端，因此策略同时位于各预设的 `agent.cordis.yml` 和 Host 默认覆盖文件。个人预设可按[压缩配置](../../packages/compaction/compaction-basic/README.zh.md#tuning-when-condensation-starts)设置自己的 `modelPolicies`。后端将固定请求成本计入预算，并在相关输入改变前跳过未改变的失败选区或单独检查点的重复摘要。

## 视频剧本交付

受管视频剧本项目通过 [screenplay-project](../../packages/drama/screenplay-project/README.zh.md) 整理视觉事实并保存各集版本。Muse 为新旧项目选择建议型审校，不要求独立批准、A/B/C 分轮或先采用前集，才可起草或采用指定集。受管视频项目使用 `workflow: video_to_screenplay` 和 `qa/screenplay-project.json`；正式文件位于同级 `final/` 目录。分块场景文件和持久化覆盖清单支持恢复，不依赖压缩后的对话摘要。

Muse 建议型 Word 导出固定本次实际 Markdown 输入，通过内置 Python 转换，并逐段核对生成的 Word 正文与实际输入，不要求项目、候选批准或 `.docx.screenplay.json` 收据。建议型交付检查预算内实际可读的 Markdown、文本或 Word，用户返稿保护继续独立生效。导出或呈现草稿不会自动采用，也不代表创作审校通过。

显式严格 Word/交付配置下，`screenplay_export_docx` 在转换前将每份受管输入与当前已验收 Markdown 比较，固定这些正文，并生成 `.docx.screenplay.json` 记录，绑定候选与输出摘要。可选 `project` 参数使跨目录导出保持绑定；显式项目不存在或未标记时拒绝导出。Office 组合还注册实际 `present` 执行器检查：受管 Markdown 须匹配验收，Word 须有匹配记录，并通过内置 Python 将实际正文与当前已验收正文独立比较。项目身份使用文件系统真实路径，使目录别名保持同一验收。替换正文或在表格中追加内容，即使伪造匹配记录也会失败。普通 Python 或 Office 生成的文件未经候选验收时，不能声明为受管视频正式交付。保源精修和故事忠实项目也使用同一final目录检查，包括精确匹配的独立修改说明；故事交付在采用已验收正文前还核对Host生成的真实检查日志记录。普通文档和没有视频或精修标记的项目保留原有转换与交付行为。

严格受管交付识别依赖约定的标记和目录；未标记项目，或移出范围且没有记录的文档，无法被识别为视频转剧本。文件系统权限仍可编辑项目与校验文件；这些是一致性记录，不是签名授权。直接文件链接和外部应用不调用 `present`。Agent 仍负责已整理清单之外的画面完整性与含义。建议型采用及交付检查不能证明抽样找到了全部事件，也不能证明创作审校通过。

`jianying_draft` 通过受管子进程调用内置 Python 生成器，输入为有大小限制的单集 JSON 请求和已有剪映草稿根目录。完成、失败和取消均等待进程退出。字幕、配乐和轨道质量疑点通过 `warnings` 与逐稿 `review_path` 返回，不拒绝生成；保存与 JSON 精确回读遇到技术错误仍会失败。保存后草稿校验不代表原生编辑器打开或渲染已验收。
