# Muse Desktop Host

[English](README.md) | 中文

私有 Host 为[桌面应用](../desktop/README.zh.md)提供 Muse 组合。内置预设文件使用普通 Cordis 配置。用户自有模型提供方与凭据独立于 Muse 账号目录。

Desktop 默认组合包在用户配置补丁之前注册[短剧设置](../../packages/drama/drama-settings/README.zh.md)。剪映专业版草稿根目录保存在用户配置中，并在重启后恢复；显式 home 和命令行覆盖仍保持优先级。保存此设置不授予草稿导出的文件系统访问权限。

桌面账号组合通过 [`excludedProviderIds`](../../packages/host/muse-account/README.zh.md#minimal-configuration) 排除独立 Gemini 提供方 `aa`，并将 `yunying` 加入 `hiddenProviderIds`：云映路由继续为已保存的 Session 注册，但新模型选择只展示账号提供的官方 DeepSeek 与智谱 GLM。个人提供方及其他已注册提供方保持不变。已有对话若选用了独立 Gemini，须在下次请求前选择可用模型；操作见[迁移指南](../../docs/upgrade-guide/v0.2.1-alpha.1/muse-gemini-provider/guide.zh.md)。

桌面账号组合还从新会话可选目录精确排除云映的 `claude-opus-5-5`、`claude-fable-5-1`、`gpt-6-astra`、`glm-5.3-flash`。网关私有目录及其他提供方（包括智谱官方 GLM 路由）保持不变。已有会话保留原模型 ID；当目录不再提供该路由时，选择器提示先切换模型。

桌面账号组合将网关与知识库请求的 `requestTimeoutMs` 设置为 60,000 毫秒，包含项目参与组合扫描。个人覆盖文件可修改这一经过验证的账号配置；底层插件默认值仍为 15,000 毫秒。超时仍报告服务不可用，不能据此判断远程写入是否完成。

<a id="compaction-defaults"></a>
短剧交付按项目明确类型和已准备画布执行；选择方式与旧项目行为见[项目圣经](../../packages/drama/drama-settings/README.zh.md)。

## 创作模式

`creation` 预设将编辑与短剧的原生工具合并到 PTC `run_code`，由一个模型执行，不提供委派、工作流模型或团队工具。现有预设与 `short-drama` 默认值保持可用。此模式使用隔离的创作与 Office 已审核技能目录，不发现目录名单外的技能名，包括插件编写技能名。名单内技能的项目或全局同名覆盖仍沿 Host 注册表的通常优先级；名称目录不认证指令正文来源。后续工具注册仍受已审核白名单约束，包括 Agent 自身作用域的贡献。

预设通过稳定的 `muse:creation-guidance` 系统部分自动提供最小共用指导：按用户请求分流任务，返回阶段产物与证据，在后续模型步检查、修正和复检后再推进依赖工作，区分参考正文格式，并保留来源、授权与费用要求。自动提供的已审核技能目录用于发现技能；专业步骤与详细[精修和 QA 指南](skills/muse-creation/SKILL.md)按当前阶段需要加载。`muse-creation` 原技能名保持兼容，不要求所有任务先读它。工具保持原有机械校验、审批、沙箱、取消与并发策略。流程指导不代表每个工具都机械强制模型审核；Node 与终端访问仍由已安装沙箱和授权策略约束。名称白名单不能证明被替换插件实现可信。

新创作受管剧本项目显式使用包的自检验收配置，记录真实模型步、正文摘要与修订证据。未声明该配置的已有项目保持独立审校；自检不能报告为独立审校。图像与完整技能正文进入模型上下文后才能用于判断，代码成功不能替代。长媒体任务沿已有任务和收据恢复，不使用启动模型的工作流。

所有剧本任务共享按需加载的[写作品质标准](skills/screenplay-format/references/writing-quality.md)：对白接话、动作因果、人物知情、情绪冲突、连续性与可制作故事。小说改编、换梗与新写按已授权大纲或简报执行。新创作视频剧本任务默认 `story-faithful-v2`；逐字转写或字幕沿严格来源路径。显式项目策略保留来源账，允许对白重写、情绪和表演强化、镜头表达与必要重分场；来源→故事→作品映射及后续语义复原报告逐集绑定。已声明的关键疑点、缺失映射或故事偏差阻止批准；代码不判断文学质量，也不能发现全部未声明剧情变化。旧 `source-preserving-v1` 精修策略仍保留原渠道、来源事实顺序与场次元数据规则，不能静默转入新策略。

创作和短剧预设通过共用的 `muse:short-drama-production` 系统段执行短剧制作要求：每镜1–4秒、每秒8个有效字、无声反应镜更快。仅场景固定、在场人物固定、人物位置保持不变的视频包可用站位图；剧本或视频提示涉及走动、靠近、后退、换位等任何人物位置移动，或有人物进出场景、换场时，整包不用站位图。摄影机移动、切镜或因取景画外不算人物走位，也不为配图强行拆包。使用时一包一张实际看过的完整全景，展示全部在场角色、每人唯一实体、空间关系与固定环境锚点；阵容、布局和环境相同且各包均适用时才可复用。生图明确沿用项目已确认风格和既有资产，包括脸型比例、材质、服装与场景渲染，3D不能变真人摄影，真人也不能强改3D。绑定视频前必须实际看图确认画风，文字或style字段不能替代；不符时按既有付费规则修复或重生成并复审。站位图约束身份和空间；站立、蹲下、坐下、姿势、情绪与动作由每镜脚本和视频提示决定，不能照搬静态姿势或让人物提前起身，姿势或表情变化无需重做站位图。每镜出镜名单优先于全包参考图。拍摄时间只进入本地预算元数据和生成参数；提交的视频提示词不含控制分镜时长的要求，原台词中的时间信息保持不变。

成片切点和身份需与项目已确认资产实际并列比对。父资产ID、材质ID及确认状态须与当前项目一致，并记录时间码和可见差异；历史图、候选图或未核图不能替代正式参考或提高通过置信度。服装相似本身不能确认身份。未解决的身份或画风差异保持失败或待确认，直到获明确授权接受或复检解决；关键参考缺失或关键检查未解决时，包整体不得通过，不绑定、不推进依赖该验收的收费操作。已核实的合理摄影机、姿态、光照及普通构图变化可以接受，但低清、光照或可能版本不同不能豁免未解决的身份或画风变化。画风相符须对照造型比例、材质表现、渲染质感与强弱，3D或CG等大类标签不足以判定。细项差异未解释或细节不足时保持待确认，不强迫风格标签，不因已核实合理的光照和机位变化判失败。照片感或低清未呈现的纹理不能证实制作来源。

视频准备从真实元数据与整段时长检查计划开始。每个输入视频关联对应集；本策略当前检查完整输入，不支持把同一个视频裁成跨集任务。仅创作模式启用的检查选项将实际采样窗口、解码帧时间和图像附件绑定到原图像能力路由的后续模型请求；纯文本或已卸载图像不能算看过。默认60秒概览不是全片检查。正式交付按原Session证据重核来源版本和已验收检查记录；进行中实时观察在冷启动后须重新建立，已验收证据可不重抽帧、不重跑模型审校而核验。原日志或模型路由信息缺失、视频或附件变化均拒绝放行。抽样不证明连续观看或完整理解事件。ASR不能证明试听，本次没有新增独立环境声观察通道。

故事验收须先让C轮审校的PTC程序成功结束，再在后续模型程序commit或export。外层程序失败不能证明审校成功：保留失败历史，重新stage候选、读回并审校。带补充批准的旧精修项目不能直接升级，因为批准绑定原策略与基线。保留该项目及其报告，再从原视频和来源账准备新的故事忠实项目。

有修改的作品遵守[精修指南](skills/muse-creation/references/refinement.md)：保留原件，交付最终成稿绑定的独立《修改说明》，含可定位改动、批注采用、获准补充、未解决项与实际验证范围。新写没有旧剧本时使用真实来源和成稿位置，不伪造前后引文。原保源精修分支继续绑定真实Host用户输入、基线版本与有界类别授权；同步动作保持typed事实与覆盖，避免重复显示。

已验收剧本、Word 与知识库正文只包含剧本。《修改说明》是独立的验收候选 sidecar，绑定同一版本；新精修 Word 收据另记说明摘要。没有标记的普通文档和原有独立审核项目保留原行为。

约定受管 `final/` 目录内的正式精修或故事忠实交付须同时 present 剧本或 Word 与同候选精确匹配的修改说明；说明可单独补送。目录外带收据的 Word 补送保留单独正文/版本校验。校验器没有首次交付历史，不机械保证任意迁移文件成对；创作流程仍要求首次完整交接并列交付两者。

## 压缩默认值

Host 默认值与 `standard`、`ptc`、`cordis`、`short-drama`、`editing`、`creation` 预设为[选定目录](../../services/muse-accounts/README.zh.md#selected-model-budgets)中的账号模型声明精确策略。每条策略预留 16,384 tokens 的额外压缩余量，将摘要上限设为 8,192 tokens；正常对话保留提供方输出预算。其他路由继承后端默认值；`minimal` 不挂载自动压缩。

每个创作预设拥有隔离的压缩后端，因此策略同时位于各预设的 `agent.cordis.yml` 和 Host 默认覆盖文件。个人预设可按[压缩配置](../../packages/compaction/compaction-basic/README.zh.md#tuning-when-condensation-starts)设置自己的 `modelPolicies`。后端将固定请求成本计入预算，并在相关输入改变前跳过未改变的失败选区或单独检查点的重复摘要。

## 视频剧本交付

编剧与短剧路由要求通过 [screenplay-project](../../packages/drama/screenplay-project/README.zh.md) 先整理视觉事实，再逐集独立审校并顺序验收。受管视频项目使用 `workflow: video_to_screenplay` 和 `qa/screenplay-project.json`；正式文件位于同级 `final/` 目录。分块场景文件和持久化覆盖清单支持恢复，不依赖压缩后的对话摘要。

`screenplay_export_docx` 在转换前将每份受管输入与当前已验收 Markdown 比较，固定这些正文，并生成 `.docx.screenplay.json` 记录，绑定候选与输出摘要。可选 `project` 参数使跨目录导出保持绑定；显式项目不存在或未标记时拒绝导出。Office 组合还注册实际 `present` 执行器检查：受管 Markdown 须匹配验收，Word 须有匹配记录，并通过内置 Python 将实际正文与当前已验收正文独立比较。项目身份使用文件系统真实路径，使目录别名保持同一验收。替换正文或在表格中追加内容，即使伪造匹配记录也会失败。普通 Python 或 Office 生成的文件未经候选验收时，不能声明为受管视频正式交付。保源精修和故事忠实项目也使用同一final目录检查，包括精确匹配的独立修改说明；故事交付在采用已验收正文前还核对Host生成的真实检查日志记录。普通文档和没有视频或精修标记的项目保留原有转换与交付行为。

默认范围依赖约定的标记和目录；未标记项目，或移出范围且没有记录的文档，无法被识别为视频转剧本。文件系统权限仍可编辑项目与校验文件；这些是一致性记录，不是签名授权。直接文件链接和外部应用不调用 `present`。项目声明的独立审校或自检仍负责已整理清单之外的画面完整性与含义，检查不能证明抽样找到了全部事件。
