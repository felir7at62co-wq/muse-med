## Local Hindsight memory

The Desktop composition registers `hindsight_memory` for creative preferences and project decisions. The Agent decides when a user-confirmed preference, correction or decision has lasting value and can retain it with a source without waiting for a separate “remember this” request. `user` scope belongs to this installation; the default `project` scope hashes the Session's canonical working directory. It does not use a Jubian project ID: productions sharing one working directory also share that project bank. Memory stays on this computer and does not synchronize through Muse accounts. No conversation capture, repository survey, automatic per-turn recall or deep reflection is added. Tool calls and returned references are recorded through ordinary Session events.

Install a local Hindsight 1.0.0 daemon separately. This Mac uses the `muse-med` embed profile on loopback port 9078, multilingual embeddings and reranking, and private API authentication. The daemon stores PostgreSQL data under `~/.pg0/instances/hindsight-embed-muse-med`; its configuration is `~/.hindsight/profiles/muse-med.env`. LLM extraction can still call a cloud model; local storage does not imply local inference. The current setup uses the signed-in Muse account's DeepSeek route, so its private model credential must be refreshed after that login expires or changes. Windows bootstrap has not been verified.

The Host reads `<Muse home>/hindsight/connection.json` with `baseUrl`, `token` and `namespace`; only literal loopback HTTP addresses are accepted. On POSIX this must be a regular, non-symlink file without group/world permissions. The `muse-hindsight` row can set an absolute `connectionFile`, `requestTimeoutMs`, `recallTimeoutMs`, `recallMaxTokens` and `maxResults`. Missing setup does not block Desktop startup; a memory call reports `not-configured` or `unavailable`, rather than claiming that no memories exist.

`retain` saves a sourced preference under a stable key and returns an async receipt; `operation` checks the original ID. `pending` and uncertain submissions are not completed memories. Updates reuse the key; `forget` removes its document after outstanding extractions finish. Recall returns bounded raw facts with their source and update time and excludes derived observations. When a returned fact omits its source, the Host can read that fact from the same bank and use its metadata only when the ID, text and document ID match and the stored state is valid. Already sourced facts require no detail read. Each recall performs at most `maxResults` detail lookups within the shared `recallTimeoutMs` deadline; caller cancellation still applies. Facts without a verified nonblank source remain excluded, with their count reported as `omitted_unsourced`. History is reference rather than new instructions, current production state or paid authorization. Original manuscripts remain in project files or the existing Wiki.

The opt-in [`hindsight-local.e2e.spec.ts`](tests/hindsight-local.e2e.spec.ts) reads `MUSE_HINDSIGHT_LOCAL_E2E_REQUESTS`, an absolute path to a private JSON array of previously authorized requests (`label`, `connectionFile`, optional `cwd`, `scope`, `key`, `content`, `source`, original UUID `operation_id`, and `query`). It reconciles existing receipts, rejects absent or failed operations without resubmitting, and verifies sourced semantic recall through both the HTTP client and registered tool in a real Session. The test uses a scripted model adapter; it does not establish autonomous creative quality or long-series memory reliability.

The private Host supplies the Muse compositions used by the [Desktop application](../desktop/README.md). Its bundled preset files remain ordinary Cordis configuration. User-owned model providers and credentials stay separate from the Muse account catalog.

Desktop enables the existing [Open In controls](../../packages/client/ui-open-in-app/README.md) with their standard compact appearance for opening files in associated applications and showing their location in the system file manager.

The Desktop defaults bundle registers [short-drama settings](../../packages/drama/drama-settings/README.md) before user profile patches. The JianyingPro draft root persists in the profile across restarts; explicit home and command-line overrides still take precedence. Saving this setting grants no filesystem access for draft export.

The Desktop account composition excludes the standalone Gemini provider `aa` through [`excludedProviderIds`](../../packages/host/muse-account/README.md#minimal-configuration). It also places `yunying` in `hiddenProviderIds`: the Yunying route remains registered for saved Sessions, but new model selections expose the official DeepSeek and Zhipu GLM account providers instead. Personal and other registered providers are unchanged. Saved standalone Gemini selections require choosing an available model before another request; [the migration guide](../../docs/upgrade-guide/v0.2.1-alpha.1/muse-gemini-provider/guide.md) describes that step.

The Desktop account composition also excludes Yunying's exact `claude-opus-5-5`, `claude-fable-5-1`, `gpt-6-astra`, and `glm-5.3-flash` IDs from new selections. The gateway directory and other providers, including official Zhipu GLM routes, remain unchanged. Existing conversations keep their saved model ID and show a switch prompt when that route is absent from the catalog.

The Desktop account composition sets `requestTimeoutMs` to 60,000 milliseconds for gateway and knowledge-base requests, including project portfolio scans. Personal overlays can change this validated account setting; the underlying plugin's default remains 15,000 milliseconds. A timeout still reports an unavailable service and does not establish whether a remote write completed.

Short-drama delivery follows the explicit project medium and prepared canvas; see the [project bible](../../packages/drama/drama-settings/README.md) for selection and legacy behavior.

Muse includes the Codex subscription plugin and its ChatGPT sign-in entry in Settings. The separate subscription login uses the official Codex OAuth provider; Muse account login does not authorize it. Credentials remain in the local Host credential service, while browser account responses omit tokens. Subscription models appear only while an account is connected. Upgrading restores the built-in bundle without replacing saved subscription settings or credentials. The optional Codex CLI subagent provider is not included or enabled by this subscription integration. The product overlay continues to disable both the Agent Notes settings page and its Host API; engineering-note files and Muse knowledge-base features remain available.

## Returned manuscript comparisons

The Office composition registers `manuscript_revision` globally. It compares the actual previous draft and returned Markdown, UTF-8 text or Word file. Changes to a file previously presented by the same Session are detected on its next human turn; the external author remains unconfirmed. Renamed files can be associated through explicit paths, and a missing baseline is reported without claiming historical edits were identified.

Comparisons show inserted, changed and deleted paragraphs. Optional candidate comparison reports differences without refusing writes, export or presentation. The Agent follows the current user request and latest returned file; legacy authorization records are readable but are not prerequisites.

Workspace-local records remain under `.muse/manuscript-revisions/`. The Office `manuscriptRevisions` settings configure resource limits; comparisons never silently truncate. Differences enter logged model context. See the [migration guide](../../docs/upgrade-guide/v0.2.1-alpha.1/muse-manuscript-protection/guide.md).

## Bundled bridge selection

The Host resolves `muse-desktop-bridge` from the bundled bridge's remote export and the existing `feishu-channel` row from the bundled `@xmanrui/dsh-im` provider. The IM row's canonical package name also identifies its native browser module. Packaged profiles use installation fallback for both halves without creating profile package links; a development link to the same package is also accepted. Startup migrates known legacy package-name guards in the profile after making a private original-byte backup; credentials, activation switches, sender policies and unrelated bytes stay unchanged. A legacy guard in the shared home patch or a profile-installed IM package that shadows the bundled artifact stops startup with a diagnostic. Missing bundled exports fail at composition with the affected entry named; other profile plugins retain normal resolution.

The [Feishu migration helper](src/feishu-migration.ts) resolves a previous `activeSessionId` against live or persisted Session headers and preserves the header's working directory. It checks the existing profile first, then same-app/scanner state in `dsh-bridge/config.json`; it neither copies credentials nor edits Session logs. Old state contains no durable chat ownership, so recovery requires an explicit choice in an authorized chat. An existing chat binding wins, and one previous Session can bind to only one chat.

## Short-drama identity

The [short-drama preset](presets/short-drama/agent.cordis.yml) defines a production prefix for model durations, shot rhythm, literal dialogue, material purposes and independent video packages. Harness plugins add their current tool instructions dynamically, and the suffix interpolates the working directory at request time. The preset retains tool schemas, runtime contexts and the skill catalog; the identity text does not select the actual model. Muse does not register `drama_shot` or bundle its compilation skill. Video generation uses native storyboard preparation and submission, with a generation-check reminder in the free preview. The production prefix follows the project aspect ratio, defines the white-background character board, scene and prop images, allows positioning images when needed and excludes facial glow or colour-change wording. Video-package descriptions omit sensitive symbols and content, including national flags and emblems. This also excludes prohibited terms inside negative instructions, examples and notes; the Agent checks the submitted text rather than copying a prohibition list into it. Original dialogue is submitted verbatim first; only a confirmed wording-related generation failure permits a minimal edit to the affected term, preserving all other dialogue. Technical failures do not authorize dialogue changes. For creative and production scripts, the Agent derives audience interests and emotional expectations from the actual text, then distinguishes medium, genre, mood and art direction. Audience hypotheses do not establish market facts or authorize dialogue changes. Live-action fantasy permits cinematic creatures, while nonhuman asset boards follow their anatomy rather than the human layout. Plain transcription and formatting add no audience-analysis stage.

Package planning follows narrative continuity, dialogue, performance and pacing within the selected model's verified limits. Plan content before assigning existing video cards; leave surplus empty cards unused and add cards only when needed. Shot-rhythm advice does not cap a package or justify omitting necessary content. Both creation and short-drama system prompts define pacing within each video package and require an explicit request before changing existing package or card pacing. Episode totals sum adopted packages with actual editing deductions; episode targets do not authorize redistributing package durations, and unclear requests are clarified before editing. This guidance adds no tool approval or execution check.

The bundled 16:9 3D and 9:16 live-action shot-writing skills provide shot format and craft through the `skill` loader when a task matches. The system prompt owns global creative direction, package planning and references. The skills use `jubian_storyboard` previews, saving and readback, with video models and resolutions following the conversation selection. The preset preserves `skill` results from mechanical middle pruning through the [pruner configuration](../../packages/compaction/compaction-tool-result-pruner/README.md); later summarization can still remove the full instructions. The skill catalog contains summaries and does not automatically reload a previously loaded body. Skill availability and pruning protection do not establish sustained creative quality over an entire series.

The [Todo tools](../../packages/todo/tool-todo/README.md) record plans and individual task changes. Tool descriptions and successful results remind the Agent to verify stage outcomes, update the current work, and distinguish generation from editing, quality checks and delivery. The UI displays recorded task states without automatically inferring completion or acceptance from other tool calls.

Each shot references its existing character, scene, prop and audio assets inline where their appearance, action or sound is described. Later shots repeat references when the asset is mentioned again; a header list is insufficient. Queried names and keys must match the selected materials; bind images once in first-key-appearance order. Keep reference markers outside original dialogue. Package writing and reference checks do not generate missing assets or positioning images; report missing essential references.

A positioning image supplies spatial relationships for the current package when those relationships determine actions, text is ambiguous, and the scene and relative subject positions remain stable. Simple close-ups use text; describe movement paths when entrances, exits, scene changes or transformations invalidate a fixed image, without splitting packages to accommodate it. Inspect identity, layout and style before use. An absent suitable image does not trigger automatic generation; explain the choice.

The system prompt persistently supplies a checklist for scope, inline references and original dialogue, style and space, actual saved readback, and generation scope and cost when applicable. Final replies provide package/card mapping, duration, references, actual readback and evidence from saved content; reuse complete existing readback. The Host configures Jubian's advisory term review for free card previews and video preparation. Findings identify the word, card and surrounding text, including negative instructions and quotes. The Agent checks original dialogue against the source, corrects authored descriptions, then verifies saved readback and prepares again. Findings add no approval or interception and do not establish complete compliance; see [Jubian prompt review](../../packages/jubian/tool-jubian/README.md).

## Unified creative Agent

New Muse tasks use one short-drama director Agent for writing, revision, transcription and video production. The retired editing preset resolves to the same composition for existing Sessions without rewriting their logs. The product hides the Agent preset settings page, mode picker and session label, together with plugin-management navigation and pages. Agent Teams, automatic permission review, the experimental inspector and voice input remain absent from the default profile. The unified preset supports fresh and conversation-seeded subagents with follow-up, listing and interruption through the existing [subagent runtime](../../packages/subagent/subagent/README.md). Children inherit the parent's model and creative preset; delegated permissions follow the runtime policy, and reminder tools are excluded. Host settings retain the default depth of one and an active continuable-child capacity of eight. Workflow and plan-mode tools remain absent, and the product disables the plan UI.

Manuscript formatting and returned-draft guidance live in the system prompt. When a character’s emotions shift, dialogue uses parenthetical descriptions of tone, expression or simultaneous short actions to make the emotion visible. During video transcription, expressions and actions follow the footage and tone follows the original audio; unclear visual details are checked in sampled frames before being written. Creative writing and review skills are retired from the bundled catalog; Office, transcription and video-production skills remain available. The Agent follows the user request without a prescribed writing or approval sequence.

The optional source-comparison implementation is not mounted in the default writing preset and adds no save reminders. `manuscript_revision` compares actual previous and returned files, preserves versioned differences across requests and optionally reports candidate differences. Comparison advice does not block writes, exports or presentation; a missing baseline is reported explicitly.

The Desktop product disables the upstream Web preview notice for native and browser access.

While Muse is busy, Enter and the Send button default to Steer; Cmd/Ctrl+Enter queues the message for the next turn. An explicit choice in Settings overrides this product default.

New sessions default to Full access (`danger-full-access`, approval `never`). The conversation's Permissions selector and `/permission` change the current session; Settings → General selects the default for future sessions and persists it across restarts. Existing sessions retain their logged permissions until the user changes them. The product supplies permission defaults below the editable profile, so upgrades preserve a saved default.

Text deliverables default to Word (`.docx`) unless the user specifies another format. The Agent keeps Markdown sources, loads `office-docx`, uses `screenplay_export_docx` for screenplay conversion and presents the checked Word file without transcribing or rewriting the source again. Video-production guidance is scoped to video work; ordinary manuscripts use autonomous source checks, with managed acceptance only when the task adopts such a project.

The bundled [micro-drama script review skill](skills/reviewing-micro-drama-scripts/SKILL.md) supports requested script safety reviews and related creative guidance. It loads on demand and includes the user-supplied [platform guidance](skills/reviewing-micro-drama-scripts/references/platform-guidelines.md). This local reference does not establish current official platform policy or approval. Adding the skill does not change the system persona or add a tool-level approval requirement.

## Creation mode

The `creation` preset combines the native editing and short-drama tools behind PTC `run_code`, with one model and no delegation, workflow-agent or Team tools. The existing presets and `short-drama` default remain available. The preset uses an isolated approved creative/Office skill catalog; skill names outside that catalog, including plugin-authoring names, are not discovered in this mode. Approved-name workspace or global overrides still follow the Host registry's normal precedence; the name list does not authenticate instruction bodies. Future tool registration stays inside the reviewed allowlist, including Agent-local contributions.

The creation preset adds technical media and receipt instructions; screenplay notation and returned-file differences use the shared editing system sections.

The default writing presets do not mount the managed screenplay-project workflow. Existing project records remain on disk and can be read by explicit project deployments.

Screenplay notation covers episode and scene headings, participants, actions, dialogue, OS/VO and flashback markers. The user format takes precedence. Word conversion uses `office-docx` and `screenplay_export_docx` with the saved manuscript.

Short-drama production uses the shared `muse:short-drama-production` system section in the creation preset: 1–4-second shots, eight effective speech characters per second and faster silent reactions. A video package may use a positioning reference only when its setting, present cast and character positions remain fixed. Any character movement in the script or video prompt, including walking, approaching, stepping back or changing places, excludes the entire package, as do entrances, exits and scene changes. Camera movement, cuts or framing a character out do not count as character movement. Packages are not split just to fit a reference. When used, one visually checked panorama shows every present character once, spatial relationships and fixed environment anchors; reuse requires the same cast, layout and environment in another eligible package. Reference generation explicitly preserves the approved project style and existing assets, including facial proportions, materials, clothing and scene rendering; it cannot change 3D into live-action photography or vice versa. Actual image review must confirm the style before video binding; text or a style field is insufficient, and mismatches require repair or regeneration and review under the existing paid-operation rules. This reference constrains identity and space; each shot's script and video prompt determine standing, crouching, sitting, posture and emotion, without copying static poses or making characters rise early. Posture or expression changes do not require a new positioning image. Each shot's visible cast takes precedence over the full-package reference. Shooting times stay in local budgeting metadata and generation parameters; submitted video prompts contain no shot-duration instructions. Source dialogue containing time expressions remains intact.

Generated cuts and identities require visual comparison with approved project references. Parent asset IDs, material IDs and confirmation states must match the current project; record them with timestamps and visible differences. Historical, candidate or unverified images cannot replace approved references or increase approval confidence. Similar clothing alone does not establish identity. Unresolved identity or style differences remain failed or unverified until explicitly accepted or resolved by review; missing critical references or unresolved critical checks prevent package approval, binding and dependent paid operations. Verified camera, pose, lighting and ordinary framing variations remain acceptable; low resolution, lighting or possible version differences cannot excuse unresolved identity or style changes. Style agreement requires visible comparison of proportions, material appearance and rendering character and intensity; broad labels such as 3D or CG are insufficient. Unexplained detailed differences or insufficient detail remain unverified, without forcing a style label or rejecting verified reasonable lighting and camera changes. Photographic appearance or textures absent at low resolution do not establish production origin.

Video preparation starts with real metadata and a full-duration inspection plan. Each input video is associated with its episode; this strategy currently checks the complete input and does not support cropping one video into cross-episode tasks. The creation-only inspection option binds actual sampled windows, decoded frame timestamps and image attachments to subsequent model requests on the original image-capable route; text-only or offloaded images do not count as viewed. A default 60-second overview is not a whole-video check. Source versions and accepted inspection records are rechecked for delivery using their original Session evidence. Pending live observations require renewed inspection after a cold restart; already accepted evidence can be verified without rerunning sampling or model review. Missing original logs or model-route information, changed videos or changed attachments fail closed. Sampling does not establish continuous viewing or complete event understanding. ASR does not prove listening, and no independent environmental-sound observation channel is added.

In an explicit strict self-check deployment, the C-review PTC program must finish successfully before a later model program commits or exports. That sequence is not a Muse advisory prerequisite. A failed outer program never establishes a successful review; preserve the actual failed history. A legacy refinement project with supplement approvals cannot directly upgrade because those approvals bind its original policy and baseline. Preserve that project and its reports, then prepare a new story-faithful project from the original videos and source account.

Modified work follows the [shared creation guidance](src/creation-guidance.ts): preserve originals and deliver final-bound `《修改说明》` with located changes, comment dispositions, authorized supplements, unresolved items and actual verification scope. New writing without an earlier screenplay uses real source/output locations rather than invented before/after quotations. Original source-preserving forks retain real Host user input, baseline versions and a bounded category grant; synchronous actions remain typed and covered without duplicate rendering.

The accepted screenplay, Word body and knowledge-base text contain only the screenplay. Modification notes are a separate accepted-candidate sidecar, with the same version binding and an additional digest in new refinement Word receipts. Existing unmarked documents retain their prior behavior; Muse applies advisory review to old managed projects without rewriting their historical records.

With strict Word/delivery configuration, formal refinement or story-faithful delivery under a conventional managed `final/` directory must present the screenplay or Word together with that candidate's exact modification-notes file. Notes can be redelivered separately. Receipt-bound Word resends outside that directory retain standalone body/version verification; the validator has no first-delivery history and does not mechanically enforce the pair on arbitrary relocated files. The creation workflow still requires the pair for the initial complete handoff.

## Compaction defaults

The Host defaults and the `standard`, `ptc`, `cordis`, `short-drama` and `creation` presets declare exact policies for the selected account models in the [selected catalog](../../services/muse-accounts/README.md#selected-model-budgets). Each policy reserves 16,384 tokens of additional compaction headroom and caps summaries at 8,192 tokens; conversation output keeps its provider budget. Other routes inherit backend defaults; `minimal` does not mount automatic compaction.

Each creative preset owns its isolated compaction backend, so its policy lives in that preset's `agent.cordis.yml` as well as the Host defaults overlay. Personal presets can set their own `modelPolicies` using the [compaction configuration](../../packages/compaction/compaction-basic/README.md#tuning-when-condensation-starts). The backend accounts for fixed request costs and avoids retrying unchanged failed selections or a lone checkpoint until its relevant input changes.

## Video screenplay delivery

Managed video screenplay projects use visual preparation and saved episode versions through [screenplay-project](../../packages/drama/screenplay-project/README.md). Muse selects advisory review for new and existing projects; it does not require independent approval, A/B/C review or adoption of an earlier episode before drafting or adopting the requested one. A managed video project uses `workflow: video_to_screenplay` and `qa/screenplay-project.json`; its formal files go under the sibling `final/` directory. Scene-file chunks and saved coverage support recovery without relying on a compressed conversation summary.

Muse's advisory Word export pins the actual Markdown inputs, converts them through bundled Python and compares the resulting Word paragraphs with those inputs. It does not require a project, candidate approval or a `.docx.screenplay.json` receipt. Advisory delivery checks the actual readable Markdown, text or Word document within configured budgets; user-return protection continues independently. Exporting or presenting a draft does not adopt it or establish that creative review passed.

With explicit strict Word/delivery configuration, `screenplay_export_docx` verifies each managed input against the current accepted Markdown before conversion, pins those contents, and saves a `.docx.screenplay.json` record binding the candidate and output digests. Its optional `project` argument retains that binding for exports elsewhere and refuses a missing or unmarked explicit project. The Office composition also registers an actual `present` executor check: managed Markdown must match acceptance, and Word needs a matching record plus an independent body comparison against the current accepted text using the bundled Python runtime. Project identity uses the real filesystem path so directory aliases retain the same acceptance. Replacing the body or adding text in a table fails even with a forged matching record. Generic Python or Office outputs without acceptance cannot be declared formal managed video deliverables. Source-preserving refinement and story-faithful projects use the same final-directory check, including their exact separate modification notes. Story delivery also rechecks the Host-issued logged inspection records before accepted text is used. Ordinary documents and projects without a video or refinement marker retain existing conversion and delivery behavior.

Strict managed-delivery identification requires the conventional marker and directory; an unmarked project or relocated document without a record cannot be identified as video conversion. Filesystem access can edit project and verification files, which are consistency records rather than signed authorization. Direct file links and external applications do not call `present`. The Agent remains responsible for visual completeness and meaning beyond the prepared fact inventory. Advisory adoption and delivery checks do not establish that sampling found every event or that creative review passed.

`jianying_draft` runs the bundled Python generator through the managed subprocess provider, using a bounded episode JSON request and an existing editor root. Completion, failure and cancellation await process exit. Subtitle, BGM and track quality findings return `warnings` and per-draft `review_path` without rejecting generation. Saving and exact JSON readback still fail on technical errors. Saved draft validation does not confirm that the native editor can open or render the result.

While the native tool is mounted, its standing system guidance also reaches continued conversations: reload the current draft skill and use the native request-file entry instead of historical absolute development paths or `DraftGenerator` shell recipes. Independent dialogue import must succeed before source-video sound is muted; existing drafts are not migrated. This is Agent guidance, not shell interception, a new approval step, or proof that a free-running model will always follow it.
