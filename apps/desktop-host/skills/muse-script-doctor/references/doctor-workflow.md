# 诊断与修复方法

## 确定本次范围与保留项

读取用户反馈、当前剧本版本、本次涉及的大纲与项目要求，确认要改善的观看效果和允许改动的集场。用户要求改稿即授权处理所指范围，无需再要求逐项批准；只要求评审时交付诊断与修订建议。沿用已定人物、关键剧情、伏笔与揭晓顺序、结局、格式和篇幅要求，不借精修另换故事方向。

读取受改正文、必要前置和后续依赖，包括相邻集的尾钩与开场；记录实际读到的版本和范围。保留已有的笑点、压迫感、亲密感、人物缺陷、直白情感与余味，确定哪些效果不能因修改而丢失。视频忠实转写的事件与台词仍按来源核对，不用本技能添加戏剧内容；原创增强在获授权的创作新稿中处理。

## 用原文诊断

先确认问题在当前版本是否成立，反馈引用旧稿时核对新稿，不照着已解决或无证据的意见继续修改。按影响列出主要问题，不凑数量、不以总分或爆款预测代替证据。每项写清以下内容，简单问题可以合并成一段：

| 内容 | 要求 |
| --- | --- |
| 定位与证据 | 稿版本、集号与场号、可逐字核对的短原文；找不到支撑则标待核。 |
| 问题与影响 | 文本实际出现什么，如何妨碍用户要求的理解、人物、情绪或追更体验。 |
| 修订目标 | 本次需要改善的效果，区分必须修复的问题与可选加强。 |
| 保留项与改动范围 | 必须保住的现有效果、固定剧情和允许修改的段落。 |
| 连带复查与状态 | 涉及哪些前后场次、集数或伏笔；标待处理、已解决、未解决或待核。 |

按实际影响排序：使关键因果、观看承诺或明确交付要求无法成立的问题优先，其次是削弱重要段落的问题，再处理局部表达。对白直说情绪、人物沉默或作出不够理智的选择均不自动构成缺陷；核对它是否符合人物此刻的认知、处境和本作表达目标。

## 选择足够的修复

先查人物即时目标、阻碍、选择、结果和下一行动是否连贯。人物行动须有当前可理解的理由，对手或环境须有回应，结果须改变信息、关系、资源或危险并影响下一选择；断在这些地方时先修因果与场景功能，再修对白语感。若因果成立而质感不足，再处理角色声音、回应、潜台词和语言节奏。

采用授权范围内最小但足够的修改：表达调整能解决就保留场景；局部调整不足时修改场景或单集，确需重排分集时使用 `muse-episode-design`。不以减少改动字数为由保留无效场面，也不顺手重写无关段落。调整人物动机或核心事件超出授权范围时说明具体影响与可选方案，继续完成已授权且不依赖该选择的部分。

优先替换重复说明、重复证明同一种情绪或无关过程，确有缺失才补戏。删除或合并前检查理解、人物、前置伏笔和必要余波是否受损。对白让双方的目的、策略和回应发生作用，不把所有人物改成统一碎句，不强制隐藏每种情感，不用堆动作或争吵掩盖场景没有变化。对白专项处理时使用 `muse-dialogue-polish`，格式沿用 `screenplay-format` 的中文场次、▲动作、对白与 OS/VO。

用户的篇幅目标与明确硬限制需要一并核对。不能为了凑字注水、为了显得精练删去必要过程，或以质量优先为由静默放弃约定；出现无法兼顾的要求时给出具体冲突和调整选择。某种修法反复没有改善时换实现、缩小单位或回到场景构思，不无限自评，也不假称问题已解决。

## 修改后读取实际正文

保存新版本后读回正文，逐项核对目标问题、保留项和本次产生的影响。检查同集内是否还有同类问题，并核对受改段落与相邻场次、前集结尾和下集开场：称呼、人物位置与状态、在场人员、知情顺序、道具、伏笔、钩子兑现和情绪是否接得上。必要时追查受影响的后续集；没有读到的依赖标未核验，不补造事实，不把局部通过写成全稿通过。

逻辑更顺却使人物更平、笑点或亲密感消失、情绪过早解决、风格化完整句被统一剁碎，或必要过程被篇幅指标挤掉时，恢复受损效果并换修法。新问题若来自本次改动，应修正或撤回该改动，再复核受影响范围。

## 交付可替换稿

评审交付当前范围的结论、保留项、按影响排序的问题及可选修订目标。修稿交付简短改动记录和约定范围的完整替换正文：包括范围内没有修改的部分，不写“其余不变”“后续同理”或“略”。标明原版与新版、修改集场；拆合或重排时附旧场到新场映射，保持未受影响部分的编号与称谓。

正文脱离改动报告仍能直接使用，审校意见另存项目 `qa/`。记录实际解决、否决、未解决和未核验的项目；长稿分批时列明已完成与待处理范围，按已授权计划继续，不把首批称作完整交付。
