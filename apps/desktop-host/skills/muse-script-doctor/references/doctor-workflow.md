# 诊断与修复方法

## 确定本次范围与保留项

读取用户反馈、当前剧本版本、本次涉及的大纲与项目要求，确认要改善的观看效果和允许改动的集场。用户要求改稿即授权处理所指范围，无需再要求逐项批准；只要求评审时交付诊断与修订建议。沿用已定人物、关键剧情、伏笔与揭晓顺序、结局、格式和篇幅要求，不借精修另换故事方向。

读取受改正文、必要前置和后续依赖，包括相邻集的尾钩与开场；记录实际读到的版本和范围。保留已有的笑点、压迫感、亲密感、人物缺陷、直白情感与余味，确定哪些效果不能因修改而丢失。严格视频来源整理的事件与台词仍按来源核对，不用本技能添加戏剧内容；新创作模式故事忠实路径的表达增强及其他原创增强在获授权的作品层处理，保留来源账。

## 用原文诊断

先确认反馈在当前稿是否成立，不照着旧稿或无证据的意见继续改。定位具体集场和能支持判断的原文，说明它如何妨碍理解、人物、情绪或衔接，以及要保住的效果。简单问题直接改，不为每处措辞写诊断表。关键因果、遗漏与明确交付要求优先；可选加强与未解决项简述，不凑数量、不打总分或预测爆款。

直说情绪、沉默或不够理智的选择不自动构成缺陷，判断它是否符合人物此刻的认知、处境与作品目标。

## 选择足够的修复

小说和视频改编均先沿共享写作品质核对用户保留的主线、当前设定和实际前情，再查人物即时目标、阻碍、选择、结果和下一行动是否连贯。人物行动须有当前可理解的理由，对手或环境须有回应，结果须改变信息、关系、资源或危险并影响下一选择；断在这些地方时先修因果与场景功能，再修对白语感。若因果成立而质感不足，再处理角色声音、回应、潜台词和语言节奏。

采用授权范围内最小但足够的修改：表达调整能解决就保留场景；局部调整不足时修改场景或单集，确需重排分集时使用 `muse-episode-design`。不以减少改动字数为由保留无效场面，也不顺手重写无关段落。调整人物动机或核心事件超出授权范围时说明具体影响与可选方案，继续完成已授权且不依赖该选择的部分。

优先替换重复说明、重复证明同一种情绪或无关过程，确有缺失才补戏。删除或合并前检查理解、人物、前置伏笔和必要余波是否受损。对白让双方的目的、策略和回应发生作用，不把所有人物改成统一碎句，不强制隐藏每种情感，不用堆动作或争吵掩盖场景没有变化。对白专项处理时使用 `muse-dialogue-polish`，格式沿用 `screenplay-format` 的中文场次、▲动作、对白与 OS/VO。

用户的篇幅目标与明确硬限制需要一并核对。不能为了凑字注水、为了显得精练删去必要过程，或以质量优先为由静默放弃约定；出现无法兼顾的要求时给出具体冲突和调整选择。某种修法反复没有改善时换实现、缩小单位或回到场景构思，不无限自评，也不假称问题已解决。

## 修订与交付

修复、回读和说明沿共享写作品质，复用已读内容与检查，只核对实际受改部分及依赖。新改动若损伤人物、笑点、亲密感或必要过程，修正或撤回再核对，不无限自评。

改稿交付约定范围的完整替换正文，未改段落一并保留，不写“其余不变”或“略”。正文稳定后简述关键改动、保留效果和未解决项；拆合集场时说明对应关系。只要求评审则给当前范围的诊断。部分交付写清完成与未处理范围，不把首批称作全稿。
