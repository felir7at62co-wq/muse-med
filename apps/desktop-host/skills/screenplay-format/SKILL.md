# 真人短剧分场剧本格式

内容怎么审、是否独立审校，由当前 Agent 按任务和用户要求自主决定；当前工具声明 advisory 时，事实和候选检查只提供建议，不把独立审校、固定复检轮次、批准记录或审校收据作为起草、续写、Word 导出和交付前提。动作数为零时复核来源，不为满足格式增加动作或旁白。严格部署明确启用时才沿工具声明的验收链。格式转换保留本次实际正文，不以转换成功冒称内容已经审校。

当前 Agent 自主核对来源、修改和交付，不因工具可用就强制登记受管事实、独立审校、候选批准或子代理。采用 `screenplay_project` 时按当前工具声明区分 advisory 和明确启用的严格部署；advisory 可整理旧项目并输出当前稿件，保留原件、历史审批和来源，不把自主检查称为独立审核，也不虚构审校通过。工具不可用时直接整理普通稿件，不调用受管命令。

小说转剧本与视频转剧本共用此格式。起草正文前阅读本技能，用户已指定其他格式时以其要求为准。格式是写作指导，不设额外确认或开写门禁；集数、单集篇幅与总字数沿用大纲阶段的可修改约定，不照搬参考剧的集数。

起草、续写、修订或审校正文前，完整读取[共享写作品质](references/writing-quality.md)与[时间线及叙述归属](references/narrative-layers.md)，分段写作和合稿沿用同一份项目记录。

按当前工具形态加载本技能；native 工具直接调用 `skill` 并保留完整返回值，PTC 时用 `return await tools.skill({name: "screenplay-format"})` 返回完整 `content`、`provider`、`resourceBase`。下一模型轮实际读到正文后，以该次返回的真实 `resourceBase` 读取上述同包 `references/` 正文并返回模型；目录型用其 `path`，URL 型用其 `url`，opaque 型按提供者支持的读取方式，不猜安装路径或兄弟技能目录。只看到名称、摘要、路径或截断片段时补读适用正文，不据此宣称采用完整标准。

## 正文结构

| 内容 | 写法 |
| --- | --- |
| 集号 | 独立一行写 `第1集`。 |
| 场次 | 独立一行写 `1-1 地点 日 内`；依次为集号-本集场号、地点、日/夜、内/外。场号每集从 1 起，同集换地点或时间另起场。 |
| 人物 | 场次下一行写 `人物：甲、乙、丙（VO）`，区分在场人物与只闻其声的人。 |
| 动作与画面 | 每段以实心 `▲` 起行，写可见、可拍的动作、表情、环境变化或必要特写，和对白分段。用户指定空心 `△` 时全稿统一。 |
| 对白 | `人物名：台词`；必要的语气或动作写成 `人物名（压低声音）：台词`，一位说话人一段。 |
| 内心独白 | `人物名 OS：内心话`；这是未当面说出的想法，不能让其他角色听见。 |
| 画外音 | `人物名 VO：话语`，适用于实际画外声音、电话或语音消息，括注声音来源；手机文字消息写成可见文字，不自动配为 VO。 |
| 集尾钩子 | 在本集结尾的悬念段前写 `【下集钩子】`，随后仍用动作、对白呈现。视频忠实整理只标记来源已有的悬念，不凭空补写。 |

使用 `screenplay_project` 时，`characters`、`actor`、`witnesses` 写准确的纯人物名；只闻其声的角色另放在本场 `voice_only_characters`，由程序给人物行加 `（VO）`。不要把“周姐（VO）”当成另一个人物身份。场内是否能听见由对应 VO 的 `audible_in_scene` 和实际听者决定，人物行标注不能替代声音依据。

角色名与地点名全稿统一；有意隐瞒的身份使用当前剧情已揭示的称呼。正文直接写分场剧本，不交付成分镜表、字幕表、资产提示词或大纲条目。镜头运动只在叙事确有需要时简写，不强加景别、镜号、每包秒数等制作字段。

## 原创格式示例

以下仅演示排法，人物与情节不属于用户的来源作品。

```text
第1集
1-1 老屋客厅 夜 内
人物：林遥、周宁、来电人（VO）
▲林遥推门进屋，将湿透的信封放在桌上。
周宁（看向信封）：你在哪里找到的？
林遥 OS：现在还不能告诉他。
▲桌上的手机响起，林遥按下免提。
来电人 VO：别打开那个信封。
【下集钩子】
▲周宁伸出的手停在半空。信封里滑出一把带血的钥匙。
```

## 写作与交付核对

小说路线把叙述转成可拍动作和自然对白，必要时用 OS/VO 保留关键信息；不能把内心话擅自改成当面对白。视频的来源账与明确逐字/字幕路径只记录可核对话语和实际看过的画面，说话人或场景不明时标“待核实”，不能为补齐人物行或钩子猜写事实。新创作模式 `story-faithful-v2` 的作品正文可按实际授权强化表达，原 ASR 与观察账保持原状，新增内容另列为作品表达或补充，不冒称来源。小说的来源索引、转写疑点、改编说明与审校意见另存 `qa/`，不混入角色台词。

逐条检查动作行能否被演员表演、摄影机拍到或声音呈现。身体感受、文学比喻和物件的历史不能仅加 `▲` 就成为当前画面；保留来源中的具体动作与环境，必要的主观信息归入明确的 OS，背景另存人物资料。来源事实与逐字整理中，不要为替换比喻编造颤抖、握拳等来源没有的行为；获授权的作品层可拍化表达按共享写作品质另列类别与依据，不能回填成已观察事实。有依据的发声与动作分行：一句应答不能埋在动作说明中。

对话前的动作、说话时的动作、说完后的反应分别核对因果顺序。“他说不下去了”应接在那轮台词之后，不能为了合并同人物动作提前发生；中间有别人提问的两次回答也不能并成一段。整场连读，检查观众能否从实际对白和行为理解人物的选择；长段 OS 逐项核对是否重复画面、复述人物表或停滞当前冲突，只保留理解身份、动机与转折必需的信息。篇幅按已确定的剧情单元调整，不用固定 OS 字数代替内容审校。

正文不带来源时间轴，包括 `[1:06–1:15]` 或字幕时间码；原始时间码留在 `transcript/raw/`，对应关系留在 `qa/`。场次的日夜、故事发生时间及对白中原有的钟点保留。完成后逐集读回，检查场次编号、人物名、▲动作与对白分行、OS/VO归属，以及原文或已定大纲中的事件和台词有无遗漏；不能为排版删掉内容。清除“改动作”“加表情”等制作批注后交付，未核实之处如实标出。

Word 交付时保存本次实际 Markdown，再加载 `office-docx` 并调用 `screenplay_export_docx`，按集数顺序合并到新的 Word 文件。保留 Markdown，核对实际 Word 正文与排版后用 `present` 交付 `.docx`；内容审校方式由 Agent 决定，不把格式转换当作内容审校。用户返稿的保留要求和不得覆盖原件仍须遵守。
