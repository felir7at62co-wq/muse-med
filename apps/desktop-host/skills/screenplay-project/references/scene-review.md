# 逐场内容审校

用于事实审校、候选验收和编辑反馈后的复核。先完整读来源、已定改编方向及本次候选，按 `screenplay-format` 检查实际正文。引用准确只说明文字来自该处；事实标为 action 也不能把心理和作者评价变成拍摄动作。

## 每场都核对

受管视频任务先按本集完整来源窗口核对事实清单，再逐条对照 `coverage.required_beats` 和正文，检查关键行动、无对白事件、人物反应及原有 OS/VO 是否有对应 beat。动作事实必须有动作行，即使同时引用文字，也不能改成 VO 来代替动作或新增旁白。没有进入事实清单的来源事件也要检查并补提审校；覆盖程序不能发现尚未提取的事件。单帧状态不能证明完整动态过程，明确未确认处；不能按台词猜动作或身份。零动作集必须复看并记录 `zero_action_reason`，来源确为纯对白可以通过。

| 项目 | 核对方法 |
| --- | --- |
| 可拍内容 | 逐条读动作行，写清演员做什么、画面出现什么或听见什么。感受、理解、比喻和年龄比较不能仅加 ▲。保留来源已有的行为；授权视觉化须另提改编事实，不编一个动作冒充原文。 |
| 表达与知情 | 区分当面对白、角色心理、作者说明、手机文字和实际声音。手机亮起不证明听到了语音；电话或语音消息须在正文交代声音来源，并用 `audible_in_scene: true` 及 `witnesses` 记录实际听者，不能把实际接听者的知情要求删掉来通过校验。未知姓名、声源和时间保留不确定，不能靠标签认定。 |
| 行动顺序 | 按故事中的先后连读动作、对白与反应，检查结果有没有先于原因。小说叙述先交代结果再补原因时，剧本可以经批准重排为可拍顺序；不能让人物已经落水后又在河岸被推，或把“记忆碎了”当作没有对象的画面。 |
| 时限与条件 | 从稿中实际写出的钟点、期限、数量、支付和设备条件逐一追踪。报名、试用、交付和结算是不同步骤；今天截止的事情不能无交代地拖到明天。修到正文中的行动或对白，不能只在方案中说明已经完成。 |
| 人物选择 | 检查本场人物目标、阻力、行动与结果，及下一场为什么发生。读者知道的身份不等于所有人物知道；人物隐瞒失业时，家人的判断可基于她说的谎，但正文须保持这一信息差。 |
| 场次承接 | 核对进出闪回、梦境和想象，返回后的位置、人物和道具。当前意识、原主经历与前世姓名分别明确；回忆影响现实须有来源支持的现实层认知事实，不能删除知情要求绕过校验。 |
| 节奏与结尾 | 连读完整一集，检查对白是否互相回应、OS 是否重复画面或履历、冲突与选择是否落地。按本作目标估计表演时长；标记了钩子不等于产生了悬念，下一集须能接住实际结尾。 |

## 记录与修订

在 `qa/` 为当前候选记录每场的开场状态、关键行动与结果、声道或时间层核对，以及对应的正文行或 beat。逐条检查可拍性和顺序；记录中引用实际检查的代表行及判断，不用人物表、事实列表或全稿通过声明代替正文核对。来源存在歧义时写清证据和剩余疑点。

发现问题先拒绝当前候选，列出集场、具体正文、原因和允许的改动范围。让写作会话局部修订，并补提需要的改编事实；重新组稿后连读修改场及前后场。已验收稿有问题时保留原件，用 `fork_project` 从受影响集之前创建修订项目。旧的通过记录不是新稿的验收依据。

画面仅有虚化肩部、局部衣袖或同色服装时，不能为了填写人物行或 `witnesses` 反向指认姓名；须有该处可核对的身份与连续性证据，否则保留未确认前景，不让已具名角色获知。驱动去向、期限和选择的手机文字或画面叠字保留为可见文字，不改为 VO。区分实际手机屏幕和给观众看的消息气泡；观众看见叠字不证明所有在场人物读到了消息，`witnesses` 只列有实际读屏、展示或转述依据的人。道具手持、桌面摆放和人物到车旁的时间分别对照实际帧，不把不同时间的动作提前合并。
