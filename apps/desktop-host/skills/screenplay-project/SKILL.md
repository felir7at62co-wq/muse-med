# 剧本项目与独立验收

视频先按剧情段查看总览，再围绕切镜、短动作与说话人疑点补看。每轮检查后立即保存人物依据、已确认事实、未确认项和来源时间码，再进入下一段；不要等全片抽帧结束才记录结果。`sampling_plan.deferred` 是待选检查点，不代表每个点都必须穷尽；优先复看会影响正文的疑点。证据已充分的片段进入事实审校与分场；新增检查仍不能确认归属时使用稳定的未识别人物标记并说明原因，不能靠反复抽帧猜姓名。

先沿用用户已确定的方向、受众、忠实程度、人物与交付标准。将方向记录在 `screenplay_project` 的 `init` 中，项目参数指向 `qa/screenplay-project.json`。已有项目先 `status`，用 `list_facts` 从 1 起始分页恢复事实和未完成审校，沿已验收集号继续；不要覆盖项目、历史候选或原件。已验收集需要修订时用 `fork_project`，以 `before_episode` 指定重写起点、`destination` 指定新的项目文件；前集状态保留到起点之前，后续逐集重新审校，原项目与导出稿保留。

导入小说原文或 `audio_transcribe` 实际导出的 JSON 片段数组。视频画面使用 `video_inspect` 实际生成的帧清单，以 `source_kind=video_inspection` 导入；审校会话通过 `read_source` 取得同一时间码的实际图片，不以编写者的画面描述代替复看。使用 `video_inspect` 的 `strategy=scene_dialogue`，按实际切镜和本片 `audio_transcribe` 转写 JSON 的发声片段抽帧；对 `sampling_plan.deferred` 逐批按时间码复看，人物归属与短动作仍不明时缩小区间，不把待复看的点当成已看。逐段 `read_source`（单次不超过工具公布的片段数量），使用返回的片段编号和原文引用，不自行编来源行号、摘要、版本或时间。完整阅读范围与未读取范围分别记录。同一原文段落包含动作和台词时分别提取事实，不能把动作埋进发声摘要后当作已写。先分类动作、发声、该角色的心理、作者分析、回忆、梦境和转述，再提交 `propose_fact`；未知人物使用稳定的未识别发声标识。视频说话人编号在不同识别任务间不代表同一个人，角色姓名须有画面、发声和前后连续性证据，不能只凭剧情猜测。作者分析不能分类成角色心理。

叙述层按实际呈现的时间、空间和表达方式判断。角色在现实现场回想前世，不必切成闪回：当前人物的内心独白可留在现实层 OS，注明其回忆的内容；只有独立呈现前世画面或原主往事的场次才标闪回。先记录同一意识、当前肉身与前世姓名的对应关系，统一各层的显示姓名；来源引用保留原名，不能把姓名差异误判为两个说话人。人物背景的作者叙述也不能仅因提到前世就变成该角色 OS。

可直接表演的当下动作须写成动作行，不能只改成第一人称就塞进 OS；同一来源同时包含动作和感受时分别提取并审校。姓名、年龄、关系与背景先放在人物资料，正文通过有依据的行为和必要的台词表现，不把人物表念成长段 OS。作者介绍只有无法用已有事实呈现且有叙事必要时才保留 VO；允许删去重复说明，但不能删除关键事件或改变人物动机。

主会话负责用户方向、全篇因果和最终验收。可以交由写作子会话提取来源事实、逐集起草，主会话逐条读取来源后用 `review_fact` 审校；事实由主会话提交时，交给另一审校会话复核。可用 `propose_facts` 和 `review_facts` 按工具公布的预算批量提交，保留每条独立的来源与审校理由；一批失败须先定位无效条目，不能盲目只换修订号。只有程序校验引用准确且独立语义审校通过的事实才能用于正式正文。忠实模式不增加新事件或新台词；用户授权改编时，新增事实须标明 `origin=adaptation` 及具体理由，与原来源事实区分。

沿因果和剧情单元定分集，不按章节数平均切集。每次子会话只处理能完整写完和审校的小段剧情，不让一个子会话同时提取多章、汇总上百事实并生成整集长 JSON。台词事实按连续发声轮次提取，不能跨另一人物的提问合并前后两次回答。单集写作只取得本集需要的来源、已确认人物关系、前集验收状态、尚未解决的问题和下一集承接要求。长集先逐场把结构化场次写入各自 JSON 文件，再用 `stage_files` 按场次顺序组稿；每个文件只包含一个完整场次，包含 `location`、`time`、来源可核实的 `setting`（内／外／内外）、`layer`、`transition`、`characters`、`beats`，每条 beat 包含 `kind`、可选 `actor`、`text`、`fact_ids`、`requires_knowledge`、`witnesses`，来源已有集尾悬念可在最后场次对应 beat 标记 `hook: true`；不为标记而增加剧情。缺少内外景依据时保留待核实，验收前核对，不让程序猜。短集可直接用 `stage`。不要在最后一条模型输出重新抄写全套长 JSON；程序从实际文件生成候选、摘要、正文和引用。OS 只属于该角色自己的心理，作者评述作为无人物归属的 VO 或经批准的可拍改编处理。进入闪回和返回现实显式标记，地点或时间变化不标为连续场。`witnesses` 仅填实际见到动作或听见对白的本场人物，OS/VO 不填见证者；必要的已有知情填入 `requires_knowledge`。保留心理信息的戏剧作用，不为形式检查删除动机或重要因果。

编写者不能自行批准候选。审校会话先 `read_candidate`，再 `read_source` 核对引用的完整上下文，对照原音、字幕及实际看过的帧检查发声归属、人物、行动、时间、可拍性和改编语义，并按 `screenplay-format` 连读检查动作与对白的因果顺序及 OS 的必要性。输出被裁剪时分段读取实际场次文件和导出正文，不能用摘要代替完整阅读。逐项有依据后 `review`，使用本次返回的候选编号及摘要；存在疑点则拒绝并定位集场、来源片段、问题与具体修改，修订后重新 `stage`，不覆盖旧稿。校验通过只说明可机械核对的条件通过，不能声称语音或剧情语义已自动验证。

独立审校通过后 `commit`，再推进下一集。跨集有依赖的正文顺序编写；无依赖的来源整理、素材检查和独立审校可以并行。每次修改使用最新 `expected_revision`；过期时先 `status`，不得盲目换修订号重放原操作。中断、上下文压缩或子会话退出后，以 `status`、已验收候选、逐场文件和原文继续，不能以会话摘要宣布已完成。子会话达到输出上限时先读回已保存的场次文件和候选，只补缺失段或具体被拒绝的场次，不能从头反复派发整集。用 `export` 导出已验收正文，再按用户要求生成 Word 等交付文件；读取导出文件核对实际范围，未验收内容不得称为正式完成。
