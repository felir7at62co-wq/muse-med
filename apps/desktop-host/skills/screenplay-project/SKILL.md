# 剧本项目与逐集验收

先读已有项目 `status`，按工具声明的策略与 self-check/independent 恢复；历史独立审校和其他 preset 的严格策略不因共通写作指南改变。分场正文起草、续写、修改或审校前，按当前工具形态加载 `screenplay-format`：native 工具直接调用 `skill` 并保留完整返回值；PTC 用 `return await tools.skill({name: "screenplay-format"})` 返回完整 `content`、`provider`、`resourceBase`。下一模型轮读到正文后，按该技能实际返回的 `resourceBase` 读取所导航的共享写作品质与时间线规范，不从本技能目录拼接跨包路径。

## 新创作模式的故事忠实路径

仅新创作模式的视频转剧本默认使用工具提供的 `init_story_faithful`，绑定真实用户授权、视频路径与版本、逐集视频关联、计划集数和类别，不要求先做逐字 baseline。单视频单集可自动关联，多视频明确每份对应的集号；本轮策略按真实总时长检查整片，不用候选自填 interval 缩成片段，也不支持同片跨集裁剪。明确逐字、字幕或继续旧项目时保持下述严格路径。来源账仍保存实际 ASR、帧、事实分类与引用；作品层按已核对故事表达事件及行动结果、情绪冲突、关系立场、因果和关键揭晓，不把每条源动作的发声/动作渠道、首次顺序或场次结构硬锁套到新作品表示。

按本集实际完整窗口整理已审校来源事实，使用 `propose_story_inventory` 提交故事清单，返回产物后在后续模型轮实际 `read_story_inventory` 与相关来源，再 `review_story_inventory`。逐项定位事件、行动结果、情绪冲突、关系立场及因果揭晓，记录依赖和人物知情；关键证据未解决先补看，不靠 free-form confirmed 通过。视频全时段取材与重点加密沿 `transcript-to-script` 的真实 metadata、窗口与后续轮看图步骤。

用 `stage`/`stage_files` 起草作品，`story_notes` 对应实际清单与成稿位置、来源 retained/merged/omitted_non_story 处置、真实变化和批注对账；省略无故事功能的重复表达不能省略关键原因、结果或揭晓。新增表演细节、少量 OS 和辅助对白按工具公开的授权类别标明，不能成为新的来源事实；重大因果、关系立场、事件反转或关键揭晓变化另待用户授权。不存在旧稿时不填虚构 before，来源→作品映射沿真实输入处理。

候选返回后按工具的后续轮读取证据与版本要求复检，`review.semantic_report` 依据实际材料分列保留、偏离和未核实的故事项，不能模板全部 pass。修正后重读受影响来源、清单、候选及说明，旧检查不复用；C轮 `review approve` 后先让当前程序成功结束，下一模型轮再 `commit`/`export`；同一程序立刻 commit 会因外层尚未成功而拒。C外层失败或被取消后，已写 review 不等于成功验收，须重新 stage 新候选、实际读回并完成成功C轮，不盲重commit。候选的 `story_adaptation` 和独立《修改说明》对应最终版本。参数以公开 schema 与工具状态为准，不手改项目 JSON 或推定任意程序已验证剧情语义。

## 原严格来源与逐字路径

原严格来源路径的视频转剧本使用 `init workflow=video_to_screenplay`，项目固定为项目根的 `qa/screenplay-project.json`。先按集整理并按项目审核方式审校视觉事实，再提交本集候选；不要先按音频生成全稿。`stage` 或 `stage_files` 的 `coverage.windows` 列出本集实际完整的转写和帧清单窗口（source_id、从1开始的 start、count），`required_beats` 列出已批准来源事实及必须保留的 action/dialogue/os/vo 类型。关键动作、无对白事件、人物反应及已有 OS/VO 都须进入清单并对应正文，不把人物资料等无关事实混进本集窗口。动作事实即使同时引用文字，也必须按 action 保留，不能改成对白或 OS/VO；原有发声另引对应事实。程序检查窗口内已批准事实的覆盖与动作的帧引用；事实提取是否完整、范围是否真实完整仍由对应审校逐场核实。

严格路径的零动作候选不能只凭格式批准。按项目声明的审校复看本集画面、转写及遗漏疑点，确认确无必须保留的行动后，在 `review approve` 中提供具体 `zero_action_reason`；否则拒绝并补看、局部修订。纯对白素材可凭来源复核通过，不能虚构动作、情绪或旁白规避检查。长视频按剧情段保存窗口、事实及逐场文件，恢复时读 `status`、分页事实与候选中的 coverage，不以摘要代替来源。

## 共用来源记录、恢复与交付

正式 Markdown 只从已验收候选 `export` 到本项目 `final/`。Word 使用同一正文调用 `screenplay_export_docx`；跨目录导出传 `project` 项目文件。保留工具生成的 `.docx.screenplay.json` 验收导出记录，`present` 会核对受管 `final/` 的正文及 Word 记录。普通文档转换和草稿目录继续可用，但直接用 Python、Office 转换得到的未验收文件不能作为受管流程的正式交付。委派审校须传递以上项目、来源、覆盖和逐集验收要求，禁止写手无依据推断身份、动作或心声。

视频先按 `transcript-to-script` 完成真实 metadata 与全时段采样计划，再围绕切镜、短动作与说话人疑点补看；计划覆盖不等于实际看过每一瞬间。每轮检查后立即保存人物依据、已确认事实、未确认项和来源时间码，再进入下一段；不要等全片抽帧结束才记录结果。`sampling_plan.deferred` 是待选检查点，优先复看影响正文的疑点；旧严格/V1门槛仍要求补齐本集declared deferred，优先级不代表可跳过。V2不机械要求耗尽算法所有候选点，但真实整片窗口及关键疑点仍须核对，清单或语义报告的关键未核实项阻止验收。证据已充分的片段进入事实审校与分场；新增检查仍不能确认归属时使用稳定的未识别人物标记并说明原因，不能靠反复抽帧猜姓名。

先沿用用户已确定的方向、受众、忠实程度、人物与交付标准。将方向记录在 `screenplay_project` 当前路径的 `init` 或 `init_story_faithful` 中，项目参数指向 `qa/screenplay-project.json`。已有项目先 `status`，用 `list_facts` 从 1 起始分页恢复事实和未完成审校，按返回的 `next` 继续到 null，不按请求数量推定已读完，沿已验收集号继续；不要覆盖项目、历史候选或原件。已验收集需要修订时用 `fork_project`，以 `before_episode` 指定重写起点、`destination` 指定新的项目文件；前集状态保留到起点之前，后续逐集重新审校，原项目与导出稿保留。

导入小说原文或 `audio_transcribe` 实际导出的 JSON 片段数组。视频画面使用 `video_inspect` 实际生成的帧清单，以 `source_kind=video_inspection` 导入；按当前项目策略的审校通过 `read_source` 取得同一时间码的实际图片，不以编写者的画面描述代替复看。使用 `video_inspect` 的 `strategy=scene_dialogue`，按实际切镜和本片 `audio_transcribe` 转写 JSON 的发声片段抽帧；对 `sampling_plan.deferred` 逐批按时间码复看，人物归属与短动作仍不明时缩小区间，不把待复看的点当成已看。逐段 `read_source`（单次不超过工具公布的片段数量），使用返回的片段编号和原文引用，不自行编来源行号、摘要、版本或时间。完整阅读范围与未读取范围分别记录。同一原文段落包含动作和台词时分别提取事实，不能把动作埋进发声摘要后当作已写。先分类动作、发声、该角色的心理、作者分析、回忆、梦境和转述，再提交 `propose_fact`；未知人物使用稳定的未识别发声标识。视频说话人编号在不同识别任务间不代表同一个人，角色姓名须有画面、发声和前后连续性证据，不能只凭剧情猜测。作者分析不能分类成角色心理。

叙述层按实际呈现的时间、空间和表达方式判断。角色在现实现场回想前世，不必切成闪回：当前人物的内心独白可留在现实层 OS，注明其回忆的内容；只有独立呈现前世画面或原主往事的场次才标闪回。先记录同一意识、当前肉身与前世姓名的对应关系，统一各层的显示姓名；来源引用保留原名，不能把姓名差异误判为两个说话人。人物背景的作者叙述也不能仅因提到前世就变成该角色 OS。

可直接表演的当下动作须写成动作行或真实同步的说话人括注，不能只改成第一人称就塞进 OS；同一来源同时包含动作和感受时分别提取并审校。姓名、年龄、关系与背景先放在人物资料，正文通过有依据的行为和必要的台词表现，不把人物表念成长段 OS。作者介绍只有无法用已有事实呈现且有叙事必要时才保留 VO；允许删去重复说明，但不能删除关键事件或改变人物动机。

主会话负责用户方向、全篇因果和最终验收。可以交由写作子会话提取来源事实、逐集起草；independent 项目由另一审校会话逐条读来源后 `review_fact`，self-check 项目由原会话按工具要求在后续模型轮实际读取、判断及复检，不能把自检称独立审核。可用 `propose_facts` 和 `review_facts` 按工具公布的预算批量提交，保留每条独立的来源与审校理由；一批失败须先定位无效条目，不能盲目只换修订号。只有程序校验引用准确且对应语义审校通过的事实才能用于正式正文。严格来源与逐字路径不增加新事件或新台词；用户授权改编时，新增事实须标明 `origin=adaptation` 及具体理由，与原来源事实区分。新故事路径的作品补充还须按工具要求绑定 `story_supplement` 及真实授权，单写 adaptation 或理由不构成许可。

沿因果和剧情单元定分集，不按章节数平均切集。每次子会话只处理能完整写完和审校的小段剧情，不让一个子会话同时提取多章、汇总上百事实并生成整集长 JSON。台词事实按连续发声轮次提取，不能跨另一人物的提问合并前后两次回答。单集写作只取得本集需要的来源、已确认人物关系、前集验收状态、尚未解决的问题和下一集承接要求。长集先逐场把结构化场次写入各自 JSON 文件，再用 `stage_files` 按场次顺序组稿；每个文件只包含一个完整场次，包含 `location`、`time`、`setting`（内／外／内外；严格来源路径须来源可核实）、`layer`、`transition`、`characters`、`beats`；`characters` 保留纯人物名，只闻其声的角色另列 `voice_only_characters`，不在身份上加 VO 括注。每条 beat 包含 `kind`、可选 `actor`、`text`、`fact_ids`、`requires_knowledge`、`witnesses`，严格来源路径已有集尾悬念可在最后场次对应 beat 标记 `hook: true`；故事忠实与其他获授权新作的钩子沿已定故事与大纲，不为标记凭空增加剧情。严格来源路径缺少内外景依据时保留待核实；获授权作品的场景表达另列改编选择，验收前核对，不让程序猜。短集可直接用 `stage`。不要在最后一条模型输出重新抄写全套长 JSON；程序从实际文件生成候选、摘要、正文和引用。OS 只属于该角色自己的心理，作者评述作为无人物归属的 VO 或经批准的可拍改编处理。进入闪回和返回现实显式标记，地点或时间变化不标为连续场。`witnesses` 仅填实际见到动作或听见发声的本场人物。OS 不填见证者；电话、播放语音等 VO 有明确声源和接听依据时写 `audible_in_scene: true`，引用已批准 speech 事实并列出实际听者，其他 VO 保持仅观众可闻；必要的已有知情填入 `requires_knowledge`。保留心理信息的戏剧作用，不为形式检查删除动机或重要因果。

已批准事实经新来源核对发现错误时，保留原审校，不覆盖事实 JSON。已有候选引用须先从最早受影响集之前 `fork_project`；审校会话用 `withdraw_fact` 撤销旧审批，编写会话提出更正事实再按项目声明复核；self-check 的撤销、更正与复检仍遵守工具的分轮及原批准身份限制。撤销事实即使仍有历史 approve，也不得用于新场次或人物知情；读回撤销与替换记录后再继续写，避免恢复时重用旧错误。

independent 项目的编写者不能自行批准候选；self-check 项目由原会话遵循工具的后续轮读取与判断证据要求。对应审校先 `read_candidate`，再 `read_source` 核对引用的完整上下文，对照实际取得的 ASR、字幕及看过的帧检查发声归属；没有独立音频观察通道，不宣称试听、环境声或语气已核实。继续核对人物、行动、时间、可拍性和改编语义，并读取[逐场内容审校](references/scene-review.md)按场完成核对。输出被裁剪时分段读取实际场次文件和导出正文，不能用摘要代替完整阅读。把候选编号、各场的实际核对记录与未解决项保存到版本化的 `qa/` 审校记录，再 `review`；不能只写“动作均可拍、因果成立”等合格声明。存在疑点则拒绝并定位集场、来源片段、问题与具体修改，修订后重新 `stage`，不覆盖旧稿。校验通过只说明可机械核对的条件通过，不能声称语音或剧情语义已自动验证。

按项目声明的对应审校通过后 `commit`，再推进下一集。跨集有依赖的正文顺序编写；无依赖的来源整理、素材检查和独立审校可以并行。每次修改使用最新 `expected_revision`；过期时先 `status`，不得盲目换修订号重放原操作。中断、上下文压缩或子会话退出后，以 `status`、已验收候选、逐场文件和原文继续，不能以会话摘要宣布已完成。子会话达到输出上限时先读回已保存的场次文件和候选，只补缺失段或具体被拒绝的场次，不能从头反复派发整集。用 `export` 导出已验收正文，再按用户要求生成 Word 等交付文件；读取导出文件核对实际范围，未验收内容不得称为正式完成。
