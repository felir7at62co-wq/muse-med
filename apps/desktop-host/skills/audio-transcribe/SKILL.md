# 音视频语音转写

对用户提供或授权读取的本地媒体，使用当前 Muse 账号的云端语音服务取得可核对的原始转写。只记录实际识别的语音，不根据画面或剧情补写对白。用户要求改编时，原始转写与创作稿分别保存。

## 项目位置

转写属于小说或剧本项目时，使用获授权的项目根目录。`source/links.md` 记录原件路径或链接、来源与实际可读状态；`source/media/` 仅存用户授权取回或复制的本项目媒体。已有媒体可原位只读，不移动或覆盖。云端任务收据保存在 `transcript/jobs/`；完成后的原始 TXT、JSON 和 SRT 按同一素材名与版本写入 `transcript/raw/`；人工听辨校订另存 `transcript/reviewed/`。只有链接、没有可读本地媒体时说明缺口，不声称已转写。

## 云端运行

先确认本地媒体和项目目录。已有分集文件时保留每集来源与收据，避免为批量转写先拼成跨集长片；可并行处理独立集数，回读各自结果，不能把一批完成当作全剧完成。Muse 账号必须已登录，服务器必须配置云端转写。`audio_transcribe` 的 `start` 会先检查时长，使用随包 FFmpeg 从音频或视频中提取 16 kHz 单声道 PCM WAV，保存包含任务 ID 的本地收据，再通过当前账号提交。只上传提取的音轨，不上传整段视频。云端转写会使用计费语音服务；仅在用户要求转写、项目已有相应授权时提交。

按实际用途设置 `purpose`：字幕生成或校时用 `subtitles`（极速识别）；音视频转小说或剧本用 `screenplay`（标准识别）。一般转写未指定用途时默认 `subtitles`。具体服务版本与资源由 Muse 服务器分配，不向用户索要提供方密钥或让用户选择资源。用途写入收据和所有音轨分段，查询与重试保持原用途；已有未完成任务不能改用途，先用原收据查清结果。同一原片确需另一用途时，应先判断现有结果能否复用；仅在用户明确授权额外计费转写后，显式传入新用途，创建独立版本收据，不改写或重投旧任务。省略用途时不会跨用途创建新付费任务。

```json
{"method":"start","project":"<项目根目录>","input":"<获授权的本地音频或视频>","language":"zh","purpose":"screenplay"}
```

`language` 可为 `zh` 或 `auto`，省略时为 `zh`。保存 `start` 返回的 `receipt`，然后对同一收据调用：

```json
{"method":"inspect","project":"<同一项目根目录>","receipt":"<start 返回的收据路径>","wait_seconds":20}
```

限流的 `error_code` 区分 `queue_full`（队列满）、`upload_busy`（上传繁忙）、`request_rate`（账号请求频率）和 `provider_rate`（服务额度或提交频率）。有 `retry_after_seconds` 时按该秒数等待，再查询原收据。`inspect` 只查询原任务，绝不补传音轨；若已完成则发布本地转写结果。只有用户另行授权补传后才用 `status`，它先回读，确认原任务尚未受理后可能补传同 ID 音轨并计费；不更换 ID、用途或收据。`daily_quota` 先处理账号日额度，`sign-in-required` 先登录，`idempotency_conflict` 先核对原任务，不能直接重投。可用 `wait_seconds` 在单次调用内等待查询，最多 30 秒；返回未完成时按 `resume_status` 和实际诊断继续。收据是上次查询的快照，不会自行刷新；不能用 Bash 循环读收据代替 `inspect`。

先读取实际 `service_version`、`queued`、`error_code`、安全的 `provider_diagnostic` 和 `recovery`；旧任务未提供版本或诊断时只记未知，不由用途猜是 1.0、2.0 或极速。`processing` 本身不能证明提供方一直在识别，`uncertain` 更不能当成待处理结果反复盲等：

- `recovery.next_action=poll_original`：沿原收据查询原任务，不创建新任务。
- `wait`：原任务在执行或已受理排队，等待实际建议后回读原收据；`queued=true` 只表示这一任务排队，不说明全池满。
- `inspect_receipt`：停止反复轮询，保留原 ID、版本、错误类别和已处理范围，进行只读核对。极速的 `capability=no_query` 表示 Muse 当前极速适配器没有可用的原任务查询恢复路径，等待更久也不能补回已丢失的响应；不能自动重投或称仍在识别。标准的未知结果可按服务能力查原任务。
- `resume_upload`：网关确认原任务尚未向供方提交，工具可补传原 ID 音轨；补传可能计费，不能换用途或身份。`automatic_resubmit=false` 禁止自动新建付费任务。

客户端网络超时仍先回读服务器原任务，不预判提供方已结束或未受理。`complete` 才有输出，`silent` 是未识别到语音，不能编造台词；有可靠可见文字时可另走 OCR。留存到期保留收据和原 ID 供只读核对。未登录、未部署、限额或提取失败时报告实际障碍，不假称成功，不自动切离线。

## ASR 优先与 OCR 分流

视频转小说、视频转剧本的语音文字优先复用现有转写，缺失时用已获授权的云 ASR；新任务用 `purpose: "screenplay"`，字幕校时才用 `subtitles`。标准 2.0 与标准 1.0 尚无本项目同素材质量对比，不能称等价或为速度自动降级；用户明确选择 1.0 时须确认网关新任务路由已配置，旧收据版本不变。多账户的实际容量由网关调度，不能由 Key 数量直接保证完成时间。 多集任务提交与完成查询分开安排：取得一集的原收据即可在当前可用容量内提交其他未处理集，不等待这一集 complete 才提交下一集；保留每集收据、状态和已提交范围。根据实际受理速度、队列反馈和 retry_after_seconds 控制在途工作，避免高频查询抢占请求额度。长媒体的分段也只提交异步任务，不循环等待某一分段完成。

只有服务器明确 `queue_full` 且尚未受理的新任务或未提交集，才考虑把其中有可靠可见文字的几集交给 `video_ocr`。先按同素材少量样本的实际耗时、失败帧、覆盖范围和当前容量估计效率，再分配剩余范围；不设置固定 ASR/OCR 比例，不把 40 分钟当所有作品保证。只有 `queued=true` 的已受理任务仍可能之后计费，保留原收据安排查询，先处理别的集或独立工作；没有取消依据就不能称已取消。同集并行 OCR 须明确重复工作的目的，不能自动重投 ASR。`provider_rate`、`server_draining`、登录失效、网络错误和未知结果不等于队列满。

纯文字视频或 `silent` 来源只有可靠画面文字时才适用 OCR。OCR 是画面文字，ASR 是声音识别，两者分文件、分时间码保存；OCR 不能代替漏听的无字幕对白，ASR 不能证明人物动作、场景、闪回、转场或是谁发声。视频转剧本仍须按 `transcript-to-script` 实际查看相邻抽帧；姿势、惊讶表情不能扩写成已发生的拉拽动作或不存在的“啊”台词。

TXT 每段格式为 `[00:00:01.250 --> 00:00:03.500] 台词`；JSON 为包含秒数 `start`、`end`、`text` 和字词 `words` 的逐段数组；SRT 使用相同时间轴。长媒体自动切分后合并为原视频时间轴。正式字幕须按 draft-build 技能将字词时间对齐到剧本原文，不能直接把识别文本当成经过审校的台词。完成后读取输出，核对时间顺序、明显错词和漏识别；人工修订另存新文件，保留原始版本。

JSON 中可选的 `speaker_id` 只是本次识别的声学分组，不是角色名。多个角色可能合并到同一编号，同一角色也可能被拆成多个编号；全稿只有一个编号不表示只有一个人物。逐段核对实际画面、字幕与发声时段，保留归属依据和未知声音；一段含多轮对白时另记分轮对照，不能把整段全部指给当前镜头中的人。姓名、公司名、专业词与画面文字冲突时补看相应时间码；有充分校订依据才另存修正版，原 ASR 保留。

用户要求视频转剧本时，继续加载 `transcript-to-script` 整理正文；带时间戳的原始转写用于内部核对，不直接作为剧本交付。剧本的时间码处理与场次格式遵循该技能。

## 获得离线转写授权时

用户明确要求本地离线转写，或云服务不可用后同意改用离线转写时，才使用另行准备的 faster-whisper 依赖与本地模型；默认安装包不含这套识别依赖和模型：

```text
python -B "<skill-dir>/scripts/transcribe.py" --input "<音频或视频文件>" --output-txt "<新的时间轴.txt>" --output-json "<新的片段.json>" --language zh
```

脚本要求已有 `MUSE_WHISPER_MODEL_DIR`，并使用 `DSH_FFMPEG_PATH` 或 PATH 中的 FFmpeg；不会下载模型。两个输出路径必须是新文件，不覆盖云端或人工校订结果。此技能只做语音转写；画面 OCR 和场景截图需分别核对。
