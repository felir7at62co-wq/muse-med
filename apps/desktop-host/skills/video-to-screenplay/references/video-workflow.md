# 视频转剧本方法

## 本轮目标与来源

用户要求转写、来源整理或按原片还原时，保留原片实际的台词含义、事件、人物归属、时间层和先后。用户已授权改编、扩写或重构时，沿其主线与改动范围处理作品表达，来源原稿和作品新增分开保留；不借整理暗中改变结果、承诺、知情或揭晓。已有授权直接沿用，未明的实质冲突说明具体影响，继续完成不受影响的部分。

确认实际可读的原件及本轮集数或片段。在项目来源记录里保留视频路径、转写结果与收据、视频审看 `review_id`、版本及已处理范围，多集逐集对应；同名文件、相近目录或匹配时长不证明同源。只有链接而未取得可读媒体时先用可用的来源工具取回，无法取得就说明缺口，不声称已看过或已转写。

## 取得语音文字与画面材料

优先复用本项目已有的原始转写，读取带时间码的完整结果和实际覆盖范围。需要新转写时沿已获授权的 `audio-transcribe`，视频转剧本使用 `purpose: "screenplay"`，保留原收据并按该技能查询、恢复；不因超时或排队重投已受理任务。原始 ASR 与人工校订分开保存，不将重写后的台词冒充识别原文。定说话人时读 `output_json` 各段的 `start`、`end`、`speaker_id` 和 `text`，不必读 `words`；分组变化处和三人以上的场面结合该段画面定人物，片中字卡和称呼是定名依据。`speaker_id` 只表示任务内分组，不是人物姓名；跨段、跨集不按相同编号合并身份。

画面有烧录字幕时，每集用 `video_ocr` 读字幕；未加载时用 `tool_search` 搜 `video_ocr`。取样间隔用默认值；单次扫描有范围上限，结果带 `next_start_seconds` 时从该秒续扫，直到不再返回。`raw_json_path`、`merged_text_path` 传项目 `transcript/ocr/` 下的新文件完整路径，续扫各用新文件名，返回的路径记入来源记录。返回忙碌时先处理别的集再重试。`scan_status` 为 `partial` 或 `failed` 只说明未扫全，按 `coverage` 记下缺口，不证明没有字幕；`persistent_text_candidate` 多为台标、水印或招牌，不当台词。抽帧拼图上读出的字只是待核线索，不算字幕来源；`video_ocr` 实际返回失败前，不称没有 OCR 工具。

写每集前按时间重叠把 OCR 字幕段对应到 ASR 段，一句 ASR 可对应几条连续字幕：人名、同音字、数字和地名以清晰字幕为准，时间和说话人分组看 ASR；字幕残缺时保留 ASR 并标疑。只有字幕的句子按字幕补入并注明来源；手机屏幕、招牌和字卡上的字是画面文字，不写成对白。对照和判断不了的冲突存入 `qa/` 下该集的核对材料。写完一集后，`transcript_coverage` 传 `ocr_paths` 会列出字幕与稿件不同的字（`on_screen_text_differs`，同列 ASR 原文）：同音不同字、照抄 ASR 的错词按清晰字幕改正；读音不同、只是繁简体或字形相近的（如干／千、狠／狼、胁／肋）多为 OCR 误读，保留正文。

视频转写每集都做完整审看：用 `video_inspect` 的 `metadata` 确认原片实际时长，`scan` 建立候选，再按 `next` 逐批取得图像，实际查看后用 `observe` 记录所见、变化与疑点，直到 `status` 显示 `complete`；`observe` 结果已附带下一批图片时，看完这批直接接着 `observe`，不另调 `next`。全部帧记录后，看帧报告写入工作区 `.muse/video-observations/`，交付时程序据此逐集核对。`status` 显示已记录和待处理范围，`revisit` 可回看已保存的原帧。帧图在记录观察后、或看过再回复一轮后会从之后的上下文移除，历史里显示为 image omitted 占位；这不表示当时没看到，已写的 `observe` 与 `complete` 状态就是逐帧看图的记录。对具体疑点用 `revisit` 回看该帧，不另用 ffmpeg 导出整集帧再 `read_image` 重看，也不因占位让分集代理整集重做。完整扫描、候选或图像已返回不表示模型已经看过全部内容；遵循当前工具的批次与恢复要求，不用一批概览代表全片。

按原片时间对应台词与实际可见事件，重点查关键动作的前后状态、发声归属、切场和进入／退出回忆的标记。写稿前用 `timeline` 并传 `transcript_path`，把每段 ASR 与同一时刻的帧记录并列，逐句定说话人：看画面中谁在开口、正对镜头或做出对应动作；说话人闭嘴或不在画面时按 OS 或 VO 判断；ASR 的说话人编号只是声学分组，不当人物身份。写完后用 `transcript_coverage` 查说话人：ASR 带 `speaker_id` 时，它列出说话人与同组多数不一致的台词（`speaker_voice_conflicts`）及秒数。逐条回看该时间的帧确认谁在开口：用 `timeline` 找到帧号后 `revisit`，那一刻没有帧时 `scan` 传 `timestamps_seconds` 补帧，看 `scan` 返回的新帧图并 `observe` 记录；改正说话人和相应 ▲ 行，或在交回说明里写明保留理由。分组常把相近的声音并成一组，列出的只是待核位置，不按分组直接改人。姿势或表情不足以证明完整动作，切镜不自动等于换场；对白间隙与字卡也可能改变时间层。需要补看时回到对应原帧及相邻上下文，仍有缺口就保留未知。图像路由不可用时可继续整理已取得的语音文字，画面事实明确未核实。当前视频工具没有独立原音观察通道，ASR 不是试听；语气、声线、环境声和音画同步没有实际依据时，不称已经听清或核验。

## 多集整剧转写

用户要整部或多集转写时，在收到该请求的同一轮调用 `create_goal`；之后由下载、转写或其他通知唤醒的轮次不能再创建目标。目标写明剧名、集数范围、同时运行的分集代理数（默认约 8–10 个）、原片目录、项目位置和最后交付整剧 Word，不写每集必须补集尾钩子。沿默认做法开工：从第 1 集起按集序、格式沿 `screenplay-format`、忠实转写。样集照常给用户看，但不等回复；用词、顺序等待定问题写进当批汇报，继续下一批。等下载、转写或子代理结果而手头没有别的集可写时，用 `update_goal` 的 `wait`：等转写设 `wake_after_seconds`，等后台任务填 `job_id`；不以纯文字回复结束目标轮次，也不连续空跑 `inspect`。只有缺少来源、账号或额度等真正阻塞时才用 `blocked`，目标轮次不以只提问的回复结束。没有目标时不说“结果出来后接着写”：同一轮用 `inspect` 的 `wait_seconds` 继续回读，或明说工作停在这里。

整部多集短剧先备齐来源和原始材料，再分段写正文。按集保留原片、转写收据与结果，核对已下载集数与该剧总集数一致。语音转写的提交、查询与恢复沿 `audio-transcribe`，同一集只由一个会话提交。转写提交后即可逐集跑 `video_ocr`，不等全部转写完成，按上文与 ASR 对齐。画面里有人说话或有字幕的集 ASR 却返回 `silent` 时按可疑结果处理：用 `video_ocr` 扫全集，台词只取字幕实际出现的句子，不按稀疏抽帧补句，汇报中写明该集 ASR 为 `silent`，不自动重转。

写首集前从各集转写和字幕中整理人名、姓氏、称呼、地名和店名，沿 `screenplay-format` 共享写作品质的“人物表与分段协作”保存人物表，再写首集或分派区间；简报与等待方式见该节。人物表存成 JSON（例如 `outline/人物表.json`）：`{"characters": [...]}`，每人一条，`name` 为正文唯一定名，`variants` 为 ASR 或旧稿里的错写（没有就省略），另可记称呼、外貌和身份；各集集尾状态等其他记录放在 `characters` 之外的字段。`transcript_coverage` 用 `characters_path` 直接读这份文件，主控和各分集代理共用同一份；只有主控改这份文件。整部转写按集分派子代理，同时保持约 8–10 个分集代理在运行，一个交回就派下一集，不等整批；出现限流或连续请求失败时减少同时运行数。简报写明人物表 JSON 路径，要求先用 `video_inspect` 看完并记录该集全部帧，用 `timeline` 对齐台词与画面定说话人后再写稿；写完用 `compare` 传 `draft_path`，对照没有 ▲ 的动作段和对白顺序补齐遗漏。交回前做分集自查：`transcript_coverage` 的 `transcript_sources` 只给本集一项（`path` 为本集稿件、`asr_path`，有烧录字幕时加 `ocr_paths`），另给 `characters_path`，逐条处理 `speaker_voice_conflicts`、`on_screen_text_differs`、`speakers_outside_table`、`asr_uncovered` 和 `lines_without_source`，按上文回看帧和字幕后改正，或写明保留理由；人物表里没有的人物报主控登记，不自起名字。处理完再跑一次，交回时附本集 `summary` 和仍保留的条目及理由。看帧工具返回忙碌时等待后重试，不跳过。每批写完用 `grep` 在已写各集查人物表登记的其他写法，查到时按该节先改人物表再改正文；已交付的集另存新版本修正。

忠实转写保留原片实际结尾：`【下集钩子】` 只标在原片已有的悬念前，最后一句台词之后不新增没有画面依据的 ▲ 动作或台词。每批汇报只写实际做过的核对：哪些集跑了 `video_ocr` 及其 `scan_status`、字幕与 ASR 不同的处数、ASR 为 `silent` 或 OCR 未覆盖的集，以及仍未解决的人名疑点。

每批写完，用 `manuscript_revision` 的 `transcript_coverage` 逐集比对稿件与该集转写 `output_json`（有 `video_ocr` 时给 `raw_json_path`，并给人物表 `characters_path`），分集代理交回时仍保留的条目逐条看理由，没处理的退回该集代理；它只做字面计量，ASR 里的同音错字只有对上字幕才查得出，不代替 `source_fidelity`。每批汇报和交付说明照录各集 `summary`。

合稿后核对集数、集号连续和区间接缝，同一人物在不同区间的定名与称呼按人物表统一；用 `cross_episode` 检查全部相邻两集的接缝（上集结尾与下集开头的人物、道具、知情状态和称呼）：合稿在材料上限内时一次提交整份，接缝多于单个审校上限时工具自动分段并行；工具报 `MANUSCRIPT_MATERIALS_BUDGET` 时按集分批提交，相邻两批共用边界那一集。用 `continuity` 查剧情前后逻辑。查出的问题多是说话人、▲ 行认人或场景日夜写错，要回原片看帧修正；看帧记录只在写该集的会话里，主控不在自己会话里补看整集，而是把问题位置和秒数发回负责该集的分集代理，它已结束时为该集另派一个代理看帧修正。修正后重跑受影响的接缝，再按下文“核对与交付”检查来源、衔接与重复。只核对了部分集时按实际范围说明。

整剧收尾按顺序做：完整 Markdown 合稿；`transcript_coverage` 覆盖全部集；`screenplay_export_docx` 导出 Word；`manuscript_revision delivery`（`source_mode: "video"`、`video_dir`）登记 Word 并 `present`；最后标目标完成。缺其中任何一步或有集没看完帧时，`update_goal complete` 的结果会列出缺口；标完成前先补齐，补不了的在收尾汇报里逐条写明。

## 从来源写成场景

为实际使用的场景保留来源对应：视频版本和时间范围、相关转写原句、已见帧或观察记录，以及未核实处。短任务可用简明对照，长剧按集保存，来源时间码放在 `qa/` 等核对材料里。剧本正文沿 `screenplay-format` 写场次、人物、▲动作和对白，不把媒体时间码搬成小标题或括注；故事中的日夜、回忆时间和台词钟点照常保留。

台词、画面动作与角色内心分清归属，保留起因、行动和结果，不把观众知道的信息变成角色已知。声音无法归属时保留稳定的未知声音标识，不能把整段多轮对白指给镜头中的一个人。校订明显错词须有实际来源依据，疑点不靠剧情常识补成确定原话。忠实整理不补造动作、台词或悬念；授权改编可调整表达，但保留来源对应和实际新增，不能称逐字还原。

理解受改片段及必要前后文后，先保存可用场景或单集，再沿实际结束状态继续写作。重分集、移动揭晓或改动事件后，核对受影响前后集及后文回指，不用重演同一事件补字。分集和对白专项分别使用 `muse-episode-design`、`muse-dialogue-polish`，不为了加载新技能重新改写已确认内容。

## 核对与交付

已有稿修订先按共享写作品质保存版本和批注。`source_fidelity` 是对具体疑点的抽查：每次只选疑点所在的少量正文行与帧（总帧数受部署上限约束，默认 4 张），不用它逐集复核全片；逐集完整看帧记录已经是画面依据。核对视频来源时，对实际保存稿调用 `manuscript_revision` 的 `source_fidelity`，用 `video_sources` 明确每项 `review_id`、原片秒范围 `start_seconds`／`end_seconds`、对应稿件行范围 `draft_lines: {start, end}` 和已保存的实际 `frame_ids`。稿件行号是提取正文行号，不是 Word 页码或字幕序号；来源秒数沿原片时间，不按剧情发生时间替换。来源材料不明时先查清，不凭同名文件或剧情概括代填。

独立只读审校会实际接收所选缓存原帧与保存的 ASR 原段。回读 `source_checks` 的逐图、选区内 ASR 逐段结论及引用，核对来源材料中的遗漏、稿件错误、授权改编取舍与未知项；额外补带的上下文 ASR 不算选区内的覆盖。查看 `source_manifest`、`source_verification` 和实际范围，来源或稿件版本变化后重新核对受影响部分。结果为独立的 `video_source_review`，范围仅 `sampled_frames_and_saved_asr`；ASR 不是原音、人物身份或同源真值，文字路由和证据缺口不能称已核对。

完成所选范围的来源核对后，按正文实际变化范围使用 `continuity`、`cross_episode` 或 `repetitions` 检查因果、衔接与重复。来源问题与文字问题分别保留，任一类的通过结论不能抹去另一类已知未解决项。疑点返回相应原帧、转写和正文，不用文字自洽或已有观察笔记替代实际来源依据。

视频稿件用 `manuscript_revision delivery` 显式传 `source_mode: "video"`，用 `video_dir` 给出本剧原片目录，选择实际符合情况的 `reviewed` 或 `draft`。标签和逐集核对结果 `video_check` 由程序按剧本格式和看帧记录生成；列出的格式问题和没看完帧的集逐条处理后重新登记。Host 会将已通过的来源凭据与既有文字审校分别绑定到实际稿件，在登记时和 `present` 前后核对。成功加载本视频入口或调用来源动作后，本轮已知来源要求会保留，不能靠省略字段绕过已知问题。各集看帧完整且格式无误的转写是完成稿，未做独立审校时用 `draft` 登记，返回标签会写成“转写完成”；文件名和交付说明不称草稿，把具体待核点写进说明。仍有集没看完帧、格式错误、已知来源遗漏或文字问题未解决时，使用明确草稿并说明缺口，不冒称已修复；呈现描述逐字使用工具返回标签。

同版本、同实际范围的凭据可复用；稿件或来源材料变化时核对受影响范围并更新登记，不因局部措辞或排版主动重跑整剧。Word 操作沿 `office-docx`，保留 Markdown 源稿并回读实际输出；各集默认连排，用户要一集一页时用 `episode_layout: "page_per_episode"` 重新导出，不自己写脚本改 Word；最终文件字节仍须绑定，不能假定 Markdown 的凭据会自动转给 Word。标签只说明实际正文行、原片秒范围内抽样原帧与保存 ASR 的核对，不认证全片、原音、人物身份或同源。按用户约定交付实际范围的完整稿件并说明改编取舍与缺口，不以扫描、文字审校或导出成功扩大结论，也不增加知识库入库、制作成片或额外批准前提。
