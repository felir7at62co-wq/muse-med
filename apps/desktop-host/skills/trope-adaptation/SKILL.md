# 换梗与改编大纲

涉及正文起草、修订或续写时，先加载 `screenplay-project`，通过 `screenplay_project` 管理来源、人物知情及逐集独立验收，再按本技能完成内容。工具生成的引用、版本和已验收状态是续写依据；未通过独立审校的候选不作为正式交付。

写逐集大纲、创作分集或重新分集前，读取本技能的 [剧情与情绪分集指南](references/episode-design.md)。先按事件因果与情绪推进确定边界，再调整篇幅、增强对白互动，联合设计集尾钩子与下集承接。用户可调整集数和篇幅；当前已确定的创作方向直接沿用。

## 来源分析

先读 `outline/source-v1.md` 和实际取得的原剧材料。接收用户已有的小说、剧本、视频，以及切片转写或切片描述；逐项记录文件或链接、集数或章节、时间码或原文行号等来源位置，无法定位的标为待核实。区分亲自看过的画面、转写中的话、用户描述和推测；仅有切片转写时不声称已核对画面。按实际覆盖的关键事件分析主角目标、阻力、人物关系、冲突、转折和情绪变化，未覆盖的范围列为缺口，不用剧情简介补足原剧事实。

用户提供重点切片但没有播放量、互动量等热度证据时，称为**用户指定重点片段**，不声称已自动识别热点或证明它是原剧最热片段。注意与地位的变化、何时被需要或被替代、观众的焦虑如何积累和释放可作为分析视角，不把“三层重视”或任何热门配方当成固定公式。

## 看点清单与用户确认

从有来源依据的片段形成编号看点清单。每个看点依次写出**事件、冲突机制、情绪回报、反转、必要铺垫**及来源位置；没有反转或暂缺铺垫依据时如实标注，不硬造。必要铺垫说明看点成立之前观众必须知道什么、由哪个已覆盖片段提供。原剧事实与可迁移的情绪机制分开。

把清单交用户确认哪些看点**必须保留**，并逐项确认是保留原事件，还是只保留核心机制后重设计事件。已有明确要求时记录所依据的用户消息、选择和版本，不重复询问；选择仍会改变本作方向且尚未明确时，先等用户确认，不把模型推荐当成用户决定。

## 候选方案

完成上述看点决定后，按用户指定数量给换梗方案；未指定时给少量明显不同的方向。每个方案写一句话定位、新主角与世界、核心欲望和阻力、情绪推进、关键新事件、结局、适合的受众和制作取舍。附逐项看点对应表，以看点编号标明**保留、改写或遗漏**，写清保留的是原事件还是核心机制、新事件怎样承接必要铺垫并兑现情绪回报，以及改变人物关系后反转是否仍有因果。必保留看点不能无声遗漏；候选方案漏掉它时先修订方案，不能直接写改编大纲。

以成果冒领为看点时，每个候选先写明**被冒领的具体成果**及用户要讨回的具体主张：样式设计、实际制作、词曲创作、研发贡献、署名或名分不能互换；不得为了通过审查擅自缩小用户必保留的成果、名分或反转目标，需要改变时先交用户决定。按**主张→主证据实际证明的事实→允许得出的结论**逐项核对，结论不得超过证据的证明力；同时核对指向该成果的记录是否在冒领前形成、由谁保存及如何供第三方核对、冒领者如何接触成果、证据为何到反转时才公开。区分**主证据**与**补强证据**；日期、持有、送检、技艺、现场复现各自只证明对应的时间、占有、送检或能力，技艺、持有、现场复现不得单独证明具体成果归属，也不得从这些事实直接推出原创归属。每个候选提出至少一种与已知事实相容、对冒领者最有利的合理替代解释，检查主证据能否排除；证据不足或无法排除时明确标记缺口，优先修订争夺主张或证据链而非堆砌巧合，但不得擅自改变用户必保留目标，不得宣称因果闭环或仅凭候选直接进入正式大纲。虚构剧情只要求内部因果自洽，不要求法律级证明；篇幅建议不得提出无依据的绝对规则，例如「20 集以上必须新增更大对手」。

可保留抽象的冲突与情绪节奏，同时重新设计人物身份、关系、事件因果、场景、台词与结局；不得把原作逐场换名、复制标志性画面或保留相同剧情顺序。用户指定题材时重点深化该方向，不强制凑选项。把方案连同**建议的集数、单集篇幅或总字数、分场密度、目标时长与交付格式**交给用户选择；篇幅建议必须依据实际覆盖的来源素材和用户目标，说明素材能支撑的范围及扩写所需的新增情节，数字是可调整的起点。用户已限定集数或篇幅时直接沿用；不得无依据地把长篇或新增更大对手当作必需设定，扩展方向只能作为待用户选择的可选方案。用户可选一个、混合多个或提出新梗；未确定故事方向时停在候选阶段，不写正式本作大纲或正文。用户已明确选定换梗方向时，记录其决定和依据，直接沿该方向完成看点对应与因果检查，不重新提供候选方案要求再次选择；进入大纲仍须完成下述独立人工审核。

## 候选人工审核与进入大纲

在候选阶段单独停下，把所选候选的具体成果与主张、主证据实际证明的事实、未排除的替代解释、反转因果和关键缺口交用户人工审核。用户选择候选方向、集数或篇幅不等于证据链审核通过，也不等于授权写正式大纲；不得代替用户作出审核决定。若用户此前已明确审核当前候选版本的证据链与反转因果并确认可以进入大纲，记录所依据的用户消息与版本，不重复询问。

存在未解决的关键证据或反转因果缺口时，不得把候选写成确定翻盘或声称因果闭环；先修订候选并复核，或请用户明确决定如何处置缺口。用户接受待解决项不等于该项已被证明；若用户明确允许带着待解决项进入大纲，该大纲仍是待审草案，须标明缺口与待补条件，不把条件性反转写成确定结局或将草案当成已审定版本。只有用户明确确认当前所选候选版本的证据链与反转因果可以进入大纲，并明确决定未解决缺口的处置方式后，才继续；否则停在候选阶段。

## 改编大纲与审校

完成候选人工审核并取得用户明确进入大纲的确认后，记录其决定及版本，再写 `outline/adaptation-v1.md`：人物与关系、全剧主线、逐集目标/冲突/转折/钩子、结局和篇幅计划，并附最终看点对应表。逐项复查必保留看点及其必要铺垫、改写后的因果、情绪回报和结局；对遗漏、互相矛盾或来源不足的部分先修订或标缺口，不把候选草稿当成已确定大纲。发现篇幅与素材量冲突时给出修订理由。按已选大纲进入 `screenplay_project` 的事实与逐集独立审校，未验收版本不作为正式交付；用户确定大纲后依该版本连续写完，不在每一集重新征求选择。

处理下列情况时，按本轮已有材料决定下一步；表格是执行提醒，不代替实际来源核对或用户选择：

| 情况 | 下一步 |
| --- | --- |
| 来源依据不足 | 列出缺口并等待可核对材料，不编造来源事实；在有依据的范围内保留分析记录。 |
| 用户尚未确认看点 | 展示看点清单征求确认，在候选方案前暂停；不得替用户决定必保留项。 |
| 用户已有明确要求 | 记录依据、已选必保留项及保留原事件或核心机制的决定，不重复询问。 |
| 候选方案遗漏必保留看点 | 退回修订并补足看点与必要铺垫，不得进入改编大纲。 |
| 用户仅选定方向 | 记录所选候选版本，交用户人工审核证据链与反转因果；未获明确确认前停在候选阶段。 |
| 候选仍有关键缺口 | 修订并复核，或记录用户对待解决项的明确处置；接受待解决项不表示已证明，不写确定翻盘。 |
| 正常流程 | 核对来源和看点决定后给候选方案；用户选定方向、完成候选人工审核并明确确认可进入大纲后，写改编大纲并审校。 |
