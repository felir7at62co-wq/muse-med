# Desktop 工作区后继存储

[English](guide.md) | 中文

## 变更

Desktop 将工作区领域路由到 `muse-workspace-owned`。首次打开时，从之前选定的活跃 JSON 后端复制完整快照到配置的后继 `root`，保留 Workspace ID、Session ID、顺序、归档和置顶状态。来源 JSON 保持原样；后继租约不会锁住仍在写该来源的旧进程。迁移回执记录其规范路径及 SHA-256。后续工作区变动将成员关系代次和 authority ID 一起原子保存。

一个进程在整个领域打开期间持有后继存储的内核所有权租约。第二个持有者会立即失败；进程终止会释放所有权。移除绑定成员、删除其工作区或归档其 Session 时，会在提交归属变更前撤销活跃的视频续聊。模型与工作目录选择分别有作用域内保护。

首次发布前，有界的本机进程快照会拒绝仍在运行的其他受支持 Desktop Host，包括父进程退出后尚未排空的旧 Host。查询不完整时拒绝迁移，不会终止任何进程。检查范围是同用户的 Desktop 进程，Windows 还限定为同交互会话。不支持手工非 Desktop 写入方，以及跨用户或跨交互会话共享产品 home。

发布后以后继存储为准。旧版本对保留来源文件的修改不会再次导入，降级也不会将后继工作区修改写回来源。不支持的来源后端、未完成的来源变更及缺少迁移回执的后继存储会报错，不会启动空替代库。没有记录原始绑定的旧任务保持待处理状态。

## 迁移

1. 首次启动更新版本前，正常关闭旧 Desktop。保留原工作区 JSON 和 Session 目录。Desktop 组合从原工作区路由推导 `sourceBackend` 并保留该后端配置的根目录；不要用默认主目录替代自定义来源。
2. 启动更新后的 Desktop 一次。迁移在当前 Harness home 下的 `storages/workspace-owned-v1/` 内写入 `state.json` 和 `migration.json`；不会改写 Session 日志代际和原 JSON。
3. 确认 Workspace 和 Session ID 保持一致。如迁移报告不匹配，检查回执中的来源路径和 SHA-256。来源存在未完成的创建或删除时，应先由原所有者恢复，再迁移。
4. 此后使用更新后的 Desktop 修改工作区。删除、移动或归档绑定的工作会取消其自动续聊。需要检查旧版本时使用隔离 home；旧来源写入不会同步到后继存储。
