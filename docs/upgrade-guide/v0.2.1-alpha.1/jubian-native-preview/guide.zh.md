# 聚变原生视频预览

[English](guide.md) | 中文

## 变更

原生准备在已保存设置缺失或为 null 时补入 `backupModelList: []`，保留显式列表并拒绝其他类型。列表参与冻结请求体与指纹。缺少该字段、尚未提交的旧预览不再与当前准备结果一致。

准备按 key 和数字父资产身份解析素材，再按提示词标记首次出现的顺序输出，包括交错的图片与音频参考。物理行顺序不同、尚未提交的旧预览可能具有不同的请求体指纹。已有结果若包含同一组图片身份或 URL，但顺序不同，须继续对账；重排的证据既不能确认完全匹配，也不允许再次提交。相同提交的旧图片后音频分组 key 已有记录时，即使旧文件或远端任务缺失，也会阻止以规范化后的 key 收费。单次提交返回 `reconcile_conflict` 和 `original_idempotency_key`；批量预检在新增预约前拒绝。

`submit_video` 在尝试 PUT 后报告 `put_sent: true`，包括提供方拒绝或传输失败；此前发生异常时会错误地报告 false。结果新增 `put_error`，携带已去除凭据的提供方诊断或通用本地错误。两个字段都不确认任务或费用；结果不明的请求保留预约金额，原键不能重复提交。

## 迁移

1. 仅对原 key 与规范化 key 均无账本记录的预览重新运行 `prepare_video`，审阅新文件并使用它自己的键。
2. 已有记录的键保留原预览，以同一键只读对账。返回 `original_idempotency_key` 时使用该键。原文件缺失时继续保留结果未明状态，不为重试结果不明的请求使用新键。
3. 将 `put_error` 展示为提交诊断；回读到匹配任务后才能声称已生成。验证重放不再发送 PUT。
