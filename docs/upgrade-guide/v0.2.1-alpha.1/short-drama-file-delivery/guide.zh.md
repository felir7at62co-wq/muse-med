# 先归档短剧候选再交付文件

[English](guide.md) | 中文

## 变更

Desktop 编辑与创作会话原先允许 `present`、`send_file`、`dsh_im_return_file` 直接交付短剧工作成片。现在，原生工具已登记的单集输出、已绑定短剧项目正式输出位置中的视频，须与当前 `stage_delivery` 候选一致才能交付。修改 MP4、SRT、时间线、已记录选源或原配对证据后，这些文件交付操作不再接受旧候选。仅后续编辑原生草稿文件不会使已有 MP4 失效。其他文件任务与原始视频包附件保持原行为。

## 迁移

1. 按[渲染器证据要求](../../../../packages/drama/tool-episode-render/README.zh.md)完成源片 OCR 与实际帧观察。创作会话保留原抽样，使用 `video_source_review` 完成观察；短剧预设使用完整模式 `video_inspect`。无需切换预设。
2. 使用 `resume=true` 渲染，以同一时间线和显示 SRT 生成可编辑草稿，保存在 `02_剪映草稿`。正式交付不因项目开关而豁免源片复验。竖屏还须有当前产品字幕配置及实际朱雀字族的文本、宽度和字体测量通过证据；横屏和方形保留原字体规则。
3. 调用 `drama_render method=stage_delivery`，传入真实工作视频、时间线、字幕与草稿路径。返回的 `candidate` 状态与内容验收分开保留。
4. 将返回的 `01_可交付视频/第NN集.mp4` 传给文件交付工具。插入视频包、裁切或修改渲染 SRT 后，重建受影响产物并重新归档。文件交付不证明内容、剪映显示或与后续编辑草稿的一致性已通过验收。需要交付新的一致产物时，重新归档整套。

这些检查不拦截任意 shell 复制或 Markdown 链接。可编辑项目回执用于一致性核对，不能抵御故意篡改。规范输出位置以外的原生输出登记只在当前会话策略挂载期间有效。
