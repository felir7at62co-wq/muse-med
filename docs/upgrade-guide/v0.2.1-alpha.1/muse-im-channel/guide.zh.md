# Muse IM 通道设置

English | [中文](guide.md)

## 变更

Muse 使用 `@xmanrui/dsh-im` 连接即时通信平台。机器人管理入口移至设置 → IM机器人。原 `feishu-channel` 配置只对已启用且凭证完整的飞书应用执行一次导入；之后的机器人设置和凭证由原生 IM 存储管理。账号独立使用的桌面远程连接提供方保持不变。

同一飞书机器人的私聊和群聊使用其 IM 设置中选择的工作区，共享文件和素材，各聊天分别保存 Session 历史。单个聊天的目录覆盖不再生效。启动时会解除已有记录中 Session 工作目录与机器人工作区不同的绑定，不移动或删除对应的 Session 日志和文件；目录匹配的绑定保留原 Session ID。无法读取 Session 元数据时会拒绝复用，并保留绑定。对话命令不能单独为某个聊天指定其他工作区。

## 迁移

1. 完成正在运行的任务，再于更新后重启 Muse。profile 准备过程会备份包清单并替换旧飞书 bundle。迁移成功前，保留原凭证 patch、Session 日志和 `feishu/accounts` 目录。
2. 打开设置 → IM机器人 → 飞书，确认原机器人已连接。导入保留原允许群的使用范围，仍要求精确 @ 当前机器人。已登记的主人也可在新群通过精确 @ 当前机器人使用。原生访问策略仍然生效；新群其他成员不会因此获得本机权限，控制命令和操作卡片仍仅向主人开放。私聊保留已配置的主人身份。
3. 在机器人设置中核对当前工作区，选择私聊和群聊需要共享的文件与素材所在目录。修改此选项会影响该机器人所有聊天的后续工作，不会搬迁旧文件或改写历史。
4. 从原有已授权对话发送消息。目录匹配时保留原 Session ID；原绑定指向其他工作目录时，下一条消息会在所选工作区新建独立 Session。旧私聊绑定还需要真实消息证明旧聊天 ID 与已授权发送者的对应关系。确认私聊和群聊都使用所选目录，且各自保留独立历史。其他已配置的原生机器人及设置不会被覆盖。
5. 后续在 IM机器人中管理连接，不再使用旧开关修改已导入的机器人。如果导入提示主人不明确或数据无效，先修正旧配置再重试；导入器保留原文件，并维持关闭的访问权限。
